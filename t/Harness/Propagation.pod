=head1 NAME

Harness::Propagation - the scenario harness for the propagation rows

=head1 SYNOPSIS

  use lib 't';
  use Harness::Propagation;

  my $h = make_harness(envs => ['qa', 'lab']);
  my $sha = publish_from_b($h, files => {'ops/shared.yml' => "---\n"});

=head1 DESCRIPTION

The harness is a bare repository standing as R plus two real clones of it.
Copy A belongs to the operator and every command under test runs there.  Copy
B belongs to a teammate, and the publish helpers write from it, because most
of the hazards only show themselves once somebody else has published.

Every helper that builds repository, vault, or API state lives in this module
and nowhere else.  A helper that asserts lives beside the test that uses it,
except for the two invariant assertions, which every row reads through.

=head1 FUNCTIONS

=head2 make_harness(%opts)

Builds R, clones copy A and copy B, writes the deployment root through
C<Genesis::Top-E<gt>create>, and publishes the control branch.  Returns the
harness object.  Takes C<envs>, C<type>, C<control>, C<pr_prefix>,
C<provider>, C<mode>, C<root>, C<pipeline>, C<vault>, C<github>, and C<kit>.

C<vault> defaults on, and the harness spins the suite's own vault through
C<fixture_vault> when it does.  A row that wants no vault at all passes
C<vault =E<gt> 0>.

The named environments get their files through C<write_env_file>, and they are
committed along with the deployment root, so the control branch's first commit
is a repository a command can be run against.

The first deployment root sits at copy A's own git root, so the repository and
the deployment root are one directory.  C<Genesis::Top-E<gt>create> appends the
deployment name to the path it is handed and refuses a directory that already
exists, so the harness lets it build the root under a scratch directory and
moves what it wrote into place.  The configuration is still the one the real
code path writes.

=head2 commit_on_control($h, %opts)

Commits a file set in copy A and returns the new sha.  Takes C<files>,
C<message>, C<trailers>, C<branch>, and C<push>.

=head2 commit_from_b($h, %opts)

The same commit in copy B, never published.

=head2 publish_from_b($h, %opts)

Commits in copy B and publishes it with a real C<git push>.  The push is per
branch, carries no forced refspec, and sets the upstream, so copy B's own
remote-tracking ref moves with the publish.  A
divergence read taken straight after therefore reports in-sync with no second
refresh, while copy A's refs stay where they were until copy A fetches or
pushes.

=head2 push_from($h, $copy, @branches)

Pushes each named branch on its own and returns a hashref of branch to 1 or 0.
The push sets the upstream, as the push behind the commit helpers does, so the
harness's two push paths leave a branch in the same state.

=head2 refresh($h, $copy, @branches)

Fetches in the named copy so that T moves and L does not.

=head2 ref_in($dir, $ref)

Returns the sha the named ref stands at in the repository at C<$dir>, or undef
where the ref is absent, so a row proving an absence reads it rather than
trapping a death.

=head2 tree_of($dir, $ref)

Returns the commit's paths as a sorted arrayref, or an empty arrayref where the
ref is absent.

=head2 upstream_of($dir, $branch)

Returns the upstream the named branch tracks, as C<origin/E<lt>branchE<gt>>,
or undef where the branch has no upstream, so a row proving that absence reads
it rather than trapping git's complaint.

=head2 counts($dir, $branch)

Returns the two numbers C<git rev-list --left-right --count> prints for the
branch against its remote-tracking ref, ahead first and behind second.  The
read names the remote-tracking ref outright rather than the upstream, so it
answers even where no upstream is configured.

=head2 init_branch($h, $env, %opts)

Cuts the environment's branch on R as C<pipeline-apply> would, which is an
orphan root commit adding a single C<init> file under the subject
C<Initialize E<lt>slugE<gt> branch [ci skip]>.  It is written with plumbing
and checks nothing out in either copy, so the rows that assert on working
state are not disturbed by their own setup.  Takes C<root>, C<type>, and
C<push>, which defaults on.  C<root> is taken for symmetry with the helpers
that write into a deployment root and has no effect today, because a slug is
composed from the environment and the type alone and no root appears in it.

=head2 deliver($h, $env, %opts)

Writes one delivered commit onto the deployment branch, mirroring the
propagation set as it stood at the delivered control commit and carrying the
marker.  C<keep> leaves named paths standing so a row can stop the mirror's
removing half, and C<corrupt> lands a named path at the wrong content, which
is what the snapshot assertion has to catch.  Also takes C<control>, which is
required, C<files>, C<body>, C<type>, C<pr>, which writes onto the
environment's pull request branch instead of its deployment branch, C<copy>,
which defaults to C<b>, and C<push>, which defaults on.

The delivery is a teammate's published work, so it is written in copy B and
the operator's clone reads behind it until the row refreshes.  Copy B is given
whatever objects it lacks with a fetch that names its source by path, so no
remote-tracking ref moves behind the row's back, and it sits its delivery on
its own branch tip where it has one and on R's where it has not, so the push
that follows fast-forwards.  There is no C<remove_init> option, because the
mirror starts from an empty index and the C<init> file goes by construction.

=head2 propagation_set($h, $env, %opts)

Returns the set's git-root-relative paths as a list, computed by the harness
from the tree at a control commit.  It is deliberately not
C<propagation_files>, because a row that asserted a delivery through the
product's own reader would be asserting that reader against itself.  Takes
C<at>, which defaults to control's tip, C<root>, and C<extra>.  The tree is
read in whichever of the three repositories holds the commit, so a control
commit published from copy B reads the same as one made in copy A.

=head2 harness_marker($h, $ref, %opts)

Returns the control commit the newest marker at C<$ref> names, walking
subjects and bodies alike, or undef where no marker stands.  Also the
harness's own read, for the same reason.  The options are C<limit>, which
defaults to twenty commits, and C<copy>, which names C<a>, C<b>, or C<r> and
reads that repository alone.  Where no copy is named, R is asked for the ref
first, since a delivery is published and R is what the copies eventually
agree with, and a copy is read only where R has no such ref at all.  A caller
comparing trees in one copy names that copy, so the marker and the trees come
out of the same repository.

=head2 add_deployment_root($h, %opts)

Adds a second deployment root to the same repository, so a row can build two
roots that share an environment name, and returns its repository-relative
path.  Takes C<type>, which is required, C<envs>, and C<path>, which defaults
to the type.  C<Genesis::Top-E<gt>create> is told the directory to write, so
the second root lands where it belongs with no scratch directory and no move;
only the first root, which has to sit at copy A's own git root, needs that.

=head2 write_env_file($h, $env, %opts)

Writes an environment file on control and returns its git-root-relative path.
C<site> writes it at a level of the hierarchy rather than at the leaf.  Also
takes C<root>, C<genesis> and C<pipeline> as hashrefs merged into the file,
and C<commit>, which defaults on.  C<type> is taken for symmetry with the
helpers that compose a slug and is not written into the file, because nothing
in the file body names a deployment type.

=head2 fixture_vault($h)

Spins the suite's own local vault through C<helper::vault_start> and points the
harness's environments at it, returning the safe target.  A real vault rather
than a double, because the rows run whole commands and a C<genesis> child
cannot read a double living in the parent's memory.  C<make_harness> calls it
when C<vault> is on, and a row calls it directly where it built its harness
without one.  C<helper::vault_start> is the TAP-free half of
C<helper::vault_ok>, so building the fixture adds nothing to the plan of the
subtest that builds it.

The vault is spun once and then shared by every harness in the file, so the
fixture clears the exodus mount as it attaches.  Each harness therefore starts
on an empty record tree rather than on whatever the subtest above it wrote, and
a row that proves a record's absence proves it of its own harness.

=head2 fixture_applied($h, %opts)

Writes the applied record at C<< $h->applied_path >>, carrying the control
commit the apply applied from, the provider, and the time, and returns that
path.  Takes C<control>, C<provider>, which defaults to the harness's own,
C<type>, and C<at>.

=head2 fixture_pipeline_record($h, $env, %opts)

Writes that environment's compiled pipeline facts beside its own exodus
record, under a C<pipeline> subpath, and returns that path.  Its absence is how
the walk knows the applied record does not know the environment, so a row that
wants that case simply does not call this.  Takes C<dependencies> as an
arrayref written as one comma-joined value, C<discovery>, which is C<complete>
or C<incomplete> and defaults to C<complete>, and C<type>.

=head2 certify($h, $env, %opts)

Writes the environment's exodus deployment record, so a row can give it a
certified commit or advance one, and returns its path.  C<commit> is the
deployment-branch commit the deploy stood on and C<control_commit> is the
control commit that tip's newest marker names, which are the pair the hatch
case has to tell apart.  Also takes C<state>, which defaults to C<success>,
C<type>, C<at>, and C<dependencies_read> as an arrayref of deployment slugs,
written as one comma-joined value and left out of the record altogether where
the row does not give it.

=head2 fixture_hold($h, $env, %opts)

Writes the hold record with C<reason>, C<user>, C<hostname>, and C<at> and
nothing else, and returns its path.  The reason is required.  C<user> defaults
to C<operator> and C<hostname> to C<harness.example.com>.

=head2 fixture_proposed($h, $env, %opts)

Writes the record naming the pull request an environment has open, as the four
fields C<control_commit>, C<number>, C<url>, and C<at>, and returns its path.
The pull request's number arrives under C<pr>, which is what the GitHub double
and the rows that open one call it, and C<number> is taken as an alias for a
caller that has the record's own spelling to hand.  Also takes C<control>,
C<url>, C<type>, and C<at>.

=head2 break_vault($h, %opts)

Moves records aside so a read of them refuses, so a row can assert that an
unreadable input makes the run refuse.  C<envs> is an arrayref naming the
environments to break and defaults to every environment the harness declares,
and C<applied> is a boolean that adds the applied record to whatever C<envs>
named.  An C<envs> given as an empty arrayref means no environments rather
than falling back to the default, so C<break_vault($h, envs =E<gt> [], applied
=E<gt> 1)> breaks the applied record alone while C<break_vault($h, applied
=E<gt> 1)> breaks it along with every environment.

Both movers name the fixture's target outright, so a harness built with
C<vault =E<gt> 0> is refused with a plain death rather than left to move
records in whatever vault the ambient C<safe> target happens to be.

=head2 restore_vault($h)

Puts back everything C<break_vault> moved aside, so the same row can assert the
run succeeding once its input is readable again.  It refuses a harness with no
vault fixture for the reason C<break_vault> does.

=head2 snapshot_w($h, %opts)

Reads the branch, the HEAD sha, the current directory, the porcelain status,
and the index, and returns them as one hashref.  The one option is C<copy>,
which defaults to C<a>.  The directory is read before the rest, because a
command that switched away can leave the process standing in a directory the
switch removed, and the git reads below run through C<pushd>, which cannot
return to a directory that is gone.  Where that has happened the snapshot
steps back into the copy and still answers the directory as undefined.

=head2 assert_w_restored($w, $name)

Compares all five against the snapshot and fails naming every one that
differs.  It runs on success and on failure alike, because I1 promises
restoration on every exit path and an assertion that runs only on success
proves nothing about the paths that matter.  It is the one helper here that
emits TAP, since it is an assertion rather than a builder of state, and a test
that wants to read a deliberate failure as a result rather than a failure of
its own file sets C<$Harness::Propagation::BUILDER> to a private
C<Test::Builder> for the length of the call.

=head2 assert_snapshot_invariant($h, $env, %opts)

Compares the deployment branch against the control commit its newest marker
names.  Two comparisons and not one: the branch matches the source over the
propagation set's paths, and the branch holds nothing outside the set.  The
second is the half that fires in practice, because a copy-only writer never
removes a leftover C<init> or a path that dropped out of the set.  Every
difference is named, and a branch with no marker fails rather than passing
vacuously.  Options are C<commit>, which defaults to the branch tip, C<copy>,
C<type>, and C<name>.  A named C<copy> is where the trees are read and is
passed through to the marker read, so both come out of one repository; where
none is named the trees are read in copy A and the marker search order
stands.  Where the listing of the branch cannot be read at all, the second
comparison fails naming the ref rather than reading git's complaint as a list
of paths.

=head2 fixture_command($h, $kind, %opts)

Returns a coderef for one of four shapes of working state, C<restores>,
C<leaves_branch>, C<leaves_staged>, and C<loses_cwd>, which exercise the
assertion itself rather than a genesis command.  The one option is C<copy>.

=head2 run_genesis($h, @argv) and run_genesis_in($h, $copy, @argv)

Run a whole genesis command in a copy, taking the W snapshot before it and
asserting the restoration after it, and return the output, the error, and the
exit code, in that order.  The exit code is the one the command really exited
with, because C<Genesis::run> has already shifted C<$?> and shifting it again
would read every real code as a zero.

A leading hashref takes C<copy>, default C<a>, C<dir> for a subdirectory to
run from, C<answers> as an arrayref, C<pipeline_task>, which sets
C<GENESIS_PIPELINE_TASK>, C<git_version>, which puts a fixture git reporting
that version first on the path for this run alone, C<no_token>, which leaves
C<GITHUB_AUTH_TOKEN> out of the child's environment while leaving every
fixture binary on its path, C<restore>, default 1, which a row turns off where
it asserts the restoration in its own words, and C<terminal>, default 1, which
is accepted and does nothing today.

The fixture binaries the harness writes reach the child through the path this
run builds and through nothing else, so no helper puts a fixture on the
parent's own C<PATH> and a run that asks for none sees none.

C<run_genesis_in> is the same run in a named copy.

=head2 stand_on($h, $branch, %opts)

Puts a copy on a branch, and optionally in a subdirectory of it.  Options are
C<copy>, default C<a>, and C<dir>.

=head2 fault_git($h, %opts)

Returns a C<Harness::Propagation::Git> handle for a copy and arms the plan
file and the step log, which a spawned command picks up.  The one option is
C<copy>, default C<a>.  C<Service::Git> hands every caller the one instance it
caches per repository, so the handle a row already held is re-blessed and
faults from here on as well.

=head2 fail_on($git, $step, $n, %opts)

Arms one named git step to die on its nth call.  C<from> makes every call
from the nth onward die rather than the nth alone, and C<message> fixes what
it dies with.

=head2 step_log($git) and reset_steps($git)

Return every intercepted call in order, each an arrayref of the step's name
and its arguments, and empty the log and the counters between a row's phases.

=head2 sever_remote($h, %opts) and restore_remote($h)

Make every remote step fail with the text a real unreachable remote emits,
and disarm them again.  C<after> severs the remote partway through a run.

=head2 hold_session_lock($h, %opts) and release_session_lock($h, $pid, %opts)

Take the switch lock in a child process and release it.  The lock is the
C<flock> on C<genesis-session.lock> in the git directory, and the holder
writes its pid on the first line and its command on the second for the
refusal message to read.  Options are C<copy> and C<command>.  C<hard> kills
the holder without letting it finish, so a row can show that the kernel drops
the lock with the process.

=head2 github_double($h, %opts)

Stands the GitHub double up as a fixture C<curl> first on the path, backed by
a state file the harness writes and a call log it reads back, and returns the
double.  It is a binary rather than an object because C<Genesis::curl> shells
out, so an in-process double could not reach a spawned command.  Options are
C<token>, which defaults to C<harness-token>, C<admin>, which defaults to 1,
and C<repository>, which defaults to C<owner/repo>.  C<make_harness> calls it
for you under C<< github => 1 >>.

=head2 gh_pull_request($gh, %opts)

Declares an open pull request and returns its number.  Options are C<env>,
which names the environment whose pull request branch and deployment branch
the request runs between, C<head> and C<base>, which override those two,
C<title>, C<body>, C<review>, which takes C<none>, C<approved>, or
C<changes_requested>, C<reviewer>, C<review_body>, and C<at>.

=head2 gh_close_pr($gh, $number, %opts)

Closes a pull request.  C<merged> marks it merged rather than abandoned and
C<at> dates it.

=head2 gh_merge_pr($gh, $number, %opts)

Merges a pull request by a named method, which C<method> gives and which
defaults to C<rebase>, and closes it as merged.

=head2 gh_protection($gh, %opts)

Declares what the protection endpoints answer and returns what the run has
set, so a row can read the settings back.  C<branch> and C<settings> name one
branch's protection, and C<admin> off makes every protection call answer 403,
which is the non-admin case.

=head2 gh_unreachable($gh)

Takes the API away, so every call reads as a failed C<curl> rather than as an
answer with a status.

=head2 gh_reachable($gh)

Gives the API back again.

=head2 gh_no_token($h)

Runs the next command with no token in its environment.  It takes the harness
rather than the double, because the token is a fact about the environment a
run is given, and it is one shot: C<run_genesis> consumes the flag, so the
command after it carries the token again and the fixture C<curl> stays where
it is.

=head2 gh_calls($gh)

Returns every call the run made, each as a hashref of the C<method>, the
C<url>, the C<body>, and the C<token> the caller's environment held, so a row
can assert that a preview was read-only, that exactly one client was built,
or that a run went out unauthenticated.

=head1 METHODS

C<r>, C<a>, and C<b> return the three paths.  C<git> returns a
C<Service::Git> handle for a copy.  C<type>, C<control>, and C<envs> return
the declared values.  C<slug> and C<pr_branch> render the deployment slug and
its pull request branch.  C<exodus_mount>, C<applied_path>, and C<env_path>
render the vault addresses.  C<gh> returns the GitHub double once
C<github_double> has stood one up, and undef before that.

=cut
