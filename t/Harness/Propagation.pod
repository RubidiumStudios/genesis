=head1 NAME

Harness::Propagation - the scenario harness for the propagation rows

=head1 SYNOPSIS

  use lib 't';
  use Harness::Propagation;

  my $h = make_harness(envs => ['qa', 'lab']);
  my $sha = publish_from_b($h, files => {'ops/shared.yml' => "---\n"});

=head1 DESCRIPTION

The harness is a bare repository standing as R plus two real clones of it.
Copy A belongs to the operator and every command under test runs there.  Copy
B belongs to a teammate, and the publish helpers write from it, because most
of the hazards only show themselves once somebody else has published.

Every helper that builds repository, vault, or API state lives in this module
and nowhere else.  A helper that asserts lives beside the test that uses it,
except for the two invariant assertions, which every row reads through.

=head1 FUNCTIONS

=head2 make_harness(%opts)

Builds R, clones copy A and copy B, writes the deployment root through
C<Genesis::Top-E<gt>create>, and publishes the control branch.  Returns the
harness object.  Takes C<envs>, C<type>, C<control>, C<pr_prefix>,
C<provider>, C<mode>, C<root>, C<pipeline>, C<source_control>, C<vault>,
C<github>, C<kit>, C<embed>, and C<exodus_mount>.

C<exodus_mount> names the vault subtree the harness's records hang off, and it
defaults to C</secret/exodus/>.  A mount below that default is taken, and one
above it is refused by name, because the vault fixture clears the mount whole
as it attaches and a wider mount would take records the harness does not own.
The refusal comes when the fixture attaches rather than when the option is
read, so a harness built with C<vault =E<gt> 0> and a short mount is refused
by the first call to C<fixture_vault> instead.

C<Genesis::Top-E<gt>create> writes no pipeline section at all, and every row
that reads a provider reads it out of that file, so the harness writes the
section afterwards from the options it was declared with.  C<pipeline> takes
three values rather than two, because an enabled pipeline, a section whose
C<enabled> is false, and a configuration with no pipeline section are three
states and one boolean cannot tell the last two apart.  1 is enabled, 0 is a
section whose C<enabled> is false, the string C<none> writes no section, and a
hashref is an enabled pipeline with those repository-wide keys set.
C<source_control> is a hashref merged under C<pipeline.source_control>.

Three source-control keys are seeded whether or not C<source_control> names
them, and they are C<control_branch>, C<pr_prefix>, and C<repository>.  The
first two are seeded so the configuration agrees with the branch and the
prefix the harness actually built.  The third is the one value the harness
cannot leave to the code, because copy A is cloned from a bare repository at a
filesystem path and that URL carries no GitHub owner and repo pair for the
derivation to read.  A row proving that refusal takes the override away by
naming C<repository> as undef in C<source_control>, which is how a seeded key
is removed rather than replaced.

C<kit> names one of the kits the suite ships under C<t/kits/>, and the harness
copies it in as the deployment root's dev kit before the seeding commit, so a
row runs against a repository whose kit is part of the control branch.  A
value carrying a slash is read as a path under the checkout root instead, so a
row that wants a kit the suite already ships elsewhere, such as
C<t/src/ops-blueprint>, names that path rather than a copy of the kit written
for these rows alone.  The
two kits written for these rows are C<exodus-reader>, whose manifest reads the
exodus record of every deployment the environment names and whose blueprint
refuses to render where a deployment it was told to require has none, and
C<broken-blueprint>, whose blueprint refuses any environment whose file sets
C<genesis.kit_blueprint_fails>.  A row that wants a kit of its own shape
writes one with C<fixture_kit> instead.

C<pipeline> defaults to 1, so a default harness carries an enabled section,
which is what nearly every row runs against now that the C<.genesis/config>
schema declares the key.  A row that wants the section switched off, or wants
no section at all, says which it wants.

C<mode> writes nothing into C<.genesis/config>, because whether a delivery
goes through a pull request is a per-environment question and there is no
repository-wide key for it.  A harness declared as C<mode =E<gt> 'pr'> gets
C<genesis.pipeline.require_pr> on each of its environment files instead.

C<vault> defaults on, and the harness spins the suite's own vault through
C<fixture_vault> when it does.  A row that wants no vault at all passes
C<vault =E<gt> 0>.

C<embed =E<gt> 1> writes an executable stub at C<.genesis/bin/genesis> and
commits it with the deployment root, which is where C<Genesis::Top::embed>
puts the running genesis for CI to call.  A row that asserts the eighth kind
of the propagation set, in the set itself or in a delivered tree, needs a file
there to find, and the stub stands in for the megabytes of the real one.

The named environments get their files through C<write_env_file>, and they are
committed along with the deployment root, so the control branch's first commit
is a repository a command can be run against.

The first deployment root sits at copy A's own git root, so the repository and
the deployment root are one directory.  C<Genesis::Top-E<gt>create> appends the
deployment name to the path it is handed and refuses a directory that already
exists, so the harness lets it build the root under a scratch directory and
moves what it wrote into place.  The configuration is still the one the real
code path writes.

=head2 commit_on_control($h, %opts)

Commits a file set in copy A and returns the new sha.  Takes C<files>,
C<message>, C<trailers>, C<branch>, and C<push>.

=head2 commit_from_b($h, %opts)

The same commit in copy B, never published.

=head2 publish_from_b($h, %opts)

Commits in copy B and publishes it with a real C<git push>.  The push is per
branch, carries no forced refspec, and sets the upstream, so copy B's own
remote-tracking ref moves with the publish.  A divergence read taken straight
after therefore reports in-sync with no second refresh, while copy A's refs
stay where they were until copy A fetches or pushes.

Copy B is given the branch before it commits, the way C<hand_commit> gives it
one, so a branch that was cut or delivered in copy A can be published onto
without a fetch of its own.  No remote-tracking ref moves in the giving.

=head2 push_from($h, $copy, @branches)

Pushes each named branch on its own and returns a hashref of branch to 1 or 0.
The push sets the upstream, as the push behind the commit helpers does, so the
harness's two push paths leave a branch in the same state.

=head2 refresh($h, $copy, @branches)

Fetches in the named copy so that T moves and L does not.

=head2 ref_in($dir, $ref)

Returns the sha the named ref stands at in the repository at C<$dir>, or undef
where the ref is absent, so a row proving an absence reads it rather than
trapping a death.

=head2 tree_of($dir, $ref)

Returns the commit's paths as a sorted arrayref, or an empty arrayref where the
ref is absent.

=head2 upstream_of($dir, $branch)

Returns the upstream the named branch tracks, as C<origin/E<lt>branchE<gt>>,
or undef where the branch has no upstream, so a row proving that absence reads
it rather than trapping git's complaint.

=head2 counts($dir, $branch)

Returns the two numbers C<git rev-list --left-right --count> prints for the
branch against its remote-tracking ref, ahead first and behind second.  The
read names the remote-tracking ref outright rather than the upstream, so it
answers even where no upstream is configured.

=head2 tip_of($h, $branch, %opts)

Returns the branch's tip in one of the two copies, or undef where that copy has
no such ref.  Takes C<copy>, which defaults to C<a>, and C<remote>, which reads
the copy's remote-tracking ref instead, so a row can tell L from T without
reaching for git itself.

=head2 remote_sha($h, $branch)

Returns the branch's sha on R, or undef where R has never had the branch.

=head2 refs_in($dir, %opts)

Returns every ref in the repository at C<$dir> as a hashref of the full ref name
to its sha, or an empty hashref where the repository has none.  Takes C<prefix>,
a ref pattern that narrows the read to one namespace, as in C<refs/heads>.

=head2 branch_of($dir)

Returns the name of the branch the repository at C<$dir> is standing on, or
undef where the read fails, as it does for a repository whose HEAD is unborn.

=head2 files_at($h, $ref, %opts)

Returns the commit's paths with their contents, as a hashref, or an empty
hashref where the ref is absent.  It reads R unless it is told otherwise, and
takes C<copy> to read one of the two copies and C<dir> to read a repository by
path.  The rows that assert a mirror want the whole tree in one hashref, so they
can compare a branch against its source without a call per file.  The contents
come back with their trailing whitespace stripped, because C<run> strips it, so
a row comparing against a literal that ends in a newline should read its other
side through the same reader.

=head2 slurp($path)

Returns the file's whole contents, or undef where the file is not there.
C<Genesis> exports a C<slurp> of its own that bails on a missing file, so a test
file that wants this one imports C<Genesis> before the harness.  Under C<perl
-w> Exporter reports that second import as a redefinition, which the lexical
C<use warnings> of a test file does not.

=head2 branches_on_r($h)

Returns R's branch names, short and sorted, as an arrayref, so a row asserting
that nothing was created compares against a plain list rather than against a
hashref of full ref names.

=head2 fresh_clone($h)

Clones R again, now, into a directory beside the two copies, and returns that
directory.  The clone carries none of the fixture's own history of fetches,
which neither copy does once the harness is built, so a row asking what a
clone made today can still fetch reads it here.  A clone cuts one local branch
for itself whatever R holds, so what it sees of R is its remote-tracking refs
under C<refs/remotes/origin>.

=head2 clone_copy($h, %opts)

Cuts a third copy from R now, registers it under a copy key, stands it on the
control branch, and returns that key.  A row that wants to run real code inside
the copy wants a C<Service::Git> handle on it, and the C<git> accessor builds a
handle from a copy key, so registering the copy is what lets every accessor the
harness already has read it rather than having the row build a handle of its
own.  Takes C<as>, the key to register it under, which defaults to C<c>.  A key
the harness already holds is refused rather than taken, because registering a
copy over C<a> would replace copy A for every accessor that reads it
afterwards.

The clone is made over C<file://> rather than over the path, because git
hardlinks the whole object store for a plain local clone and a commit no ref of
R can reach would arrive in the copy anyway.  A row asking what a copy cut
today does not hold needs the ordinary transfer, which sends what the refs
reach and nothing else.  Standing it on control is the other half: R is bare
and its own HEAD never names that branch, so a clone of it lands on an unborn
HEAD with no local branch.

=head2 subjects_of($h, $branch, $n, %opts)

Returns the branch's last C<$n> commit subjects as a list, oldest first, or an
empty list where the branch is not there.  It reads the copy's remote-tracking
ref, because a row asking what a run wrote is asking what reached R, so a row
refreshes before it reads.  Takes C<copy>, which defaults to C<a>, and
C<local>, which reads the name given as it stands rather than its
remote-tracking ref.

=head2 commits_on($dir, $ref)

Returns every commit the ref can reach as a list of shas, newest first, or an
empty list where the ref is not there.  A row asking whether a teammate's
delivery survived a run asks whether its sha is still on the branch, and a list
answers that without the row having to know where on the branch the commit
sits.  It takes a directory rather than a copy, because a row asks it of R as
often as of a copy.

=head2 heads_in($h, %opts)

Returns every local head in a copy as a sorted arrayref of C<E<lt>ref nameE<gt>
E<lt>shaE<gt>> lines, so a row proving that a command left L alone takes this
before and after the run and compares the two.  Takes C<copy>, which defaults
to C<a>.

=head2 reachable_on_r($h, $sha)

Returns true where R holds the commit and some branch of R can reach it, and
false otherwise, including where the commit was never handed in.  A record
naming a commit R cannot reach is a breach the pre-flight has to catch, and a
row proves it by asking R rather than by trusting the record.

=head2 newest_record($h, $path)

Returns the record set's newest entry as a nested hashref, or undef where the
path holds nothing.  The fixtures write a record flat, because an exodus record
is flat, so the dotted keys are inflated here and a row reads
C<$record-E<gt>{git}{commit}> the way the product does.  A set is either one
record at the path itself, which is what the harness's writers lay down, or a
path whose children are its entries, one per deploy and named for when it
happened, which is what a deploy writes; the path's own record is preferred,
and where there is none the newest child by name is the entry.

=head2 trailers_of($h, $ref, %opts)

  my $stage = trailers_of($h, $sha)->{'Genesis-Stage'};

Returns the commit's trailers as a hashref of name to value, read by handing
the commit message to C<git interpret-trailers --parse> rather than by picking
the message apart here, so a row asserting on a gate agrees with what git
itself sees.  The one option is C<copy>, which is C<a> by default.  A commit
carrying no trailer, and a commit the copy does not hold, each answer an empty
hashref, so a row proving an absence reads it rather than trapping a death.

=head2 init_branch($h, $env, %opts)

Cuts the environment's branch on R as C<pipeline-apply> would, which is an
orphan root commit adding a single C<init> file under the subject
C<Initialize E<lt>slugE<gt> branch [ci skip]>.  It is written with plumbing
and checks nothing out in either copy, so the rows that assert on working
state are not disturbed by their own setup.  Takes C<root>, C<type>, and
C<push>, which defaults on.  C<root> is taken for symmetry with the helpers
that write into a deployment root and has no effect today, because a slug is
composed from the environment and the type alone and no root appears in it.

=head2 deliver($h, $env, %opts)

Writes one delivered commit onto the deployment branch, mirroring the
propagation set as it stood at the delivered control commit and carrying the
marker.  C<keep> leaves named paths standing so a row can stop the mirror's
removing half, and C<corrupt> lands a named path at the wrong content, which
is what the snapshot assertion has to catch.  Also takes C<control>, which is
required, C<files>, C<body>, C<type>, C<pr>, which writes onto the
environment's pull request branch instead of its deployment branch, C<copy>,
which defaults to C<b>, and C<push>, which defaults on.

The delivery is a teammate's published work, so it is written in copy B and
the operator's clone reads behind it until the row refreshes.  Copy B is given
whatever objects it lacks with a fetch that names its source by path, so no
remote-tracking ref moves behind the row's back, and it sits its delivery on
its own branch tip where it has one and on R's where it has not, so the push
that follows fast-forwards.  There is no C<remove_init> option, because the
mirror starts from an empty index and the C<init> file goes by construction.

=head2 propagation_set($h, $env, %opts)

Returns the set's git-root-relative paths as a list, computed by the harness
from the tree at a control commit.  It is deliberately not
C<propagation_files>, because a row that asserted a delivery through the
product's own reader would be asserting that reader against itself.  Takes
C<at>, which defaults to control's tip, C<root>, and C<extra>.  The tree is
read in whichever of the three repositories holds the commit, so a control
commit published from copy B reads the same as one made in copy A.

The environment file kind is the ancestors and the environment's own file
together, where an ancestor is a cumulative hyphen-prefix of the
environment's name.  That is the name-based ancestors alone and not everything
C<propagation_files> joins, because the product's reader also picks up files
an environment inherits explicitly and paths it has cached.  A site file has to
travel for the same reason the leaf does, because a command standing on the
deployment branch reads every C<genesis.pipeline.*> key through the merged
hierarchy and finds a key set above the leaf absent wherever the file holding
it stayed behind.

The kit source under C<dev/> and the reaction scripts under C<bin/> are kinds
of their own and they stand whatever the environment file says, because
C<propagation_files> builds its kinds independently of one another and adds
the tracked paths on top of them.  A reader that took the kit away wherever a
list was declared would read a correctly mirrored branch as one that had lost
its whole kit.

The ops files are the one kind the tracked list stands in for here, because
the harness runs no blueprint hook and the list is the only statement the
repository makes about which of them the merge consumes.  Where the
environment file at C<at> declares
C<genesis.pipeline.track_additional_files>, which is the key the product
itself reads, those paths are the ops files that are in, and a path under
C<ops/> that the file does not name is out.  Where the file declares no list
the kind stands whole and matches everything under C<ops/>, which is every
environment the suite writes without saying otherwise.  The list is read from
the tree at C<at> and never from the working tree, because a delivery made
under a wider list leaves behind paths the next delivery has to remove.

=head2 harness_marker($h, $ref, %opts)

Returns the control commit the newest marker at C<$ref> names, walking
subjects and bodies alike, or undef where no marker stands.  Also the
harness's own read, for the same reason.  The options are C<limit>, which
defaults to twenty commits, and C<copy>, which names C<a>, C<b>, or C<r> and
reads that repository alone.  Where no copy is named, R is asked for the ref
first, since a delivery is published and R is what the copies eventually
agree with, and a copy is read only where R has no such ref at all.  A caller
comparing trees in one copy names that copy, so the marker and the trees come
out of the same repository.

=head2 hand_commit($h, $branch, %opts)

Writes a commit carrying no marker, which is the emergency hatch of D33.  It
is written from copy B by default and pushed, because the interesting case is
a hand edit that the operator's own clone has not yet seen.  The options are
C<copy>, C<files>, C<message>, and C<push>, which defaults on.  Where the
copy has never seen the branch, it is cut from R's tip first, so the commit
lands where the caller named it.

=head2 local_only_commit($h, $branch, %opts)

Writes a commit in copy A that is never pushed.  C<marker> takes a control
sha to give the commit a marker subject, or 0 to give it none, and C<files>
and C<message> say what it carries.

=head2 squash_merge($h, $env, %opts)

Squashes the environment's pull request branch onto its deployment branch, so
the tip's subject is the merger's and the marker survives in the body alone,
and returns the squash commit.  C<subject> is the merger's title, C<control>
names the control commit the aggregate carried, C<keep_marker> off is the
site that lost the marker altogether, and C<push> defaults on.  Where copy A
has no pull request branch yet, one is cut off the deployment branch and the
aggregate delivered onto it, which is the shape the product leaves behind.

=head2 unrelated_branch($h, $env, %opts)

Makes a local branch of the slug's name in copy A that shares no ancestor
with R's branch of the same name, and returns its orphan root commit.

=head2 diverge($h, $branch, %opts)

Leaves L and T each holding commits the other lacks, C<local> of the first
and C<remote> of the second, each defaulting to one.  The teammate's commits
are published and copy A is refreshed before the local ones are written, so
the divergence is one copy A can read from its own refs.

Copy A's branch is cut before the teammate publishes anything, where copy A
has no branch of that name yet.  A branch cut afterwards would start at the
teammate's own tip, and a call with C<local =E<gt> 0> would then read in-sync
rather than behind, which is the one shape that call is for.

=head2 move_on_r($h, $branch, %opts)

Has copy B advance a branch on R after copy A's refresh, which is how a row
makes an expected-tip push fail, and returns the commit R now carries.
C<files> and C<message> say what that commit holds.

Copy B is put on the branch with a checkout rather than with C<update-ref>, so
its working tree and its index move with the ref.  A copy standing on the
branch under C<update-ref> came back with an index that no longer matched its
own HEAD, and the commit made straight afterwards recorded the removal of
everything the branch had gained.  The checkout is the one thing here that can
fail, so a copy B carrying changes the move would overwrite makes the call die
by name, where C<update-ref> used to succeed quietly and leave the mismatch
for a later commit to record.

=head2 delete_on_r($h, @branches)

Takes branches away from R.

=head2 delete_local($h, $copy, @branches)

Takes branches away from one copy's local refs.

=head2 rewrite_control($h, %opts)

Force-pushes the control branch with one commit dropped, and returns the sha
that is now unreachable.  It is C<rewrite_branch> on the control branch and
takes the same options.

=head2 rewrite_branch($h, $branch, %opts)

Force-pushes any branch with one commit dropped, and returns the sha that is
now unreachable.  C<drop> names the commit to remove, and where it is left out
the commit behind the tip is taken.  One commit is dropped whichever way the
call is written, and there is no option that changes how many.  The rewrite
runs in copy B, because a rebase checks out and copy A's working state is what
the rows assert on.

=head2 amend_tip($h, $branch, %opts)

Amends a branch tip in place and force-pushes it, returning the new sha.
C<subject> replaces the subject and pushes the old message down into the
body, which is the shape a marker reader has to survive, and C<message>
replaces the message outright.  Also takes C<copy>, which defaults to B,
C<files>, and C<push>, which defaults on.

=head2 local_branch($h, $branch, %opts)

Makes a branch that no delivery created, under any name, and returns the sha
it was written at.  C<copy> defaults to A and C<at> names the commit to write
it at, defaulting to wherever that copy is standing.  C<push> defaults off,
so the branch stays local unless the row asks for it on R.

=head2 tag_branch($h, $copy, $name, %opts)

Writes a tag under the name it is given in the named copy and returns the sha
it was written at.  C<at> names the ref to tag, defaulting to wherever that
copy is standing.  A tag carrying a deployment branch's name is how a reader
built on C<git rev-parse --verify> comes to call a branch local when the branch
is not there, and that is the state the divergence query has to read past.

=head2 local_branch_only($h, $env, %opts)

Makes the environment's deployment branch in copy A alone, so R has never had
it, and returns its sha.  This is a different shape from C<unrelated_branch>,
where R has the branch and the two share no ancestor.  C<copy> is not passed
on, so the branch is always copy A's, and a row that wants one in copy B calls
C<local_branch> and names the branch itself.

=head2 unset_control($h, %opts)

Takes the configured control branch away from R, from both copies' local
refs, and from their remote-tracking refs, and parks each copy on a branch of
its own.  The remote-tracking ref has to go too, because the refresh never
prunes and would re-create the local branch from it.

=head2 set_remotes($h, %opts)

Replaces a copy's configured remotes and sets or clears the control branch's
upstream, returning that copy's handle.  C<copy> defaults to A, C<remotes> is
a hashref of name to URL, and C<upstream> names the remote the control branch
should track or clears the tracking where it is false.

Every remote named is fetched as it goes in, so that a row reading a
divergence straight afterwards has the remote-tracking refs to read it from.
C<fetch>, which defaults on, turns that off.  A row whose remote is a URL
something only has to parse, such as a github URL a derivation reads an owner
and repository out of, passes C<fetch =E<gt> 0> and gets the remote without
the conversation, which keeps the row off the network and out of the hands of
whatever that machine's git configuration rewrites a github URL into.

=head2 set_repo_config($h, $key, $value, %opts)

Writes one key into the deployment root's C<.genesis/config> and commits it on
control, returning the config file's git-root-relative path.  Takes C<root>
and C<commit>, which defaults on.  The rows that turn a single arbitrary key
on use this rather than rebuilding the harness for it.

=head2 move_on_r_at($h, $branch, %opts)

Commits in copy B straight away, so it can return the sha, and arms the push
to R for a named step of copy A's next run, so the push is rejected rather
than absorbed by the run's own refresh.  C<at> names the step and defaults to
C<push>, C<nth> says which call of it and defaults to the first, and C<files>
and C<message> shape the commit.  Where this harness has no fault plan yet
this arms one through C<fault_git>, so a row need not know that the way the
harness times a teammate's push is the fault plan.

C<nth> counts from the moment the plan was armed, not from the start of the
run.  The counter lives in the plan file so that it survives into a spawned
command, which means calls a row made before it armed are already counted; a
row that wants the count to start again calls C<reset_steps> first.

=head2 add_deployment_root($h, %opts)

Adds a second deployment root to the same repository, so a row can build two
roots that share an environment name, and returns its repository-relative
path.  Takes C<type>, which is required, C<envs>, and C<path>, which defaults
to the type.  C<Genesis::Top-E<gt>create> is told the directory to write, so
the second root lands where it belongs with no scratch directory and no move;
only the first root, which has to sit at copy A's own git root, needs that.

=head2 write_env_file($h, $env, %opts)

Writes an environment file on control and returns its git-root-relative path.
C<site> writes it at a level of the hierarchy rather than at the leaf.  Also
takes C<root>, C<genesis> and C<pipeline> as hashrefs merged into the file,
and C<commit>, which defaults on.  C<type> is taken for symmetry with the
helpers that compose a slug and is not written into the file, because nothing
in the file body names a deployment type.

A value in either hashref that is an arrayref renders as a YAML list rather
than a scalar, because C<genesis.pipeline.track_dependencies> and its
neighbours are lists and a reference printed as a scalar writes an address
into the file.  A value in the C<genesis> hashref that is itself a hashref of
scalars and flat lists renders as a block one level in, which is how a row
writes C<genesis.pipeline.track_additional_files> without composing the body
itself; anything nested deeper than that dies by name rather than writing an
address.  A list holding a reference dies by name too, for the same reason,
since a reference printed into a list entry writes an address the row never
asked for.  Where a row fills both the C<pipeline> key under C<genesis> and
the C<pipeline> option itself, the two fold into one block and the
C<pipeline> option wins a key they name together, because one file carries
one pipeline key.  A C<pipeline> key under C<genesis> that is not a hash
cannot fold at all, and that is refused by name rather than written out as a
second C<pipeline:> key.  The C<genesis> key is written wherever anything is
to be nested under it, so a site file carrying C<genesis> or C<pipeline>
entries is a file a YAML reader will load.

A harness declared in pr mode adds C<require_pr> to the C<pipeline> block of
every environment file it writes, so a row asks for pr mode once rather than
naming the key on every environment.

=head2 fixture_vault($h)

Spins the suite's own local vault through C<helper::vault_start> and points the
harness's environments at it, returning the safe target.  A real vault rather
than a double, because the rows run whole commands and a C<genesis> child
cannot read a double living in the parent's memory.  C<make_harness> calls it
when C<vault> is on, and a row calls it directly where it built its harness
without one.  C<helper::vault_start> is the TAP-free half of
C<helper::vault_ok>, so building the fixture adds nothing to the plan of the
subtest that builds it.

The vault is spun once and then shared by every harness in the file, so the
fixture clears the exodus mount as it attaches.  Each harness therefore starts
on an empty record tree rather than on whatever the subtest above it wrote, and
a row that proves a record's absence proves it of its own harness.

Because that clearing takes the whole subtree, a harness whose C<exodus_mount>
is shorter than the default C</secret/exodus/> is refused by name here rather
than clearing records it does not own, which would include the records another
harness in the same file is standing on.

A recording C<safe> is laid down beside the target, in the directory
C<run_genesis> puts first on the path of the command under test, and that
wrapper is what C<vault_read_log> reads its answer out of.  The parent's own
path is left exactly as it was, so the harness's own reads still reach the
C<safe> underneath and are never counted as reads a run made.

=head2 fixture_applied($h, %opts)

Writes the applied record at C<< $h->applied_path >>, carrying the control
commit the apply applied from, the provider, and the time, and returns that
path.  Takes C<control>, C<provider>, which defaults to the harness's own,
C<type>, and C<at>.

=head2 fixture_pipeline_record($h, $env, %opts)

Writes that environment's compiled pipeline facts beside its own exodus
record, under a C<pipeline> subpath, and returns that path.  Its absence is how
the walk knows the applied record does not know the environment, so a row that
wants that case simply does not call this.  Takes C<dependencies> as an
arrayref written as one comma-joined value, C<discovery>, which is C<complete>
or C<incomplete> and defaults to C<complete>, and C<type>.

=head2 certify($h, $env, %opts)

Writes the environment's exodus deployment record, so a row can give it a
certified commit or advance one, and returns its path.  C<commit> is the
deployment-branch commit the deploy stood on and C<control_commit> is the
control commit that tip's newest marker names, which are the pair the hatch
case has to tell apart.  Also takes C<state>, which defaults to C<success>,
C<type>, C<at>, and C<dependencies_read> as an arrayref of deployment slugs,
written as one comma-joined value and left out of the record altogether where
the row does not give it.

=head2 fixture_hold($h, $env, %opts)

Writes the hold record with C<reason>, C<user>, C<hostname>, and C<at> and
nothing else, and returns its path.  The reason is required.  C<user> defaults
to C<operator> and C<hostname> to C<harness.example.com>.

=head2 fixture_proposed($h, $env, %opts)

Writes the record naming the pull request an environment has open, as the four
fields C<control_commit>, C<number>, C<url>, and C<at>, and returns its path.
The pull request's number arrives under C<pr>, which is what the GitHub double
and the rows that open one call it, and C<number> is taken as an alias for a
caller that has the record's own spelling to hand.  Also takes C<control>,
C<url>, C<type>, and C<at>.

=head2 break_vault($h, %opts)

Moves records aside so a read of them refuses, so a row can assert that an
unreadable input makes the run refuse.  C<envs> is an arrayref naming the
environments to break and defaults to every environment the harness declares,
and C<applied> is a boolean that adds the applied record to whatever C<envs>
named.  An C<envs> given as an empty arrayref means no environments rather
than falling back to the default, so C<break_vault($h, envs =E<gt> [], applied
=E<gt> 1)> breaks the applied record alone while C<break_vault($h, applied
=E<gt> 1)> breaks it along with every environment.

Both movers name the fixture's target outright, so a harness built with
C<vault =E<gt> 0> is refused with a plain death rather than left to move
records in whatever vault the ambient C<safe> target happens to be.  Each move
is checked, and one that fails is refused by name and says what C<safe> said,
because a move nobody looked at leaves the row asserting against a vault
nothing changed.

=head2 restore_vault($h)

Puts back everything C<break_vault> moved aside, so the same row can assert the
run succeeding once its input is readable again.  It refuses a harness with no
vault fixture for the reason C<break_vault> does, and it checks each move back
and refuses a failed one by name for the same reason again.

=head2 snapshot_w($h, %opts)

Reads the branch, the HEAD sha, the current directory, the porcelain status,
and the index, and returns them as one hashref.  The hashref carries a sixth
key, C<dir>, which is the copy the five were read in, and that is how
C<assert_w_restored> finds the repository to read them again.  The one option
is C<copy>, which defaults to C<a>.  The directory is read before the rest,
because a command that switched away can leave the process standing in a
directory the switch removed, and the git reads below run through C<pushd>,
which cannot return to a directory that is gone.  Where that has happened the
snapshot steps back into the copy and still answers the directory as
undefined.

=head2 assert_w_restored($w, $name)

Compares all five against the snapshot and fails naming every one that
differs.  It runs on success and on failure alike, because I1 promises
restoration on every exit path and an assertion that runs only on success
proves nothing about the paths that matter.  It is the one helper here that
emits TAP, since it is an assertion rather than a builder of state, and a test
that wants to read a deliberate failure as a result rather than a failure of
its own file sets C<$Harness::Propagation::BUILDER> to a private
C<Test::Builder> for the length of the call.

=head2 assert_snapshot_invariant($h, $env, %opts)

Compares the deployment branch against the control commit its newest marker
names.  It makes two comparisons and not one, because the branch has to match
the source over the propagation set's paths and hold nothing outside the set.
The second is the half that fires in practice, because a copy-only writer
never removes a leftover C<init> or a path that dropped out of the set.  Every
difference is named, and a branch with no marker fails rather than passing
vacuously.  Options are C<commit>, which defaults to the branch tip, C<copy>,
C<type>, and C<name>.  A named C<copy> is where the trees are read and is
passed through to the marker read, so both come out of one repository; where
none is named the trees are read in copy A and the marker search order
stands.  Where the listing of the branch cannot be read at all, the second
comparison fails naming the ref rather than reading git's complaint as a list
of paths.

=head2 fixture_command($h, $kind, %opts)

Returns a coderef for one of four shapes of working state, C<restores>,
C<leaves_branch>, C<leaves_staged>, and C<loses_cwd>, which exercise the
assertion itself rather than a genesis command.  The one option is C<copy>.

=head2 run_genesis($h, @argv) and run_genesis_in($h, $copy, @argv)

Run a whole genesis command in a copy, taking the W snapshot before it and
asserting the restoration after it, and return the output, the error, and the
exit code, in that order.  The exit code is the one the command really exited
with, because C<Genesis::run> has already shifted C<$?> and shifting it again
would read every real code as a zero.

A leading hashref takes C<copy>, default C<a>, C<dir> for a subdirectory to
run from, C<answers> as an arrayref, C<pipeline_task>, which sets
C<GENESIS_PIPELINE_TASK>, C<git_version>, which puts a fixture git reporting
that version first on the path for this run alone, C<no_token>, which leaves
C<GITHUB_AUTH_TOKEN> out of the child's environment while leaving every
fixture binary on its path, C<restore>, default 1, which a row turns off where
it asserts the restoration in its own words, and C<terminal>, default 1, which
is accepted and does nothing today.

The fixture binaries the harness writes reach the child through the path this
run builds and through nothing else, so no helper puts a fixture on the
parent's own C<PATH> and a run that asks for none sees none.

C<run_genesis_in> is the same run in a named copy.

=head2 stand_on($h, $branch, %opts)

Puts a copy on a branch, and optionally in a subdirectory of it.  Options are
C<copy>, default C<a>, and C<dir>.

=head2 fault_git($h, %opts)

Returns a C<Harness::Propagation::Git> handle for a copy and arms the plan
file and the step log, which a spawned command picks up.  The one option is
C<copy>, default C<a>.  C<Service::Git> hands every caller the one instance it
caches per repository, so the handle a row already held is re-blessed and
faults from here on as well.

=head2 run_in_child($h, $code, @args)

Runs a snippet of perl in a process of its own, under the fault plan, the step
log, and the subclass that a whole spawned command meets, and answers the
output, the exit code, and the standard error the way C<run> does.  C<@args>
reach the snippet in C<@ARGV>.  The plan and the log are read off this harness
rather than off the environment, so a file holding two harnesses runs each
child against its own plan rather than against whichever harness armed last.
It refuses where the harness has armed no plan, since a child that met no
subclass would report nothing.

=head2 fail_on($git, $step, $n, %opts)

Arms one named git step to die on its nth call.  C<from> makes every call
from the nth onward die rather than the nth alone, and C<message> fixes what
it dies with.

=head2 step_log($git) and reset_steps($git)

Return every intercepted call in order, each an arrayref of the step's name
and its arguments, and empty the log and the counters between a row's phases.

=head2 sever_remote($h, %opts) and restore_remote($h)

Make every remote step fail with the text a real unreachable remote emits,
and disarm them again.  C<after> severs the remote partway through a run.

=head2 hold_session_lock($h, %opts) and release_session_lock($h, $pid, %opts)

Take the switch lock in a child process and release it.  The lock is the
C<flock> on C<genesis-session.lock> in the git directory, and the holder
writes its pid on the first line and its command on the second for the
refusal message to read.  Options are C<copy> and C<command>.  C<hard> kills
the holder without letting it finish, so a row can show that the kernel drops
the lock with the process.

C<hold_session_lock> watches the holder as well as the lock file while it
waits, and it refuses rather than answering where the holder is not going to
take the lock.  What it watches the file for is this holder's own pid, and not
merely a file with something in it, so a line an earlier holder left behind
cannot end the wait early and hand a row a holder that is still blocked.  The
holder writes that line only once it has the lock, and it empties the file
under the lock rather than on the way in, so what an earlier holder wrote
stands until a later one has actually taken over.  It says the holder exited
before it took the lock where the child has gone, and that the holder never
took it where the wait runs its length out with the child alive, so a row that
meets a broken fixture reads a complaint about the fixture rather than one
about the code under test.  The holder is killed and reaped on both refusals,
since a holder left standing would sit on the lock for the five minutes it
gives itself.

Every holder is registered as it is forked, and an C<END> block kills and
reaps whatever is still registered when the file finishes, so a row that dies
between forking a holder and releasing it costs the run nothing beyond its own
failure.

=head2 fork_and_switch($h, $branch, %opts)

Opens a branch session in a process of its own and switches it to C<$branch>,
answering a hashref of C<out>, C<err>, and C<exit>.  A row uses it because an
C<flock> is held by a process, so a second attempt made in the test's own
process would find the handle that process already holds and take the lock
rather than meet it.  The one option is C<copy>, default C<a>.

The child spells its include paths absolutely, since it runs from a copy of
the repository under test and a relative C<-I> would name that copy's own
C<lib>.  The exit code is handed back as C<run> gives it, which is already
shifted.

=head2 github_double($h, %opts)

Stands the GitHub double up as a fixture C<curl> first on the path, backed by
a state file the harness writes and a call log it reads back, and returns the
double.  It is a binary rather than an object because C<Genesis::curl> shells
out, so an in-process double could not reach a spawned command.  Options are
C<token>, which defaults to C<harness-token>, C<admin>, which defaults to 1,
and C<repository>, which defaults to C<owner/repo>.  C<make_harness> calls it
for you under C<< github => 1 >>.

A pull request created through the double lands in that state file, so a
listing taken after the create sees what was made, and a request for one
pull request's reviews answers its reviews rather than the collection.

=head2 gh_pull_request($gh, %opts)

Declares an open pull request and returns its number.  Options are C<env>,
which names the environment whose pull request branch and deployment branch
the request runs between, C<head> and C<base>, which override those two,
C<title>, C<body>, C<review>, which takes C<none>, C<approved>, or
C<changes_requested>, C<reviewer>, C<review_body>, and C<at>.

=head2 gh_close_pr($gh, $number, %opts)

Closes a pull request.  C<merged> marks it merged rather than abandoned and
C<at> dates it.

=head2 gh_merge_pr($gh, $number, %opts)

Merges a pull request by a named method, which C<method> gives and which
defaults to C<rebase>, and closes it as merged.

=head2 gh_protection($gh, %opts)

Declares what the protection endpoints answer and returns what the run has
set, so a row can read the settings back.  C<branch> and C<settings> name one
branch's protection, and C<admin> off makes every protection call answer 403,
which is the non-admin case.

=head2 gh_unreachable($gh)

Takes the API away, so every call reads as a failed C<curl> rather than as an
answer with a status.

=head2 gh_reachable($gh)

Gives the API back again.

=head2 gh_no_token($h)

Runs the next command with no token in its environment.  It takes the harness
rather than the double, because the token is a fact about the environment a
run is given, and it is one shot: C<run_genesis> consumes the flag, so the
command after it carries the token again and the fixture C<curl> stays where
it is.

=head2 gh_calls($gh)

Returns every call the run made, each as a hashref of the C<method>, the
C<url>, the C<body>, and the C<token> the caller's environment held, so a row
can assert that a preview was read-only, that exactly one client was built,
or that a run went out unauthenticated.

A line the decoder refuses comes back as C<{torn =E<gt> the line}> rather than
taking the read down, because two writers landing on the log at once would
leave half a line behind and a reader that died inside the decoder would stop
the whole file where the row that asked should have failed.  Such a record
carries no C<method>, so a row counting calls of a kind reads one fewer and
fails its own assertion.

=head2 record_at($h, $path)

Reads one vault path back as a hashref, or undef where nothing is written
there.  The harness writes records through C<certify>, C<fixture_applied>,
C<fixture_proposed>, C<fixture_pipeline_record>, and C<fixture_hold>, and this
is the one way a row reads one of them back.

C<safe export> answers with the whole subtree under the path it is given, so
the record asked for is picked out by its own key and the children beneath it
are left where they are.  A deployment record still reads back as itself once a
pipeline record or a hold has been written under it, and a path that holds
nothing of its own answers undef even where its children hold something.

The read is made on the parent's own path, which the recording C<safe> is
deliberately kept off, so a row that reads a record in order to assert on it
never counts as one of the reads the run under test made.

=head2 vault_read_log($h)

Every vault path the last run read, in order, as an arrayref.  The reads are
made by a child process, so the log is a file the wrapper on the path appends
to rather than a counter on this object, and C<run_genesis> empties it as each
run starts so that the answer is that run's reads and nothing earlier.

The log holds the address C<safe> was handed, so a read of a whole record
appears as the record's path while a read of a single field appears as
C<path:key>, which is how C<Service::Vault::get> asks for one field.  A row
counting reads of a whole record matches the path, and a row counting keyed
reads matches the longer form.

=head2 fixture_preflight($h, $kind, %opts)

Returns the path of a repository in one of the three shapes the pre-flight
classifies, which are C<safe_directory>, C<no_identity>, and C<no_commits>.
The one option is C<copy>, which shapes one of the harness's own clones in
place instead of building a repository beside them.  It cannot be paired with
C<no_commits>, because both clones already carry the seeding commit, and that
pairing is refused by name rather than answered with a repository that has
commits.

Each shape is built in a fresh repository beside the harness, because the
C<safe.directory> shape needs an ownership git will actually refuse and neither
clone can be given one.  The first two shapes leave a marker in the repository
and lean on the fixture C<git> the harness puts first on the path of the
command under test, because a process running as the one user that owns
everything the suite writes can neither hand a directory to another owner nor
lose the global identity C<helper::import> wrote it.  A row that reads a shape
itself puts that same directory first on its own path for the length of the
row.

=head2 child_recorder($h, %opts) and child_runs($h)

Puts a recording wrapper first on the path of the run under test and points
C<GENESIS_CALLBACK_BIN> at it, so every genesis child a command spawns is
logged, and reads those children back in order.  Each run carries its
arguments, its pid, when it started and ended, its exit, its working
directory, whether its standard input was a terminal, and what the switch lock
was doing at its start, at its end, and while it ran.

Each run also carries C<status_lost>, which is false on an ordinary run and
true where the recorder could not reap its own child, which happens where
something else reaped it first.  A child somebody else reaped leaves its
status nowhere to be read, so the recorder writes an exit of 99 into the
record and exits 99 itself rather than writing a zero that would read as a
child that succeeded.  A row that weighs a child's exit should read the field
as well, because those are the two ways an exit of 99 can arise.

The options are C<copy>, which says whose switch lock is watched, C<exec>,
which defaults on and runs the real genesis underneath, C<exit>, which answers
a chosen code without running anything, C<probe>, which polls the lock while
the child runs and fills C<lock_seen>, and C<hold_lock>, a command string that
has the wrapper take the lock from a process of its own for the child's whole
life.  That last is how a row puts a stranger in the window D46 leaves open
between the session's finish and the child's own start.

The wrapper is the committed C<t/Harness/bin/genesis-recorder> rather than a
sub in this process, for the same reason the GitHub double is a fixture
C<curl>: the thing being watched is a child process, and a double living in
the parent's memory would never see one.  The parent's own path is left
exactly as it was, because C<run_genesis> carries the fixture directory to the
command under test alone.

=head2 lock_probe($h, %opts), lock_probe_bin, and lock_probe_log($h)

Asks whether the switch lock is held and by whom, without waiting.  The probe
answers undef for a free lock and a hashref of C<pid> and C<command> for a held
one, reading both out of the lock file, where the holder writes its pid on the
first line and its command on the second.  The one option is C<copy>.

C<lock_probe_bin> is the same probe as a standalone script, so a kit hook or
any other child can call it with a label of its own, and C<lock_probe_log>
returns those answers in order, each a hashref of C<label>, C<held>, C<pid>,
and C<command>.

=head2 shuttle_spy($h) and shuttle_requests($spy)

Records what a run put to the shuttle, so a row can tell a run that made no
request from a run that had nowhere to make one.  Under the manual provider
there is no backend at all and D23 refuses a file one, which is why that
difference needs an observer rather than a reading of the tree.

The spy names its log in C<GENESIS_SHUTTLE_SPY> and lays the file down empty,
so a row that reads no requests back has read a file the spy really wrote.  A
request is one JSON object on a line of its own, and C<shuttle_requests>
returns them decoded and in the order they were made.

=head2 fixture_kit($h, %opts)

Writes a dev kit into the deployment root with the hook bodies a row needs and
returns its path.  The options are C<hooks>, a hashref of hook name to shell
body, C<name>, which defaults to C<pipeline>, C<version>, which defaults to
C<0.0.1>, and C<root>.  Each hook is written executable with a C<bash> shebang
and C<set -eu> above the body it was given.

C<helper::mk_test_kit> builds a kit with no hooks at all, so a row that needs a
blueprint that raises, or a hook that probes the lock, or a hook that spawns a
genesis child of its own has nothing else to build on.  A row that wants one of
the two kits the suite ships names it through C<make_harness>'s C<kit> option
instead.

=head2 skip_on($git, $step, $n, %opts)

Makes the nth call of a named git step return without delegating, so the write
is reported in the step log and never lands.  The options are C<from>, which
makes every call from the nth onward the armed one, and C<return>, which says
what the skipped call answers.  C<fail_on> cannot make this shape, because a
death is not a silence.

=head2 load_with($h, $body, %opts)

Commits C<$body> as the repository's whole pipeline block on the control
branch, builds a C<Genesis::Top> on copy A, reads its configuration, and
returns the Top.  The body is the pipeline block alone and the rest of the
configuration is written round it, so a row says what it is proving and
nothing else.  Each load carries a count of its own beside the configuration,
because two rows in a row can ask for the same block and a commit needs a
delta to make.

The one option is C<deployment_type>, which names the type the configuration
declares and defaults to C<bosh>.  The type is a top-level key rather than
part of the pipeline block, so a file whose rows vary it has nowhere in the
body to say so and names it in the call instead.

=head2 automated_config($type, @lines)

Answers the pipeline block of an automated provider of that type, as text,
carrying the clone credential, the committer identity, the shuttle, the vault,
and the locker the schema requires.  The repository is named rather than
derived, because copy A is cloned from a filesystem path whose URL carries no
GitHub owner and repo pair.  Any C<@lines> go under the provider at the
provider's own depth, so a row that wants a target or a team says so in a
word.

=head2 automation_blocks() and automation_block_lines()

Answer the three blocks the configuration schema requires of an automated
provider, which are the shuttle, the vault, and the locker.
C<automation_blocks> answers them as a list of key and hashref pairs, for a
file that builds the configuration as a structure, and
C<automation_block_lines> answers the same thing as YAML lines indented to sit
under a C<pipeline:> key, for a file that writes the configuration as text.
Neither answers the C<pipeline:> key itself, so a caller puts the blocks
beside whatever else its own pipeline block holds.

C<automation_block_lines> takes C<without>, an arrayref naming blocks to leave
out, so a row that proves what the schema refuses of an automation missing one
of the three builds that shape here rather than writing the lines itself.  The
lines are rendered off the hash form, so the two answers cannot drift apart.

=head2 ready_envs($h, %opts)

The five things every walking row needs before it can run a command, which
are the init branch on R per environment, the applied record, each
environment's pipeline record, the delivery, and the certified commit.  Every
named scenario below is this plus the one thing its own name says.  The
options are C<envs>, C<control>, C<type>, C<provider>, C<dependencies> as a
hashref of environment to its ancestors, C<delivered> and C<certified>, each
an arrayref naming the environments that get one and each defaulting to every
environment, and C<applied>, which turned off leaves the applied record out.
Every scenario passes them through, so a row stands an unseeded or an
uncertified environment up without building the tree by hand.

=head2 ready_harness(%opts)

  my $h = ready_harness(envs => ['lab', 'qa']);
  my $n = ready_harness(delivered => [], certified => ['lab']);

The scenario most walking rows start from, which is C<lab> and C<qa> walked,
delivered, and certified.  It hands its options on to C<make_harness> and to
C<ready_envs>, so a row that wants a third environment, a second deployment
type, or a narrower delivery set asks for it in the call.

=head2 seeded_harness(%opts)

C<ready_harness> over one environment, which is C<qa> unless the call says
otherwise.  Its C<applied> option turned off leaves the applied record out,
whose absence is the membership test that stands in for a roster.

=head2 staged(%opts)

  my $h = staged(envs => ['lab']);

The applied pipeline that has propagated nothing yet, which is
C<ready_harness> with every init branch cut and neither a delivery nor a
certified commit on any of them.  It is the unseeded reading a walk has to
answer for, and the name is the one the step files use.

=head2 due_harness(%opts)

  my ($h, @due) = due_harness();
  my $shape     = due_harness();

The walked tree with two control commits the branches have not taken, or
C<count> of them.  It answers the harness and those commits in list context,
because the rows that name a commit index into them, and the harness alone in
scalar context, because the rows that only want the shape say so.

=head2 gated_harness(%opts)

  my ($h, @shas) = gated_harness();

The walked tree with four control commits, of which the third carries the
C<Genesis-Stage> trailer that C<stage> names and C<prod> supplies by default.
It answers in the same two shapes C<due_harness> does.

=head2 held_harness(%opts)

The C<lab> and C<prod> tree carrying a hold record, whose environment and
reason the C<env> and C<reason> options name.

=head2 held_prod(%opts)

The single-environment C<prod> tree the hold rows stand on, walked and cut but
neither delivered nor certified.  It writes no hold of its own, because every
one of those rows writes the hold through the command it is testing, and
C<delivered> and C<certified> take a list back where a row wants one.

=head2 tracked_harness(@prereqs)

  my $h = tracked_harness(qw/lab ops/);

A tree whose C<qa> environment tracks the prerequisites the call names.  They
arrive positionally, because every call reads as a list of environment names
and an options hash around two of them would say nothing the list does not.
The environment file it writes is published before the walk reads it, because
the commit a delivery's marker names has to be one R holds.

=head2 two_env_harness(%opts)

The C<lab> and C<qa> pair, walked and delivered, under the name the rows that
care about the pair rather than about the walk use.

=head2 inherited_harness(%opts)

Writes its pipeline keys at a site file rather than at the leaf, which is the
merged read the hierarchy rows need.  C<site> names the file, C<pipeline_keys>
are the keys that go on it, and C<leaf_keys> are the keys that go on each
environment file beneath it.  Both writes are published before the walk reads
them, for the reason C<tracked_harness> gives.

=head2 ready(%opts)

The PR-mode shape, which is a harness in C<pr> mode with the GitHub double
standing, the vault fixture, an init branch, one delivery, and the applied
record.  C<admin> turned off is a site whose token the protection endpoints
refuse, which is how a row means that it could not grant the merge method, and
C<due> with C<message> lays one control commit the branch has yet to receive.

=head2 with_open_pr(%opts)

  my ($h, $gh, $number, $control) = with_open_pr();

C<ready> with one commit due, a pull request open on the GitHub double, and
the proposed record naming it, which is the whole shape a pull request column
reads.  It answers the harness, the double, the pull request number, and the
control commit the pull request proposes.  C<env> names the environment, which
is C<qa> by default and which the default C<envs> and the default C<due> file
both follow, and C<review> is the review state the pull request opens with.
The rest of the options go on to C<ready>.

=head2 two_roots(%opts)

The C<lab> and C<prod> pair across two deployment roots, the second of the
type C<second> names and C<vault> by default, with both roots readied.  The
second ready names that root's path as well as its type, because a propagation
set is read under a prefix and a delivery given the type alone would mirror the
first root's files onto the second root's branch.

=head2 a_delivery($h, $env, %opts)

One delivery onto an environment's branch at control's tip, and the delivered
commit's sha.

=head2 seeded(%opts)

  my ($h, $control, $delivered) = seeded();

Builds a harness with no vault fixture, cuts the branch, writes one control
commit, delivers it, and answers all three, so a row that compares a delivery
against its source has both shas without reading either back.

=head2 stale_set_delivery($h, %opts)

Stands up the one shape the writer's removing half needs, which is a branch
delivered under a tracked set that control has since narrowed.  It tracks an
extra file, delivers under that set, drops the file from the tracked list, and
returns the control commit whose delivery has to remove the path that fell
out.  It is not C<a_delivery>, which is one plain delivery at control's tip,
so it takes a name of its own.  The options are C<env>, C<root>, C<file> for
the tracked path relative to the deployment root, and C<path> for that same
file relative to the git root.

=head2 stage_unrelated($h, $path, %opts)

Writes a file into copy A's working tree and puts it in copy A's index, and
returns the path.  The refusal it sets up names the file, so handing the path
back keeps the row from repeating the literal.  The options are C<copy>,
default C<a>, and C<content>.

=head2 modify_unrelated($h, $path, %opts)

Appends to a file in copy A's working tree and leaves the change unstaged, and
returns the path, for the same reason.  It takes the same two options.

=head2 two_due($h, %opts)

Two undelivered control commits, in order, and their shas.

=head2 three_due($h, %opts)

Three undelivered control commits, in order, and their shas.

=head2 three($h, %opts)

The same sub as C<three_due>, under the name the rows that want a run of three
use, so that neither name can drift from the other.

=head2 chain($h, %opts)

One control commit per environment, each touching the file the next
environment's row reads, and their shas in the order the environments were
named.

=head2 gated($h, %opts)

One control commit carrying the C<Genesis-Stage> trailer that C<stage> names,
and its sha.  The files it writes come from the call, as they do for
C<commit_on_control>.

=head2 proposed($h, $env, %opts)

The proposed record for an environment, written through C<fixture_proposed>,
and its path.

=head2 automated($h, %opts)

Puts the repository under an automated provider, which is C<concourse> unless
C<provider> names another, and answers the harness.

It writes five blocks beside the provider type, because the configuration
schema requires all five of an automated provider and a repository missing any
of them is refused when a C<Genesis::Top> loads it.  They are the clone
credential under C<source_control.auth>, which takes C<auth_type> and
C<auth_vault>, the committer identity under C<source_control.identity>, which
takes C<identity_name> and C<identity_email>, and the shuttle, the vault, and
the locker, which come from C<automation_blocks>.

All eleven keys land in one commit on control, and that commit is made only
where the file changed, so asking for the shape twice, or asking for it on a
repository that already carries it, is not a death.

=head2 $h-E<gt>git($copy, %opts)

This one is a method and not an exported name, unlike its neighbours here, so
it is called on the harness rather than given one as a first argument.  It has
an entry among them because it takes options and because the one handle per
copy is worth a paragraph.

Returns the C<Service::Git> handle for a copy, which defaults to C<a>, and
hands C<%opts> on to C<Service::Git-E<gt>new>, so a row that wants a handle of
a shape the harness does not build asks for it here rather than building one
itself.

There is one handle per copy however it is asked for.  C<Service::Git> keeps a
single instance per repository root and answers every caller naming that root
with it, so two rows holding a handle on the same copy hold the same object,
and the branch session hanging off it is the same session.  A row that wants
to switch a branch opens that session and switches through it, because the
handle refuses a checkout from anywhere else.

=head2 top_for($h, %opts)

A C<Genesis::Top> for the harness's deployment root, or for the root C<root>
names.  Its C<config> option writes the whole C<.genesis/config> on control
first, replacing what was there, so a row can build the shape with no provider
key at all rather than editing one key of the file C<make_harness> left.

=head1 METHODS

C<r>, C<a>, and C<b> return the three paths.  C<type>, C<control>, and C<envs>
return the declared values.  C<git> answers the C<Service::Git> handle for a
copy and has an entry of its own above, because it takes options and the one
handle per copy is worth a paragraph.  C<slug> and C<pr_branch> render the
deployment slug and its pull request branch.  C<exodus_mount>,
C<applied_path>, and C<env_path> render the vault addresses.  C<gh> returns
the GitHub double once C<github_double> has stood one up, and undef before
that.  C<deliver_all> writes one delivery per environment at control's tip and
answers the harness, and it is a method rather than an exported name because
only the harness's own composition wants the whole set delivered in one line.

C<preflight_bin> returns the directory the fixture C<git> sits in, and builds
it on the first ask.  C<run_genesis> puts that directory first on the path of
the command it runs, so a whole run meets whichever shape C<fixture_preflight>
built; a row that calls into the library instead has no command to arrange it
for, and puts the directory first on its own path for the length of the call.

=cut
