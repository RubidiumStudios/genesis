=head1 NAME

Genesis::BranchClass - which branch a pipeline-aware command belongs on

=head1 SYNOPSIS

    require Genesis::BranchClass;

    my $class = Genesis::BranchClass::classify_branch($top, 'qa/bosh');
    # 'deployment'

    Genesis::BranchClass::assert_pre_deploy($top, $git);
    # refreshes control, then bails at DATAERR unless the current branch
    # may be written on

=head1 DESCRIPTION

Under D81 every pipeline-aware command declares one of two branch classes
at its registration. This module answers the questions that declaration
raises, which are what class of branch the repository is standing on and
whether a pre-deploy command may run from it.

Every pre-deploy command also brings the control branch in from the remote
before it reads anything, because the question the assertion answers is
asked of the remote's tip and not of whatever this clone last happened to
fetch.

A pre-deploy command changes what will be delivered, so it belongs on the
control branch or on a feature branch cut from it. The deployment branch,
the pull request branch, and the artifacts branch are all derived, and a
hand commit made on one of them is overwritten by the next propagate run.
That is the one rule the refusal below enforces.

=head1 FUNCTIONS

Nothing is exported. Every function is called by its full name, because
the gate that calls them is the only caller and one qualified call reads
better than an import nobody else uses.

=head2 artifacts_branch_for($top, $env_name)

Returns the artifacts branch of a deployment, which is C<artifacts/>
joined onto the deployment slug, so C<qa> of a C<bosh> root reads
C<artifacts/qa/bosh>.

B<Parameters:>

=over 4

=item C<$top>

The C<Genesis::Top> the deployment root was loaded as.

=item C<$env_name>

The environment's name, as a string.

=back

B<Returns:> the branch name.

B<Examples:>

  Genesis::BranchClass::artifacts_branch_for($top, 'qa');
  # Returns: 'artifacts/qa/bosh'

=head2 classify_branch($top, $branch)

Returns one of C<control>, C<deployment>, C<pr>, C<artifacts>, or
C<feature>. The three derived classes are computed from the environments
the repository knows about rather than matched against a pattern, because
a deployment branch's name is the deployment slug and nothing else.

A branch that matches none of them is C<feature>, and so is an undefined
branch, since a caller holding no name has nothing derived in its hand.

The environment names are read once and the three branch names are composed
from that one list, because the list is rebuilt from the deployment root's
environment files every time it is asked for. The pull request prefix is
joined here rather than through C<< $top->pr_branch_for >> for that reason,
so a prefix that collides with a deployment branch or with control is
refused by the commands that create the branch and not by this
classification.

B<Parameters:>

=over 4

=item C<$top>

The C<Genesis::Top> the deployment root was loaded as.

=item C<$branch>

The branch name to classify, or undef.

=back

B<Returns:> the class, as one of the five strings above.

B<Examples:>

  Genesis::BranchClass::classify_branch($top, 'control');
  # Returns: 'control'

  Genesis::BranchClass::classify_branch($top, 'pr/qa/bosh');
  # Returns: 'pr'

  Genesis::BranchClass::classify_branch($top, 'wes/try-a-thing');
  # Returns: 'feature'

=head2 refresh_control($top, $git)

Brings the control branch from the remote into the repository's
remote-tracking refs, and bails at C<Genesis::Exit::TEMPFAIL> naming the
remote when it cannot. Every pre-deploy command runs it at pre-flight,
because the descent condition is read through the remote-tracking ref and a
stale one would let a feature branch cut from an older control tip pass a
check it should fail.

Only the control branch is fetched. A deployment branch's tip answers a
question no pre-deploy command asks, and fetching one is what let a
branch-exists check read a ref that is now derived.

A repository with no remote has nothing to refresh, and the function says so
by returning rather than by refusing. So does a clone that has no local
control branch, because materialising one is a repair, the pre-flight owns
it, and the pre-flight reports the creation as it makes it. A fetch here
would take that repair silently.

B<Parameters:>

=over 4

=item C<$top>

The C<Genesis::Top> the deployment root was loaded as.

=item C<$git>

The C<Service::Git> handle on the repository the command is running in.

=back

B<Returns:> 1 when the refs are current, or when there is no remote to ask.
Anything else exits.

B<Errors:>

=over 4

=item Refuses a remote it cannot reach.

I<Could not reach origin to refresh the control branch.> The remote's own
words follow, taken from the C<err> key of the fetch result, and the exit is
C<Genesis::Exit::TEMPFAIL>, because a remote nobody can reach is a condition
a re-run fixes rather than input a person must correct.

=back

B<Examples:>

  Genesis::BranchClass::refresh_control($top, $git);
  # Returns: 1  (refs/remotes/origin/control now holds the remote's tip)

  Genesis::BranchClass::refresh_control($top, $git);
  # Exits 75  (the remote is unreachable)

=head2 permitted_feature_branch($top, $git, $branch, %opts)

Answers whether a feature branch may carry a command that changes what will
be delivered. Three conditions hold together.

=over 4

=item *

It descends from the tip of the control branch as observed through the
remote-tracking ref after a refresh, so it carries every environment file
control has.

=item *

It is not a deployment, pull request, or artifacts branch, which
C<classify_branch> has already settled before this is called.

=item *

Its name is not an environment's name, existing or being added, because a
branch named C<prod2> occupies C<refs/heads/prod2> and the deployment
branch C<prod2/bosh> could never be created beside it.

=back

Returns a single true value when all three hold, and otherwise returns
false with the condition that failed and the remedy for it, so the caller
writes one refusal and the reasons stay here.

B<Parameters:>

=over 4

=item C<$top>

The C<Genesis::Top> the deployment root was loaded as.

=item C<$git>

The C<Service::Git> handle on the repository the command is running in.

=item C<$branch>

The branch the working tree is standing on, as a string.

=item C<%opts>

C<adding> is the environment name the command is about to create, which
C<genesis new> is given as its argument. A branch may collide with a name
the repository does not carry yet, and this is how the predicate hears
about one.

=back

B<Returns:> C<(1)> when the branch is permitted, and C<(0, $reason,
$remedy)> when it is not.

B<Examples:>

  Genesis::BranchClass::permitted_feature_branch($top, $git, 'add-prod',
    adding => 'prod');
  # Returns: (1)

  Genesis::BranchClass::permitted_feature_branch($top, $git, 'prod2',
    adding => 'prod2');
  # Returns: (0, 'prod2 is named for an environment, so prod2/bosh could
  #               never be created beside it',
  #              "Rename the feature branch:\n\n    git branch -m prod2
  #               add-prod2\n")

=head2 assert_pre_deploy($top, $git, %opts)

Refreshes the control branch through C<refresh_control>, then refuses when
the current branch is derived, naming the branch, the class it belongs to,
and the checkout that fixes it, and exiting C<Genesis::Exit::DATAERR>. A
branch that is none of the derived three goes to
C<permitted_feature_branch>, and a refusal from there names the condition
that failed and the remedy for it at the same exit. It switches nothing, on
a refusal or otherwise.

The refresh runs above the classification, so a run the gate goes on to
refuse has refreshed control by the time it refuses. Where a command ends
therefore says nothing about whether it refreshed.

A detached HEAD is allowed through, because it is neither control nor
derived and neither remedy the predicate offers can be carried out on it. A
repository that has lost its control branch is repaired by the pre-flight,
which re-creates it from the remote, and a clone that never had one is
refused by the apply at C<Genesis::Exit::CONFIG>. A refusal raised here
would speak before either of them and say less.

B<Parameters:>

=over 4

=item C<$top>

The C<Genesis::Top> the deployment root was loaded as.

=item C<$git>

The C<Service::Git> handle on the repository the command is running in.

=item C<%opts>

C<refresh> is read, and C<refresh =E<gt> 0> skips the refresh for the one
command that promises no network call, which is C<pipeline-status> under
C<--no-refresh>. C<adding> is the environment name the command is about to
create, and it is passed straight to C<permitted_feature_branch>.

=back

B<Returns:> 1 when the command may run. Anything else exits.

B<Errors:>

=over 4

=item Refuses a derived branch.

I<qa/bosh is a deployment branch, which holds what was delivered, and this
command changes what will be delivered.>

=item Refuses a feature branch that fails one of the three conditions.

I<add-prod does not descend from the tip of control, and this command
changes what will be delivered.> The remedy follows, and the exit is
C<Genesis::Exit::DATAERR>.

=item Refuses a remote it cannot reach.

Raised through C<refresh_control>, at C<Genesis::Exit::TEMPFAIL>.

=back

B<Examples:>

  Genesis::BranchClass::assert_pre_deploy($top, $git);
  # Returns: 1  (standing on control)

  Genesis::BranchClass::assert_pre_deploy($top, $git);
  # Exits 65  (standing on artifacts/qa/bosh)

=cut
