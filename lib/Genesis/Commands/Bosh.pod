=head1 NAME

Genesis::Commands::Bosh - Command handlers for Genesis BOSH director interaction

=head1 SYNOPSIS

  # Registered in bin/genesis via define_command:
  genesis <env> bosh [--connect] [bosh-args...]
  genesis <env> credhub [--raw] <cmd> [credhub-args...]
  genesis <env> logs [extra-args...]
  genesis <env> broadcast [--on <instance>] <cmd> [extra-args...]
  genesis <env> bosh-configs [upload|summary|list|view|compare|delete] \
      [--type <cloud|runtime|cpi>] [--name <config>] [--uploaded] [--yes]

  # In Perl (dispatch layer):
  use Genesis::Commands::Bosh;
  Genesis::Commands::Bosh::bosh($env_name, @bosh_args);
  Genesis::Commands::Bosh::credhub($env_name, $cmd, @args);
  Genesis::Commands::Bosh::logs($env_name, @extra_args);
  Genesis::Commands::Bosh::broadcast($env_name, @extra_args);
  Genesis::Commands::Bosh::bosh_configs($env_name, $action, @extra_args);

=head1 DESCRIPTION

Provides command handler functions for all BOSH-director-related Genesis CLI
commands.  Each function in this module corresponds to a top-level Genesis CLI
subcommand and is registered via C<define_command> in the Genesis binary.

The module covers direct BOSH CLI passthrough (C<bosh>), CredHub CLI
passthrough with Genesis-managed authentication (C<credhub>), VM log retrieval
(C<logs>), multi-instance SSH broadcast (C<broadcast>), and BOSH config
management (C<bosh-configs>).

All functions load the named environment from the current directory's Genesis
top-level and connect to Vault before performing their work.

=head1 FUNCTIONS

=head2 bosh($env_name, @bosh_args)

  bosh($env_name, @bosh_args)

Entry point for the C<genesis E<lt>envE<gt> bosh> command.  Wraps the C<bosh>
CLI, routing through the environment's target BOSH director with all
authentication already configured.

Supports two modes of operation:

=over 4

=item Normal passthrough mode

Executes C<bosh @bosh_args> interactively against the environment's BOSH
director.  Exit code propagates directly to the shell.

=item C<--connect> mode

When the C<--connect> flag is passed, outputs shell C<export> statements for
the BOSH environment variables so they can be applied to the current shell via
C<eval>.  This mode must be invoked as:

  eval "$(genesis <env> bosh --connect)"

If C<--connect> is used but the command is running in a controlling terminal
(i.e., not under C<eval>), an error is printed explaining the required
invocation and the process exits with status 1.

=back

Output is automatically redacted when stdout is not a TTY.

B<Parameters:>

=over 4

=item C<$env_name>

The Genesis environment name.  Used to load and connect to the environment's
configured BOSH director.

=item C<@bosh_args>

Arguments passed through verbatim to the C<bosh> CLI.  At least one argument
is required; the function calls C<command_usage(1)> if C<@_> is empty.

=back

B<Returns:> Does not return.  Calls C<exit> with the BOSH command's exit code,
or C<exit 0> after exporting environment variables in C<--connect> mode.

B<Examples:>

  # Run 'bosh deployments' for a given environment
  # prints the BOSH director's deployment list to stdout
  genesis my-env bosh deployments

  # Set BOSH env vars in the current shell
  eval "$(genesis my-env bosh --connect)"
  # Returns: shell export statements applied to current environment

=head2 credhub($env_name, $cmd, @args)

  credhub($env_name, $cmd, @args)

Entry point for the C<genesis E<lt>envE<gt> credhub> command.  Executes a
C<credhub> CLI command against the CredHub instance associated with the
environment's BOSH director, using Genesis-managed authentication.

Relative credential names (those not beginning with C</>) are automatically
prefixed with the environment's CredHub base path, so that users do not need
to specify full paths for commands that accept C<--name> or
C<--path>/C<--prefix> options.  This path expansion is skipped when C<--raw>
is passed.

The following CredHub subcommands are blocked because Genesis manages
authentication internally: C<login> (C<l>), C<api> (C<a>), C<logout> (C<o>).

B<Parameters:>

=over 4

=item C<$env_name>

The Genesis environment name.  Used to load the environment and determine the
target CredHub instance.  At least one argument (the environment name) is
required; the function calls C<command_usage(1)> if C<@_> is empty.

=item C<$cmd>

The CredHub subcommand to execute (e.g., C<get>, C<set>, C<find>, C<export>).

=item C<@args>

Additional arguments passed to C<credhub $cmd>.  Relative C<--name> and
C<--path>/C<--prefix> values are automatically expanded to full CredHub paths
unless C<--raw> is active.

=back

B<Options> (read from parsed command-line flags):

=over 4

=item C<--raw>

Skips automatic base-path expansion for C<--name>/C<--path>/C<--prefix> values.
Credential paths are passed to CredHub exactly as provided.

=back

B<Errors:>

=over 4

=item C<"Command #C{genesis credhub %s} is not allowed in when Genesis is managing authentication to CredHub">

Raised (via C<bail()>) when C<$cmd> is one of C<login>, C<api>, or C<logout>
(or their single-letter aliases C<l>, C<a>, C<o>).  The C<%s> placeholder is
the disallowed command name.

=back

B<Returns:> Does not return.  Calls C<exit> with the CredHub command's exit
code.

B<Examples:>

  # Retrieve a credential using a relative name (auto-prefixed to base path)
  # Returns: credential details printed to stdout by the credhub CLI
  genesis my-env credhub get --name /my-credential

  # Find all credentials under the environment's base path
  # Returns: list of matching credential paths printed to stdout
  genesis my-env credhub find

  # Pass a fully-qualified path without auto-prefixing
  # Returns: credential details printed to stdout
  genesis my-env credhub --raw get --name /absolute/path/to/credential

=head2 logs($env_name, @extra_args)

  logs($env_name, @extra_args)

Not available for environments deployed with C<create-env>, since those
environments do not have a separate BOSH director to query for logs.

B<Parameters:>

=over 4

=item C<$env_name>

The Genesis environment name.

=item C<@extra_args>

Additional arguments forwarded to C<< $env->bosh_logs >>.

=back

B<Errors:>

=over 4

=item C<"No bosh logs for environments deployed with #M{create-env}">

Raised (via C<bail()>) when the environment is a C<create-env> environment.

=back

B<Returns:> Nothing.  Log output is displayed directly by C<< $env->bosh_logs >>.

B<Examples:>

  # Fetch BOSH logs for an environment
  # Returns: list of BOSH log entries
  genesis my-env logs

=head2 broadcast($env_name, @extra_args)

  broadcast($env_name, @extra_args)

Entry point for the C<genesis E<lt>envE<gt> broadcast> command.  Runs an
arbitrary command on one or more BOSH VMs by SSHing to each matching instance
in sequence.

Fetches the full VM list from the BOSH director (C<bosh vms --json>) and
matches it against the C<--on> filter option.  If no filter is provided, the
command is broadcast to all VMs in the deployment.  Each matching instance is
targeted individually via C<bosh ssh>.

Target matching rules:

=over 4

=item *

If the target string contains a C</>, it is matched as an exact instance ID
(e.g., C<web/0>).

=item *

Otherwise it is matched as an instance type prefix (e.g., C<web> matches
C<web/0>, C<web/1>, etc.).

=back

Duplicate targets (after resolution) are de-duplicated with C<uniq> before
SSH execution.

B<Parameters:>

=over 4

=item C<$env_name>

The Genesis environment name.

=item C<@extra_args>

The command and its arguments to execute on each target VM via C<bosh ssh>.

=back

B<Options> (read from parsed command-line flags):

=over 4

=item C<on>

An arrayref of target instance specifiers.  Each entry may be an instance type
(e.g., C<web>) or a fully qualified instance ID (e.g., C<web/0>).  Defaults to
all VMs in the deployment when not specified.

=back

B<Errors:>

=over 4

=item C<"Failed to fetch VM list: %s">

Raised (via C<bail()>) when the C<bosh vms --json> call fails.  The C<%s>
placeholder contains the error output from the BOSH CLI.

=item C<"Failed to parse VM list: %s">

Raised (via C<bail()>) when the JSON response from C<bosh vms> cannot be
parsed.  The C<%s> placeholder contains the Perl C<eval> error string.

=item C<"Errors were encountered while determining broadcast targets:\n%s">

Raised (via C<bail()>) when one or more entries in the C<--on> filter did not
match any running instance.  The C<%s> placeholder is a newline-joined list of
per-target error messages.

=back

B<Returns:> Returns after all instances have been targeted.  Individual SSH
failures are reported via the C<error> function but do not abort the broadcast
loop.

B<Examples:>

  # Broadcast a command to all VMs in the environment
  # prints uptime output from each VM separated by dividers
  genesis my-env broadcast -- uptime

  # Broadcast only to web instances
  # prints df output from each web/* instance
  genesis my-env broadcast --on web -- df -h

  # Broadcast to a specific instance
  # prints syslog output from web/0
  genesis my-env broadcast --on web/0 -- cat /var/log/syslog

=head2 bosh_configs($env_name, $action, @extra_args)

  bosh_configs($env_name, $action, @extra_args)

Entry point for the C<genesis E<lt>envE<gt> bosh-configs> command.  Validates
the action and the C<--type> option, loads the environment, connects to the
director that deploys it, and dispatches to the C<bosh_configs_*> function
for the action.

Valid actions are C<upload>, C<summary>, C<list>, C<view>, C<compare>, and
C<delete>.  The default action (when C<$action> is omitted) is C<upload>.

The configs an environment provides come from the kit's hooks: the
C<cloud-config> hook yields one cloud config named C<< <env>.<type> >>, the
C<runtime-config> hook yields one runtime config per build enabled under
C<bosh-configs.runtime>, named C<< <env>.<type>.<build> >>, and the
C<cpi-config> hook yields one cpi config named for the environment's cpi.
Cloud and cpi configs live on the director that deploys the environment;
runtime configs live on the environment itself when it is a BOSH director.

B<Parameters:>

=over 4

=item C<$env_name>

The Genesis environment name.

=item C<$action>

One of C<upload>, C<summary>, C<list>, C<view>, C<compare>, C<delete>.
Defaults to C<upload> when not supplied.

=item C<@extra_args>

No extra arguments are accepted.  The function calls C<bail()> if any are
provided.

=back

The command options reach the sub-actions as C<%options>: C<type> restricts
the action to one config type, C<name> restricts it to one config name,
C<uploaded> makes C<view> show the director's copy, and C<yes> skips the
confirmation prompts of C<upload> and C<delete>.

B<Errors:>

=over 4

=item C<"Invalid action: %s - expected one of: %s (leave blank for 'upload')">

Raised (via C<bail()>) when C<$action> is not one of the valid action strings.

=item C<"Too many arguments provided">

Raised (via C<bail()>) when C<@extra_args> is non-empty.

=item C<"Invalid config type: %s - expected one of: %s">

Raised (via C<bail()>) when C<--type> is not C<cloud>, C<runtime>, or C<cpi>.

=item C<"Environment %s is deployed with create-env and is not a BOSH director, so there is no BOSH director to hold bosh configs for it.">

Raised (via C<bail()>) for a create-env environment that is not itself a
director.  A create-env director is accepted; only its runtime configs apply.

=back

B<Returns:> Returns the result of the dispatched sub-action function.

B<Examples:>

  # Upload the synthesized configs, confirming each change (default action)
  genesis my-env bosh-configs

  # Show what the environment provides and how the director compares
  genesis my-env bosh-configs summary

  # Diff only the cloud config
  genesis my-env bosh-configs compare --type cloud

  # Delete one runtime config without prompting
  genesis my-env bosh-configs delete --name my-env.cf.dns --yes

B<The C<bosh-configs> sub-actions.>
The six functions below implement the actions of
C<genesis E<lt>envE<gt> bosh-configs>. They are not called by name from
anywhere: C<bosh_configs()> builds the name from the action the operator
typed and dispatches symbolically, so C<upload> reaches
C<bosh_configs_upload> purely by that construction.

Two consequences follow, and both matter more than they look:

=over 4

=item *

B<Their names are load-bearing.> Renaming one, or adding an underscore to
mark it internal, silently removes a subcommand -- there is no call site to
update and nothing to fail at compile time.

=item *

B<The action is validated before the symbolic call.> C<bosh_configs()>
rejects anything outside its list of valid actions first, which is what
keeps operator input from resolving to an arbitrary function.

=back

All six take the same arguments: the loaded C<Genesis::Env>, the
C<Service::BOSH::Director> that deploys it (C<undef> for a create-env
director), and the parsed command options.

=head2 bosh_configs_summary($env, $bosh, %options)

  bosh_configs_summary($env, $bosh, %options)

Synthesizes every config the environment provides (honoring C<--type> and
C<--name>), compares each with the director's copy, and prints a table of
type, name, director, and status.  The status is C<identical>, C<different>,
C<missing> (the director holds no copy), or C<not synthesized> (the hook
reported a failure for it).  Config types the kit does not provide, or that
do not apply to the environment, are explained in notes after the table.

B<Parameters:>

=over 4

=item C<$env>

A C<Genesis::Env> object for the target environment.

=item C<$bosh>

The C<Service::BOSH::Director> that deploys the environment.

=item C<%options>

Parsed command-line options hash (C<type>, C<name>).

=back

B<Returns:> C<1>.

B<Examples:>

  # Dispatched internally by bosh_configs():
  bosh_configs_summary($env, $bosh, type => 'runtime');
  # Prints one row per enabled runtime config

=head2 bosh_configs_upload($env, $bosh, %options)

  bosh_configs_upload($env, $bosh, %options)

Synthesizes the provided configs and uploads those that differ from, or are
missing on, the director.  For each such config it shows the diff (or the
whole content when the director has none) and asks for confirmation unless
C<--yes> was given; outside a controlling terminal C<--yes> is required.
Configs that are already identical are reported and skipped.

Cloud configs are handled the way the deploy path handles them: the network
claims lock is taken on the director before the cloud config is synthesized,
the config is uploaded with C<upload_config>, the network map the hook
produced is written to the director's exodus data, and the lock is released
even when something fails.  Cpi configs go through
C<< Genesis::Env->_fix_cpi_config >>, which also creates the CredHub secrets
the config references.  Runtime configs are uploaded by running the kit's
C<runtime-config> hook for the confirmed builds, so the hook can store the
secrets it generated.

B<Parameters:>

=over 4

=item C<$env>

A C<Genesis::Env> object.

=item C<$bosh>

The C<Service::BOSH::Director> that deploys the environment.

=item C<%options>

Parsed command-line options hash (C<type>, C<name>, C<yes>).

=back

B<Errors:>

=over 4

=item C<"%d bosh config%s could not be synthesized, so %s not uploaded.">

Raised (via C<bail()>) after the other configs have been handled, when one
or more hooks failed to produce a config.

=back

Errors from the helpers it calls (lock contention, a failed upload, a lost
lock, a refused prompt) propagate after the network claims lock is released.

B<Returns:> C<1>.

B<Examples:>

  # Dispatched internally by bosh_configs():
  bosh_configs_upload($env, $bosh, yes => 1);
  # Uploads every changed or missing config without prompting

B<Parameters:>

=over 4

=item C<$bosh>

The C<Service::BOSH::Director> that deploys the environment.

=item C<%options>

Parsed command-line options hash (C<type>, C<name>).

=back

B<Returns:> C<1>.

B<Examples:>

  # Dispatched internally by bosh_configs():

=head2 bosh_configs_view($env, $bosh, %options)

  bosh_configs_view($env, $bosh, %options)

Prints the synthesized configs on standard output, each under a heading on
standard error so the YAML can be redirected.  With C<--uploaded> it prints
the director's current copy of each config that belongs to the environment
instead.  Honors C<--type> and C<--name>.

B<Parameters:>

=over 4

=item C<$env>

A C<Genesis::Env> object.

=item C<$bosh>

The C<Service::BOSH::Director> that deploys the environment.

=item C<%options>

Parsed command-line options hash (C<type>, C<name>, C<uploaded>).

=back

B<Errors:>

=over 4

=item C<"No bosh configs belonging to %s%s were found on %s.">

Raised (via C<bail()>) with C<--uploaded> when the director holds nothing
matching the filters.

=item C<"%s config %s on %s BOSH director has no current version to show.">

Raised (via C<bail()>) with C<--uploaded> when the director lists the config
but cannot return its content.

=item C<"No bosh configs are provided for %s%s.">

Raised (via C<bail()>) when the environment provides nothing matching the
filters.

=item C<"%d bosh config%s could not be synthesized.">

Raised (via C<bail()>) after printing the others, when a hook failed to
produce a config.

=back

B<Returns:> C<1>.

B<Examples:>

  # Dispatched internally by bosh_configs():
  bosh_configs_view($env, $bosh, type => 'cloud');
  # Prints the synthesized cloud config YAML on stdout

  bosh_configs_view($env, $bosh, uploaded => 1, name => 'my-env.cf');
  # Prints the director's copy instead

=head1 INTERNAL FUNCTIONS

Helpers shared by the C<bosh-configs> actions.  A "config record" below is
the hash the helpers pass around: C<type>, C<name>, C<bosh> (the director
that holds it), C<content> (the synthesized YAML, or C<undef>), and, once
C<_bosh_configs_status> has run, C<status>, C<uploaded>, and C<diff>.  Cloud
records also carry C<network_map>, cpi records C<cpi_config>, and runtime
records C<build> and C<description>.

=head2 _bosh_configs_provided($env, $bosh, %options)

  my ($configs, $notes) = _bosh_configs_provided($env, $bosh, %options);

Runs the kit hooks to synthesize the configs the environment provides,
restricted by C<$options{type}> and C<$options{name}>.  The cloud config
comes from the C<cloud-config> hook when the environment can build cloud
configs, the cpi config from the C<cpi-config> hook when the environment is
OCFP with the cpi enabled, and the runtime configs from the
C<runtime-config> hook in collect mode for the builds returned by
C<_bosh_configs_runtime_requests>.  Runtime configs of a BOSH director
environment target the environment's own director.  A runtime hook failure
becomes a note rather than an error, so the other types still report.

B<Parameters:>

=over 4

=item C<$env>

A C<Genesis::Env> object.

=item C<$bosh>

The C<Service::BOSH::Director> that deploys the environment.

=item C<%options>

The command options; C<type> and C<name> are consulted.

=back

B<Errors:>

=over 4

=item C<"The cpi-config hook reported errors: %s">

Raised (via C<bail()>) when the cpi-config hook returns an error.

=back

B<Returns:> A list of two array references: the config records, and the
notes explaining each type that was left out.

B<Examples:>

  my ($configs, $notes) = _bosh_configs_provided($env, $bosh, type => 'cloud');
  # $configs holds at most one cloud record; $notes is empty

=head2 _bosh_configs_runtime_requests($env, $name)

  my $requests = _bosh_configs_runtime_requests($env, $name);

Builds the C<args> for the C<runtime-config> hook.  Without C<$name> it is
the C<bosh-configs.runtime> hash from the environment file, or C<undef>
when that hash is absent or empty (the same rule the post-deploy hook
applies).  With C<$name> it is a one-entry hash for the build the name
denotes (the part after C<< <env>.<type>. >>), carrying that build's options
from C<bosh-configs.runtime> when present, or C<undef> when the name cannot
be a runtime config of this environment.

B<Parameters:>

=over 4

=item C<$env>

A C<Genesis::Env> object.

=item C<$name>

An optional BOSH config name.

=back

B<Returns:> A hash reference of build name to options, or C<undef>.

B<Examples:>

  _bosh_configs_runtime_requests($env, 'my-env.cf.dns');
  # Returns: { dns => {} }

=head2 _bosh_configs_status($config)

  my $status = _bosh_configs_status($config);

Compares a config record with the director's copy and records the outcome
on it: C<unsynthesized> when C<content> is undefined, C<missing> when the
director has no current config of that type and name, otherwise
C<identical> or C<different> from C<spruce_diff>.  Sets C<uploaded> and
C<diff> on the record when a comparison was made.

B<Parameters:>

=over 4

=item C<$config>

A config record.

=back

B<Returns:> The status string, also stored in C<< $config->{status} >>.

B<Examples:>

  _bosh_configs_status($config);
  # Returns: 'different'; $config->{diff} holds the spruce diff output

=head2 _bosh_configs_confirm($question, $yes, $default)

  my $ok = _bosh_configs_confirm($question, $yes, $default);

Asks the operator a yes/no question before the director is changed.
Returns true at once when C<$yes> is set; otherwise prompts, and refuses to
continue when there is no controlling terminal to prompt on.

B<Parameters:>

=over 4

=item C<$question>

The prompt text, ending in C<[y|n]>.

=item C<$yes>

True when C<--yes> was given.

=item C<$default>

The answer offered when the operator presses enter.

=back

B<Errors:>

=over 4

=item C<"Not in a controlling terminal, so cannot prompt for confirmation.  Use --yes to skip the confirmation prompt.">

Raised (via C<bail()>) when a prompt is needed but no terminal is attached.

=back

B<Returns:> C<1> when the change may proceed, otherwise C<0>.

B<Examples:>

  _bosh_configs_confirm("Upload cloud config my-env.cf? [y|n]", 0, 1);
  # Returns: 1 when the operator answers yes

=head2 _bosh_configs_acquire_network_lock($env, $bosh, $yes)

  _bosh_configs_acquire_network_lock($env, $bosh, $yes);

Takes the network claims lock on the director before a cloud config is
synthesized, following the deploy path: a live lock stops the upload, a
stale lock is cleared after confirmation (or at once with C<--yes>), and
then the lock is acquired.

B<Parameters:>

=over 4

=item C<$env>

A C<Genesis::Env> object.

=item C<$bosh>

The C<Service::BOSH::Director> holding the network claims.

=item C<$yes>

True when C<--yes> was given.

=back

B<Errors:>

=over 4

=item C<"Network claims are currently locked -- cannot upload a cloud config now!">

Raised (via C<bail()>) when another process holds a live lock.

=item C<"Aborted by user!">

Raised (via C<bail()>) when the operator declines to clear a stale lock.

=item C<"Network claims are locked with a stale lock: %s\n\nRerun with --yes to clear it.">

Raised (via C<bail()>) when a stale lock is found outside a controlling
terminal without C<--yes>.

=back

B<Returns:> C<1>.

B<Examples:>

  _bosh_configs_acquire_network_lock($env, $bosh, 1);
  # Clears a stale lock without asking, then acquires the lock

=head2 _bosh_configs_upload_cloud($env, $config)

  _bosh_configs_upload_cloud($env, $config);

Uploads a cloud config record and records its network claims, as the deploy
path does: checks the lock is still held, uploads with C<upload_config>,
then writes the record's C<network_map> under the director's exodus
C</network> path.

B<Parameters:>

=over 4

=item C<$env>

A C<Genesis::Env> object.

=item C<$config>

A cloud config record with C<content>, C<name>, C<bosh>, and
C<network_map>.

=back

B<Errors:>

=over 4

=item C<"Network claims lock was lost since it was acquired (it may have become stale and been removed) -- cannot upload the cloud config!">

Raised (via C<bail()>) when the lock is gone at upload time.

=item C<"Failed to upload cloud config %s to BOSH director: %s\n\nContent:\n%s">

Raised (via C<bail()>) when the bosh upload fails.

=item C<"Cloud config %s was uploaded, but the network map could not be updated:\n\n%s">

Raised (via C<bail()>) when the exodus write fails after the upload.

=back

B<Returns:> C<1>.

B<Examples:>

  _bosh_configs_upload_cloud($env, $config);
  # Uploads my-env.cf and submits its network claims
