=head1 NAME

Genesis::Commands::Core - Command handlers for Genesis core operations

=head1 SYNOPSIS

  # Registered in bin/genesis via define_command:
  genesis version [<field> ...]
  genesis version --json [<field> ...]
  genesis ping
  genesis update [--version <ver>] [--check] [--pre] [--force] [--details]
  genesis hack [<env>] [<cmd> [<args> ...]]
  genesis config [<key>]

=head1 DESCRIPTION

Implements the built-in core commands available to all Genesis invocations
regardless of environment context: C<version>, C<ping>, C<update>,
C<hack>, and C<config>.

C<version> reports or queries structured build metadata for the running
Genesis executable.  C<ping> is a connectivity probe.  C<update> downloads
and installs a new Genesis release from GitHub.  C<hack> is a developer
inspection tool that evaluates Perl expressions, invokes object methods, or
calls module functions against a live Genesis object graph.  C<config>
reads the deployment repository's configuration.

C<config> lives here rather than beside the repository commands because
the configuration it reads is not exclusively a repository concern: the
same L<Genesis::Config> class backs the user-level configuration, and a
scope selector is the intended way to reach it.  Filing the handler with
the core commands keeps that door open.

=head1 FUNCTIONS

=head2 version(@fields)

  version()
  version('semver')
  version('major', 'minor', 'patch')
  version('semver', 'build_date', 'commit')

Prints Genesis version and build information.

When called with no arguments and no options, outputs the version string in
the form C<Genesis vX.Y.ZBuild-Info> and exits.  When called with one or more
field names, outputs each requested field on a separate line.  With the
C<--json> option, outputs a JSON object containing the requested fields (or
all fields if none are specified).

B<Parameters:>

=over 4

=item C<@fields>

Zero or more field names to query.  Valid field names are:

=over 4

=item C<semver> - Full semantic version string (e.g., C<1.2.3> or C<1.2.3-rc.4>)

=item C<is_dev> - Boolean; true when running a development build

=item C<major> - Major version number

=item C<minor> - Minor version number

=item C<patch> - Patch version number

=item C<rc> - Release candidate number, or C<undef> if not an RC

=item C<is_rc> - Boolean; true when the version is a release candidate

=item C<build_epoch> - Build timestamp as a Unix epoch integer

=item C<build_code> - Build timestamp as C<YYYYMMDD.HHMMSS> string

=item C<build_date> - Build timestamp as a human-readable date/time string

=item C<commit> - Git commit hash of the build

=item C<is_dirty> - Boolean; true when the build was made from a dirty working tree

=back

Boolean fields (those beginning with C<is_>) are printed as the literal strings
C<true> or C<false> in plain output mode.  In JSON mode they are proper JSON
booleans.

=back

B<Returns:> Does not return; always calls C<exit 0>.

B<Errors:>

=over 4

=item C<"Invalid version field(s): %s"> - One or more supplied field names are
not in the valid set.  The invalid field names are listed in the message.

=back

B<Examples:>

  # Print the full version string
  genesis version
  # prints: Genesis v3.1.0 (abc1234) build 20240315.120000

  # Query a single field
  genesis version semver
  # prints: 3.1.0

  # Query multiple fields
  genesis version major minor patch
  # prints:
  #   3
  #   1
  #   0

  # Output all version fields as JSON
  genesis version --json
  # Returns: {"semver":"3.1.0","is_dev":false,"major":3,...}

=head2 config($key)

  config()
  config('manifest_store')
  config('ci.provider.type')

  genesis config --set manifest_store exodus
  genesis config --set manifest_store exodus --set ci.enabled false

Reads and writes the deployment repository's configuration in
F<.genesis/config>.  With no argument, prints the whole configuration as
YAML; with a key, prints just that key's value.

B<Writing requires C<--set>, so a bare argument never assigns
anything.> C<genesis config a b> reads two keys; it does not set C<a> to
C<b>.  The alternative -- taking a second bare argument as a value, as
C<git config> does -- turns a mistyped read into a silent write, and a
surprising read is recoverable in a way a surprising write is not.

C<--set> takes a key and a value, and may be repeated.  Values are
coerced to the type the schema declares before being stored, so
C<ci.enabled false> records a false boolean rather than the string
C<'false'>, which Perl would treat as true.  See
L<Genesis::Config/_coerce_to_schema_type>.

C<--unset> removes a key, and may also be repeated.

B<A key that is not set is accepted; a key the schema does not define
is not.> Unset states a desired end state, and a key that was never
there already satisfies it -- so C<--unset a.b --unset a> is redundant
rather than wrong.  The check that matters is validity: a misspelling
is always absent, so only the schema can tell one from a key that
simply is not in use.

B<Nothing is written until the whole result validates.> Every set and
unset is applied in memory, the configuration is checked, and only then
is it persisted -- so a rejected value leaves the file exactly as it
was rather than half-updated into a state L<Genesis::Top> would refuse
to load.  The two can be combined in one run, and a key appearing in
both is refused; see L</LIMITATIONS>.

B<The configuration is reported as Genesis will actually use it>, not as
the file literally reads.  Schema defaults and environment overrides are
merged in, so C<ci.provider.insecure> is reported even when the file
never mentions it.  This answers "what value is in effect", which is the
question an operator debugging a deployment is asking.  It does mean the
output cannot be diffed against the file on disk.  Distinguishing the
sources visually is deferred; see L</LIMITATIONS>.

Keys are dotted paths, resolved by L<Genesis::Config/get>, so
C<ci.provider.type> walks into nested sections.

B<A key naming a section prints that section as YAML> rather than
stringifying the reference.  A scalar prints bare, with no YAML framing,
so C<$(genesis config manifest_store)> yields the value and nothing else.

B<Values go to standard output and everything else to standard error>,
so the command composes in a pipeline.  This falls out of C<output()>
being the only reporting call used here: L<Genesis::Log> routes the
C<OUTPUT> level to C<STDOUT> and every other level to C<STDERR>.

B<Parameters:>

=over 4

=item C<$key> (optional)

A dotted path into the configuration.  Omit it to dump everything.

=back

B<Returns:> C<0> when the key was found, when dumping, or after a
successful write; C<1> when the key is not set.

B<Errors:>

=over 4

=item C<"%s is (unset)">

Reported on standard error, with a return of C<1>, when the key is
absent.  Deliberately not silent-and-zero: printing an empty line to
standard output would be indistinguishable from a key legitimately set
to the empty string, leaving a caller unable to tell the two apart.

=item C<"Configuration validation failed for %s">

Raised by L<Genesis::Config/validate> when a value written with
C<--set> does not satisfy the schema.  The message names the offending
key.  The file is left untouched.

=item C<"Cannot unset unknown configuration key%s: %s">

Raised when C<--unset> names a key the schema does not define.  Names
every unrecognised key, not just the first.

=item C<"Cannot set and unset overlapping keys in one run: %s">

Raised before anything is applied when a key named by C<--set> and one
named by C<--unset> are the same, or one contains the other.  Keys that
merely share a prefix -- C<ci.enabled> and C<ci.provider> -- do not
overlap and are allowed together.

=item C<"Reading and writing cannot be combined in one run">

Raised as a usage error when a key is given alongside C<--set> or
C<--unset>.

=item C<"Only one key can be read at a time">

Raised as a usage error when more than one key is given.  The full
configuration is available by giving none.

=back

B<Examples:>

  genesis config
  # prints: the whole configuration as YAML

  genesis config manifest_store
  # prints: exodus

  genesis config ci
  # prints: the ci section as YAML, defaults included

  genesis config no_such_key
  # prints (stderr): no_such_key is (unset)
  # exits: 1

=head2 ping()

  ping()

Connectivity probe.  Prints C<PING!> to standard output and exits.

Accepts no arguments.  Calls C<command_usage(1)> to print usage and exit with
an error if any arguments are passed.

B<Returns:> Does not return; always calls C<exit 0>.

B<Examples:>

  genesis ping
  # prints: PING!

=head2 update()

  update()

Downloads and installs a Genesis release from GitHub, replacing the running
executable in-place.

With no options, finds the latest stable release newer than the current
version and, after prompting for confirmation, downloads and installs it.
The installed binary preserves the original file's ownership and permission
bits.  When the target path is not writable by the current user, a temporary
shell script is generated and executed via C<sudo>.

After a successful install, clears the C<GENESIS_HOME>, C<GENESIS_LIB>, and
C<GENESIS_CALLBACK_BIN> environment variables and execs the newly installed
binary with C<version> to confirm the upgrade.

Accepts no positional arguments.  Calls C<command_usage(1)> to print usage
and exit with an error if any positional arguments are passed.

B<Options> (read from the command-line options hash):

=over 4

=item C<--version E<lt>verE<gt>>

Install a specific version.  The leading C<v> is stripped automatically.
Fails if the version does not exist on GitHub or if the downloadable
executable is no longer available.

=item C<--check>

Report whether an update is available without installing it.  Exits 0 when
already at the latest version; exits 1 when no matching version can be found
or the requested version is unavailable.

=item C<--pre>

Include pre-release versions when searching for updates.

=item C<--details>

Print release notes for each available version before prompting.

=item C<--force>

Skip the interactive confirmation prompt and install without asking.

=back

B<Returns:> Does not return.  In C<--check> mode, exits 0 on success or 1 on
failure.  Otherwise, calls C<exit 0> after printing release information, or
execs the newly installed binary to verify the upgrade.

B<Errors:>

=over 4

=item C<"$err - cannot update."> - The requested version does not exist, the
executable is unavailable, or no newer version is available (not in C<--check>
mode).  C<$err> contains the specific reason.

=item C<"Aborted!"> - The user declined the confirmation prompt.

=back

B<Examples:>

  # Check whether an update is available
  genesis update --check
  # prints: SUCCESS: You are on the latest version of Genesis (currently v3.1.0).

  # Update to the latest stable release
  genesis update
  # prompts for confirmation, then installs and verifies

  # Install a specific version
  genesis update --version 3.0.5

  # Install the latest pre-release
  genesis update --pre

=head2 hack($cmd, @args)

  hack()
  hack('pry')
  hack('$Genesis::VERSION')
  hack('$top', '->', 'load_env', '(', 'my-env', ')')
  hack('Genesis::Env::some_func', 'arg1')
  hack('Genesis::Env->class_method', 'arg1')
  hack('<env-name>', '$top', '->', 'load_env', '(', '<env-name>', ')')

Developer inspection tool.  Evaluates Perl expressions, invokes chains of
object methods, or calls module functions against the live Genesis object
graph.  Intended for debugging and exploration during development.

B<Parameters:>

=over 4

=item C<$cmd>

The command or expression to evaluate.  Interpretation depends on the value:

=over 4

=item C<undef> or C<'pry'>

Loads L<Pry> and drops into an interactive Pry debugging session.

=item A string beginning with C<$> (e.g., C<$Genesis::VERSION>)

Evaluates the string as a Perl expression using C<eval()>.  The result is
printed using C<dump_var>.  If C<@args> are present they are interpreted as a
method-chain continuation (see below).

=item A string in the form I<Module>::I<func> or I<Module>-E<gt>I<method>

Loads the named module and calls the specified function or class method with
C<@args> as positional arguments.  The result is printed using C<dump_var>.

=back

=item C<@args>

When C<$cmd> is a Perl expression (C<$...>), C<@args> encodes a method chain
to execute on the result.  Tokens are interpreted as follows:

=over 4

=item C<-E<gt>> - Chain operator; begins a new method call

=item A bare word following C<-E<gt>> - Method name

=item C<(> - Opens argument list for the current method

=item A bare word inside C<(...)> - Argument value passed to the method

=item C<)> - Closes argument list and triggers the call

=back

The chain is executed left-to-right; each call's return value becomes the
receiver for the next.  If the method name is C<pry>, drops into an
interactive Pry session with C<$obj> bound to the current receiver.

When C<$cmd> is a module function or method call, C<@args> are passed directly
as positional arguments.

=back

B<Returns:>

=over 4

=item C<1> - When dispatching to a module function or class method.

=item The result of C<defined($obj)> - After executing a Perl expression with
a method chain.  Returns true if the final result is defined.

=item Does not return (C<exit 0>) - When C<$cmd> is C<undef> or C<'pry'>.

=back

B<Context detection:> If the current directory contains C<.genesis/kits/> or
C<dev/>, a C<Genesis::Top> object is constructed automatically.  If C<$cmd>
matches an environment file name in that top-level directory (with or without
the C<.yml> extension), the corresponding environment is loaded into C<$env>
and the next element of C<@args> becomes the new C<$cmd>.

B<Errors:>

=over 4

=item C<"Attempted to load environment from %s, but encountered error: %s"> -
Loading the environment file failed.  The first C<%s> is the C<.yml> file
path; the second is the caught exception.

=item C<"Attempted to load Pry, but encountered error: %s"> - The Pry module
could not be loaded.  The C<%s> is the caught exception.

=item C<"Attempted to evaluate Perl expression, but encountered error: %s"> -
C<eval()> of the C<$cmd> expression raised an exception.  The C<%s> is the
caught exception.

=item C<"Improperly formatted expression: no method specified for call"> -
A closing parenthesis was encountered before a method name was set.

=item C<"Improperly formatted expression: expecting a -> operator, but found '%s'"> -
A token appeared where a C<-E<gt>> operator was expected.  The C<%s> is the
unexpected token.

=item C<"Improperly formatted expression: unexpected argument '%s' while waiting for %s"> -
An argument token appeared while the parser was not expecting one.  The first
C<%s> is the unexpected token; the second is the parser state description.

=item C<"Improperly formatted expression: unexpected opening parenthesis while waiting for %s"> -
An opening parenthesis appeared while the parser expected a method name.
The C<%s> is the parser state description.

=item C<"Improperly formatted expression: unexpected opening parenthesis while waiting for argument"> -
An opening parenthesis appeared while an argument was already being collected.

=back

B<Examples:>

  # Drop into a Pry debugging session
  genesis hack pry

  # Inspect a package variable
  genesis hack '$Genesis::VERSION'
  # Returns: result = "3.1.0"

  # Call a method chain on an evaluated expression
  genesis hack '$top' -> load_env '(' my-env ')'

  # Call a package function directly
  genesis hack 'Genesis::Env::some_func' arg1 arg2

  # Call a class method
  genesis hack 'Service::Github->new'

=head1 INTERNAL FUNCTIONS

These are internal to this module and may change without notice.

=head2 _contains($ancestor, $key)

  _contains('ci', 'ci.enabled');       # 1
  _contains('ci', 'ci');               # 0 -- equal, not contained
  _contains('a',  'ab');               # 0

Reports whether one dotted path lies inside another.

B<A shared prefix is not containment.> The next character has to be a
separator, so C<a> does not contain C<ab>.  Both C<.> and C<[> count,
so an indexed path such as C<a[0].b> is recognised as inside C<a>.

Equality is deliberately not containment: callers test for it
separately, because the two cases usually warrant different wording.

B<Returns:> C<1> when C<$key> lies inside C<$ancestor>, C<0> otherwise.

B<Errors:> None.

B<Examples:>

  _contains('ci.provider', 'ci.provider.type');   # 1
  _contains('ci.enabled',  'ci.provider');        # 0

=head2 _detect_feature_compatibility($env_name)

Determines the feature-compatibility floor in effect, and where it came from,
for display alongside the version.

Resolution order: an environment's own effective minimum version when
C<$env_name> is given, otherwise the repository's C<minimum_version>. Outside
a Genesis repository there is nothing to report.

The whole lookup runs inside an C<eval> and any failure is swallowed. That is
deliberate: this decorates a version string, and a broken repo, an
unreadable config or an environment that will not load should leave the
version unadorned rather than prevent the operator from finding out what
version they are running.

C<0.0.0> is treated as absent rather than as a floor -- it is the sentinel
for "no opt-in", and reporting it as a feature level would imply a
constraint that is not there.

B<Parameters:>

=over 4

=item C<$env_name>

An environment name, or C<undef> to report the repository-level floor.

=back

B<Returns:> The two-element list C<($level, $source)>, or C<(undef, undef)>
when no floor applies, when the sentinel is found, or when anything went
wrong looking.

B<Examples:>

  my ($level, $source) = _detect_feature_compatibility('my-env');
  # returns ('3.1.0', 'environment')

  my ($level, $source) = _detect_feature_compatibility(undef);
  # returns ('3.0.0', 'repository') inside a repo with a minimum_version

  my ($level, $source) = _detect_feature_compatibility(undef);
  # returns (undef, undef) outside a Genesis repository

=head2 _format_feature_level_tail($fc_level, $fc_source)

Formats the pair from C<_detect_feature_compatibility> into the suffix
appended to a version line.

B<Parameters:>

=over 4

=item C<$fc_level>

The feature level, or C<undef>.

=item C<$fc_source>

Where the level came from -- C<environment> or C<repository>.

=back

B<Returns:> The formatted suffix, or the empty string when C<$fc_level> is
C<undef>. Returning C<''> rather than C<undef> is what lets callers
concatenate the result unconditionally.

B<Examples:>

  my $tail = _format_feature_level_tail('3.1.0', 'environment');
  # returns ' (feature level: v3.1.0 [environment])'

  my $tail = _format_feature_level_tail(undef, undef);
  # returns '' -- safe to concatenate either way

=head1 LIMITATIONS

=head2 C<config> reports no provenance

The configuration is reported fully realized -- file, schema defaults and
environment overrides merged -- with nothing to distinguish them.  A
value coming from C<GENESIS_*> in the caller's environment looks
identical to one written in F<.genesis/config>, which is precisely the
case an operator is likely to be hunting.  L<Genesis::Config/get_source>
already reports the winning source per key (C<env>, C<set>, C<loaded>,
C<default>), so this is a rendering gap rather than a missing capability.
Marking the sources, filtering by source, and a machine-readable form
carrying value and source together are all deferred.

=head2 Setting and unsetting overlapping keys is refused

Getopt::Long collects each option into its own list, so the order the
two were typed in is not recoverable: C<--set a 1 --unset a> and
C<--unset a --set a 1> arrive identical.  No destination preserves
arity, ordering and attribution together -- a shared array loses which
option supplied a value, and a callback destination forces a single
value per occurrence, discarding the arity.  Rather than pick an order
and be wrong half the time, the invocation is rejected.

The same applies when one key contains the other: unsetting C<ci>
removes what C<--set ci.enabled> just wrote, and which of the two wins
again depends on the order that was lost.  Keys that only share a
prefix are unrelated and remain allowed.

=head2 Reading and writing cannot be combined

There is no output contract for printing one value while changing
another, so an invocation naming a key alongside C<--set> or
C<--unset> is a usage error.  Only one key may be read at a time; the
whole configuration is available by naming none.

=head2 An arity option cannot be abbreviated

C<--set> is parsed in a first pass configured with C<no_auto_abbrev>, so
C<--se> does not resolve to it.  Every other option still abbreviates.
See L<Genesis::Commands/_parse_two_pass>.

=head2 C<config> is repository-scoped only

Only F<.genesis/config> is reachable.  The user-level
F<~/.genesis/config> uses the same L<Genesis::Config> class and has its
own schema, including per-key environment-variable bindings, but no
option selects it.  The command name is deliberately unqualified so that
a scope selector can be added without renaming it; repository scope
remains the default if one is.
