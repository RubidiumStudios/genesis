=head1 NAME

Genesis::Commands::Pipelines - Command handlers for Genesis CI/CD pipeline management

=head1 SYNOPSIS

  # Registered in bin/genesis via define_command:
  genesis embed
  genesis repipe [layout] [--config ci.yml] [--target <fly-target>] [--dry-run] [--yes] [--paused]
  genesis graph  [layout] [--config ci.yml]
  genesis describe [layout] [--config ci.yml]

=head1 DESCRIPTION

Provides operator-facing command handlers for Genesis CI/CD pipeline
management.  C<embed>, C<repipe>, C<graph>, and C<describe> are run by a
Genesis operator to embed the Genesis binary, configure a Concourse
pipeline, visualize the pipeline dependency graph, or display a
human-readable pipeline description.

The legacy Concourse-facing pipeline task handlers
(C<ci_pipeline_deploy>, C<ci_show_changes>, C<ci_generate_cache>, and
C<ci_pipeline_run_errand>) have been retired.  Their commands remain
registered in F<bin/genesis> with a C<retired> property so a legacy
Concourse pipeline that shells to C<genesis ci-*> fails loudly at
dispatch time with a migration message; the earlier v3.1 semantics
that would have deployed based on C<VAULT_ROLE_ID>/C<VAULT_SECRET_ID>
plus C<CURRENT_ENV>/C<GIT_BRANCH>/C<WORKING_DIR>/C<OUT_DIR>/C<CACHE_DIR>
environment variables no longer applies.  See L<Genesis::Commands> for
the C<retired> mechanism.

=head1 FUNCTIONS

=head2 embed()

    genesis embed

Embeds the current Genesis binary into the deployment repository under
C<.genesis/>.  This ensures that all pipeline tasks use the same Genesis
version that was present when the pipeline was configured.

The binary to embed is taken from the C<GENESIS_CALLBACK_BIN> environment
variable, falling back to C<$0> (the currently executing Genesis binary).

Takes no arguments.  Prints usage and exits if any arguments are supplied.

B<Returns:> The return value of C<Genesis::Top-E<gt>embed>.

B<Examples:>

  # Embed the currently running genesis binary into the deployment repo
  genesis embed

=head2 repipe([$layout])

    genesis repipe
    genesis repipe sandbox
    genesis repipe --config ci.yml --target my-concourse --dry-run

Generates and uploads a Concourse pipeline configuration from the genesis
CI config file.  Parses the pipeline definition, generates Concourse YAML,
then pauses, sets, unpauses, and exposes or hides the pipeline via the
C<fly> CLI.

B<Parameters:>

=over 4

=item C<$layout> (optional)

The pipeline layout to use.  Defaults to the layout inferred from the CI
config file when omitted.

=back

B<Options (via C<get_options>):>

=over 4

=item C<--config> (default: C<ci.yml>)

Path to the CI config file to parse.

=item C<--target>

The Concourse C<fly> target to use.  Defaults to the layout name when not
specified.

=item C<--dry-run>

Print the generated Concourse YAML to standard output and exit without
uploading.

=item C<--yes>

Pass the C<-n> flag to C<fly set-pipeline> to skip interactive confirmation.

=item C<--paused>

Leave the pipeline paused after uploading instead of unpausing it.

=back

B<Returns:> Nothing.  Exits 0 on success.  When C<--dry-run> is specified,
prints the Concourse YAML to standard output and exits 0 without uploading.

B<Errors:>

Calls C<bail()> with C<"No vault specified or configured."> if no Vault is
configured.

Calls C<bail()> with C<"Could not pause %s pipeline: %s"> (where the first
C<%s> is the pipeline name and the second is the command output) if
C<fly pause-pipeline> fails with an error other than
C<pipeline '...' not found>.

Calls C<bail()> via C<onfailure> if C<fly set-pipeline>,
C<fly unpause-pipeline>, C<fly expose-pipeline>, or C<fly hide-pipeline>
fails.

B<Examples:>

  # Upload pipeline using defaults
  genesis repipe
  # Returns: exits 0 on success

  # Preview the generated pipeline YAML without uploading
  genesis repipe --dry-run
  # Prints: Concourse YAML to standard output

  # Upload with a specific Concourse target
  genesis repipe --target prod-concourse
  # Returns: exits 0 on success

=head2 graph([$layout])

    genesis graph
    genesis graph sandbox

Generates and prints a Graphviz DOT-format representation of the pipeline
dependency graph.  The DOT output can be piped to C<dot> or rendered with any
Graphviz tool.

B<Parameters:>

=over 4

=item C<$layout> (optional)

The pipeline layout to use.  Defaults to the layout inferred from the CI
config file when omitted.

=back

B<Options (via C<get_options>):>

=over 4

=item C<--config> (default: C<ci.yml>)

Path to the CI config file to parse.

=back

B<Returns:> Prints the Graphviz DOT source to standard output.

B<Examples:>

  # Print DOT graph for the default pipeline
  genesis graph

  # Render pipeline graph as PNG
  genesis graph | dot -Tpng -o pipeline.png

=head2 describe([$layout])

    genesis describe
    genesis describe sandbox

Parses the pipeline configuration and prints a human-readable description
of the environments and their pass/trigger relationships.

Where the repository configures a pipeline, the report opens with the
resolved source-control values, each beside the tier it came from, so an
override that has drifted away from what git says is visible rather than
silent.

B<Parameters:>

=over 4

=item C<$layout> (optional)

The pipeline layout to use.  Defaults to the layout inferred from the CI
config file when omitted.

=back

B<Options (via C<get_options>):>

=over 4

=item C<--config> (default: C<ci.yml>)

Path to the CI config file to parse.

=back

B<Returns:> Prints the pipeline description to standard output.

B<Examples:>

  # Describe the default pipeline
  genesis describe

  # Describe a specific pipeline layout
  genesis describe sandbox

=head1 INTERNAL FUNCTIONS

=head2 _describe_source_control

  _describe_source_control($top);

Prints the repository's source-control values, one to a line, each beside
the tier it resolved from.

The resolution belongs to C<< $top->source_control_resolved >>, which
settles what every value is and whether the operator wrote it, git answered
for it, or nobody set it at all.  This lays those rows out and nothing more.

The key column and the tier column are both sized from the rows, and the
tier is printed before the value rather than after it.  A remote URL is
routinely longer than what is left of an eighty-column line, and C<output>
wraps on whitespace, so whichever field comes last is the one that takes a
line of its own when the line runs long.  That has to be the value, because
a tier on a line with no key beside it says nothing at all.

B<Parameters:>

=over 4

=item C<$top>

The C<Genesis::Top> for the repository being described.

=back

B<Returns:> 1, having printed the block to standard output.

B<Errors:> None of its own.

B<Examples:>

  _describe_source_control($top);
  # Source control
  #   remote         derived origin
  #   uri            derived https://github.com/fivetwenty-io/lmelt.git
  #   repository     derived fivetwenty-io/lmelt
  #   control_branch default control
  #   pr_prefix      default pr/

Every key the block resolves is printed, so the report is five rows and
not two, and both column widths come from those rows.  A repository that
overrides one of them widens the tier column to hold C<explicit>.

=head2 _missing_env_branches

  my @missing = _missing_env_branches($git, \@scope);

Returns the environments in C<@scope> that have no local branch, in the
order given.

Kept apart from C<propagate> so the decision can be tested without a
repository: reaching it in situ needs a working tree, a DAG and a vault.

B<Returns:> The subset of C<@scope> lacking a branch; empty when all are
present.

B<Errors:> None.

B<Examples:>

  my @missing = _missing_env_branches($git, ['mgmt','lab','qa']);
  # returns ('lab') when only lab has no branch

=head2 _authorize_branch_creation

  _authorize_branch_creation($opts, \@missing, $control);

Decides whether propagation may create the branches it found absent.
Returns true when authorized and raises otherwise, so callers proceed
directly to creation.

B<Creating a branch is incidental to propagating, so it is opted into
rather than assumed.> C<propagate>'s purpose is to move files between
branches that already exist; making one is a repair it happens to be
positioned to perform. The operator therefore authorizes it explicitly
with C<-y>, or by answering a prompt.

B<Outside a controlling terminal it refuses rather than guessing.> There
is no one to ask, and creating branches unattended is exactly the
silent, hard-to-notice change this ought not make on its own. The
refusal names both C<-y> and C<pipeline-prepare>, because an operator
told only that something is wrong has been given a complaint rather than
a remedy.

B<The refusal exits with C<Genesis::Top/PROPAGATE_NO_BRANCH_EXIT>>
rather than the default 1, so a C<deploy> running C<propagate> as a
subprocess can distinguish "refused, and here is the one-command fix"
from "propagation actually broke". See L<Genesis::Env/_post_deploy>.

The environment list is printed before the question rather than folded
into it: approving a list you cannot see is not consent, and
C<prompt_for_boolean> collapses a multi-line prompt onto its question
line.

B<Parameters:>

=over 4

=item C<$opts>

The parsed command options. Only C<yes> is consulted.

=item C<\@missing>

Environments whose branches are absent. Named in full in the output.

=item C<$control>

The control branch, named in both the prompt and the refusal as the
source the new branches would be built from.

=back

B<Returns:> True when creation is authorized. Does not return otherwise.

B<Errors:>

=over 4

=item C<"No branch exists for ...">

Raised with exit code C<PROPAGATE_NO_BRANCH_EXIT> when there is no
terminal to ask and C<-y> was not given.

=item C<"Aborted - no branches were created.">

Raised when the operator declines the prompt. Continuing would propagate
against a branch they just refused to create.

=back

B<Examples:>

  _authorize_branch_creation({yes => 1}, ['lab'], 'control');
  # returns 1 without asking

  _authorize_branch_creation({}, ['lab'], 'control');
  # prompts when interactive; raises otherwise

=head2 _create_missing_branches

  my @created = _create_missing_branches($top, \@missing, $dry_run);

Builds a branch for each environment, via
L<Genesis::Env/prepare_branch>.

B<Creating the branch is the propagation for that environment.>
C<prepare_branch> seeds the new branch with the environment's
propagation files copied from control HEAD, so the diff computed
immediately afterwards is empty by construction and the environment
never appears in the propagation targets. There is no second step.

B<Which is why the caller must push these explicitly.> Receiving no
propagation commit, a created branch never reaches C<@pushed_branches>
in L<Genesis::CI::Propagation/propagate_envs>, and would be left local:
the pipeline would never see it, and the next run would find it
local-only and proceed quietly. C<propagate> passes the returned names
as C<push_extra_branches>, which C<--no-push> still suppresses.

Creation is safe to perform implicitly because C<prepare_branch> reads
existence off two refs that are already here, the local branch and its
remote-tracking ref, and creates only a branch that is in neither. It
contacts the remote for nothing. The refresh is what brings the tracking
refs up to date, and it creates the local ref for a branch the remote
alone had, so by the time this is asked a branch that exists on the
remote is here and will not be forked.

B<Parameters:>

=over 4

=item C<$top>

The C<Genesis::Top> used to load each environment.

=item C<\@missing>

Environments to create branches for.

=item C<$dry_run>

Reports what would be created without committing.

=back

B<Returns:> The names created, for the caller to add to the push set.

B<Errors:>

=over 4

=item C<"Could not load ... to create its branch">

Raised when the environment cannot be loaded. Deliberately fatal rather
than skipped: a skipped environment would leave the branch absent while
the run reported success, which is the failure this whole path exists to
end.

=back

B<Examples:>

  my @created = _create_missing_branches($top, ['lab'], 0);
  # returns ('lab'); refs/heads/lab now exists with a seed commit

=head2 _resolve_propagation_base

  my ($sha, $depth) = _resolve_propagation_base($branch, $git, $control);

Finds the control-branch commit an environment branch was last brought
up to, so propagation knows what to diff against.

It reads the branch's own log first, looking for the most recent
C<[pipeline] control@E<lt>shaE<gt>> marker, and warns when that marker is
not the tip, since commits on top of it were made by hand. A branch
carrying no marker was spawned from control and never propagated to, so
the merge base with the control branch is used instead.

B<The control branch is passed in rather than assumed.> Its name is
configured per repository at C<pipeline.source_control.control_branch>,
every caller has already read it through
L<Genesis::Top/control_branch>, and taking a merge base against the
wrong branch would silently change what the diff is computed from.

B<Parameters:>

=over 4

=item C<$branch>

The environment branch to resolve a base for.

=item C<$git>

The C<Service::Git> handle to read through. Optional, and it defaults to
one opened on the current directory.

=item C<$control>

The repository's control branch, as its configuration names it.
Mandatory, and it has no default, because there is no name this sub
could fall back to that would be right for every repository.

=back

B<Returns:> Two values. The first is the control commit the branch was
last brought up to, spelled as fully as this repository can spell it. A
marker naming a commit this clone has never fetched comes back at the
width the marker wrote it, because a sha the repository cannot reach is
a sha it cannot expand. The second is a count only on the marker path,
where it is the number of commits standing on top of the newest marker,
and it is a literal zero on the merge-base path, where nothing is
counted. A branch that shares no history with control comes back as
C<undef> and zero.

B<Errors:> None, in that no input makes it die, and an unresolvable base
comes back as C<undef>. It does warn: where the newest marker is not the
tip, it says how many commits were made by hand on top of the last
propagation, because those commits are about to be diffed against
control.

B<Examples:>

  my ($sha, $depth) = _resolve_propagation_base('qa', $git, 'trunk');
  # returns the sha from qa's newest [pipeline] marker, and 0
  # returns the merge base with trunk, and 0, when qa has no marker
