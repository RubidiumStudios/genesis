=head1 NAME

Genesis::Env - A deployable environment in a Genesis deployment repository

=head1 SYNOPSIS

    use Genesis::Top;
    use Genesis::Env;

    my $top = Genesis::Top->new('.');

    # Load an existing environment
    my $env = Genesis::Env->load(
      top  => $top,
      name => 'us-west-1-preprod',
    );

    # Create a new environment (interactive)
    my $env = Genesis::Env->create(
       top  => $top,
       name => 'us-west-1-preprod',
       kit  => $top->local_kit_version('some-kit', 'latest'),
    );

    # Query environment properties
    print $env->name;             # us-west-1-preprod
    print $env->deployment_name;  # us-west-1-preprod-bosh
    print $env->type;             # bosh
    print $env->secrets_base;     # /secret/us/west/1/preprod/bosh/

    # Deploy
    $env->deploy(yes => 1);

=head1 DESCRIPTION

The Env class represents a single, deployable unit of YAML files in a
Genesis deployment repository / working directory, and wraps up all of the
core rules for dealing with the set as a whole.

To load an existing environment, all you need is the C<Genesis::Top> object
that represents the top of the deployment repository, and the name of the
environment you want:

    use Genesis::Top;
    use Genesis::Env;

    my $top = Genesis::Top->new('.');
    my $env = Genesis::Env->load(
      top  => $top,
      name => 'us-west-1-preprod',
    );

To create a new environment, you need a bit more information.  You also need
to be ready to run through interactive ask-the-user-questions mode, for
things like the C<new> hook:

    my $env = Genesis::Env->create(
       top  => $top,
       name => 'us-west-1-preprod',
       kit  => $top->local_kit_version('some-kit', 'latest'),
    );

You can also avail yourself of the C<new> constructor, which does a lot of
the validation, but won't access the environment files directly:

    my $env = Genesis::Env->new(
       top  => $top,
       name => 'us-west-1-preprod',
    );

=head1 CONSTRUCTORS

=head2 new(%opts)

    my $env = Genesis::Env->new(%opts);

Create a new Env object without making any assertions about the filesystem.
Usually, this is not the constructor you want.  Check out C<load> or
C<create> instead.

The following options are recognized:

=over 4

=item B<name> (required)

The name of your environment.  See L</NAME VALIDATION> for details on naming
requirements.

=item B<top> (required)

The C<Genesis::Top> object that represents the root working directory of the
deployments repository.  This is used to fetch things like deployment
configuration, kits, etc.

=item B<secrets_path>

A path in the Genesis Vault, under which secrets for this environment should
be stored.  Normally, you don't need to specify this.  When an environment
is loaded it will probably be overridden by the operator's C<genesis.secrets_path>
parameter.  Otherwise, Genesis can figure out the correct default value.

=back

Unrecognized options will be silently ignored.

B<Returns:> a blessed C<Genesis::Env> object.

B<Errors:>

=over 4

=item *

Calls C<bug("No '$_' specified in call to Genesis::Env->new!!")> if C<name> or C<top> is missing.

=item *

Calls C<bail("Bad environment name '$opts{name}': %s", $err)> if the name fails validation.

=item *

Calls C<bail("No deployment type specified in .genesis/config!\n")> if the repository has no deployment type.

=back

B<Examples:>

    my $env = Genesis::Env->new(
      top  => Genesis::Top->new('.'),
      name => 'us-east-1-sandbox',
    );
    # Returns a Genesis::Env object (kit not loaded, files not read)

=head2 load(%opts)

    my $env = Genesis::Env->load(%opts);

Create a new Env object by loading its definition from constituent YAML
files on-disk (by way of the given C<Genesis::Top> object).  If the given
environment cannot be loaded, this constructor calls C<bail>, so callers
that want to handle failures gracefully should wrap the call in C<eval>.

C<load> validates the environment file, checks for deprecated parameters
(C<kit.subkits>, C<params.genesis_version_min>, C<params.bosh>), normalizes
C<genesis.use_create_env> to a boolean, validates C<bosh-configs> keys,
checks Genesis version requirements, and loads the kit.

B<Parameters:>

=over 4

=item B<%opts>

Same options as for C<new>: C<name> (required) and C<top> (required).

=back

B<Returns:> a C<Genesis::Env> object with its kit loaded and parameters
parsed from the environment hierarchy.

B<Errors:>

=over 4

=item *

Calls C<bug("No '$_' specified in call to Genesis::Env->load!!")> if C<name> or C<top> is missing.

=item *

Bails with C<"Environment #C{%s} could not be loaded:\n[[- >>%s\n\nPlease fix the above errors and try again."> if validation fails.

=item *

Bails if the environment file fails C<is_valid_env_file> validation (file not found, missing C<genesis.env>, name mismatch, missing kit info).

=item *

Bails if C<kit.subkits> is present (deprecated, use C<kit.features>).

=item *

Bails if C<genesis.use_create_env> has an invalid value.

=item *

Bails if C<bosh-configs> contains unrecognised keys.

=item *

Bails if the Genesis version does not meet the environment or repository minimum.

=item *

Bails if the kit cannot be found.

=item *

Bails with C<"Cannot use the selected kit."> if kit prerequisites fail.

=back

B<Examples:>

    my $env = Genesis::Env->load(
      top  => Genesis::Top->new('.'),
      name => 'us-east-1-sandbox',
    );
    print $env->kit->id;
    # prints my-kit/1.2.3

=head2 exists

    my $bool = $env->exists;
    my $bool = Genesis::Env->exists(name => $name, top => $top);

Returns true (C<1>) if the environment exists on-disk and passes validation,
false otherwise.

When called as an instance method (C<$env->exists>), checks whether the
environment's YAML file exists.  When called as a class method
(C<Genesis::Env->exists(name =E<gt> ..., top =E<gt> ...)>), delegates to
C<is_valid_env_file> in scalar context.

B<Parameters:>

=over 4

=item B<%args>

When called as a class method, requires C<name> and C<top> keys.
When called as an instance method, no arguments are needed.

=back

B<Returns:> boolean.

B<Errors:>

=over 4

=item *

Calls C<bug("%s::exists called without name and/or top named arguments", __PACKAGE__)> if called as a class method without the required arguments.

=back

B<Examples:>

    if (Genesis::Env->exists(name => 'us-east-1-sandbox', top => $top)) {
      my $env = Genesis::Env->load(name => 'us-east-1-sandbox', top => $top);
    }
    # prints 1 if exists

=head2 create(%opts)

    my $env = Genesis::Env->create(%opts);

Create a new Env object by running the user through the wizardly setup of
the C<hooks/new> kit hook.  This often cannot be run unattended and
definitely cannot be run without access to the Genesis Vault.

If the named environment already exists on-disk, C<create> throws an error
and dies.  After the C<new> hook runs, C<create> reloads the environment
using C<load> and then calls C<add_secrets>.  If secrets generation fails,
the environment file is removed and C<undef> is returned.

C<create> recognizes the following options, in addition to those recognized
by and required by C<new>:

=over 4

=item B<kit> (required)

A C<Genesis::Kit> object for provisioning this environment.

=item B<vault>

A vault target alias or descriptor URL.

=item B<create-env>

Boolean.  Force or prevent use of C<bosh create-env> deployment method.

=item B<secrets_mount>

The Vault mount point for secrets (default: C</secrets/>).

=item B<exodus_mount>

The Vault mount point for exodus data (default: C<$secrets_mount/exodus>).

=item B<ci_mount>

The Vault mount point for CI secrets (default: C<$secrets_mount/ci>).

=item B<secrets_path>

Override the path under C<secrets_mount> for environment secrets.

=item B<root_ca_path>

Path to a common root CA for signing otherwise self-signed certificates.

=item B<credhub_env>

Environment that provides the CredHub login credentials.

=back

B<Returns:> a C<Genesis::Env> object on success, or C<undef> if secrets
generation fails.

B<Errors:>

=over 4

=item *

Calls C<bug("No '$_' specified in call to Genesis::Env->create!!")> if C<name>, C<top>, or C<kit> is missing.

=item *

Dies with C<"Environment file $env->{file} already exists.\n"> if the environment file already exists.

=item *

Bails with C<"Cannot find a vault target with alias '$opts{vault}'"> if the vault alias cannot be resolved.

=item *

Bails with C<"No vault specified or configured."> if no vault is available.

=item *

Bails with C<"Cannot continue with existing secrets for this environment"> if existing secrets cannot be removed.

=item *

Bails with C<"Could not move existing ... to ...: ..."> when an existing environment file cannot be moved aside.

=item *

Bails with C<"Cannot specify a bosh environment for environments that use create-env deployment method."> when a BOSH environment is named for a create-env deployment.

=item *

Bails with C<< "Kit ... requires use of create-env, but --no-create-env option was specified" >>, C<< "Kit ... cannot use create-env, but --create-env option was specified" >>, or C<< "Kit ... does not support the --[no-]create-env option" >> when the requested create-env mode conflicts with what the kit supports.

=item *

Bails with C<"Kit %s is not supported in Genesis %s (no hooks/new script).  Check for a newer version of this kit."> if the kit lacks the C<new> hook.

=back

B<Examples:>

    my $env = Genesis::Env->create(
      top  => $top,
      name => 'us-east-1-sandbox',
      kit  => $top->local_kit_version('bosh', 'latest'),
    );
    # Returns undef if secrets generation fails; Genesis::Env otherwise

=head2 bare

    my $env = Genesis::Env->bare($name, $top);

Build an environment with no deployment behind it.

This is the constructor every C<genesis.pipeline.*> read goes through.  It
performs the name check and the file-existence check and nothing else, and
the object it returns resolves its ancestral hierarchy through
L<lookup|/"lookup($key, [$default])">, with no kit loaded, nothing
connected, and no full C<load> paid for a configuration read.

Use it whenever you want a configuration value rather than a deployment.
Reading the leaf environment file directly is the mistake it exists to
prevent, because most pipeline settings are shared across a foundation and
live high in the hierarchy, so a leaf-only read finds them absent, silently,
and answers wrongly with no error.

Each bare environment gets a scratch directory of its own, rather than the
process-wide one L<new|/"new(%opts)"> takes, because the merged manifest
cached there is named for the environment and its signature and that
signature covers the leaf file alone.  Two reads of one environment whose
ancestors differ would otherwise share an answer.  That directory is
allocated here rather than in L</_bare_with_errors>, so a validation that
never reads through the environment never pays for one.

B<Parameters:> The environment's name, as a string, with or without its
C<.yml> suffix, and the C<Genesis::Top> it belongs to.

B<Returns:> A C<Genesis::Env>.  Bails when the name is invalid or the file is
absent.

B<Errors:>

=over 4

=item *

Calls C<bug("No 'top' specified when checking an environment name and
file!!")> if C<$top> is not provided. The message names the check rather than
either caller, because L</bare> and L</is_valid_env_file> both reach it.

=item *

Calls C<bail> with the name or file-existence error where either check fails.

=back

B<Examples:>

    my $cron = Genesis::Env->bare('qa', $top)
        ->lookup('genesis.pipeline.redeploy_cron');
    # returns the site file's value when the leaf does not set it

=head1 CLASS FUNCTIONS

=head2 from_envvars

    my $env = Genesis::Env->from_envvars($top);

Builds a pseudo-environment object from the current process's environment
variables.  This is only valid during a C<new> kit hook callback, where
Genesis populates the process environment with serialized environment state.

B<Parameters:>

=over 4

=item B<$top>

A C<Genesis::Top> object for the deployment repository.

=back

B<Returns:> a C<Genesis::Env> object populated from environment variables
rather than YAML files.

B<Errors:>

=over 4

=item *

Bails with C<"Can only assemble environment from environment variables in a kit hook callback"> if called outside a C<new> hook callback.

=item *

Calls C<bug("No 'GENESIS_$_' found in enviornmental variables - cannot assemble environemnt!!")> if C<GENESIS_ENVIRONMENT>, C<GENESIS_KIT_NAME>, C<GENESIS_KIT_VERSION>, or C<GENESIS_ENVIRONMENT_PARAMS> is missing.

=item *

Bails with C<"Unable to locate ... kit for ... environment."> when the kit named by the environment variables cannot be found.

=item *

Bails with C<<< "Environment `...` requires Genesis v... or higher." >>> when the environment declares a minimum Genesis version newer than the running one.

=item *

Bails with C<< "Kit #M{...} is not compatible with #C{secrets_mount} feature" >> or the corresponding C<exodus_mount> message when the kit predates the mount feature the environment uses.

=item *

Bails with C<"No vault specified or configured."> when no Vault target is available.

=back

B<Examples:>

    # Inside a hooks/new script called by Genesis:
    my $env = Genesis::Env->from_envvars($top);
    print $env->name;
    # prints us-east-1-sandbox

=head2 is_valid_env_file

    # List context: (1) on success or (undef, @errors) on failure
    my ($ok, @errors) = Genesis::Env->is_valid_env_file($name, $top);

    # Scalar context: truthy on success, falsy on failure
    my $ok = Genesis::Env->is_valid_env_file($name, $top);

Validates an environment file without fully instantiating a C<Genesis::Env>
object.  Results are cached by absolute file path.

Checks performed in order: name validity, file existence, presence of a
single matching C<genesis.env> declaration, and kit name/version availability
in the file hierarchy.

The first two of those live on L</_bare_with_errors>, which is the same pair
of checks L</bare> runs, so the two readers agree on what makes a name and a
file acceptable and neither carries a copy of those checks.  The environment
it hands back is the one this sub walks the ancestors on.

B<Parameters:>

=over 4

=item B<$name>

The environment name (C<.yml> suffix is stripped automatically).

=item B<$top>

A C<Genesis::Top> object identifying the deployment root.

=back

B<Returns:> In list context, C<(1)> on success or C<(undef, @errors)> on
failure.  In scalar context, truthy on success or C<undef> on failure.

B<Errors:>

=over 4

=item *

Calls C<bug("No 'top' specified in call to is_valid_env_file!!")> if C<$top> is not provided.

=back

B<Examples:>

    my ($ok, @errs) = Genesis::Env->is_valid_env_file('us-east-1-sandbox', $top);
    if (!$ok) {
      print "Invalid: $_\n" for @errs;
    }
    # prints (no output when environment is valid)

=head2 search_for_env_file

    my ($deployment_root, $file_path) =
      Genesis::Env->search_for_env_file($env_pattern, $deployment_type);

Searches for an environment YAML file matching C<$env_pattern> across known
deployment roots (current directory, parent directory, and roots configured
in C<.genesis/config>).

B<Parameters:>

=over 4

=item B<$env>

The environment name or glob pattern.  C<^> and C<$> anchors are stripped
and the value is wrapped in C<*> wildcards.  Pass C<'*'> to match all.

=item B<$deployment>

Optional deployment type to restrict the search.  When omitted, only C<bosh>
and C<bosh-deployments> directories are searched.

=back

B<Returns:> a two-element list C<($deployment_root, $file_path)>.  If
multiple files match and a terminal is available, prompts the user to choose.

B<Errors:>

=over 4

=item *

Bails with C<"No environment files found matching #C{%s}"> if no files match.

=item *

Bails with C<"Ambiguous environment name: #C{%s} matches multiple files:\n  - %s\n\nPlease refine your match criteria."> if multiple files match and no terminal is available.

=item *

Bails with C<"No environment file selected."> if the user cancels the interactive prompt.

=back

B<Examples:>

    my ($root, $file) =
      Genesis::Env->search_for_env_file('us-east-1-sandbox', 'bosh');
    # Returns: ('/path/to/bosh-deployments', '/path/to/bosh-deployments/us-east-1-sandbox.yml')

=head2 type

    my $type = $env->type;

Returns the deployment type for this environment (e.g. C<bosh>,

B<Returns:> string.

=head2 path

    my $abs = $env->path;
    my $abs = $env->path($relative);

Returns the absolute path to the deployment repository root directory.
If C<$relative> is given, it is appended to the root path.
Delegates to C<< $env->top->path >>.

B<Returns:> string (absolute filesystem path).

B<Examples:>

    print $env->path;
    # prints /home/user/deployments/bosh

    print $env->path('us-west-1-preprod.yml');

=head2 signature

    my $sig = $env->signature;

Returns a unique 12-character hexadecimal identifier for this environment,
derived from a SHA-1 hash of the environment name, type, file path, and
file contents.  The result is memoized.

B<Returns:> string (12 hex characters).

B<Examples:>

    print $env->signature;
    # prints a1b2c3d4e5f6

=head2 deployment_name

    my $dep = $env->deployment_name;

Returns the BOSH deployment name for this environment, constructed as
C<E<lt>env-nameE<gt>-E<lt>typeE<gt>> (e.g. C<us-west-1-preprod-bosh>).
The result is memoized.

B<Returns:> string.

B<Examples:>

    print $env->deployment_name;
    # prints us-west-1-preprod-bosh

=head2 deployment_slug

    my $slug = $env->deployment_slug;

The deployment slug for this environment, which is C<< <env>/<type> >>.

The thin object form of C<Genesis::Top::deployment_slug_for>, so the slug is
composed in one place. The deployment branch, the vault path under the exodus
mount, and the BOSH deployment name are three renderings of it, and composing
any of them separately is how they drift apart.

B<Parameters:> None.

B<Returns:> The slug, as a string.

B<Examples:>

    print $env->deployment_slug;
    # prints us-west-1-preprod/bosh

=head2 manifest_store

    my $store = $env->manifest_store;

Returns the manifest storage strategy for this environment: C<'exodus'>,
C<'hybrid'>, or C<'repository'>.  A repository that names no store reads
C<'exodus'>, which is what a freshly created one is written with.
Environments that do not specify a C<genesis.minimum_version> of 3.1.0 or
higher always return C<'repository'> because older Genesis versions cannot
update exodus deployment audit data.

B<Returns:> string (C<'exodus'>, C<'hybrid'>, or C<'repository'>).

B<Examples:>

    print $env->manifest_store;
    # prints exodus

=head2 effective_minimum_version

    my $version = $env->effective_minimum_version;

Returns the higher of the environment's declared minimum
(C<genesis.min_version> / C<genesis.minimum_version>) and the repository's
(C<minimum_version> in the repo config), with any leading C<v> stripped.

Feature gates consult this single floor rather than either value alone, so a
low environment minimum cannot artificially disable kit features that the
higher repository minimum already guarantees, and vice versa.

The result is memoized.

B<Returns:> A version string; C<'0.0.0'> when neither side declares one.

B<Examples:>

    print $env->effective_minimum_version;
    # prints 3.2.0

=head2 effective_minimum_version_source

    my $source = $env->effective_minimum_version_source;

Returns which side contributed L</effective_minimum_version>: C<'environment'>
or C<'repository'>.

The result is memoized.

B<Returns:> C<'environment'>, C<'repository'>, or C<undef> when neither side
declares a minimum.

B<Examples:>

    print $env->effective_minimum_version_source;
    # prints repository

B<Limitations:> When both sides declare the same version the tie resolves to
C<'repository'>, on the grounds that it is the broader scope.  The value is
therefore not sufficient to tell whether the environment also declared a
minimum -- only which one is being enforced.

=head2 deployment_state

    my $state = $env->deployment_state;

Returns the current deployment state of this environment.  Deprecated --
use C<< $env->deployments->current_state >> instead.

B<Returns:> string (e.g. C<'deployed'>, C<'undeployed'>, C<'terminated'>).

B<Examples:>

    print $env->deployment_state;
    # prints deployed

=head2 is_bosh_director

    my $bool = $env->is_bosh_director;

Returns true if the kit used by this environment provides the C<director>

B<Returns:> boolean.

B<Examples:>

    print $env->is_bosh_director ? 'yes' : 'no';

=head2 use_create_env

    my $bool = $env->use_create_env;

Returns true if this environment must be deployed via C<bosh create-env>
rather than C<bosh deploy>.  While memoization is in progress (circular

B<Returns:> C<1>, C<0>, or C<'unknown'> during circular evaluation.

B<Examples:>

    if ($env->use_create_env) {
      print "uses bosh create-env\n";

=head2 can_build_cloud_configs

    my $bool = $env->can_build_cloud_configs;

Returns true if this environment supports building cloud configs (requires

not set to false).

B<Returns:> boolean.

B<Examples:>

    print $env->can_build_cloud_configs ? 'yes' : 'no';
    # prints yes

=head2 minimum_genesis_version

    my $version = $env->minimum_genesis_version;

Returns the effective minimum Genesis version required by this environment,
determined by comparing the environment's C<genesis.min_version> parameter
against the repository's configured minimum.  Returns C<'0.0.0'> if no
minimum is specified.  The result is memoized.

B<Returns:> version string (e.g. C<'2.8.0'>).

B<Examples:>

    print $env->minimum_genesis_version;
    # prints 2.8.0

=head2 feature_compatibility

    my $bool = $env->feature_compatibility($version);

Returns true if the effective minimum Genesis version for this environment
meets or exceeds C<$version>.

B<Parameters:>

=over 4

=item B<$version>

A version string to test against (e.g. C<'3.0.0'>).

=back

B<Returns:> boolean.

B<Examples:>

    if ($env->feature_compatibility('3.0.0')) {
      print "supports 3.0.0 features\n";

    # prints supports 3.0.0 features

=head2 validate_genesis_version_requirements

    my $result = $env->validate_genesis_version_requirements;

Checks the environment's declared minimum Genesis version against the

hashref with keys: C<errors>, C<warnings>, C<effective_minimum>,

B<Returns:> hashref.

B<Examples:>

    my $r = $env->validate_genesis_version_requirements;
    print $r->{effective_minimum};
    # prints 2.8.0

=head2 get_call_path

    my $cmd    = $env->get_call_path_with_env;

Returns a string (in scalar context) or two-element list (in list context)

=head2 workpath($relative)

=head2 instance_group_azs

    my @azs = $env->instance_group_azs;

Returns the sorted, deduped list of AZ names appearing across every
C<instance_groups[].azs> list in the environment's merged manifest.  Returns
an empty list when there are no instance groups, or when none of them declare
any AZs.  Non-hash entries in C<instance_groups> are filtered; groups with a
missing or empty C<azs:> key are skipped.

B<Returns:> list of strings (sorted, unique).

B<Bails> when any AZ value is an unresolved spruce operator -- that is, a
whole value matching C<(( ... ))>.  The merged manifest is produced without
C<--skip-eval>, so a surviving operator means the fully-evaluated invariant
has been broken and downstream AZ/CPI resolution would run on unreliable
data.  The most common cause is a spruce operator placed inside the C<value:>
block of a go-patch ops document: Genesis merges with
C<spruce merge --multi-doc --go-patch>, and spruce applies go-patch documents
verbatim without evaluating operators inside them, so the marker survives.
An unresolved C<(( grab ))> (missing target) or C<(( vault ))> (vault
unreachable at merge time) arrives by the same route.

Filtering the marker instead of bailing would be actively harmful: an
unconsumed C<(( replace ))> means the AZ entries it was meant to drop are
still present alongside the intended replacement, so silently removing the
marker leaves corrupted data behind and destroys the evidence.

B<Errors:>

=over 4

=item *

Bails with C<< "Unresolved spruce operator(s) in #C{instance_groups.*.azs}: ..." >> when an AZ value still contains an unevaluated spruce operator.

=back

B<Examples:>

    my @azs = $env->instance_group_azs;
    # returns ('z1', 'z2', 'z3')

B<Limitations:>

=over

=item *

The guard anchors on the whole value, so a partially-interpolated AZ name
such as C<"z1-(( grab x ))"> is not detected.  Spruce operators are
whole-value by design, so this is not expected in practice.

=item *

The bail names the offending value and the anti-pattern, but cannot identify
I<which> ops file introduced it -- the merged manifest carries no provenance.
Callers must trace it back through the blueprint's merge order.

=back

=head2 dependency_set

    my ($slugs, $complete) = $env->dependency_set;

The set has two sources and is the union of both. The declared source is
C<genesis.pipeline.track_dependencies>, which kits need because a hook that
calls C<exodus_lookup> never shows up in the manifest. The discovered source
is every exodus path in the unevaluated manifest, which L</vault_paths>
already walks out. The deployment's own path is excluded, and a member that
both sources name is counted once.

returns the declared set alone, and returns false for the second value. It
does not raise, because a job that cannot render cannot deploy either, so
the triggers it is missing are moot until it can. A render failure costs
the discovered half and nothing more, so the declared half survives it, and
C<pipeline-apply> answers an environment it cannot even load the same way,
through L</_declared_dependencies> on a bare environment.

B<Returns:> A list of two. The first is an arrayref of sorted deployment
slugs, and the second is true where the manifest was read and false where it
could not be.

B<Errors:> None. The one thing here that can fail is the render, and that
failure is reported as a warning and answered with the declared set rather
than raised.

B<Examples:>

    # returns (['lab/bosh', 'qa/vault'], 1)

    my ($slugs, $complete) = $env->dependency_set;
    # where the blueprint will not render, warns and
    # returns (['qa/vault'], 0)

=head2 pipeline_record

    my $record = $env->pipeline_record;
    my $record = $env->pipeline_record(%fields);

Reads or writes this environment's compiled dependency set and the mark
saying whether discovery finished.

Called with no arguments it reads what C<pipeline-apply> last wrote. An
absent subpath reads as C<undef>, and that C<undef> is the membership test,
because an environment the applied record does not know is one with no
pipeline subpath, so the walk asks about the environment it holds rather
than searching a roster.

Called with a field list it writes those fields instead and gives back what
it wrote, which is how C<pipeline-apply> records what it compiled. The set
goes in as one comma-joined value, because an exodus record is flat, and a
reader that splits one string is simpler than one that reassembles indices.

Both halves go through this environment's own vault, which is the vault
L</pipeline_record_path> addresses and the one every other exodus read in
this module goes through. An environment that names its own
C<genesis.vault> keeps its record where the repository's vault cannot see
it, so reading through the repository's vault would answer C<undef> and
drop that environment out of the walk with nothing said.

B<Parameters:>

=over 4

=item B<dependencies> (optional)

An arrayref of deployment slugs, which is joined on commas on its way into
the record. An absent or empty list writes an empty value, which reads back
as an empty set.

=item B<discovery> (optional)

C<complete> or C<incomplete>, saying whether the manifest was read. It
defaults to C<complete>.

=back

Passing neither reads rather than writes.

B<Returns:> A hashref of C<dependencies>, an arrayref of deployment slugs,
and C<discovery>, which is C<complete> or C<incomplete> and defaults to
C<complete>. A read of an absent subpath answers C<undef>, and a write
answers the fields it wrote.

B<Errors:> Whatever the vault raises on the write, which is a failed
authentication or a failed write.

B<Examples:>

    my $record = $env->pipeline_record;
    # returns {dependencies => ['lab/bosh'], discovery => 'complete'}

    my $record = $env->pipeline_record(
      dependencies => ['lab/bosh'],
      discovery    => 'incomplete');
    # writes /secret/exodus/us-west-1-preprod/bosh/pipeline and
    # returns {dependencies => ['lab/bosh'], discovery => 'incomplete'}

=head2 hold_record

    my $hold = $env->hold_record;

The propagation hold standing against this environment, or C<undef> when
there is none.

A hold is a decision somebody made for a reason the pipeline cannot see, and
under D50 the C<propagate> walk honours it: while it stands the run delivers
nothing new to this environment and opens or updates no pull request, while
everything already on the deployment branch stays deployable, because the
hold is a fact about the walk rather than about the branch. Only a person
clears it.

C<set_hold> writes the record and C<clear_hold> deletes it, and
C<pipeline-hold> and C<pipeline-release> are the two commands that call
them, while the walk has to honour the record from the day it can exist.

The read goes through this environment's own vault, for the reason
L</pipeline_record> reads through it. Whether the path exists is asked
before it is read, because a vault answers an absent path and an empty one
alike and a hold whose fields are all blank is still a hold.

The vault is asked for outright, the way L</pipeline_record> asks for it,
and not behind a guard that answers no hold where there is no vault. The
walk delivers on this answer, so an environment whose vault this run could
not reach has to end that environment rather than read as unheld.

B<Parameters:> None.

B<Returns:> A hashref of C<reason>, C<user>, C<hostname>, and C<at>, and
nothing else, or C<undef> where the path is absent.

B<Errors:> Whatever the vault raises on the read.

B<Examples:>

    my $hold = $env->hold_record;
    # returns {reason => 'waiting on the DBA', user => 'jrhunt',
    #          hostname => 'bastion', at => '2026-09-16 11:04:22 -0400'}

deploy stood on, and C<git.control_commit> is the certified commit, the

and no record carries a C<dated> field at all.

uses too, so this is a name for four fields rather than a second read of the
set. A vault this environment cannot reach answers C<undef> here rather than
raising, because the one caller is the branch-class gate and a gate that
bailed would refuse a command over a question the command is about to answer
in its own words.

=head2 warn_uncertified_secrets_target

    my $warned = $env->warn_uncertified_secrets_target($served, $git);

Warns when the secrets a run served are for a control commit other than the
one the environment is certified at, naming what a redeploy would then do, and
returns true when it warned. It says served rather than written because two of
the four commands that ask it write nothing, C<check-secrets> validating and
C<remove-secrets> removing, and because the call sits above each command's own
error bail, so a run that wrote nothing still reaches it. One vault holds the
secrets for both the version an environment is running and the version it is
about to run, so a rotation against the branch tip can leave the running
version unable to consume its own credentials. C<$served> is the deployment-branch commit the run served, or
C<undef> for the branch tip, and the control commit compared is the one that
commit's own marker names, never the deployed commit itself. This reports and
blocks nothing; the hold that would close it belongs to a later release.

The two commits compared are both control commits. The version served is a
deployment-branch commit, and L<Genesis::CI::Marker/newest> answers the
control commit its newest marker names, which is then weighed against
C<git.control_commit> from L</deployed_record>. A deployed commit is never
weighed against a certified one, because the two are different kinds and a
comparison of them would warn on every environment ever deployed.

An environment that has never deployed successfully, one whose record names no
certified commit, and one whose served version carries no marker at all each
answer false and say nothing, because none of them has the pair the warning is
about.

B<Parameters:>

=over 4

=item C<$served>

The deployment-branch commit this run served, or C<undef> where it served the
branch tip, in which case the environment's deployment branch is read instead.

=item C<$git>

The repository's git handle, which the marker reader walks.

=back

B<Returns:> true when it warned, and false when it found nothing to warn
about.

B<Examples:>

    $env->warn_uncertified_secrets_target(undef, $git);
    # returns 1, having warned that the secrets this run served are for the
    # control commit the branch tip carries rather than the certified one

    $env->warn_uncertified_secrets_target($deployed, $git);
    # returns 0, the version served being the one the environment is
    # certified at

=head2 prefetch_configs

toward a deployable manifest (blueprint, check, manifest, pre-deploy,
post-deploy).  Drives what gets downloaded and displayed, never what gets
gated on.

implicitly later inside the CPI checks.  C<download_configs> treats cpi as

every deploy against such a director.

=head2 config_file

    my $path = $env->config_file($type, $name);

Returns the path of the registered config file for the given type and
optional name, or an empty string if none is registered.

B<Parameters:>

=over 4

=item B<$type>

Config type.

=item B<$name>

Optional config name.

=back

B<Returns:> string (path or empty string).

The path is looked up in two places, in order: the overlay a prior caller
registered through L</use_config> -- normally via L</download_configs> -- and
then C<GENESIS_E<lt>TYPEE<gt>_CONFIG[_NAME]> in the environment, which an
enclosing C<< genesis -> shell >> call sets.

B<Examples:>

    print $env->config_file('cloud') || 'none';
    # prints /tmp/cloud.yml

B<Limitations:>

The empty-string return is a fragile contract, and L</has_config> and
L</config_contents> delegate here and inherit it.

When neither lookup finds anything the method returns C<''> rather than
signalling that nothing was registered.  A caller reading that as "no config"
degrades silently; one that feeds it to a spruce merge -- L</_cc_yaml_files>
does -- fails at merge time with a file-not-found error that points at the
merge rather than at the missing download.

This is latent rather than live: L</download_configs> always calls
L</use_config> on success, so every current path into C<config_file> has
populated the overlay first.  Two ways out if it ever bites: bail when neither
the overlay nor the environment has anything, which needs a config-file getter
on the director so its cache can be consulted first; or quietly fall back to
that cache as a third layer, which is lower friction but hides the
missing-download bug class entirely.

=head2 propagation_files

    my @paths = $env->propagation_files();
    my @paths = $env->propagation_files(triggering => 1);

Returns the git-root-relative paths this environment depends on, which is its
propagation set, and which is the pathspec that pipeline propagation and
pruning operate over.

The set has eight kinds of path, and they are the environment file hierarchy,
the kit source as either a compiled tarball or C<dev/>, the repository-side
fragments the kit's blueprint draws on, C<kit-overrides.yml>, the reaction
scripts under C<bin/>, C<.genesis/config>, the paths
C<genesis.pipeline.track_additional_files> names, and the embedded genesis at
C<.genesis/bin/genesis>.

They divide in two.  A triggering path is one whose change means deploy me.  A
non-triggering path has to be current on the deployment branch without its
change meaning deploy me, and those are C<.genesis/config>, since nothing in
it reaches the manifest, and the reaction scripts, since a changed script
takes effect at the next deploy whenever that comes.  The pipeline overrides
file and C<.genesis/manifests> are in neither subset and in no part of the
set, the first being compiler input read on control and the second existing
only where a deploy wrote it.

B<Parameters:>

=over 4

=item C<triggering>

Optional.  1 asks for the triggering subset and 0 asks for the non-triggering
one.  Omit it for the whole set, and passing it undefined asks for the whole
set too, so a caller that builds its arguments and means everything gets
everything rather than half of it.

=back

B<Returns:> A list of git-root-relative paths, sorted.

B<Limitations:> Already git-root-relative -- callers must B<not> apply
C<< Service::Git->prefixed >> on top, which would double the prefix.

B<Examples:>

    my @paths = $env->propagation_files(triggering => 1);
    # returns the paths whose change routes a commit to this environment

=head2 propagation_files_at

  my @paths = $env->propagation_files_at($commit);
  my @paths = $env->propagation_files_at($commit, git => $git);
  my @paths = $env->propagation_files_at($commit, triggering => 1);

The propagation set as it stood at a control commit, as git-root-relative
paths, whole or in either half of the triggering split.

A delivery mirrors the set read from the tree at the commit being delivered,
and not from the working tree.  The difference shows when a repository
restructures.  A flat repository whose files move under a C<bosh/> deployment
root has a set of C<bosh/**> from that commit onward, and a reader working
from today's configuration would look for that prefix at commits where
nothing lives there.  This method finds the deployment root by its own config
at the commit, writes that root out whole into a scratch tree, and answers
with the paths the commit holds.

Every kind that asks whether a path exists asks the commit's own listing.  A
glob in C<genesis.pipeline.track_additional_files> expands against that
listing, and the kit source is the archive the commit holds, which for a
version of C<latest> or no version at all is the newest one there.

The blueprint's repository-side fragments are enumerated over the scratch
tree, through L</_blueprint_fragments>, and checked against the same
listing.  They cannot be read out of the caller's own working tree, because
the writer reads its set while the session stands on the deployment branch,
where the kit the blueprint belongs to is not.  The hook that names them
wants a vault, so the caller's vault stands in for the length of the read.

Nothing is answered out of the working tree.  It reads through an
environment built by L</bare>, so it wants no loaded kit and asks for none,
and it leaves the process environment as it found it.

The root is written out with C<git archive>, which costs one extraction for
each commit a walk reads, and which is what carries a kit's own bytes and
modes into a tree the blueprint hook can be run against.

B<Parameters:>

=over 4

=item C<$commit>

The control commit whose tree the set is read from.

=item C<git>

An optional C<Service::Git> handle to read through.  One is built on the
current directory where the caller names none.

=item C<triggering>

Optional, and read exactly as L</propagation_files> reads it.  1 asks for the
triggering subset and 0 asks for the non-triggering one.  Omit it for the
whole set, and passing it undefined asks for the whole set too.

=back

B<Returns:> The set's git-root-relative paths, sorted, or the empty list
where this deployment had no root at that commit, or where the commit carries
no environment file of this name.  A commit that has a root and an
environment file but no kit is refused rather than answered short, since
every short answer here ends in the mirror deleting.

B<Errors:>

=over 4

=item *

Calls C<bail> through L</_resolve_track_additional_files> where the tracked
list at that commit names a path outside the deployment root.  A list that
escapes the root is refused wherever it is read from.

=item *

Calls C<bail> through L</_deployment_root_at> where the commit holds more
than one deployment root of this type and none of them is the one the
command is standing in.

=item *

C<"... declares the kit ..., which the commit ... does not carry."> -- raised
where the commit holds neither the archive the environment names nor a C<dev/>
directory.  The kit is a kind of the set, and a set read without it would have
the mirror take the kit off the branch.

=item *

C<"Cannot read the propagation set of ... without a vault."> -- raised where
the command holds no vault that can be lent to the scratch tree, naming what
it holds instead.  The blueprint hook reads through a vault, so a set cannot
be named without one.

=item *

Calls C<bail> through C<mkfile_or_fail> where the materialised tree cannot be
written, and through C<< Service::Git->show_file >> where the commit cannot be
read.

=back

B<Examples:>

  my @paths = $env->propagation_files_at($sha, git => $git);
  # returns the paths the tree at $sha holds for this environment,
  # under whatever deployment root that commit put them

  my @paths = $env->propagation_files_at($sha, git => $git, triggering => 1);
  # returns only the paths whose change routes that commit here

=head2 _propagation_file_kinds

=head2 _blueprint_fragments

Returns the manifest fragments the kit's blueprint draws from the repository,
as deployment-root-relative paths.

The blueprint hook is the authority on which repository-side files the merge
consumes, and it runs against the tree the environment this is called on
stands over, so the working-tree reader names what control holds and the
at-commit reader names what the commit held.  Running the hook needs no BOSH
configs, but it does need a reachable vault, which propagation establishes
before it gets here.  Fragments that live inside the kit are left out,
because they already travel in the kit source.

L</propagation_files_at> name the same fragments rather than keeping two
lists that can drift apart.  The paths come back deployment-root-relative and
the caller prefixes them, so the prefix is applied exactly once.  Nothing
here asks whether a named fragment exists; the caller checks that against
the tree it is reading.

The environment it is called on decides which tree the hook runs against, so
the at-commit reader calls it on an environment built over the tree it wrote
out of the commit, and the working-tree reader calls it on its own.

An environment carrying no loaded kit is answered all the same, by resolving
the kit its file declares through C<< Genesis::Top->local_kit_version >>, so
an environment built by L</bare> can enumerate.  A declaration that resolves
to no kit answers with no fragments rather than refusing, and the callers
that cannot survive that say so for themselves:
L</propagation_files_at> refuses a commit that carries no kit before it ever
reaches here.

=over 4

=item C<$git>

The C<Service::Git> handle the caller already holds, read by nothing here.
It is a parameter so that this sub builds no handle of its own.

=back

B<Returns:> The fragments' deployment-root-relative paths, sorted and unique,
or the empty list where the environment names a kit this machine does not
hold.

B<Errors:>

=over 4

=item *

Calls C<bail> through C<< Genesis::Kit->source_yaml_files >> where the kit
provides no C<blueprint> hook, or where the hook returns something other than
a list of files.  The hook itself may refuse for reasons of its own.

=back

B<Examples:>

  my @paths = $env->_blueprint_fragments($git);

=head2 _resolve_track_additional_files

    my @paths = Genesis::Env->_resolve_track_additional_files(
        $entries, $env_name, $root
    );
    my @paths = Genesis::Env->_resolve_track_additional_files(
        $entries, $env_name, $root, \@held
    );

Resolves the raw C<genesis.pipeline.track_additional_files> templates into sorted,
unique paths relative to C<$root>.  C<< <env> >> is substituted with the
environment name, glob patterns are expanded against the filesystem beneath
C<$root>, and literal paths pass through verbatim.

An entry counts as a glob where it carries C<*>, C<?>, C<[>, or C<{>. The
brace belongs there because L</_glob_regex> names brace alternation as one
of the three things a glob means, so a pattern whose only glob character
is a brace has to reach the expansion rather than being added under its
own name.

A caller reading a commit hands in the paths that commit holds, and a glob is
then matched on that list rather than on the filesystem, because the tree on
disk is not the tree the set is being read for.

Exposed as a class method so the resolution logic can be exercised without
constructing an environment or touching C<Service::Git>.

B<Parameters:>

=over 4

=item C<$entries>

Arrayref of raw path templates.  A non-arrayref or empty list yields C<()>.

=item C<$env_name>

Environment name substituted for C<< <env> >>.

=item C<$root>

Root the paths resolve against, conceptually the deployment C<Top> root.  An
undefined or empty root yields C<()>.

=item C<$held>

B<(optional)> Arrayref of the paths the caller's tree holds, relative to
C<$root>.  Where it is given, a glob is matched on it through
L</_glob_regex>; where it is absent, a glob is expanded against the
filesystem.

=back

B<Returns:> list of paths relative to C<$root> (sorted, unique).

B<Errors:>

=over 4

=item *

Calls C<bail("genesis.pipeline.track_additional_files escapes the deployment root.")>, naming the offending entry on the line below it, for any entry that is absolute, begins with C<~>, or contains a C<..> segment.  Config errors here surface loudly rather than silently resolving outside the repository.

The same test is applied again to every path an expansion returns, and it
names the entry the operator wrote rather than the result. A character
class spells the two characters of a parent segment without writing them,
so C<.[.]/outside.yml> reads as innocent and expands to a path above the
deployment root. The set is what gets copied between branches, so a
result that escaped would put a file on a deployment branch.

=back

B<Examples:>

    my @paths = Genesis::Env->_resolve_track_additional_files(
        ['ops/<env>.yml'], 'us-east-prod', $root
    );
    # Returns: ('ops/us-east-prod.yml')

=head2 _post_deploy(%opts)

    my $result = $env->_post_deploy(%opts);

Runs after the BOSH deploy has returned. It updates Exodus data, runs the
C<post-deploy> hook, cleans up the deployment cache, and then finishes the
branch session the deploy opened.

The audit record it writes carries a C<flags> string, which is this run's own
options rendered back as a command line. It is the flags the deploy acted on
and not the flags the operator typed, and the two can now differ in one place.
C<--recreate> reaches the string from C<pipeline.recreate_on_deploy> as well
as from the operator, since a repository may ask that some or every deploy
recreate. So a reader auditing a deploy that shows C<--recreate> reads it as
what BOSH was given, and looks to the repository's setting at that commit
before concluding that somebody asked for it by hand.

That is true of both records this method writes. The string is composed once,
above the two arms, by L</_deploy_option_flags($noprompt, $state, $opts)>, so
the record a failed deploy writes names the same options as the record a
successful one writes. It used to take its flags from a C<flags> key of the
options this method was called with, which no caller passes, so a failed
deploy recorded an empty string and a reader auditing the run they had come to
read about learned nothing from it.

It writes nothing to git, because a deploy observes and never commits or
pushes, and the redacted manifest reaches its
C<artifacts/E<lt>envE<gt>/E<lt>typeE<gt>> branch through C<genesis propagate>
rather than through this method.

Finishing the session asserts that the working tree and the index carry no
tracked change and returns the operator to the branch, the head, and the
directory they started on. Untracked files are ignored, so a scratch file
blocks nothing and nothing deletes it. The assertion is made after the kit's
C<post-deploy> hook has run, because that hook is the last thing the deploy
runs and the assertion is about what the whole deploy left behind.

A tracked modification here is a kit hook that wrote into the repository.
This names those files, discards them, restores the branch, and exits
non-zero even though the deploy succeeded, because the environment is running
and the repository is not what Genesis left it. Downstream propagation is
withheld until somebody runs it by hand.

The session comes in as the C<session> option, which is the one the branch
class opened for this command, and a deploy that was given none asserts
nothing. Nothing else on the deploy path finishes it, so no early return in
the command that called this one can skip the assertion, and the branch class
then finds a session already closed, on which its own finish is a no-op. A
dry run is the one path that leaves ahead of the assertion, exiting from this
function before any deployment has been made, and that exit never returns to
the branch class. So a dry run finishes the session itself before it goes,
and it finishes rather than asserts, because a dry run writes nothing and has
nothing to answer for. Without that finish the session would still be open
when the process went, the session's own last-resort net would abort it, and
the net would say so on stderr, because the status a dry run leaves behind is
zero. It takes its deployment cache away before it goes as well, because a run
that wrote nothing should leave nothing, and an operator who asked what a
deploy would do used to meet that cache standing untracked at their next git
status. The exit itself stays, because it is what withholds the propagate
child from a run that deployed nothing.

With C<manifest_store> set to C<repository> or C<hybrid>, rather than the
default of C<exodus>, Genesis puts the rendered manifest under
F<.genesis/manifests/> alongside state and credentials files, and leaves them
in the working tree for the operator to deal with.

Where the store is C<exodus> the copies go the other way, and
L</_remove_repository_manifest_copies> takes them away again, but only
where somebody wrote that store down rather than inherited it from the
schema.

The hand-off to the propagate child is not made here. It waits on the finish
above, so it belongs to the command that called this one, and it is described
under L<Genesis::Commands::Env/_spawn_propagate_child($env)>.

B<Returns:> deployment result. Unaffected by propagation's outcome. A
tracked modification at the finish exits with C<Genesis::Exit::SOFTWARE>
instead of returning.

B<Errors:> a tracked modification at the finish, which exits with
C<Genesis::Exit::SOFTWARE> after naming the files and discarding them, as the
Returns above says. Nothing else is raised here.

B<Examples:>

    my $result = $env->_post_deploy(%opts);
    # returns the deployment result after exodus is recorded

=head2 _remove_repository_manifest_copies

    my $removed = $env->_remove_repository_manifest_copies;

Deletes the environment's rendered manifest, its vars file, and its state
and store files from F<.genesis/manifests/>, and returns how many of the
five were there to delete.

A deploy under the C<repository> or C<hybrid> store leaves those files
behind, and a deploy under the C<exodus> store takes them away again,
because the exodus record holds the manifest instead.

The removal happens only where C<manifest_store> is written down in
F<.genesis/config>, never where the schema supplied C<exodus> as its
default. A repository created before the key existed, or upgraded from a
version 1 configuration, carries no key at all and has been keeping these
copies, and it would otherwise lose them on the first deploy after an
upgrade with nobody having chosen that. The check reads
C<< Genesis::Config::is_set >> rather than C<< get >> or C<< has >>,
because only C<is_set> can tell a written value from a filled default.

Which store is then in force is L</manifest_store>'s answer and not the
raw key's. An environment below the 3.1.0 floor is served out of the
repository however the key is written, because an older Genesis cannot
update the exodus deployment record, and an environment declaring no
minimum version resolves to C<0.0.0> and is one of those. Those copies
are the only manifest such an environment has, and both L</terminate> and
the create-env delete path come back for them, so nothing is removed
there.

B<Returns:> the number of files removed, which is 0 where the store was
not chosen explicitly, where the environment is served from the
repository, or where the files were not there.

B<Examples:>

    my $removed = $env->_remove_repository_manifest_copies;
    # returns 0 for a repository whose .genesis/config names no store

    my $removed = $env->_remove_repository_manifest_copies;
    # returns 0 for an environment that declares no minimum version

    my $removed = $env->_remove_repository_manifest_copies;
    # returns 5 where manifest_store is exodus and all five files existed
