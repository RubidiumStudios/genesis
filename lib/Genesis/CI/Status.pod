=head1 NAME

Genesis::CI::Status - The pipeline-status read model

=head1 SYNOPSIS

  use Genesis::CI::Status;

  my $record = Genesis::CI::Status::status_records($top, git => $git);
  print Genesis::CI::Status::render_json($record);
  print Genesis::CI::Status::render_tree($record);

=head1 DESCRIPTION

Builds the canonical status record for one deployment root and renders it
either as the indented tree or as JSON.  The module computes nothing about
routing itself; it calls the propagation walk and reads the walk's own
per-environment record.  It moves no branch and writes nothing to vault, and
it asks the pre-flight for its branch records read-only, so a branch a run
would have fast-forwarded stands exactly where it stood and a branch in a
state a run would refuse is described here rather than refused.

The refresh it does by default is not nothing, though.  It materialises a
local ref for every pipeline branch the remote already holds and this clone
lacks.  Only control's creation is raised as an event; the rest are made in
silence.  Those refs come from the remote rather than from anything this
module decided, and C<refresh> set false leaves them alone.

The events are handed to the caller rather than printed.  A module that wrote
to a terminal mid-computation would be no use to a caller that wanted the
record alone, so C<on_events> is called with them the moment the control check
answers, which is before the walk runs.  That ordering matters: a walk that
refuses would otherwise end the command with the control ref the refresh
created unaccounted for.  That one channel is the whole of it, and the lines
are not left on the record as well, because the record is the shape D91 fixes
and C<--json> emits it whole.

The one axis the walk leaves to this module is the snapshot, which is what a
deployment branch holds beyond the commit propagation last wrote on it.  One
smaller reading is left here as well, because it is answered off a branch the
walk has already named rather than off anything the walk computes, which is
whether a pending branch's delivered history is its first delivery alone.

A command runs in one deployment root, so there is one record and one
rendering of it.  A repository with a second deployment root is read by
running the command in that root, as every other pipeline command reads one.

The module also declares C<UNVERIFIABLE>, which is the word every cell resting
on a refresh carries where the operator asked for none, and C<%CLASS_MARKUP>
and C<%CLASS_GLYPH>, which map the five classes C<settled>, C<in_flight>,
C<on_ice>, C<wrong>, and C<inert> onto the markup letters and the glyphs
L<Genesis::Term> already has, so the renderer writes no escape sequence of its
own.  C<@CLASS_ORDER> is those classes worst first, which is the order
C<worst_class> reads them in.

=head1 FUNCTIONS

=head2 status_records($top, %opts)

  my $record = Genesis::CI::Status::status_records($top, git => $git);

Returns the canonical record for the deployment root it is handed.  It
refreshes the remote-tracking refs unless told not to, asks the pre-flight for
control and for the branch records, and hands both to the propagation walk, so
this command and C<genesis propagate> read one answer rather than two.  The
event lines the refresh raised are reported on standard error as it goes, and
the record itself is the return value.

It reads GitHub for one thing alone, which is the pull request each
environment whose policy asks for one has open. The client is built by
C<Genesis::CI::PullRequest::client_for_run>, and only where
C<GITHUB_AUTH_TOKEN> is set, because a client built without one warns that the
run's branches are still written and published and this command writes
nothing. What the read answers is carried onto the walk's own records by
C<Genesis::CI::PullRequest::carry_state>, and an environment whose pull
request a reviewer has approved is frozen by
C<Genesis::CI::PullRequest::freeze>, so the report and the propagation run
take that decision from one place. With no token nothing is read, no call is
made, and the pull request column falls back to the environment's proposed
record.

An API that will not answer is reported rather than refused. The read is asked
for through refusal closures that record what happened and return, so the run
warns once on standard error and every environment the client would have
served reads its proposed record flagged as possibly outdated, exactly as it
would with no token at all.

The scope goes to the walk as the pair C<Genesis::CI::Walk::scope_for>
answered, because this command composes it first to learn which pull request
branch to ask about, so the walk composes none of its own and the two cannot
disagree about a branch name. The topology under it is still built more than
once a run, since the pre-flight's environment list asks for it as well, and
nothing memoises it.

The client and that state go into the walk as well, because a deployment
branch whose pull request went in as a squash carries no marker of its own and
the merged pull request is the only thing that still says which control commit
it received. C<genesis propagate> hands the walk the same pair, so a branch
like that reads caught up in both commands rather than reading in this one as
though the whole of control were still due.

The record is one deployment root's, and it is the root the command runs in.
Each root composes its branches from its own deployment slug, so two roots
that share an environment name hold two separate branches, and one root's
marker is never read as the other root's state.  A repository with a second
root is read by running the command in that root, which is how every other
pipeline command reads one.

The walk leaves each environment's C<drifted> cell null for this function to
fill, and it is filled from C<drift_for> off the ref the walk routed that
environment from, so the snapshot the drift is measured against is the one
every other column of the row was read from.  A row that failed to load is
left alone, since there is nothing to compare.

Each row also carries C<seeded>, which is true where the branch's delivered
history is its first delivery alone.  It is an annotation on the
C<pending-deploy> reading rather than a reading of its own, because the seed
is a delivery like any other and only the branch's own history tells it from
the tenth, so a row reading anything else carries it false, and so does a row
that failed to load and a row with no branch to count it over.  It is counted
over the same ref the drift is measured against, and it is asked of a pending
row alone, so every other row costs no git work at all.

An environment with no deployment branch on either side is one
C<genesis pipeline-apply> has not cut a branch for.  The walk closes that row
itself, with the certification state C<no-branch>, so the reading reaches both
this command and C<genesis propagate> and neither has a copy of the wording.
Under C<refresh> false that state rests on remote-tracking refs nobody
refreshed, so the cell is marked and the rendered wait carries
C<[unverifiable]> after it.

The record carries the applied pipeline record at the top with C<stale>,
C<stale_envs>, and C<stale_because> beside it, read through
L<Genesis::Top/pipeline_staleness> so that this command, the deploy
pre-flight, and the propagate pre-flight all ask the same query.
C<stale_because> holds that query's own reasons, which are
C<configuration-changed> and C<dependencies-changed>, and never a path.  The
two lists run in step, so the environment and the reason for it sit at one
index.  All three are null where the staleness was never asked, because this
clone does not hold the commit the pipeline was applied from, and both
renderers read that null as unverifiable rather than as a pipeline that is
not stale.

The record also carries C</unfetchable_markers>' answer under C<breaches>,
which is every environment whose marker names a control commit no ref in this
repository still reaches.

The staleness is asked only where this clone holds the commit the pipeline was
applied from.  The query diffs that commit against control, and git refuses a
diff against an object it does not have, so a clone that never fetched it
would have ended the whole report on that refusal.  Where it is missing the
three fields are left null, which is a reading a boolean cannot carry, and
both renderers say the staleness is unverifiable.

When C<refresh> is false the command reads the remote-tracking refs as they
stand, writes nothing, and marks every value that rests on a refresh with the
constant C<UNVERIFIABLE>.  The record's C<refreshed> is then false, each
environment's divergence state reads C<unverifiable>, the routing summary
carries the word in brackets, the breach line is qualified with it, the two
divergence remedies are withheld because neither can be told from its opposite
against an unrefreshed ref, and the tree prints a header saying the report is
stale.  This is the one escape the refresh invariant names, and it exists on
C<pipeline-status> alone.

B<Parameters:>

=over 4

=item C<$top>

The L<Genesis::Top> for the deployment root the command is running in.

=item C<git>

The L<Service::Git> to read through.  One is built on the current directory
where the caller names none.

=item C<refresh>

False to read the refs as they stand, which is what C<--no-refresh> asks for.
It defaults to true.

=item C<scope>

The environments to read, passed through to the walk.  Undefined reads every
environment the deployment root has.

=item C<on_events>

A code reference called with the control check's event lines as soon as it has
them, which is before the walk runs.  A caller that names none is told nothing
as it goes, because the lines are handed over this one channel and are not
left on the record: the record is the shape D91 fixes, and C<--json> emits it
whole.

=back

B<Returns:> the record, as a hash reference, in the shape
L<Genesis::CI::Walk/plan> answers with.

B<Examples:>

  # The report as the operator asked for it, without a fetch.
  my $record = Genesis::CI::Status::status_records($top,
      git => $git, refresh => 0);
  # $record->{environments}[0]{reading} eq 'deployed'

=head2 drift_for($git, $branch)

  my $drift = Genesis::CI::Status::drift_for($git, 'lab/bosh');

Returns a hash reference of C<files>, every path that differs between the
branch's newest marked commit and its tip, and C<commit>, the newest hand
commit standing above that snapshot.  The two do not have to belong together:
C<files> is the diff across every commit above the marker, so where a branch
carries two hand commits the paths one of them changed are listed beside the
sha of the other.  C<commit> says where the hand edits start, not which commit
made a given change.  Propagation writes a marker on every commit it makes, so the
newest marked commit is the snapshot the branch is certified to hold and
everything above it was put there by a person.  That edit is legal and
temporary, so this is a report rather than a refusal, and it names every file
so the operator sees the whole of it.

The comparison reads git alone and asks nothing of vault.  Asking the
environment for its propagation set would load the kit through a vault this
caller has not connected to, and the branch's own history answers the same
question without one.

This reading is independent of the certification axis, and neither is derived
from the other.  An environment may be C<pending-deploy> and drifted at the
same time, because a branch can carry markers nothing has deployed and a hand
edit above them, and the record says both rather than whichever of the two it
looked at first.

B<Parameters:>

=over 4

=item C<$git>

The L<Service::Git> to read the branch's history and its diff through.

=item C<$branch>

The ref to read, which is the deployment branch or, where the pre-flight held
a move back, the ref a real run would have moved that branch to.

=back

B<Returns:> the drift, as a hash reference, or undef where the branch carries
no marker anywhere, where nothing differs, or where no ref was named.

B<Examples:>

  my $drift = Genesis::CI::Status::drift_for($git, 'lab/bosh');
  # {files => ['ops/shared.yml'], commit => 'e91c0aa...'}

=head2 unfetchable_markers($record, $git)

  my @breaches = Genesis::CI::Status::unfetchable_markers($record, $git);

Returns one hash reference of C<env> and C<control_commit> for each
environment whose newest marker names a control commit no ref in this
repository reaches.  A marker is a bare sha with no ancestry link to the
branch it sits on, because propagation copies files and never commits, so it
means something only while a ref still reaches the commit.  The branch
protection should make that impossible, so a breach that got past it is
reported by name rather than left for the next propagation to trip over.  The
tree prints one red line per breach beneath the table, and the record carries
them under C<breaches>.

The reading is reachability through the remote-tracking refs, through
L<Service::Git/commit_exists>, because the breach is a fact about what the
remote holds.  A commit the remote has dropped stays in this clone as a loose
object until git collects it, and the local branch that wrote it goes on
reaching it, so a reader that asked about either would report no breach in
exactly the clone an operator runs the command in.  The answer is kept per
sha for the length of the call, since one rewrite commonly orphans the marker
of every environment that had deployed it.

An environment that failed to load is skipped rather than asked about, as it
is in the drift fill, because nothing it carries was read.

B<Parameters:>

=over 4

=item C<$record>

The record the walk answered with, whose C<environments> carry the markers.

=item C<$git>

The L<Service::Git> to ask about reachability.

=back

B<Returns:> the breaches, as a list of hash references, which is empty for an
append-only control.

B<Examples:>

  my @breaches = Genesis::CI::Status::unfetchable_markers($record, $git);
  # ({env => 'lab', control_commit => '47de8d3...'})

=head2 render_json($record)

  print Genesis::CI::Status::render_json($record);

Encodes one root's record as JSON in canonical key order, as one object.  A
command runs in one deployment root, so there is one object and never an
array.

B<Parameters:>

=over 4

=item C<$record>

The record C<status_records> answered with.

=back

B<Returns:> the encoded record as a string, ending in a newline.

B<Examples:>

  my $json = Genesis::CI::Status::render_json($record);
  # {"applied":{...},"control":{...},"environments":[...],...}

=head2 render_tree($record, %opts)

  print Genesis::CI::Status::render_tree($record);

Renders one root's record as the header, the column heads, and one line per
environment in DAG order, each indented to its depth and carrying its branch
column, its deploy column, and its composed phrase.  The header names the
pipeline by the label the configuration gives it, and by the deployment type
where a repository names no label.

Beneath the table comes one red line per breach the record carries, because a
marker naming a commit the remote no longer holds is a fact about the
repository rather than a column of one row.  The row the breach names takes
the red class with it, in its glyph and in its name, because that is the worst
thing on the row and an operator scanning glyphs should not read a broken
marker as green.  The class is forced from the record's C<breaches> rather
than composed as a phrase component, since the line beneath the table says the
whole of it already.

Under C<stale> the tree opens with a line saying the report is stale because
no refresh ran, above the column heads, since an operator has to read that
before they read a row.  The same option qualifies each breach line with the
word, because the breach is read entirely off the remote-tracking refs and
unrefreshed a commit propagated an hour ago and never fetched reads exactly
like one the remote has dropped.

B<Parameters:>

=over 4

=item C<$record>

The record C<status_records> answered with.

=item C<stale>

True where nobody refreshed, which marks the cells that rest on a refresh.

=back

B<Returns:> the rendered tree as a string, ending in a newline.

B<Examples:>

  print Genesis::CI::Status::render_tree($record, stale => 1);
  #   lab   6084166  6084166  + deployed
  #     qa  82f6746  6084166  ! awaiting deployment; 1 pending

=head2 compose_phrase($row, %opts)

  my @phrase = Genesis::CI::Status::compose_phrase($row);

Returns one environment's status phrase as a list of class and text pairs, in
the fixed order the design gives, which is the certification word, the seed
annotation where the row carries one, the routing summary, the branch's own
state where no run may start from it, the snapshot flag, the hold, and
C<[manual]>.  The seed reads C<seeded> and stands directly after the
certification word, because it qualifies that word rather than standing beside
it, and it takes the in-flight class the pending reading beside it takes.
Detail belongs in square brackets after the word it qualifies, so a branch
carrying a hand edit reads C<drifted [ops/shared.yml differs: hand commit]>,
and the trailing C<[manual]> is a marker rather than detail, which its own dim
class tells apart.  A branch the remote has never had and one that shares no
ancestor with the remote's each read as what they are with the operator's
remedy in the brackets, because a report that only refused to describe them
would leave the repository unexplained.  An environment that failed to load
carries its error alone, because nothing else the row holds was read.

The pull request component stands between the snapshot flag and the hold, and
it comes from the walk's C<pr> field, which carries the branch
C<Genesis::Top::pr_branch_for> composes, so the branch this column reads and
the branch propagation opens come from one accessor. Where the state has been
read the phrase names the open pull request and what a reviewer made of it, so
it reads C<[PR #42 open: unreviewed]>; a number is only ever taken off the open
listing, so a number on the record is an open pull request. Where the read
found nothing open the component is left out, the rest of the row already
saying what the environment is doing. Where no token was set nothing was read
at all, and the phrase falls back to the environment's proposed record, names
the pull request Genesis itself opened and the control commit it proposed, and
says the review state is unread and possibly outdated.

A held environment carries the word C<held> and then the qualifier the
propagation run records for it, which is one of C<needs clearing> with the
reason, C<awaiting pipeline-apply>, C<awaiting merge> with the number of the
pull request a reviewer has approved, and C<awaiting deployment> with the
environment and the commit, followed by the reason the walk gave the held
commit.  Where an ancestor's undeployed set is what holds that commit, the
reason carries the ancestor's own state as a clause, so the phrase reads the
same words C<genesis propagate --dry-run> prints.  Both come from
C<Genesis::CI::Report>, which owns every word an operator reads about an
outcome, and the word C<held> is written here because this is where the
command decides the outcome.  Every held component takes the on-ice class,
because a hold is something a person set or the topology imposed and nothing
is moving until it is cleared.

Where the standing hold is itself what took the held commit, the phrase
carries the qualifier alone and no commit reason after it, so the row reads
C<held, needs clearing (vsphere maintenance)> and stops there.  The walk
stamps every commit the hold takes with the hold's own text, so the reason
would otherwise print what somebody wrote on the record twice in one line.

A hold somebody set carries one component more, which is
C<Genesis::CI::Report::hold_detail>'s sentence.  It names what the hold is
blocking, who set it as C<< E<lt>userE<gt>@E<lt>hostnameE<gt> >>, when they
set it, and C<genesis E<lt>envE<gt> pipeline-release>, which is what D50 asks
this command to show.  It is read from that module rather than spelled here,
because the run's report and C<genesis E<lt>envE<gt> deploy> print the same
sentence and three commands spelling one sentence are three spellings that
drift apart.  A row held by an ancestor or by a gate carries no such
component, that sub answering nothing where no hold record stands.

An environment whose approved pull request is waiting to be merged carries
both components on one row, and each answers a different question.  The held
qualifier says what the environment is waiting for, which is the merge, and
the pull request component says which pull request that is, so the row reads
C<[PR #42 open: approved]  held, awaiting merge (#42)>.  An operator who saw
only the first would not know the wait had begun, and one who saw only the
second would have to go looking for the number.

A frozen commit is the other shape where the two questions have one answer.
One approved pull request is both what the environment waits for and what
holds every commit standing behind it, so C<Genesis::CI::Report::hold_reason>
answers the merge in the words the qualifier has just used, and the row says
it once.  The two are compared on their words rather than on a second list of
reasons kept in step with that module.  The standing hold above is suppressed
by its reason name instead, because there the two strings differ, so neither
comparison would catch the other's case.

A row whose certification cell is marked carries C<[unverifiable]> after the
wait, so C<held, awaiting pipeline-apply [unverifiable]> is what an
environment with no branch reads under C<--no-refresh>.  The mark is read off
the cell rather than off the C<stale> option, so one place decides it and the
tree and C<--json> cannot come to disagree.

Under C<stale> the routing summary carries C<[unverifiable]> after the count,
because that is the component the refresh decides, and it keeps its own class,
since a component marked wrong would leave C<worst_class> answering wrong for
the whole row.  The two divergence remedies are withheld instead of marked.
Both rest on the remote-tracking refs, and unrefreshed neither can tell a
branch nobody published from one a teammate pushed an hour ago; telling an
operator to delete the second would be worse than telling them nothing.  What
says so is the divergence cell, which carries the word as its state.

B<Parameters:>

=over 4

=item C<$row>

One entry of the record's C<environments> list.

=item C<stale>

True where nobody refreshed, which marks a component resting on a refresh.

=back

B<Returns:> the components, as a list of array references of a class and its
text.

B<Examples:>

  my @phrase = Genesis::CI::Status::compose_phrase($row);
  # ([in_flight => 'awaiting deployment'], [in_flight => '1 pending'])

=head2 worst_class(@components)

  my $class = Genesis::CI::Status::worst_class(@phrase);

Returns the worst class present among a phrase's components, in the order
wrong, on ice, in flight, settled, inert, which is the class the row's glyph
and environment name take.

B<Parameters:>

=over 4

=item C<@components>

The components C<compose_phrase> answered with.

=back

B<Returns:> the class name, and C<inert> where the phrase is empty.

B<Examples:>

  my $class = Genesis::CI::Status::worst_class(
      [settled => 'deployed'], [in_flight => '1 pending']);
  # 'in_flight'

=head1 INTERNAL FUNCTIONS

=head2 _pull_request_state($top, $scope)

  my ($github, $state_of) =
      Genesis::CI::Status::_pull_request_state($top, $scope);

Reads what GitHub says about the pull request of every environment in the
scope whose policy asks for one, and answers the client it built beside that
state keyed by environment name. An environment the hash holds no key for is
one nothing was read about.

The client is built by C<Genesis::CI::PullRequest::client_for_run> and the
state by C<Genesis::CI::PullRequest::pr_state>, so the decision about when a
client is needed at all is the run's own rather than a second one here. The
client is asked for where an environment in scope would deliver into a pull
request and not at all where none would, which is narrower than the rule D57
states, since that rule counts an environment holding a proposed record as
one that needs the API too. C<genesis propagate> narrows it the same way, so
an environment whose policy no longer asks for a pull request reads its
proposed record unvalidated in both commands.

It asks for a client only where C<GITHUB_AUTH_TOKEN> is set. A client built
without one warns that the run's branches are still written and published,
which is false of a command that writes nothing, and a missing token is the
fallback the pull request column is built for rather than something to warn an
operator about.

No refusal the two subs raise ends this command. Both take a closure that
records why the API went unasked and returns, so an API that will not answer,
a repository that resolves no C<owner/repo> pair, and a token GitHub will not
name an owner for each leave the report standing. The run then says once, on
standard error, which of the three it met and what the column is reading
instead, and every environment the client would have served renders as the
no-token case does, reading its proposed record and flagged as possibly
outdated. C<genesis propagate> still refuses on all three, because a run that
is about to write a pull request branch cannot guess what a reviewer decided.

B<Parameters:>

=over 4

=item C<$top>

The deployment root the command runs in.

=item C<$scope>

The scope C<Genesis::CI::Walk::scope_for> composed, whose C<pr_branch> names
the branch the pull request is opened from.

=back

B<Returns:> the client it built and a hashref of environment name to the state
C<pr_state> answered. The client is undefined and the hashref empty where there
is no token, no client, no environment wanting one, or no answer the API would
give.

B<Examples:>

  my ($github, $state_of) =
      Genesis::CI::Status::_pull_request_state($top, $scope);
  # $github is the client the walk recovers a squashed marker with,
  # and $state_of is what the API said about each environment:
  # {qa => {state => 'approved', number => 42, url => '...', superseded => []}}

=head2 _unconsulted($why)

  return Genesis::CI::Status::_unconsulted('GitHub did not answer');

Says on standard error, in one sentence, why the API went unasked and what the
pull request column is therefore reading, and answers what
C<_pull_request_state> answers with no token at all, which is no client and no
state for any environment.

B<Parameters:>

=over 4

=item C<$why>

The clause that opens the sentence, which names what stopped the read. It is
this command's own wording rather than the refusal's, because a refusal is
written for somebody who was about to write a branch.

=back

B<Returns:> the undefined client and the empty hashref, so a caller returns it
as its own answer.

B<Examples:>

  my ($github, $state_of) =
      Genesis::CI::Status::_unconsulted('GitHub did not answer');
  # says on standard error that the column is read from each proposed
  # record, and answers (undef, {})

=head2 _mark_unverifiable($record)

  $record = Genesis::CI::Status::_mark_unverifiable($record);

Marks the values that rest on a refresh nobody ran, which is what C<--no-refresh>
asks for.  It sets C<refreshed> false and writes C<UNVERIFIABLE> into each
environment's divergence state, and it runs last, once everything the record
carries has been filled.

The state is set through the divergence hash rather than by replacing it with
a string, so C<--json> emits one shape for that field whichever form of the
command wrote the record, and an environment that had no divergence at all
gains the same shape with the same word in it.

An environment that failed to load is left alone, as the drift fill and the
breach report leave it, so the three fills agree about such a row.  Nothing
about it was read, and a divergence cell carrying the word would say a reading
had been withheld where none was ever taken.

An environment whose certification state is C<no-branch> also has that cell
marked, under C<unverifiable> beside the state.  The reading is the absence of
a branch record and nothing else, so it rests on the same refs the divergence
cell does, and unrefreshed it cannot tell an environment nobody has applied
from one a teammate applied an hour ago.  The state is left standing rather
than replaced, so the wait is still worded by
L<Genesis::CI::Report/held_qualifier>, and C</compose_phrase> reads the mark
and writes C<[unverifiable]> after the wait.

Nothing else on the record is touched.  A phrase component marked with a class
of the wrong kind would leave C</worst_class> answering wrong for every row, so
the colour an operator reads a stale report by would carry no information at
all.  What the renderers add instead is the stale header, the bracket on the
routing summary, and the qualifier on the breach line.

B<Parameters:>

=over 4

=item C<$record>

The record C</status_records> has finished filling.

=back

B<Returns:> the same record, marked in place.

B<Examples:>

  my $record = Genesis::CI::Status::_mark_unverifiable($record);
  # $record->{environments}[0]{divergence}{state} eq 'unverifiable'

=head2 _seeded($git, $branch)

  my $seeded = Genesis::CI::Status::_seeded($git, $ref);

Answers whether a branch's delivered history is its first delivery alone,
which is the seed of D61.  Nothing about the reading tells a first delivery
apart from a tenth, so the question is put to the branch's own history, which
carries one marked commit and no more where the branch has been delivered to
once.  What bounds the cost is the fifty-commit limit it asks for, since
L<Service::Git/log_subjects> runs git and builds the whole list before the
loop begins.  Returning at the second marked commit saves the iteration below
it and no git work at all.  L<Genesis::CI::Marker> owns the marker's
vocabulary and says which control commits a message names, so nothing here
spells the prefix.

B<Parameters:>

=over 4

=item C<$git>

The L<Service::Git> to walk through.

=item C<$branch>

The ref to walk, which its caller takes from the row the walk routed, so the
history the seed is counted over is the one the reading was read from.  The
fifty newest commits are read, and that is a window of commits rather than of
deliveries.  A branch whose earlier delivery sits further back than the window
and which carries one marked commit inside it reads as the seed, and that
takes about fifty hand commits between two deliveries.

=back

B<Returns:> 1 where the branch carries exactly one marked commit, and 0
otherwise, which includes a branch named as undef or as the empty string.

B<Examples:>

  my $seeded = Genesis::CI::Status::_seeded($git, 'lab/bosh');
  # 1

=head2 _newest_unmarked($git, $branch)

  my ($hand, $snapshot) = Genesis::CI::Status::_newest_unmarked($git, $ref);

Walks a ref newest first and answers the newest commit carrying no propagation
marker together with the first commit below it that carries one.  One walk
answers both, because the pair is what the snapshot comparison needs and two
walks over one history could disagree.  L<Genesis::CI::Marker> owns the
marker's vocabulary and says which control commits a message names, so nothing
here spells the prefix.

B<Parameters:>

=over 4

=item C<$git>

The L<Service::Git> to walk through.

=item C<$branch>

The ref to walk.  The fifty newest commits are read, which is further back
than any branch a run has left unmarked.

=back

B<Returns:> in list context the hand commit and the snapshot, either of which
may be undef; in scalar context the hand commit alone.

B<Examples:>

  my ($hand, $snapshot) =
      Genesis::CI::Status::_newest_unmarked($git, 'lab/bosh');
  # ('e91c0aa...', '7b2d431...')

=head2 _jsonable($value)

  my $plain = Genesis::CI::Status::_jsonable($record);

Copies a structure with every object in it written out as text.  An encoder
handed an object of any kind raises rather than guessing at one, so each is
written as its own string and the encoder's booleans alone go through
untouched.  A deployment's timestamp reaches the record as a L<Time::Piece>,
and it is written in the form vault holds it in, C<EXODUS_TIME_FORMAT>, rather
than in the ctime form L<Time::Piece> stringifies to.  This output is the one
a machine reads, and a consumer comparing a timestamp against the stored
record has to get the same string back, timezone included.

B<Parameters:>

=over 4

=item C<$value>

Any structure of hashes, arrays, and scalars.

=back

B<Returns:> a copy of the structure with no blessed reference left in it.

B<Examples:>

  my $plain = Genesis::CI::Status::_jsonable({at => Time::Piece->new});
  # {at => '2026-09-18 03:48:52 +0000'}

=head2 _applied_line($record)

  my $line = Genesis::CI::Status::_applied_line($record);

Renders the one header line that says which control commit the pipeline was
applied from, and, where the pipeline has gone stale since, names every
changed environment with the reason the staleness query gave for it and the
command that fixes it.  It reads the fields C</status_records> wrote and asks
no question of its own, so the header and C<--json> cannot come to disagree
about whether the pipeline is stale.

Where C<stale> is null rather than false, the staleness was never read,
because this clone does not hold the commit the pipeline was applied from.
The line then reads C<[stale: unverifiable]> with the reason in one clause,
which is the one reading the query cannot be asked for.

B<Parameters:>

=over 4

=item C<$record>

The record C</status_records> answered with.

=back

B<Returns:> the line, or the empty list where the repository has no applied
record and there is nothing to say about one.

B<Examples:>

  my $line = Genesis::CI::Status::_applied_line($record);
  # '  applied at 6084166  [stale: dev configuration-changed]  run genesis pipeline-apply'

=head2 _pull_request_component($row)

  my @component = Genesis::CI::Status::_pull_request_component($row);

Answers the phrase's pull request component for one row, or the empty list
where the row has nothing to say about one.

An environment whose policy asks for no pull request has no such column. The
walk seeds the branch onto every environment that would deliver into one and
leaves the field null for the rest, so that field is the whole of the question,
and the proposed record is read only for an environment the walk says would
have one. A proposed record naming no pull request is one no run has proposed
anything through, and it answers the empty list as well.

The branch it reads is the walk's C<pr> field, which
C<Genesis::Top::pr_branch_for> composes, so the branch this column reads and
the branch propagation opens come from one accessor. The baseline matched a
literal C<propagate/E<lt>envE<gt>/> prefix that propagation has never opened,
which is why an operator was told nothing waited while a pull request sat open
for review.

Where the state has been read the component names the open pull request and
what a reviewer made of it. A number is only ever taken off the open listing,
so a number on the record is an open pull request and C<open> is the truth
about it rather than a second reading. Where the read found nothing open the
component is left out, the rest of the row already saying what the environment
is doing.

Where no token was set nothing was read at all and the environment's proposed
record answers. That record is a pointer to a pull request Genesis itself
opened rather than a cache of somebody else's state, so the component names it
and the control commit it proposed, and says plainly that the review state is
unread and possibly outdated.

B<Parameters:>

=over 4

=item C<$row>

One environment's record, whose C<pr> is the walk's pull request object and
whose C<proposed> is the proposed record the walk read.

=back

B<Returns:> one array reference of a class and its text, or the empty list.

B<Examples:>

  my @component = Genesis::CI::Status::_pull_request_component($row);
  # ([in_flight => '[PR #42 open: approved]'])

=head2 _short($sha)

  my $short = Genesis::CI::Status::_short($sha);

Abbreviates one commit sha to the seven characters every column of this report
prints, so the run's report and this one print one sha at one width.

B<Parameters:>

=over 4

=item C<$sha>

A commit sha, or undefined.

=back

B<Returns:> the first seven characters, or undefined where there was no sha.

B<Examples:>

  my $short = Genesis::CI::Status::_short('6084166abc123');
  # '6084166'
