=head1 NAME

Genesis::CI::Preflight - the initial state a propagation run may find

=head1 SYNOPSIS

  use Genesis::CI::Preflight;

  my @stranded = Genesis::CI::Preflight::local_only_commits($git, 'qa/bosh');

  my $initial = Genesis::CI::Preflight::initial_state($top, $git,
      envs => \@dag_order, refreshed => $result, control => $control_state);

=head1 DESCRIPTION

The first stage of a propagation run settles what the repository holds before
anything is written.  It refreshes, it requires the control branch to exist
and to be in step with the remote, it refuses a deployment branch with no
legitimate origin, it resets a branch whose only local commits are ones a
re-run reproduces, and it fast-forwards a branch that is merely behind.  A
violation is an illegal initial state, so the run stops before it writes and
the refusal names the branch and the way out.

Each refusal spends a named exit code rather than a number.  Control that
exists nowhere is a configuration fault and exits C<CONFIG>, an initial state
the design calls illegal exits C<DATAERR>, and a remote this clone cannot
reach exits C<TEMPFAIL>, which is the one of the three a pipeline job may
retry.

=head1 FUNCTIONS

=head2 local_only_commits($git, $branch)

  my @stranded = Genesis::CI::Preflight::local_only_commits($git, $branch);

Lists the commits the branch holds that no remote has, newest first, as a
hashref each of C<sha>, C<short>, C<subject>, and C<marker>.  C<marker> is the
control commit that commit's propagation marker names, and it is C<undef> for
a hand edit.  That is the whole classification the stage needs: a commit with
a marker is one a re-run reproduces, so the branch can be reset to its
tracking ref, and a commit without one is an operator's hand edit, which
nothing here may discard.

The query runs C<git log E<lt>branchE<gt> --not --remotes>, so what counts as
local-only is decided against the remote-tracking refs this clone holds.  It
must therefore run before any prune, because a prune removes exactly the refs
that answer it and a pruned clone reports every commit on the branch as
stranded.  C<Service::Git::fetch_branches> never prunes, which is what keeps
this query honest across a refresh.

Each commit is classified by asking C<Genesis::CI::Marker::newest> for the
newest marker within a walk of one, so this module carries no second reader
of the marker.

B<Parameters:>

=over 4

=item C<$git>

A C<Service::Git> handle on the repository to read.

=item C<$branch>

The branch to walk, named as git names it.

=back

B<Returns:> A list of hashrefs, newest commit first, empty where the branch
holds nothing a remote lacks.

B<Errors:> Bails when C<git log> fails, which is a branch this repository
cannot read rather than a state the stage reports.

B<Examples:>

  my @stranded = Genesis::CI::Preflight::local_only_commits($git, 'qa/bosh');
  # ( { sha => 'a1b2...', short => 'a1b2c3d',
  #     subject => '[pipeline] control@9f8e7d6 -> qa',
  #     marker  => '9f8e7d6c5b4a...' } )

  Genesis::CI::Preflight::local_only_commits($git, 'prod/bosh');
  # () where every commit on the branch has been pushed

=head2 require_control($top, $git, %opts)

  my $state = Genesis::CI::Preflight::require_control($top, $git,
      refreshed => $result, command => 'propagate');

Settles the control branch before anything else is read.  Control is where the
environment files live, so a run that cannot trust it cannot trust a single
answer it goes on to give, and every command in this stage asks this question
first.

Three things can be true of control, and each has one answer.  Where the
remote has the branch and this clone does not, the refresh has already written
the local ref, and the creation comes back as an event line for the caller to
print rather than passing in silence.  Where the branch exists nowhere, the
command refuses, and it creates nothing, because cutting the branch that
becomes the repository's source of truth is the operator's act and not
Genesis'.  Where both places have it, the two have to agree, because an
unpushed control holds commits a deploy on another machine cannot read, since
a propagation marker names a control commit by its sha alone, and because a
stale control would propagate state a teammate has already moved past.
Genesis never moves control in either direction, so both are refusals rather
than repairs.

B<Parameters:>

=over 4

=item C<$top>

A C<Genesis::Top> on the repository, which is asked for the control branch's
name.

=item C<$git>

A C<Service::Git> handle on the same repository.

=item C<refreshed>

The result the refresh returned, whose C<created> list is what the event line
is composed from.  A caller that did not refresh leaves it out.

=item C<command>

The command's name, which the refusal's opening sentence is built from, as in
"Refusing to run C<genesis propagate>".

=item C<action>

The whole act, for a command that names itself in its own words rather than by
its invocation.  The deploy passes C<deploy>, so its refusal opens "Refusing
to deploy".

=item C<outcome>

The refusal's closing sentence, which says what did not happen.  It is
"Nothing was written." unless the caller says otherwise.

=item C<unverifiable>

Passed through to C<resolve_branch> for a caller that read without refreshing,
so the divergence it gets back says so.

=item C<on_divergence>

C<refuse> by default, and C<report> for the two commands that read without
resolving, which are C<genesis pipeline-status> and the deploy.  Every command
that writes takes the default, because a divergence on control reaches the
remote through whatever it writes.  A branch that exists nowhere is refused
either way, since it leaves the command nothing at all to read.

=back

B<Returns:> A hashref of C<divergence>, the record C<resolve_branch> gives for
control, and C<events>, the lines the caller prints.  C<events> holds one line
where the refresh created the local ref, which reads "created control from
origin/control", and is empty otherwise.

B<Errors:> Bails at C<CONFIG> when the control branch exists neither on the
remote nor locally, naming the branch and both places and telling the operator
to create and push it.  Bails at C<DATAERR> for every one of the five states
the design calls illegal, which are ahead, behind, diverged, local only, and
remote only, naming what is true of the branch and the one command that fixes
it.  The remote-only refusal is the one that says the refresh should have
written the local ref and did not, which is what a working tree standing on an
unborn control does to it, so it asks for the ref to be written rather than
reading a staleness out of two counts that are both zero.  Where the
repository has no remote configured at all, the local-only refusal asks for a
remote instead of printing a push command with nothing to push to.  No refusal
writes anything, and no path here moves control.

B<Examples:>

  my $state = Genesis::CI::Preflight::require_control($top, $git,
      refreshed => $result, command => 'propagate');
  info("  #Gi{%s}", $_) for @{$state->{events}};
  # $state->{divergence} is { state => 'in-sync', ahead => 0,
  #                           behind => 0, unverifiable => 0 }

  Genesis::CI::Preflight::require_control($top, $git,
      refreshed     => $result,
      action        => 'deploy',
      outcome       => 'Nothing was deployed.',
      on_divergence => 'report');
  # refuses a control branch that is nowhere, and reports every other state
  # back to a caller that resolves nothing

=head2 initial_state($top, $git, %opts)

  my $state = Genesis::CI::Preflight::initial_state($top, $git,
      envs => \@dag_order, refreshed => $result, control => $control_state);

Runs the whole first stage of a propagation run and returns what it found:

  { refreshed => 1,
    control   => $div,
    branches  => { qa => { branch => 'qa/bosh', state => 'in-sync',
                           ahead => 0, behind => 0,
                           reset => 0, fast_forwarded => 0 } },
    events    => [ 'created control from origin/control' ] }

The refresh and the control check come first, and a caller that has already
made them passes their answers in rather than having them made twice.  Every
deployment branch named in C<envs> is then classified, and two classes have no
legitimate origin.  A branch this clone holds that the remote has never had is
a legacy checkout or one somebody cut by hand, because a deployment branch is
derived from control and never originates locally.  A branch that shares no
ancestor with its counterpart on the remote is the same thing again, found
after C<pipeline-apply> cut the real branch beside it.  Both refuse.

Every refusal is collected before anything is written, so a run that stops
here has left nothing partial behind, and a repository holding a branch of
each class hears about both in one refusal rather than meeting the second on
the next run.  An environment with no branch on either side is not a refusal;
it is awaiting C<pipeline-apply>, which the walk reports as that environment's
outcome.  Neither is a branch the remote has that this clone lacks, which the
refresh creates locally before this stage reads it.

The whole pipeline is classified rather than the environments one run happens
to touch, because the initial state is a property of the repository and not of
the run.  A hand-made branch anywhere in the pipeline is a defect the operator
should hear about before anything is written, and the caller passes the whole
topology in for that reason.

B<Parameters:>

=over 4

=item C<$top>

A C<Genesis::Top> on the repository, which is asked for each environment's
deployment branch and for the control branch's name.

=item C<$git>

A C<Service::Git> handle on the same repository.

=item C<envs>

The environments to classify, which is the whole topology rather than one
run's scope.

=item C<refreshed>

The result the refresh returned.  A caller that has not refreshed leaves it
out and this stage refreshes for itself.

=item C<control>

The record C<require_control> returned.  A caller that has not asked leaves it
out and this stage asks for itself.

=item C<command>

The command's name, which the refusals' opening sentence is built from, as in
"Refusing to run C<genesis propagate>".

=item C<action>

The whole act, for a command that names itself in its own words rather than by
its invocation, which is the option C<require_control> reads by the same name.

=item C<outcome>

The refusals' closing sentence, which says what did not happen.  It is
"Nothing was written." unless the caller says otherwise.

=item C<dry_run>

True where the run reports and writes nothing, which the stages below this one
read.

=back

B<Returns:> A hashref of four keys.

=over 4

=item C<refreshed>

True once the refresh has run, whether this stage ran it or the caller did.

=item C<control>

The divergence record for the control branch.

=item C<branches>

One record per environment that has a branch on either side, keyed by the
environment's name.

=item C<events>

The lines the caller prints.  They are seeded from the control record, so the
caller prints the whole stage's events once and in order.

=back

B<Errors:> Bails at C<DATAERR> for a local deployment branch the remote has
never had, and for one that shares no ancestor with the remote's.  The two
classes come back in one refusal, which names every offending branch and gives
the remedy in order, which is to inspect the branch, move anything wanted to
control, delete the branch, and then run the command the case calls for.
Genesis deletes nothing itself.  The refresh and the control check raise their
own codes where the caller has left them to this stage.

B<Examples:>

  my $initial = Genesis::CI::Preflight::initial_state($top, $git,
      envs      => \@dag_order,
      refreshed => $refreshed,
      control   => $control_state,
      command   => 'propagate');
  info("  #Gi{%s}", $_) for @{$initial->{events}};
  # $initial->{branches}{qa}{state} is 'in-sync'

  Genesis::CI::Preflight::initial_state($top, $git, envs => ['lab']);
  # refuses at DATAERR where lab/bosh is a branch origin has never had

=head1 INTERNAL FUNCTIONS

Every public entry of this module goes above this heading, under
C<FUNCTIONS>.  What follows documents the subs this module keeps to itself.

=head2 _shares_history

    my $shared = Genesis::CI::Preflight::_shares_history($git, $branch, $remote);

Answers whether a local branch and its counterpart on the remote have a commit
in common.

The question is asked through C<Genesis::run> with C<passfail> on and C<stderr>
off rather than through C<Service::Git::merge_base>, which folds git's standard
error into the value it hands back.  A ref this clone cannot resolve makes
C<git merge-base> print a message and exit non-zero, and a folded message is a
truthy string, so a reader that took the value would read a missing ref as a
shared ancestor and let the branch through.  The command's status is the whole
answer here, and the two states that answer no, a pair with no common commit
and a ref that is not there, are both states the stage refuses.

B<Parameters:>

=over 4

=item C<$git>

A C<Service::Git> handle on the repository to read.

=item C<$branch>

The deployment branch, named as git names it.

=item C<$remote>

The remote whose tracking ref the branch is compared against.

=back

B<Returns:> 1 where the two share a commit, and 0 where they share none or
where either ref cannot be resolved.

B<Examples:>

  Genesis::CI::Preflight::_shares_history($git, 'qa/bosh', 'origin');
  # 1, where the branch was cut from origin/qa/bosh

  Genesis::CI::Preflight::_shares_history($git, 'qa/bosh', 'origin');
  # 0, where the local branch is an orphan of the same name

=head2 _origin_refusal

    my $text = Genesis::CI::Preflight::_origin_refusal(
        $action, $outcome, $remote, \@local_only, \@unrelated);

Frames whichever classes of illegitimate branch the stage found as one
refusal.

The stage raises at most one refusal, so the act is named once and the closing
sentence is said once however many branches and however many classes the run
met.  The local-only paragraphs come first and the unrelated-history
paragraphs follow, which is the order the two questions are asked in.  The act
and the closing sentence are arguments, because the deploy raises the same
text in its own words.

B<Parameters:>

=over 4

=item C<$action>

The act the refusal opens with, as in C<run genesis propagate>.

=item C<$outcome>

The closing sentence, which says what did not happen.

=item C<$remote>

The remote the branches were classified against.

=item C<\@local_only>

The branches the remote has never had, one hashref each of C<env> and
C<branch>.  It may be empty.

=item C<\@unrelated>

The names of the branches that share no ancestor with their counterpart.  It
may be empty.

=back

B<Returns:> The composed refusal, which the caller hands to C<bail> through a
C<'%s'> format.

B<Examples:>

  Genesis::CI::Preflight::_origin_refusal(
      'run #C{genesis propagate}', 'Nothing was written.', 'origin',
      [{env => 'lab', branch => 'lab/bosh'}], []);
  # 'Refusing to run #C{genesis propagate}.  The local branch #C{lab/bosh}
  #  has no counterpart on #C{origin}.  ...  Nothing was written.'

  Genesis::CI::Preflight::_origin_refusal(
      'run #C{genesis propagate}', 'Nothing was written.', 'origin',
      [{env => 'lab', branch => 'lab/bosh'}], ['qa/bosh']);
  # one refusal naming lab/bosh and then qa/bosh, with one opening sentence
  # and one closing sentence

=head2 _local_only_refusal

    my @paragraphs = Genesis::CI::Preflight::_local_only_refusal(
        $remote, \@offenders);

Composes D48's paragraphs for deployment branches the remote has never had.

One paragraph per branch, so a run with one offender reads exactly as the
design quotes it and a run with several names them all.  The act the refusal
opens with and the sentence it closes with belong to C<_origin_refusal>, which
frames whichever classes the stage found.

B<Parameters:>

=over 4

=item C<$remote>

The remote the branches have no counterpart on.

=item C<\@offenders>

One hashref per branch, each of C<env> and C<branch>.  It may be empty, and it
may be C<undef>.

=back

B<Returns:> One paragraph per offending branch, and an empty list where there
is none.

B<Examples:>

  Genesis::CI::Preflight::_local_only_refusal('origin',
      [{env => 'lab', branch => 'lab/bosh'}]);
  # ( 'The local branch #C{lab/bosh} has no counterpart on #C{origin}.  ...' )

  Genesis::CI::Preflight::_local_only_refusal('origin', []);
  # ()

=head2 _unrelated_refusal

    my @paragraphs = Genesis::CI::Preflight::_unrelated_refusal(
        $remote, \@branches);

Composes D48's paragraphs for deployment branches that share no ancestor with
their counterpart on the remote.

It says that the marker-only reset never applies across unrelated histories,
whatever the local commits carry, because that is the question an operator
reaching this refusal is most likely to ask next.  Like its neighbour, it
leaves the opening and the closing sentence to C<_origin_refusal>.

B<Parameters:>

=over 4

=item C<$remote>

The remote whose counterparts the branches share no ancestor with.

=item C<\@branches>

The offending branch names.  It may be empty, and it may be C<undef>.

=back

B<Returns:> One paragraph per offending branch, and an empty list where there
is none.

B<Examples:>

  Genesis::CI::Preflight::_unrelated_refusal('origin', ['qa/bosh']);
  # ( 'The local branch #C{qa/bosh} shares no ancestor with
  #    #C{origin/qa/bosh}, ...' )

  Genesis::CI::Preflight::_unrelated_refusal('origin', []);
  # ()

=head2 _commits

    my $phrase = Genesis::CI::Preflight::_commits($n);

Spells a commit count as English, so a refusal reads aloud at one commit as
well as at four.

A refusal that said "by 1 commits" would be read past rather than read, and
the sentences around it agree with the number the same way, so the caller asks
this for the phrase and picks its own verb from the count.

B<Parameters:>

=over 4

=item C<$n>

A count of commits.

=back

B<Returns:> The count and its noun, as in C<1 commit> or C<4 commits>.

B<Examples:>

  Genesis::CI::Preflight::_commits(1);
  # '1 commit'

  Genesis::CI::Preflight::_commits(4);
  # '4 commits'
