=head1 NAME

Genesis::CI::Preflight - the initial state a propagation run may find

=head1 SYNOPSIS

  use Genesis::CI::Preflight;

  my @stranded = Genesis::CI::Preflight::local_only_commits($git, 'qa/bosh');

  my $initial = Genesis::CI::Preflight::initial_state($top, $git,
      envs => \@dag_order, refreshed => $result, control => $control_state);

  Genesis::CI::Preflight::assert_not_disowned($top, command => 'propagate');

  Genesis::CI::Preflight::assert_provider_gate($top, $options,
      owns        => 'deploys of this environment',
      outcome     => 'Nothing was deployed.',
      acknowledge => 'I accept the risk');

=head1 DESCRIPTION

The first stage of a propagation run settles what the repository holds before
anything is written.  It refreshes, it requires the control branch to exist
and to be in step with the remote, it refuses a deployment branch with no
legitimate origin, it resets a branch whose only local commits are ones a
re-run reproduces, and it fast-forwards a branch that is merely behind.  A
violation is an illegal initial state, so the run stops before it writes and
the refusal names the branch and the way out.

The module also holds the refusals that more than one command makes about the
pipeline itself, because a state described in two places is a state an
operator ends up fixing twice.  There are two of them, and both the propagate
run and C<genesis E<lt>envE<gt> deploy> ask each the same question and are
answered in their own words.  C<assert_not_disowned> answers for a pipeline
the configuration has disowned, and C<assert_provider_gate> answers for a
pipeline that owns the work the operator is about to do by hand.

Each refusal spends a named exit code rather than a number.  Control that
exists nowhere is a configuration fault and exits C<CONFIG>, an initial state
the design calls illegal exits C<DATAERR>, and a remote this clone cannot
reach exits C<TEMPFAIL>, which is the one of the three a pipeline job may
retry.  The provider gate spends two more, refusing at C<NOPERM> and exiting
C<ABORTED> where the operator declines it.

=head2 The order the first stage runs in

The stage runs in one order and the order matters.  The refresh comes first,
so every later question is asked of current remote-tracking refs.  Control is
settled next, because the topology is read from it.  Then every deployment
branch in scope is classified and every refusal is raised, before anything is
written.  Only then does the stage write: a branch whose local-only commits a
re-run reproduces is reset, and a branch that is merely behind is
fast-forwarded.

After the stage, a deployment branch in scope is C<in-sync> or it has no local
ref, which is the fact the walk rests on when it diffs from the local ref.
Under C<dry_run> nothing is written, and each write the stage would have made
is reported as a warning saying the report assumes it.

=head1 FUNCTIONS

=head2 problem($code, $text)

    my $p = Genesis::CI::Preflight::problem(CONFIG,
        'The pipeline has never been applied.  Run #C{genesis pipeline-apply}.');

One thing a check found, with the code its refusal carries. A check that
answers rather than refuses hands back problems, and the run refuses once with
every one of them through L</refuse_once(%opts)> (D115). The text is the
paragraph the check's own refusal said, without the "Refusing to ..." frame
or the outcome, so a run with one problem reads as it did before.

B<Parameters:>

=over 4

=item C<$code>

The C<Genesis::Exit> code the problem alone would refuse with.

=item C<$text>

The paragraph naming the problem and its remedy.

=back

B<Returns:> A hashref of C<code> and C<text>.

B<Errors:> None.

B<Examples:>

    problem(DATAERR, 'The working tree has uncommitted changes.');
    # returns {code => 65, text => 'The working tree has uncommitted changes.'}

=head2 exit_code_for(@problems)

    my $code = Genesis::CI::Preflight::exit_code_for(@problems);

The code a refusal naming these problems exits with: the highest-ranked
problem's, in the order D106 gives as noted on 2026-10-07, C<CONFIG>,
C<NOPERM>, C<DATAERR>, C<UNAVAILABLE>, C<TEMPFAIL>. A person must fix or
configure before a retry helps, which outranks a fault the next run clears,
and a permission is a person's decision too, ranked just below the
configuration it cannot carry.

B<Parameters:>

=over 4

=item C<@problems>

Problems from L</problem($code, $text)>.

=back

B<Returns:> The code, or the one problem's own code where it is unranked, or
C<undef> for no problems.

B<Errors:> None.

B<Examples:>

    exit_code_for(problem(DATAERR, $a), problem(CONFIG, $b));
    # returns CONFIG

=head2 refuse_once(%opts)

    Genesis::CI::Preflight::refuse_once(
        action   => 'propagate',
        outcome  => 'Nothing was written.',
        problems => \@problems);

One refusal naming every problem the run found, so an operator meets them all
at once rather than fixing one only to meet the next (D115). It is framed as
the stage's refusals always were: "Refusing to E<lt>actionE<gt>.", each
problem's paragraph in the order found, then the outcome. A gate that ended
the questions early says which it left unasked and why, rather than guessing at
answers its failure made meaningless. The text goes through a C<'%s'> format,
because C<bail> reads its argument as one and a branch name can carry a
percent sign.

B<Parameters:>

=over 4

=item C<problems>

The problems found. An empty list refuses nothing.

=item C<action>, C<outcome>

The act refused, as in "Refusing to propagate.", and the closing sentence,
such as "Nothing was written."

=item C<not_checked>

Optional. A hashref of C<because>, the gate that failed, and C<checks>, the
questions it left unasked, said as "Not checked, because E<lt>becauseE<gt>:
E<lt>checksE<gt>."

=back

B<Returns:> 1 where there are no problems.

B<Errors:>

=over 4

=item *

The composed refusal, at L</exit_code_for(@problems)>'s code, where any
problem stands.

=back

B<Examples:>

    refuse_once(action => 'propagate', outcome => 'Nothing was written.',
        problems => [problem(DATAERR, $dirty), problem(CONFIG, $never)]);
    # exits CONFIG: "Refusing to propagate.  <dirty>  <never>  Nothing was written."

    refuse_once(action => 'propagate', problems => []);
    # returns 1

=head2 applied_record_problems($top)

    my ($applied, @problems) = Genesis::CI::Preflight::applied_record_problems($top);

The applied record, read from the vault, and why the run cannot have it (D109):
no record at all, which means the pipeline was never applied or the mount
holding it is gone, at C<CONFIG>; and a vault that would not say, at
C<UNAVAILABLE>, which is not taken for a record that is not there. Each is in
the words the run's refusal had, the outcome left to the one refusal. Nothing
else a run asks reads the vault, so neither is a gate.

B<Parameters:>

=over 4

=item C<$top>

The deployment root, whose L<Genesis::Top/applied_record> is read.

=back

B<Returns:> The record, or C<undef>, then at most one problem.

B<Errors:> None.

B<Examples:>

    my ($applied, @problems) = applied_record_problems($top);
    # returns (undef, problem(CONFIG, "genesis pipeline-apply has never been run ..."))
    # where the vault holds no record

=head2 github_problems($top, %opts)

    my ($github, @problems) = Genesis::CI::Preflight::github_problems($top,
        envs => \@pull_request_envs);

The GitHub client the run needs and what its pull request environments' review

first problem ends the reads, because an API that refused one environment will
not answer the rest (D115, noted 2026-10-07). A run with no token is warned and
carries on, as before; that is no problem.

B<Parameters:>

=over 4

=item C<envs>

The pull request environments, as C<state_for_scope> takes them.

=back

B<Returns:> A hashref of C<client>, C<owner_repo> and C<state_of>, then the
problems.

B<Errors:> None of its own.

B<Examples:>

    my ($github, @problems) = github_problems($top, envs => \@envs);
    # returns ({client => undef, ...}, problem(UNAVAILABLE, "Could not read the review state ..."))
    # where the API would not answer

=head2 prefix_problems($top, %opts)

    my ($branch_of, @problems) = Genesis::CI::Preflight::prefix_problems($top,

Every pull request branch's collision, for every environment that delivers by

through L<Genesis::Top/pr_branch_problems>. Every collision
is named, so an operator who changes the prefix is not told about a second one
by the next run (D115).

B<Parameters:>

=over 4

=item C<topology>

The pipeline's topology, read from control.

=back

B<Returns:> A hashref of environment to its pull request branch, then the
problems.

B<Errors:> None.

B<Examples:>

    my ($branch_of, @problems) = prefix_problems($top, topology => $topo);
    # returns ({qa => 'pr/qa/bosh'}) where nothing collides

=head2 repository_problems($git)

    my @problems = Genesis::CI::Preflight::repository_problems($git);

What the clone itself must have before a run: the problems
L<Service::Git/preflight_problems> answers, a repository with no commits and
a process with no committer identity, and a working tree with uncommitted
changes at C<DATAERR>, listing every changed path in the words the session's
C<begin> refuses with. Untracked files are not changes. None of them leaves
another question without valid input, so the run collects them with the rest
(D115, noted 2026-10-07).

On an unborn HEAD the working tree is not asked about: with no commit to
compare against, every file the index holds reads as a change, and the
pre-flight's own problem already names the branch the tree stands on.

B<Parameters:>

=over 4

=item C<$git>

The C<Service::Git> handle on the clone.

=back

B<Returns:> A list of problems from L</problem($code, $text)>, empty for a
healthy, clean clone.

B<Errors:>

=over 4

=item *

Dubious ownership, refused on the spot by the git handle at C<CONFIG>.

=back

B<Examples:>

    repository_problems($git);
    # returns (problem(DATAERR, "Working tree has uncommitted changes, ...  - qa.yml\n"))
    # where qa.yml was edited and not committed

    repository_problems($git);
    # returns only the pre-flight's unborn-branch problem on an unborn branch
    # in a repository with commits, whatever the index holds

=head2 local_only_commits($git, $branch)

  my @stranded = Genesis::CI::Preflight::local_only_commits($git, $branch);

Lists the commits the branch holds that no remote has, newest first, as a
hashref each of C<sha>, C<short>, C<subject>, and C<marker>.  C<marker> is the
control commit that commit's propagation marker names, and it is C<undef> for
a hand edit.  That is the whole classification the stage needs: a commit with
a marker is one a re-run reproduces, so the branch can be reset to its
tracking ref, and a commit without one is an operator's hand edit, which
nothing here may discard.

The query runs C<git log E<lt>branchE<gt> --not --remotes>, so what counts as
local-only is decided against the remote-tracking refs this clone holds.  It
must therefore run before any prune, because a prune removes exactly the refs
that answer it and a pruned clone reports every commit on the branch as
stranded.  C<Service::Git::fetch_branches> never prunes, which is what keeps
this query honest across a refresh.

Each commit is classified by asking C<Genesis::CI::Marker::newest> for the
newest marker within a walk of one, so this module carries no second reader
of the marker.

The read keeps git's standard error off what comes back, because every line
that does come back is parsed as a commit record and a git that warned while
succeeding would have its warning read as a commit.

B<Parameters:>

=over 4

=item C<$git>

A C<Service::Git> handle on the repository to read.

=item C<$branch>

The branch to walk, named as git names it.

=item C<tracking>

Optional. A view of R excluded beside the tracking refs, such as D115's
snapshot, so a commit R holds that the tracking ref has not yet seen is not
taken for one only this clone has.

=back

B<Returns:> A list of hashrefs, newest commit first, empty where the branch
holds nothing a remote lacks.

B<Errors:> Bails when C<git log> fails, which is a branch this repository
cannot read rather than a state the stage reports.

B<Examples:>

  my @stranded = Genesis::CI::Preflight::local_only_commits($git, 'qa/bosh');
  # ( { sha => 'a1b2...', short => 'a1b2c3d',
  #     subject => '[pipeline] control@9f8e7d6 -> qa',
  #     marker  => '9f8e7d6c5b4a...' } )

  Genesis::CI::Preflight::local_only_commits($git, 'prod/bosh');
  # () where every commit on the branch has been pushed

=head2 require_control($top, $git, %opts)

  my $state = Genesis::CI::Preflight::require_control($top, $git,
      refreshed => $result, command => 'propagate');

Settles the control branch before anything else is read.  Control is where the
environment files live, so a run that cannot trust it cannot trust a single
answer it goes on to give, and every command in this stage asks this question
first.

Three things can be true of control, and each has one answer.  Where the
remote has the branch and this clone does not, the refresh has already written
the local ref, and the creation comes back as an event line for the caller to
print rather than passing in silence.  Where the branch exists nowhere, the
command refuses, and it creates nothing, because cutting the branch that
becomes the repository's source of truth is the operator's act and not
Genesis'.  Where both places have it, the two have to agree, because an
unpushed control holds commits a deploy on another machine cannot read, since
a propagation marker names a control commit by its sha alone, and because a
stale control would propagate state a teammate has already moved past.
Genesis never moves control in either direction, so both are refusals rather
than repairs.

B<Parameters:>

=over 4

=item C<$top>

A C<Genesis::Top> on the repository, which is asked for the control branch's
name.

=item C<$git>

A C<Service::Git> handle on the same repository.

=item C<refreshed>

The result the refresh returned, whose C<created> list is what the event line
is composed from.  A caller that did not refresh leaves it out.

=item C<command>

The command's name, which the refusal's opening sentence is built from, as in
"Refusing to run C<genesis propagate>".

=item C<action>

The whole act, for a command that names itself in its own words rather than by
its invocation.  The deploy passes C<deploy>, so its refusal opens "Refusing
to deploy".

=item C<outcome>

The refusal's closing sentence, which says what did not happen.  It is
"Nothing was written." unless the caller says otherwise.

=item C<unverifiable>

Passed through to C<resolve_branch> for a caller that read without refreshing,
so the divergence it gets back says so.

=item C<on_divergence>

C<refuse> by default, and C<report> for the two commands that read without
resolving, which are C<genesis pipeline-status> and the deploy.  Every command
that writes takes the default, because a divergence on control reaches the
remote through whatever it writes.  A branch that exists nowhere is refused
either way, since it leaves the command nothing at all to read.

=item C<permit_ahead>

Returns rather than refusing where control is C<ahead> of its remote, which is
what C<genesis propagate --dry-run> passes.  A preview refuses nothing it can
warn about instead, and it warns about this one under its own banner.
Everything the preview reads is on control itself, and all the push settles is
whether another machine could resolve the markers a real run would write, so
C<ahead> is the one divergence a preview can still answer.  Staleness is not
like that, so C<behind> and C<diverged> are refused with it set as they are
without it.

=back

B<Returns:> A hashref of C<divergence>, the record C<resolve_branch> gives for
control, and C<events>, the lines the caller prints.  C<events> holds one line
where the refresh created the local ref, which reads "created control from
origin/control", and is empty otherwise.

B<Errors:> Bails at C<CONFIG> when the control branch exists neither on the
remote nor locally, naming the branch and both places and telling the operator
to create and push it.  Bails at C<DATAERR> for every one of the five states
the design calls illegal, which are ahead, behind, diverged, local only, and
remote only, naming what is true of the branch and the one command that fixes
it.  The remote-only refusal is the one that says the refresh should have
written the local ref and did not, which is what a working tree standing on an
unborn control does to it, so it asks for the ref to be written rather than
reading a staleness out of two counts that are both zero.  The remote every
refusal names is L<Genesis::Top/source_control_remote> (D29), which a
pipeline repository always resolves, since the load refuses one that cannot
derive it.  No refusal writes anything, and no path here moves control.

B<Examples:>

  my $state = Genesis::CI::Preflight::require_control($top, $git,
      refreshed => $result, command => 'propagate');
  info("  #Gi{%s}", $_) for @{$state->{events}};
  # $state->{divergence} is { state => 'in-sync', ahead => 0,
  #                           behind => 0, unverifiable => 0 }

  Genesis::CI::Preflight::require_control($top, $git,
      refreshed     => $result,
      action        => 'deploy',
      outcome       => 'Nothing was deployed.',
      on_divergence => 'report');
  # refuses a control branch that is nowhere, and reports every other state
  # back to a caller that resolves nothing

  Genesis::CI::Preflight::require_control($top, $git,
      refreshed    => $result,
      command      => 'propagate',
      permit_ahead => 1);
  # returns where control is ahead, for the preview to warn about, and
  # refuses behind and diverged as it does for a run that writes

=head2 control_problems($top, $git, %opts)

  my @problems = Genesis::CI::Preflight::control_problems($top, $git,
      tracking      => 'refs/genesis/preflight/origin',
      creates_local => 1);

The questions L</require_control($top, $git, %opts)> asks, each answered as a
problem in the words its refusal had, the frame left to the one refusal
(D115): control nowhere at all at C<CONFIG>, and local only, missing locally,
ahead, behind or diverged at C<DATAERR>. Control's divergence is a gate,
because every question that reads control is left without a control anyone
can trust while it stands.

B<Parameters:>

=over 4

=item C<tracking>

Optional. The view of R control is measured against, as for
L<Service::Git/resolve_branch>, which D115's run gives as its snapshot.

=item C<creates_local>

Optional. True where the run will create a control the clone lacks from what
it read of R, so its absence is no problem. A tree standing on control unborn
is still answered, because no run writes the branch the tree stands on.

=item C<preview>

Optional. True for a preview, which stands on control as a run does and
creates nothing, so a control the clone lacks is answered as a C<DATAERR>
problem naming C<git checkout E<lt>controlE<gt>> or a real run, either of
which creates it (D44, noted 2026-10-09).

=item C<permit_ahead>, C<unverifiable>

As for L</require_control($top, $git, %opts)>.

=back

B<Returns:> A list of at most one problem, empty where control stands in step.

B<Errors:> None.

B<Examples:>

  control_problems($top, $git, tracking => 'refs/genesis/preflight/origin');
  # returns (problem(DATAERR, "The control branch control is behind ..."))
  # where R gained a commit control has not

=head2 assert_not_disowned($top, %opts)

  my $applied = Genesis::CI::Preflight::assert_not_disowned($top,
      command => 'propagate');

Reads the applied record beside C<pipeline.enabled>.  Where a record stands
while the pipeline is disabled, the configuration disowns a pipeline that is
still live, still watching its branches, and still deploying, and this
refuses at C<Genesis::Exit/CONFIG>.

The check reads the record and not only the key, because a repository that
never had a pipeline has neither and is disowning nothing.  Such a repository
passes and meets the pre-flight, which has its own words for it.

Two commands ask about this one state and want two answers, which is why the
check lives here rather than beside either of them.  The propagate run is
about to write, so it refuses.  A deploy is about to read what is already
there, and an operator part way through tearing a pipeline down has a reason
to be running one, so it warns and carries on.  Inside a pipeline job, which
Genesis recognises by C<GENESIS_PIPELINE_TASK> in the environment, the answer
is a refusal whatever the caller asked for, because nobody there reads a
warning and a job never acts on what its own configuration disowns.  What a
job must not do is said in the caller's own words, through C<in_job>, since
the sub cannot know which command it is standing in for.

Every message names the control commit the pipeline was applied from, the
time it was applied, and both remedies, which are to set
C<pipeline.enabled: true> again or to tear the pipeline down by hand.
Tearing it down has no command yet, and the message says so rather than
naming one that does not exist.

B<Parameters:>

=over 4

=item C<$top>

A C<Genesis::Top> on the repository, which is asked for C<pipeline.enabled>
and for the applied record.

=item C<command>

The command's name, which the refusal spells back so the operator reads the
command they ran, as in "Refusing to run C<genesis qa deploy>".  It is
C<propagate> unless the caller says otherwise.

=item C<outcome>

The refusal's closing sentence, which says what did not happen.  It is
"Nothing was written." unless the caller says otherwise.

=item C<in_job>

The sentence the refusal inside a pipeline job makes about what a job must
not do.  Only the caller knows what it was about to do, so only the caller
can say it: C<genesis E<lt>envE<gt> deploy> passes "A job never deploys what
its own configuration disowns."  The default, "A job never acts on what its
own configuration disowns.", names no command and fits every caller.

=item C<locally>

C<warn> makes a disowned pipeline a warning rather than a refusal outside a
pipeline job, which is what C<genesis E<lt>envE<gt> deploy> asks for.  It is
C<refuse> unless the caller says otherwise, and it changes nothing inside a
job.

=back

Where the pipeline is disabled and the vault answers an error for the applied
record, whether the pipeline is still live cannot be told, and this check is
not what decides whether the vault is fit to use: a propagate run refuses on
the same read a step later.  So it warns naming the record and what the vault
said, and carries on, for every caller and inside a job alike.

B<Returns:> the applied record, where the state was warned about; 1, where
the pipeline is enabled, no applied record stands, or the record could not be
read.  It does not return where it refuses.

B<Errors:>

Calls C<bail()> at C<Genesis::Exit/CONFIG> where an applied record stands
while C<pipeline.enabled> reads false, unless C<locally> is C<warn> and
C<GENESIS_PIPELINE_TASK> is unset.

B<Examples:>

  Genesis::CI::Preflight::assert_not_disowned($top, command => 'propagate');
  # [FATAL] Refusing to run genesis propagate.  The pipeline is disabled
  #         in .genesis/config, but the applied record says pipeline-apply
  #         applied it from control@a1b2c3d at 2026-09-15 11:04:22 +0000

  Genesis::CI::Preflight::assert_not_disowned($top,
      command => 'qa deploy',
      outcome => 'Nothing was deployed.',
      locally => 'warn');
  # [WARNING] Warning: the pipeline is disabled in .genesis/config, but the
  #           applied record says pipeline-apply applied it from
  #           control@a1b2c3d at 2026-09-15 11:04:22 +0000.

=head2 assert_provider_gate($top, $opts, %how)

  Genesis::CI::Preflight::assert_provider_gate($top, $options,
      owns        => 'deploys of this environment',
      outcome     => 'Nothing was deployed.',
      acknowledge => 'I accept the risk');

Refuses a command-line run of work an automated provider's pipeline owns,
because such a run takes none of the locks the pipeline's own jobs take.
C<--force> at a terminal turns the refusal into an acknowledgement, which
C<--yes> does not suppress, and outside a terminal the refusal stands even
with the flag.

C<owns> and C<outcome> give the refusal the caller's own words. C<acknowledge>
names a phrase the operator types, which C<genesis E<lt>envE<gt> deploy> asks
for and the propagate run does not, the run being asked a yes-or-no question
instead. C<dry_run> warns and passes, which a preview that writes nothing uses.

A pipeline job, which Genesis recognises by C<GENESIS_PIPELINE_TASK> in the
environment, skips the gate, and a repository under the manual provider never
meets it, the operator there being the pipeline.

It is the two halves D115 asks apart, joined: it refuses with the first
problem L</provider_gate_problems($top, $opts, %how)> answers, followed by
the outcome, and otherwise asks L</confirm_provider_gate($top, $opts, %how)>.
The deploy calls it whole; the propagate run asks the halves apart, so the
confirmation comes after every other question.

The typed acknowledgement says what the deploy does not do as well as what to
do before it. It recommends pausing the pipeline and waiting for quiescence
on the target environment, on its director, and on every pipeline that
deploys to that director, and it says that no shuttle event is written for
this command, so nothing fans out to the deployments that read this one.

B<Parameters:>

=over 4

=item C<$top>

A C<Genesis::Top> on the repository, which is asked for the provider type.

=item C<$opts>

The command's options, as C<get_options> answered them. C<force> is the only
one the gate reads, since C<--yes> answers no part of this.

=item C<owns>

The sentence about what the pipeline owns, as in "deploys of this
environment". It is "propagation for this repository" unless the caller says
otherwise.

=item C<outcome>

The refusal's closing sentence, which says what did not happen. It is
"Nothing was written." unless the caller says otherwise.

=item C<acknowledge>

The phrase the operator types to pass the gate. A caller that names none is
asked "Proceed anyway? [y|n]" instead.

=item C<dry_run>

True where the command writes nothing, in which case the gate warns and
passes rather than refusing.

=back

B<Returns:> 1, where the gate is passed or does not apply. It does not return
otherwise.

B<Errors:>

=over 4

=item *

Calls C<bail()> at C<Genesis::Exit/NOPERM> for a bare run under an automated
provider, and again for a C<--force> run with no controlling terminal.

=item *

Calls C<bail()> at C<Genesis::Exit/ABORTED> where the operator declines at the
terminal, by answering no or by typing anything but the phrase.

=back

B<Examples:>

  Genesis::CI::Preflight::assert_provider_gate($top, {});
  # returns 1 under the manual provider

  Genesis::CI::Preflight::assert_provider_gate($top, {}, dry_run => 1);
  # warns that this is the pipeline's work, asks nothing, returns 1

=head2 initial_state($top, $git, %opts)

  my $state = Genesis::CI::Preflight::initial_state($top, $git,
      envs => \@dag_order, refreshed => $result, control => $control_state);

Runs the whole first stage of a propagation run and returns what it found:

  { refreshed => 1,
    control   => $div,
    branches  => { qa => { branch => 'qa/bosh', state => 'in-sync',
                           ahead => 0, behind => 0,
                           reset => 0, fast_forwarded => 0,
                           assumed => undef, assumed_move => undef,
                           assumed_commits => undef } },
    events    => [ 'created control from origin/control' ] }

The refresh and the control check come first, and a caller that has already
made them passes their answers in rather than having them made twice.  Every
deployment branch named in C<envs> is then classified, and two classes have no
legitimate origin.  A branch this clone holds that the remote has never had is
a legacy checkout or one somebody cut by hand, because a deployment branch is
derived from control and never originates locally.  A branch that shares no
ancestor with its counterpart on the remote is the same thing again, found
after C<pipeline-apply> cut the real branch beside it.  Both refuse.

Every refusal is collected before anything is written, so a run that stops
here has left nothing partial behind, and a repository holding a branch of
each class hears about both in one refusal rather than meeting the second on
the next run.  An environment with no branch on either side is not a refusal;
it is awaiting C<pipeline-apply>, which the walk reports as that environment's
outcome.  Neither is a branch the remote has that this clone lacks, which the
refresh creates locally before this stage reads it.

Each branch's local-only commits are then classified, which is the last
question the stage asks and the only one whose answer it writes.  A commit
carrying a propagation marker is one a re-run reproduces, so a branch whose
local-only commits all carry one is reset to its remote-tracking ref and the
reset is reported as an event line beside the environment rather than as that
environment's outcome.  A commit carrying no marker is a hand edit that
belongs on control, so it refuses the whole run.  The refusal is raised before
the first reset, so a repository holding both never has a branch moved under
it.

The reset is the run's first write, and it is the one forced write onto a
deployment branch the design admits outside the session's own abort.  It
settles the branch's record with it, because the branch now stands on its
tracking ref and the state and the two counts the classification wrote are no
longer true of it.  Under C<dry_run> nothing is written; the line is reported
as an assumption the real run would make, so a report never reads as though
the branch had already moved.

Last of all, a branch that is merely behind its remote-tracking ref is moved
up to it by fast-forward, which resolves nothing a human would decide and
which the deploy's own C<--ff-only> is the precedent for.  The divergence is
asked again rather than read off the record, because a branch this stage has
just reset stands where its tracking ref does and the record was written
before that move.  The fast-forward settles the branch's record too, and it is
reported as an event line.

Under C<dry_run> neither write is made, and the record of a branch the stage
would have moved says so instead.  C<assumed> names the ref a real run would
have left the branch on, and the state and the counts stay as the
classification wrote them, because nothing moved.  A caller taking a diff base
off such a record takes C<assumed> where it is set, so a report says what a
real run would deliver rather than naming files a teammate has already
delivered.  C<assumed_move> names which move it was, C<reset>,
C<fast-forward>, or C<create>, so a caller that cares which one the branch
escaped asks rather than inferring it from the counts, and
C<assumed_commits> says how many local commits a reset would discard.  A
fast-forward discards nothing, so it leaves that count unset.

The third move is the creation a run makes before the stage begins.  A branch
R has and this clone lacks reaches the stage only under C<dry_run> or
C<read_only>, since a run has created it by then, and it is read at its
tracking ref, as the created branch would stand, with C<assumed_move> set to
C<create> (D44, noted 2026-10-09).  Under either, each event line is in the
conditional, "would reset", "would fast-forward", "would create", because
nothing moved.

The reset's assumption is not warned about here.  The preview says it under its
own banner, through C<Genesis::CI::Report::preview_warnings>, and a caveat
printed above that banner is one the operator meets before they have been told
they are reading a preview.  The fast-forward keeps a caveat of its own on that
banner, beside the reset's and the unpushed control's, and it takes the same
sentence shape, "This preview assumes ... is fast-forwarded first", as the
creation's does, "... is created first", so an operator who meets all four
reads one kind of sentence.  The event line beside each move is printed under
both kinds of run, in the tense of what happened, so nothing about what would
be done goes unsaid and nothing reads as done that was not.

Once the stage has run, a deployment branch in scope is C<in-sync> or it has
no local ref at all.  That is what lets the walk take its diff base from the
local ref: a delivery a teammate published is already on the branch by then,
so it is part of what the walk diffs against rather than something the walk
delivers a second time.

The whole pipeline is classified rather than the environments one run happens
to touch, because the initial state is a property of the repository and not of
the run.  A hand-made branch anywhere in the pipeline is a defect the operator
should hear about before anything is written, and the caller passes the whole
topology in for that reason.

B<Parameters:>

=over 4

=item C<$top>

A C<Genesis::Top> on the repository, which is asked for each environment's
deployment branch and for the control branch's name.

=item C<$git>

A C<Service::Git> handle on the same repository.

=item C<envs>

The environments to classify, which is the whole topology rather than one
run's scope.

=item C<refreshed>

The result the refresh returned.  A caller that has not refreshed leaves it
out and this stage refreshes for itself.

=item C<control>

The record C<require_control> returned.  A caller that has not asked leaves it
out and this stage asks for itself.

=item C<command>

The command's name, which the refusals' opening sentence is built from, as in
"Refusing to run C<genesis propagate>".

=item C<action>

The whole act, for a command that names itself in its own words rather than by
its invocation, which is the option C<require_control> reads by the same name.

=item C<outcome>

The refusals' closing sentence, which says what did not happen.  It is
"Nothing was written." unless the caller says otherwise.

=item C<dry_run>

True where the run reports and writes nothing, which the stages below this one
read.  The stage then also says, under the caveats' own sentence shape, that
its answer assumes a fast-forward nobody has made.

=item C<read_only>

True where the caller only ever reports, as C<genesis pipeline-status> does.
The stage moves no branch, exactly as under C<dry_run>, and says nothing about
a preview, because nobody is about to make the run those caveats are about.
It also raises none of the illegal-state refusals below, since those stand in
front of the propagate run's first write and this caller makes none.  The
branches are still classified, and each record says which class it fell in, so
a caller reading them back can describe the branch rather than being refused
over it.  The three states this admits are the unpushed hand commit, the
branch the remote has never had, and the branch that shares no ancestor with
the remote's.  A hand commit that was pushed is not among them: an in-sync
branch has no local-only commit for the classification to find, so that one
was never refused to begin with.

=back

B<Returns:> A hashref of four keys.

=over 4

=item C<refreshed>

True once the refresh has run, whether this stage ran it or the caller did.

=item C<control>

The divergence record for the control branch.

=item C<branches>

One record per environment that has a branch on either side, keyed by the
environment's name.  A branch this stage reset carries C<reset> set on its
record and one it fast-forwarded carries C<fast_forwarded>, and either way
C<state> is then C<in-sync> and both counts are 0, because the branch stands
on its tracking ref.  C<unrelated> is 1 where this branch and the remote's of
the same name share no commit, which the divergence states cannot say on their
own, since an orphan and an ordinary divergence both hold the name on both
sides.  Under C<dry_run> or C<read_only> no record is settled
that way.  The one
the stage would have moved carries C<assumed>, which is the ref a real run
would have left the branch on, and its C<state> and counts are the ones the
classification wrote, with C<assumed_move> beside it naming which move it
escaped, C<reset> or C<fast-forward>, and C<assumed_commits> saying how many
commits a reset would discard.

=item C<events>

The lines the caller prints.  They are seeded from the control record, and
the reset and fast-forward lines are appended to them in that order, so the
caller prints the whole stage's events once and in order.

=back

B<Errors:> Bails once at C<DATAERR> for every illegal initial state the stage
found, in one refusal that names each offending branch under the class it
belongs to, unless C<read_only> is set, which reports every one of them
instead.  A local deployment branch the remote has never had and one that
shares no ancestor with the remote's are each given the remedy in order, which
is to inspect the branch, move anything wanted to control, delete the branch,
and then run the command the case calls for.  Genesis deletes nothing itself.
A branch carrying a local-only commit with no propagation marker is named with
every such commit, both of the branch's counts, and the command for each of
the two ways out, which are to push the commit or to move the change to
control and reset the branch.  No option performs either, so the refusal is
the whole path out.  The refresh and the control check raise their own codes
where the caller has left them to this stage.

B<Examples:>

  my $initial = Genesis::CI::Preflight::initial_state($top, $git,
      envs      => \@dag_order,
      refreshed => $refreshed,
      control   => $control_state,
      command   => 'propagate');
  info("  #Gi{%s}", $_) for @{$initial->{events}};
  # $initial->{branches}{qa}{state} is 'in-sync'

  Genesis::CI::Preflight::initial_state($top, $git, envs => ['lab']);
  # refuses at DATAERR where lab/bosh is a branch origin has never had

  my $initial = Genesis::CI::Preflight::initial_state($top, $git,
      envs => ['qa'], refreshed => $refreshed, control => $control_state);
  # $initial->{branches}{qa}{reset} is 1, and $initial->{events} carries
  # 'reset qa/bosh to origin/qa/bosh, discarding 1 commit that the walk
  # reproduces'

  my $initial = Genesis::CI::Preflight::initial_state($top, $git,
      envs => ['qa'], refreshed => $refreshed, control => $control_state);
  # where a teammate published a delivery this clone had not seen,
  # $initial->{branches}{qa}{fast_forwarded} is 1, its state is 'in-sync',
  # and $initial->{events} carries
  # 'fast-forwarded qa/bosh to origin/qa/bosh, 1 commit behind'

  my $initial = Genesis::CI::Preflight::initial_state($top, $git,
      envs => ['qa'], refreshed => $refreshed, control => $control_state,
      dry_run => 1);
  # the same repository under a dry run leaves the branch behind, and
  # $initial->{branches}{qa}{assumed} is 'refs/remotes/origin/qa/bosh',
  # which is the ref the walk takes its diff base from

=head2 initial_state_problems($top, $git, %opts)

  my ($state, @problems) = Genesis::CI::Preflight::initial_state_problems(
      $top, $git, envs => \@envs, tracking => 'refs/genesis/preflight/origin');

What L</initial_state($top, $git, %opts)> asks of every deployment branch,
read against the view of R the caller names, which D115's run gives as its
snapshot, and answered as problems at C<DATAERR>, one per paragraph of the
refusal the stage would have raised: the branches R never had, then the ones
sharing no ancestor with R's, then the ones carrying a commit no marker
accounts for. L</refuse_once(%opts)> joins paragraphs as that refusal did, so
the run's one refusal reads it word for word. Nothing moves. The resets it
found are left on the state under C<reset>, and each branch's standing under
C<branches>, for the run to make once it proceeds.

B<Parameters:>

=over 4

=item C<envs>

The environments whose deployment branches are asked about.

=item C<tracking>

Optional. The view of R the branches are measured against, T where it is not
given.

=back

B<Returns:> The state, then the problems, empty where every branch may be
walked from.

B<Errors:> Whatever the git reads raise, as for
L</local_only_commits($git, $branch)>.

B<Examples:>

  my ($state, @problems) = initial_state_problems($top, $git,
      envs => ['qa', 'lab'], tracking => 'refs/genesis/preflight/origin');
  # returns ($state, problem(DATAERR, "The local branch qa/bosh ...")) where
  # qa/bosh carries a hand commit, with lab's standing behind R in $state

=head2 shares_history($git, $branch, $remote)

  my $shared = Genesis::CI::Preflight::shares_history($git, $branch, $remote);

Answers whether a local branch and its counterpart on the remote have a commit
in common.

It is called from outside this class, because C<Genesis::Commands::Env> asks it
before it offers to reset a deployment branch.  So the name and the arguments
are a documented seam rather than this file's own business, and a change to
either reaches that caller.

The question is asked through C<Genesis::run> with C<passfail> on and C<stderr>
off rather than through C<Service::Git::merge_base>, which folds git's standard
error into the value it hands back.  A ref this clone cannot resolve makes
C<git merge-base> print a message and exit non-zero, and a folded message is a
truthy string, so a reader that took the value would read a missing ref as a
shared ancestor and let the branch through.  The command's status is the whole
answer here, and the two states that answer no, a pair with no common commit
and a ref that is not there, are both states the stage refuses.

B<Parameters:>

=over 4

=item C<$git>

A C<Service::Git> handle on the repository to read.

=item C<$branch>

The deployment branch, named as git names it.

=item C<$remote>

The remote whose tracking ref the branch is compared against.

=item C<tracking>

Optional. The ref prefix the remote's copy is read under in place of
C<refs/remotes/E<lt>remoteE<gt>>, such as D115's snapshot.

=back

B<Returns:> 1 where the two share a commit, and 0 where they share none or
where either ref cannot be resolved.

B<Examples:>

  Genesis::CI::Preflight::shares_history($git, 'qa/bosh', 'origin');
  # 1, where the branch was cut from origin/qa/bosh

  Genesis::CI::Preflight::shares_history($git, 'qa/bosh', 'origin');
  # 0, where the local branch is an orphan of the same name

=head2 _illegal_state_refusal

    my $text = Genesis::CI::Preflight::_illegal_state_refusal(
        $action, $outcome, $remote, \@local_only, \@unrelated, \@hand);

Frames whichever illegal initial states the stage found as one refusal.

The stage raises at most one refusal, so the act is named once and the closing
sentence is said once however many branches and however many classes the run
met.  The three classes come in the order the stage asks about them, which is
the branch the remote has never had, then the branch that shares no ancestor
with the remote's, then the branch carrying a commit no marker accounts for.
The act and the closing sentence are arguments, because the deploy raises the
same text in its own words.

It was named for the two origin classes while it carried only those.  A hand
commit is not a question about where a branch came from, so the name moved to
what all three have in common, which is that each is an initial state the
design calls illegal.

B<Parameters:>

=over 4

=item C<$action>

The act the refusal opens with, as in C<run genesis propagate>.

=item C<$outcome>

The closing sentence, which says what did not happen.

=item C<$remote>

The remote the branches were classified against.

=item C<\@local_only>

The branches the remote has never had, one hashref each of C<env> and
C<branch>.  It may be empty.

=item C<\@unrelated>

The names of the branches that share no ancestor with their counterpart.  It
may be empty.

=item C<\@hand>

The branches carrying a local-only commit with no marker, as
C<_hand_commit_refusal> takes them.  It may be empty.

=back

B<Returns:> The composed refusal, which the caller hands to C<bail> through a
C<'%s'> format.

B<Examples:>

  Genesis::CI::Preflight::_illegal_state_refusal(
      'run #C{genesis propagate}', 'Nothing was written.', 'origin',
      [{env => 'lab', branch => 'lab/bosh'}], [], []);
  # 'Refusing to run #C{genesis propagate}.  The local branch #C{lab/bosh}
  #  has no counterpart on #C{origin}.  ...  Nothing was written.'

  Genesis::CI::Preflight::_illegal_state_refusal(
      'run #C{genesis propagate}', 'Nothing was written.', 'origin',
      [{env => 'lab', branch => 'lab/bosh'}], [],
      [{branch => 'qa/bosh', ahead => 1, behind => 0, commits => \@commits}]);
  # one refusal naming lab/bosh and then qa/bosh, with one opening sentence
  # and one closing sentence

=head2 _hand_commit_refusal

    my @block = Genesis::CI::Preflight::_hand_commit_refusal(
        $remote, \@offenders);

Composes the paragraphs for deployment branches carrying a local commit that
no remote has and that carries no propagation marker.

It lists each branch with the short sha and the subject of every markerless
commit, so the operator can see what has to be dealt with without going to
look for it, and it then gives both counts and the command for each of the two
ways out.  No flag does the operator's half of either, because the change
belongs on control and the friction of moving it there by hand is the point.

It answers with one block rather than a paragraph per branch, since the
opening sentence and the indented list are shared and a block per branch would
say the opening once for every offender.  The act the refusal opens with and
the sentence it closes with belong to C<_illegal_state_refusal>, which frames
whichever classes the stage found.

The counts belong to the branch and the list does not.  A branch carrying a
marker commit beside a hand commit reads as ahead by two over a list of one,
which is right, because the counts say how the branch stands against the
remote while the list says what has to be dealt with.

B<Parameters:>

=over 4

=item C<$remote>

The remote the branches are measured against.

=item C<\@offenders>

One hashref per branch, carrying C<branch>, C<ahead>, C<behind>, and
C<commits>, where C<commits> holds the markerless commits alone, as
C<local_only_commits> returns them.

=back

B<Returns:> The one composed block, or the empty list where there are no
offenders, so the frame can join it with its siblings unconditionally.

B<Examples:>

  Genesis::CI::Preflight::_hand_commit_refusal('origin',
      [{branch => 'qa/bosh', ahead => 1, behind => 0,
        commits => [{short => 'a1b2c3d', subject => 'patch it by hand'}]}]);
  # 'These branches carry a commit the remote does not have ...
  #  #C{qa/bosh} is ahead of #C{origin/qa/bosh} by 1 commit and behind it by
  #  0 commits.  ...'

  Genesis::CI::Preflight::_hand_commit_refusal('origin', []);
  # ()
