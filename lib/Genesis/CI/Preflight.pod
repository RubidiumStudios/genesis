=head1 NAME

Genesis::CI::Preflight - the initial state a propagation run may find

=head1 SYNOPSIS

  use Genesis::CI::Preflight;

  my @stranded = Genesis::CI::Preflight::local_only_commits($git, 'qa/bosh');

=head1 DESCRIPTION

The first stage of a propagation run settles what the repository holds before
anything is written.  It refreshes, it requires the control branch to exist
and to be in step with the remote, it refuses a deployment branch with no
legitimate origin, it resets a branch whose only local commits are ones a
re-run reproduces, and it fast-forwards a branch that is merely behind.  A
violation is an illegal initial state, so the run stops before it writes and
the refusal names the branch and the way out.

Each refusal spends a named exit code rather than a number.  Control that
exists nowhere is a configuration fault and exits C<CONFIG>, an initial state
the design calls illegal exits C<DATAERR>, and a remote this clone cannot
reach exits C<TEMPFAIL>, which is the one of the three a pipeline job may
retry.

=head1 FUNCTIONS

=head2 local_only_commits($git, $branch)

  my @stranded = Genesis::CI::Preflight::local_only_commits($git, $branch);

Lists the commits the branch holds that no remote has, newest first, as a
hashref each of C<sha>, C<short>, C<subject>, and C<marker>.  C<marker> is the
control commit that commit's propagation marker names, and it is C<undef> for
a hand edit.  That is the whole classification the stage needs: a commit with
a marker is one a re-run reproduces, so the branch can be reset to its
tracking ref, and a commit without one is an operator's hand edit, which
nothing here may discard.

The query runs C<git log E<lt>branchE<gt> --not --remotes>, so what counts as
local-only is decided against the remote-tracking refs this clone holds.  It
must therefore run before any prune, because a prune removes exactly the refs
that answer it and a pruned clone reports every commit on the branch as
stranded.  C<Service::Git::fetch_branches> never prunes, which is what keeps
this query honest across a refresh.

Each commit is classified by asking C<Genesis::CI::Marker::newest> for the
newest marker within a walk of one, so this module carries no second reader
of the marker.

B<Parameters:>

=over 4

=item C<$git>

A C<Service::Git> handle on the repository to read.

=item C<$branch>

The branch to walk, named as git names it.

=back

B<Returns:> A list of hashrefs, newest commit first, empty where the branch
holds nothing a remote lacks.

B<Errors:> Bails when C<git log> fails, which is a branch this repository
cannot read rather than a state the stage reports.

B<Examples:>

  my @stranded = Genesis::CI::Preflight::local_only_commits($git, 'qa/bosh');
  # ( { sha => 'a1b2...', short => 'a1b2c3d',
  #     subject => '[pipeline] control@9f8e7d6 -> qa',
  #     marker  => '9f8e7d6c5b4a...' } )

  Genesis::CI::Preflight::local_only_commits($git, 'prod/bosh');
  # () where every commit on the branch has been pushed

=head2 require_control($top, $git, %opts)

  my $state = Genesis::CI::Preflight::require_control($top, $git,
      refreshed => $result, command => 'propagate');

Settles the control branch before anything else is read.  Control is where the
environment files live, so a run that cannot trust it cannot trust a single
answer it goes on to give, and every command in this stage asks this question
first.

Three things can be true of control, and each has one answer.  Where the
remote has the branch and this clone does not, the refresh has already written
the local ref, and the creation comes back as an event line for the caller to
print rather than passing in silence.  Where the branch exists nowhere, the
command refuses, and it creates nothing, because cutting the branch that
becomes the repository's source of truth is the operator's act and not
Genesis'.  Where both places have it, the two have to agree, because an
unpushed control holds commits a deploy on another machine cannot read, since
a propagation marker names a control commit by its sha alone, and because a
stale control would propagate state a teammate has already moved past.
Genesis never moves control in either direction, so both are refusals rather
than repairs.

B<Parameters:>

=over 4

=item C<$top>

A C<Genesis::Top> on the repository, which is asked for the control branch's
name.

=item C<$git>

A C<Service::Git> handle on the same repository.

=item C<refreshed>

The result the refresh returned, whose C<created> list is what the event line
is composed from.  A caller that did not refresh leaves it out.

=item C<command>

The command's name, which the refusal's opening sentence is built from, as in
"Refusing to run C<genesis propagate>".

=item C<action>

The whole act, for a command that names itself in its own words rather than by
its invocation.  The deploy passes C<deploy>, so its refusal opens "Refusing
to deploy".

=item C<outcome>

The refusal's closing sentence, which says what did not happen.  It is
"Nothing was written." unless the caller says otherwise.

=item C<unverifiable>

Passed through to C<resolve_branch> for a caller that read without refreshing,
so the divergence it gets back says so.

=item C<on_divergence>

C<refuse> by default, and C<report> for the two commands that read without
resolving, which are C<genesis pipeline-status> and the deploy.  Every command
that writes takes the default, because a divergence on control reaches the
remote through whatever it writes.  A branch that exists nowhere is refused
either way, since it leaves the command nothing at all to read.

=back

B<Returns:> A hashref of C<divergence>, the record C<resolve_branch> gives for
control, and C<events>, the lines the caller prints.  C<events> holds one line
where the refresh created the local ref, which reads "created control from
origin/control", and is empty otherwise.

B<Errors:> Bails at C<CONFIG> when the control branch exists neither on the
remote nor locally, naming the branch and both places and telling the operator
to create and push it.  Bails at C<DATAERR> for every one of the five states
the design calls illegal, which are ahead, behind, diverged, local only, and
remote only, naming what is true of the branch and the one command that fixes
it.  The remote-only refusal is the one that says the refresh should have
written the local ref and did not, which is what a working tree standing on an
unborn control does to it, so it asks for the ref to be written rather than
reading a staleness out of two counts that are both zero.  Where the
repository has no remote configured at all, the local-only refusal asks for a
remote instead of printing a push command with nothing to push to.  No refusal
writes anything, and no path here moves control.

B<Examples:>

  my $state = Genesis::CI::Preflight::require_control($top, $git,
      refreshed => $result, command => 'propagate');
  info("  #Gi{%s}", $_) for @{$state->{events}};
  # $state->{divergence} is { state => 'in-sync', ahead => 0,
  #                           behind => 0, unverifiable => 0 }

  Genesis::CI::Preflight::require_control($top, $git,
      refreshed     => $result,
      action        => 'deploy',
      outcome       => 'Nothing was deployed.',
      on_divergence => 'report');
  # refuses a control branch that is nowhere, and reports every other state
  # back to a caller that resolves nothing

=head1 INTERNAL FUNCTIONS

Every public entry of this module goes above this heading, under
C<FUNCTIONS>.  What follows documents the subs this module keeps to itself.

=head2 _commits

    my $phrase = Genesis::CI::Preflight::_commits($n);

Spells a commit count as English, so a refusal reads aloud at one commit as
well as at four.

A refusal that said "by 1 commits" would be read past rather than read, and
the sentences around it agree with the number the same way, so the caller asks
this for the phrase and picks its own verb from the count.

B<Parameters:>

=over 4

=item C<$n>

A count of commits.

=back

B<Returns:> The count and its noun, as in C<1 commit> or C<4 commits>.

B<Examples:>

  Genesis::CI::Preflight::_commits(1);
  # '1 commit'

  Genesis::CI::Preflight::_commits(4);
  # '4 commits'
