=head1 NAME

Genesis::CI::Shuttle::S3 - the keys an S3 shuttle block reads

=head1 SYNOPSIS

    my $declared = Genesis::CI::Shuttle::S3->options_schema;

    # Selected by the configuration, not constructed:
    #   pipeline:
    #     shuttle:
    #       backend:  s3
    #       bucket:   genesis-signals
    #       region:   us-east-1
    #       endpoint: https://minio.internal
    #       auth:     secret/ci/s3

=head1 DESCRIPTION

The backend L<Genesis::CI::Shuttle> dispatches to, selected by
C<backend: s3> under C<pipeline.shuttle>. It declares the keys the S3
shuttle resource reads and inherits its validation from the base, having no
rule a declaration cannot state.

The region and the endpoint are declared here rather than on the block
because S3 is the backend that reads them. C<auth> is the vault reference
to this backend's credentials, and the configuration surface calls it by
that name too. How one reference becomes the access key and the secret key
the emitted resource takes is the emitter's question and not this file's.

=head1 CLASS METHODS

=head2 options_schema()

    my $declared = Genesis::CI::Shuttle::S3->options_schema;

The seven keys an S3 shuttle block may carry: C<bucket>, which is required,
C<region>, C<endpoint>, and C<auth>; C<tls_skip_verify>, false by default,
for a store whose certificate cannot be verified (contract a9); and C<image>
and C<image_tag>, which default to the shuttle resource at C<latest>.

B<Returns:> a hash reference of key name to schema entry.
