=head1 NAME

Genesis::CI::Shuttle::S3 - the keys an S3 shuttle block reads

=head1 SYNOPSIS

    my $declared = Genesis::CI::Shuttle::S3->options_schema;

    # Selected by the configuration, not constructed:
    #   pipeline:
    #     shuttle:
    #       backend:  s3
    #       bucket:   genesis-signals
    #       region:   us-east-1
    #       endpoint: https://minio.internal
    #       auth:     secret/ci/s3

=head1 DESCRIPTION

One of the two backends L<Genesis::CI::Shuttle> dispatches to, selected by
C<backend: s3> under C<pipeline.shuttle>. It declares the keys the S3
shuttle resource reads and inherits its validation from the base, having no
rule a declaration cannot state.

The region and the endpoint are declared here rather than on the block
because S3 is the backend that reads them. C<auth> is the vault reference
to this backend's credentials, which is what D23 and the configuration
surface both call it; how one reference becomes the access key and the
secret key the emitted resource takes is the emitter's question, filed as
FWT-1153, and not this file's.

=head1 CLASS METHODS

=head2 options_schema()

    my $declared = Genesis::CI::Shuttle::S3->options_schema;

The six keys an S3 shuttle block may carry: C<bucket>, which is required,
C<region>, C<endpoint>, and C<auth>, and C<image> and C<image_tag>, which
default to the community shuttle resource at C<latest>.

B<Returns:> a hash reference of key name to schema entry.
