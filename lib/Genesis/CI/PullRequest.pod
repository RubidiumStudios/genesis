=head1 NAME

Genesis::CI::PullRequest - the pull request arm of the propagate run

=head1 SYNOPSIS

    use Genesis::CI::PullRequest;

    # Once, at the top of the run, and only where an environment in scope
    # needs the API at all.
    my $github = Genesis::CI::PullRequest::client_for_run($top,
        records => \@in_scope, refuse => $refuse);

    # Before the run writes anything, for every environment that delivers
    # into a pull request.  A run that cannot read this refuses.
    my $state = Genesis::CI::PullRequest::pr_state($github,
        'acme/deployments', $env_record, refuse => $refuse);

    # Inside the run's open session, for one environment whose policy says
    # its branch may only ever receive a proposal.
    my $word = Genesis::CI::PullRequest::deliver($session, $env_record,
        env     => $env,
        commits => \@pending,
        state   => $state);

    # Once the branch has published, and not before.
    Genesis::CI::PullRequest::sync_pull_request($github, 'acme/deployments',
        $env_record, env => $env);

=head1 DESCRIPTION

An environment in pull request mode takes its propagation on
C<< <pr_prefix><env>/<type> >> as one aggregate commit, and a pull request
from there into C<< <env>/<type> >>. This module owns that aggregate, the
rule that reads what a reviewer decided, and the proposed record's lifecycle.

The pull request branch is derived state under D51. It is rebuilt from the
deployment branch on every run rather than appended to, so what stands on it
is always exactly one commit above the branch the pull request is opened
against, and a run that is declined or aborted can put the branch back
without having to work out which commits on it were its own.

Nothing here opens a session. The arm writes inside the run's own session,
because the run owes the operator their branch back whatever happens and a
second session could not promise that.

C<deliver> is never imported. The test harness exports a helper of the same
name that the rows in this area also call, so the two are kept apart by
always naming this one in full.

=head1 FUNCTIONS

=head2 align_with_remote($git, $branch)

    my $aligned = Genesis::CI::PullRequest::align_with_remote($git,
        'pr/qa/bosh');

Brings the local pull request branch level with what the remote carries, and
says whether the remote carried it at all.

The discard report reads what is about to be destroyed, and what is about to
be destroyed is what the remote carries, so the local ref has to be level
with the remote before it is read. The run's own refresh fetches control and
the deployment branches alone, because those are the branches the pre-flight
classifies, so the pull request branch is fetched here, by the arm that is
about to stand on it.

The fetch runs on every call. This is the only thing that writes that
remote-tracking ref, so from the second run for an environment onward the ref
holds the previous run's tip, and a fetch skipped over a ref that is merely
present would reset the branch to yesterday's value.

The reset is a hard one and moves the checked-out branch, so the caller is
already standing on the branch it names.

B<Parameters:>

=over 4

=item C<$git>

The repository handle.

=item C<$branch>

The pull request branch.

=back

B<Returns:> 1 where the remote carried the branch and the local ref is now
level with it, and 0 where the remote has no such branch or the repository
has no remote at all.

B<Errors:> Whatever the fetch or the reset raises.

B<Examples:>

    align_with_remote($git, 'pr/qa/bosh');
    # returns 1, with the checked-out branch now at origin/pr/qa/bosh

    align_with_remote($git, 'pr/prod/bosh');
    # returns 0, and touches nothing, where the remote has never had it

=head2 aggregate_message($git, $env, $commits, %opts)

    my $message = Genesis::CI::PullRequest::aggregate_message($git, $env,
        \@pending);

The aggregate commit's whole message.

The subject is the marker naming the newest commit in C<$commits>, and the
body lists every commit oldest first with its short hash, its subject, and
its C<diff --stat> lines within the environment's propagation set as that set
stood at the delivered commit. The pull request carries that body verbatim,
so the commit and the pull request can never disagree about what is being
proposed.

The sha in the subject is abbreviated, which is the form every other builder
in the tree hands the marker. Nothing downstream loses by it:
C<Genesis::CI::Marker::in_text> parses four to forty hex digits, so the
subject is still the machine-read marker, and a reader wanting the whole sha
resolves the abbreviation through the git handle it already holds, which is
what the marker's own contract asks of it.

The set is read at the commit being delivered rather than from the working
tree, through the same reader C<< $session->apply_files >> uses, because a
restructure moves the prefix that defines the set and a body scoped by
today's configuration would name files the delivery did not move.

The sha of each commit is read under the name the walk writes on a pending
entry, which is C<control_commit>.

Each entry's summary is taken of the commit itself rather than between it and
its parent, because control's own first commit has no parent and an
environment introduced there has that commit due on its first run.

B<Parameters:>

=over 4

=item C<$git>

The repository handle, used to abbreviate each sha and to take each
summary.

=item C<$env>

The environment being delivered, which is what names the propagation set and
what the marker addresses.

=item C<$commits>

The due control commits, oldest first, each carrying C<control_commit> and
C<subject>.

=item C<%opts>

C<gate>, C<supersedes>, and C<review> each append one closing paragraph, in
that order, where the caller has one.

=back

B<Returns:> The whole message as one string, ending in a single newline.

B<Errors:> Whatever the marker builder raises for a sha or an environment it
will not accept, and whatever C<< $git->commit_stat >> raises for a commit
the repository cannot summarise.

B<Examples:>

    aggregate_message($git, $env, [
        {control_commit => $a, subject => 'Raise the instance count'},
        {control_commit => $b, subject => 'Rotate the uaa signing key'},
    ]);
    # returns "[pipeline] control\@a1b2c3d -> prod\n\n" .
    #         "Carries 2 control commits:\n\n" .
    #         "9e8d7c6 Raise the instance count\n" .
    #         " prod.yml | 2 ++\n 1 file changed, 2 insertions(+)\n\n" .
    #         "a1b2c3d Rotate the uaa signing key\n" .
    #         " prod.yml | 1 +\n 1 file changed, 1 insertion(+)\n"

=head2 gate_line($commit, $held)

    my $line = Genesis::CI::PullRequest::gate_line($newest,
        {count => 2, env => 'prod'});

The one paragraph an aggregate's body carries when a gate ends the delivery,
naming the reason the C<Genesis-Stage> trailer gave and how many of that
environment's commits are held behind it.

D49, as it was corrected on 2026-09-09, has a gate constrain only what
follows it. So the gate travels with the commits already ahead of it and ends
the delivery there, and this line is what tells a reviewer why the pull
request stops where it does.

The reason is read under C<gate_reason>, which is the name the walk writes it
by on every entry the gate governs. C<gate> beside it is the gate's own
commit, and a line that printed that would name a sha where the trailer wrote
a sentence.

A gate standing on control's own tip holds nothing, and the sentence about
what waits is left off there rather than said of nought commits. The gate is
still named, because the reviewer is being asked to deploy it before anything
later lands, and that is true whether or not anything later exists yet.

B<Parameters:>

=over 4

=item C<$commit>

Any entry the walk marked with this gate, whose C<gate_reason> is the text
the trailer gave. That is one of the entries the gate holds where it holds
anything, and the gate's own pending entry where it does not.

=item C<$held>

C<count> is how many of the environment's commits wait behind the gate, and
C<env> is the environment they wait for.

=back

B<Returns:> The paragraph as one string, with no trailing newline.

B<Examples:>

    gate_line({gate_reason => 'rotate the signing key first'},
              {count => 1, env => 'prod'});
    # returns 'Gate: rotate the signing key first. Holding 1 later ' .
    #         'commit for prod until this deploys.'

    gate_line({gate_reason => 'rotate the signing key first.'},
              {count => 0, env => 'prod'});
    # returns 'Gate: rotate the signing key first.'

=head2 review_paragraph($number, $review [, %opts])

    my $said = Genesis::CI::PullRequest::review_paragraph(7, $review,
        opening => 'Changes were requested');

Returns the paragraph that quotes a reviewer, with the pull request's number,
the reviewer, the date, and the review's own text quoted. C<opening> and
C<prefix> give the caller its own opening sentence. Returns C<undef> when the
review carried no text.

Two bodies quote a reviewer and they are the same paragraph. D49 has a
superseding body carry the rejection text of the attempt it replaces, and D56
has a rebuild that answers a request for changes name the review it answers.
One renderer writes both, so the quoting cannot drift apart between them.

B<Parameters:>

=over 4

=item C<$number>

The number of the pull request the review was left on, which is the attempt
being superseded for D49 and the pull request being rebuilt for D56.

=item C<$review>

The decisive review C<pr_state> carried, whose C<body> is the reviewer's own
text, C<reviewer> their login, and C<at> the time they submitted it. The date
is taken off the front of C<at> and left out where there is none.

=item C<%opts>

C<opening> is the sentence the paragraph opens on, and defaults to C<Changes
were requested>. C<prefix> is put in front of that opening, which is where the
superseding body says which attempt it is talking about.

=back

B<Returns:> The paragraph as one string, the opening sentence on its own line
and the reviewer's text quoted beneath it, or C<undef> where the review
carried no text to quote.

B<Examples:>

    review_paragraph(7, {reviewer => 'dbell', body => 'Not yet.',
                         at => '2026-09-13T00:00:00Z'});
    # returns "Changes were requested on #7 by dbell on 2026-09-13:\n" .
    #         '> Not yet.'

    review_paragraph(7, {reviewer => 'dbell', body => ''});
    # returns undef

=head2 supersedes_paragraph($rejected)

    my $said = Genesis::CI::PullRequest::supersedes_paragraph(
        $state->{rejected});

Returns the closing paragraph the body of a superseding pull request carries,
which quotes the reviewer and their words where the API gave one and otherwise
names the closed pull requests and links to them. Returns C<undef> when
nothing was closed without merging.

A rejection deliberately leaves nothing behind. The pull request is closed,
its branch is rebuilt in place because it is derived state, and the only place
the chain of attempts can be recorded is the pull request that follows. So the
paragraph names every attempt, and it quotes the one that said why.

A merged pull request is never a prior attempt, and C<pr_state> never puts one
in the list this reads, so a merged pull request is never named here either.

An attempt the API answered with no C<html_url> is named without the colon and
the link, rather than ending the sentence on a colon with nothing after it.
Nothing reaches that, since every pull request GitHub answers carries the
field, so it stands for one that has gone missing.

B<Parameters:>

=over 4

=item C<$rejected>

The closed-unmerged pull requests C<pr_state> answered under C<rejected>, each
with its C<number>, its C<html_url>, and the decisive C<review> where one was
left.

=back

B<Returns:> The paragraph as one string, or C<undef> where nothing was closed
without merging.

B<Examples:>

    supersedes_paragraph([
        {number => 7, html_url => 'https://github.test/o/r/pull/7',
         review => {reviewer => 'dbell', body => 'Not yet.',
                    at => '2026-09-13T00:00:00Z'}},
        {number => 8, html_url => 'https://github.test/o/r/pull/8'},
    ]);
    # returns "Supersedes #7. Changes were requested on #7 by dbell on " .
    #         "2026-09-13:\n> Not yet.\n\n" .
    #         'Supersedes #8, closed without merging: ' .
    #         'https://github.test/o/r/pull/8.'

=head2 forget_lost_branch($git, $branch [, %opts])

    my $lost = Genesis::CI::PullRequest::forget_lost_branch($git,
        'pr/qa/bosh');

Asks the remote about the pull request branch and answers whether the remote
has lost it, taking the leftover refs off where it has.

The remote is authoritative for whether this branch exists, because the branch
is derived state this run publishes and nobody else keeps. A branch somebody
removed there leaves two refs behind in the clone, the local one and the
remote-tracking one, and both of them say the remote still has it until
something asks. The tracking ref is the one that costs, because the expected
tip is read off it and a lease against a value the remote has not got is
refused on this run and on every run after it.

So the local ref and the tracking ref both go, and the arm then cuts the
branch again from the deployment branch, which is where it comes from every
run anyway. The local ref is what made the next cycle's creation meet a name
that was already taken, and this is what closes that.

The remote is asked by C<ls-remote> and not by a fetch, which matters. A fetch
would bring the tracking ref up to date, and the expected tip read just after
this is the one value in the run that has to come off a ref nobody refreshed,
because that is what catches a teammate who moved the branch after the run
read it. The probe answers the existence question without touching a ref. A
probe that could not be run says nothing about the branch and takes nothing
off, because an unreachable remote is the publish's to answer.

B<Parameters:>

=over 4

=item C<$git>

The repository the refs are read and removed in.

=item C<$branch>

The pull request branch to ask about.

=item C<%opts>

C<dry_run> gets the same answer with neither ref taken off, because a ref
removed is a write like any other.

=back

B<Returns:> 1 where the remote has lost the branch, and 0 where it still has
it, where neither ref is here to be lost, where there is no remote, and where
the probe failed.

B<Errors:> Whatever the tracking-ref removal or the local deletion raises.

B<Examples:>

    forget_lost_branch($git, 'pr/qa/bosh');
    # returns 1, with the local ref and origin/pr/qa/bosh both gone

    forget_lost_branch($git, 'pr/qa/bosh', dry_run => 1);
    # returns 1, with both refs still standing

=head2 expected_tip($git, $pr_branch)

    my $expected = Genesis::CI::PullRequest::expected_tip($git, 'pr/prod/bosh');

Returns the pull request branch's value on the remote as the run's refresh
read it, or C<undef> when the remote does not carry the branch. The publish
pushes against this value, so a branch someone moved since the refresh has its
own push rejected and no other branch in the run is affected.

It is read before the arm fetches the branch and rewrites it, because a read
taken afterwards would name the value this run is about to overwrite, and the
lease would then be against a teammate's commit rather than against the one
the run reasoned from. That is the whole window D51 asks the expected tip to
close.

The C<undef> is the answer for a branch the remote has never had, and it is
carried onto the push spec as C<expect> all the same, because
C<Service::Git::_push_one> reads that key with C<exists> and turns the C<undef>
into C<Service::Git::NULL_SHA>. A spec that dropped the key instead would be
pushed with no lease at all.

B<Parameters:>

=over 4

=item C<$git>

The C<Service::Git> handle onto the operator's repository. Its default remote
is what R is read through, and a repository with no remote answers C<undef>,
since there is nothing to publish to and so nothing to lease against.

=item C<$pr_branch>

The pull request branch's name, without a remote on the front of it.

=back

B<Returns:> the full sha the remote-tracking ref names, or C<undef>.

B<Examples:>

    expected_tip($git, 'pr/prod/bosh');
    # returns 'd1f65205d4b31d65dc81864dfc0f56a73b6bd74c' where the remote
    # carries the branch, and undef where it does not

=head2 freeze($record, $commits)

    my $word = Genesis::CI::PullRequest::freeze($record, \@pending);

Takes the approved arm of D51. It writes nothing, holds every due commit with
the reason C<awaiting-merge> and the pull request's number, and answers
C<undef>, so the report settles the environment as C<held> with the qualifier
C<Genesis::CI::Report::held_qualifier> composes.

Rebuilding a branch somebody has already approved would throw that review
away, and on a repository that does not dismiss stale approvals it would leave
the approval standing over a change nobody read. So the branch is left exactly
as the reviewer saw it, and the merge is what releases the commits waiting
behind it on a later run. A long-stale approval is the operator's to merge or
to dismiss, and the run never dismisses one for them.

It answers C<undef> rather than a word because the outcome is the bare enum
word C<held> and the qualifier beside it is composed where every other hold's
qualifier is, so C<genesis propagate>, its dry run, and C<genesis
pipeline-status> all read one phrase from one place.

B<Parameters:>

=over 4

=item C<$record>

The walk's per-environment record. Its C<pr> is the pull request object, whose
C<number> each held entry carries and whose C<action> is set to C<freeze>; its
C<pending> is emptied and its C<held> is what the commits move onto.

=item C<$commits>

The arrayref of due control commits, oldest first, each with its
C<control_commit> and its C<subject>.

=back

B<Returns:> C<undef>, always.

B<Examples:>

    freeze($record, [{control_commit => '1a2b3c4', subject => 'Raise it'}]);
    # returns undef, with $record->{pending} emptied and $record->{held}
    # carrying {reason => 'awaiting-merge', number => 42}, which the report
    # renders as "awaiting merge (#42)"

=head2 discard_report($git, $branch, $base)

    my $report = Genesis::CI::PullRequest::discard_report(
        $git, 'pr/prod/bosh', 'prod/bosh');

Returns a hashref of C<count> and C<authors> for the commits on the pull
request branch above C<$base> that carry no propagation marker, which are the
ones this run did not write, or C<undef> when there are none.

The branch is derived state, reproducible from the deployment branch and the
due commits, so rebuilding it every run is right. I4 still forbids resolving a
divergence silently, so the arm reads what the rebuild is about to destroy and
names it before the reset takes it off.

A commit a propagate run wrote carries a marker naming a control commit, so
anything above the deployment branch without one was pushed onto the branch by
hand. The marker is asked for without naming an environment, because a commit
carrying any marker at all was written by a run and none of them is a hand
push.

Both refs are read locally. The caller has just brought the local pull request
branch level with R, and the deployment branch's local ref is the one the
delivery is about to be made from, so reading C<origin/> on one side and the
working ref on the other would compare two different moments.

The range is walked once. C<Service::Git::log_subjects> splits a record into
the sha and everything after the first unit separator, so a format that puts
the author between the sha and the body hands the author back at the head of
the message and the message behind it, and one call answers all three fields.
The authors are kept as a set, because nothing reads a count per author.

B<Parameters:>

=over 4

=item C<$git>

The C<Service::Git> handle onto the operator's repository.

=item C<$branch>

The pull request branch's name, which the caller has already brought level
with the remote. A branch this repository does not carry answers C<undef>.

=item C<$base>

The deployment branch's name, which is the other side of the range and the
commit the rebuild is about to reset onto.

=back

B<Returns:> a hashref of C<count> and C<authors>, where C<authors> is the
distinct author names sorted, or C<undef> when the run wrote every commit on
the branch.

B<Examples:>

    discard_report($git, 'pr/prod/bosh', 'prod/bosh');
    # returns {count => 2, authors => ['A Teammate']} where a teammate has
    # pushed twice, and undef where nobody has

=head2 discard_line($branch, $report)

    my $line = Genesis::CI::PullRequest::discard_line(
        'pr/prod/bosh', $report);

Renders what C<discard_report> answered as the one qualifier the run prints
beside the environment's outcome. The count is pluralised and the authors are
joined with commas, so the operator reads how much work is going and whose it
was.

The C<by> clause is rendered only where there is a name to put in it. git
refuses an empty author, so a report with no names at all is not something an
operator will meet, but the reader counts a commit whose author it could not
read and a clause composed unconditionally would render C<by ,> on one.

B<Parameters:>

=over 4

=item C<$branch>

The pull request branch's name, which the line names so an operator with
several environments in the report can tell whose work it was.

=item C<$report>

The hashref C<discard_report> answered. Nothing calls this with C<undef>,
because the caller takes this arm only where there is a report to render.

=back

B<Returns:> the qualifier as a string, without the outcome word in front of
it.

B<Examples:>

    discard_line('pr/prod/bosh', {count => 2, authors => ['A Teammate']});
    # returns '2 commits on pr/prod/bosh that this run did not write, by
    # A Teammate, discarded by the rebuild'

    discard_line('pr/prod/bosh', {count => 1, authors => []});
    # returns '1 commit on pr/prod/bosh that this run did not write,
    # discarded by the rebuild'

=head2 settled($git, $pr_branch, $newest, $tree)

    my $bool = Genesis::CI::PullRequest::settled($git, $pr_branch,
        $newest_due_sha, $tree);

Returns true when the pull request branch on the remote already carries the
newest due control commit as its marker and holds the same tree the rebuild
would write, which is what makes a repeated run push nothing and touch no
pull request.

D48 makes idempotency the marker walk on both branches rather than a match on
the tip's subject. The subject broke three ways. A squash or an amend rewrote
it and re-propagated, an edited subject re-propagated, and a short hash that
happened to appear in somebody else's subject suppressed a real propagation.
The marker reader walks subjects and bodies alike and skips commits carrying
no marker, so all three read correctly here.

The marker alone is not enough. A branch can name the right control commit
and still hold a different tree, because the propagation set may have moved
or a file may have been changed under it, so the tree the writer has just
built is compared against the tree the branch carries and only a branch that
matches on both is settled.

The remote is asked for by name rather than spelled C<origin>, for the reason
C<expected_tip> gives: C<align_with_remote> reads the same ref through the
same accessor a few lines above, and the two must not disagree about which
remote R is.

B<Parameters:>

=over 4

=item C<$git>

The run's git handle, standing on the repository the branch lives in.

=item C<$pr_branch>

The pull request branch's local name. The remote's copy of it is what is
read, because R is what a push would move.

=item C<$newest>

The newest due control commit's sha, which is what the marker on a settled
branch names.

=item C<$tree>

The tree the rebuild would write, read off the commit the single writer has
already built.

=back

B<Returns:> C<1> or C<0>. C<0> where the clone has no remote, where R does not
have the branch, where the branch carries no marker at all, where its newest
marker names another commit, or where the trees differ.

A marker naming a commit this clone has never fetched falls under the same
C<0>. L<Genesis::CI::Marker/newest> hands such a marker back at the width the
delivery wrote it, which cannot equal a full sha, so the branch reads
unsettled and the run propagates again. That is the safe direction to be
wrong in, and it is what the predicate this sub replaced did too, because a
branch this clone cannot name is one it should rebuild rather than skip.

B<Examples:>

    settled($git, 'pr/qa/bosh', $newest, $tree);
    # returns 1 when R's pr/qa/bosh names $newest and holds $tree

=head2 deliver($session, $record, %opts)

    my $word = Genesis::CI::PullRequest::deliver($session, $record,
        env     => $env,
        commits => \@pending,
        state   => $state);

Delivers one environment's due commits onto its pull request branch as one
aggregate commit and returns that environment's outcome word, or C<undef>
where the report is to settle the environment itself.

The session is already open, and the branch is rebuilt from the deployment
branch on every run, because it is derived state. The switch cuts the branch
where neither this repository nor the remote holds it, and the session
records the absence so a run that is declined or aborted can take it off
again.

An environment with nothing due takes C<retire_branch> instead, ahead of
everything below, where the branch still stands on either side or a proposed
record still points at a proposal. R's copy is asked for through the expected
tip, which is the value this arm has just read off that very ref.

An environment holding commits is never retired, whatever stands on either
side. The walk sends every held commit to C<held> and leaves nothing pending,
so an environment waiting on the merge of its own open pull request arrives
here with nothing due, and a retirement would take the branch, the pull
request, and the proposed record away while the report settled the
environment as held and named the merge it was waiting for.

An environment whose pull request a reviewer has approved takes C<freeze>
instead, ahead of everything below, so nothing is built and nothing is
pushed. That state is read off C<< $record->{pr} >> for the reason the
supersedes paragraph's is.

A run given C<dry_run> stops above the switch and answers C<undef>, because
everything below that line writes and a preview writes nothing. The report
then settles the environment as one that would propagate, which is the answer
the direct arm's preview gives, and no word about a run that never happened
reaches the record.

The single writer is called once, at the newest due commit's source. D69
makes a delivery a mirror, so the mirror of the newest commit is the whole
aggregate's tree, and the writer's own index assertions run against that same
commit.

The message it writes is what C<aggregate_message> composes, so the one
commit says which control commits it carries and what each of them changed,
and the pull request opened from it carries that same body.

Where a gate ends the delivery, the body closes with the paragraph
C<gate_line> composes, which names the reason the trailer gave and how many
of that environment's commits are held behind it.

Which gate that is comes off the walk's record rather than off the newest
commit delivered. C<Genesis::CI::Walk::gate_state> reads the trailer over
every control commit in range whatever it touched, so a gate that changes
nothing in this environment's propagation set holds every commit after it
while never becoming a pending entry at all, and the aggregate then ends
before the gate rather than at it. The count is of what this gate holds for
this environment, so a commit stopped for another reason is not named twice.

Where every pull request the environment has had was closed without merging,
the body closes with the paragraph C<supersedes_paragraph> composes, which
names each of those attempts and quotes whoever asked for the change. That
state is read off C<< $record->{pr} >> rather than off C<state> itself,
because a run given no token at all is handed no state and the record already
carries the one copy every reader here takes.

Where a reviewer asked for changes and the fix has landed on control, the body
closes with the paragraph C<review_paragraph> composes, opening on C<Changes
were requested>, so a reviewer who comes back to a rebuilt branch reads their
own words above the aggregate that answers them. It is the renderer the
superseding body uses, given a different opening sentence, so no second body
in this module quotes a reviewer. That state is read off C<< $record->{pr} >>
for the same reason the supersedes paragraph's is.

Once the writer has built the aggregate, the branch is asked whether it is
settled, which C<settled> answers from the marker on R's copy of it and from
the two trees. A branch that is settled has the run reset it back to what R
carries, and the environment reads C<idempotent>, so nothing is pushed and no
pull request is touched. A branch this run has just reported a discard on is
never settled, because the discard is the thing that makes it differ.

What the publish and the pull request sync read afterwards is left on
C<< $record->{pr} >>: the action, the control commit the aggregate names, the
title and the body, and the commit that was written.

B<Parameters:>

=over 4

=item C<$session>

The run's open branch session, which is what the switch and the write go
through.

=item C<$record>

The walk's per-environment record. Its C<pr> is the pull request object the
walk composed, and its C<branch> is the deployment branch the aggregate is
built from and the pull request is opened against.

=item C<%opts>

C<env> is the L<Genesis::Env> whose propagation set the writer reads,
C<commits> is the arrayref of due control commits, oldest first, C<state>
is what C<pr_state> answered for this environment, which the caller read
before the run began and hands in rather than having the arm ask the API
again, and C<dry_run> says this is a preview, which reads everything a run
reads and writes none of it.

=back

B<Returns:> C<propagated> where an aggregate was written, C<idempotent> where
nothing was due, and C<undef> where the report is to settle the environment
itself, which is a freeze and a preview.

B<Errors:>

=over 4

=item *

C<< "Genesis::CI::PullRequest::deliver was handed %s, which the walk composed
no pull request branch for" >> -- raised via C<bug()> where the record has no
C<pr>, because an environment reaching this arm without one is a walk that
disagrees with the dispatch about which environments deliver this way.

=item *

Whatever the switch, the reset, or the single writer raises.

=back

B<Examples:>

    deliver($session, $record, env => $env, commits => \@pending);
    # returns 'propagated', with one aggregate commit on pr/qa/bosh

    deliver($session, $record, env => $env, commits => []);
    # returns 'idempotent', having written nothing

    deliver($session, $record, env => $env, commits => \@pending);
    # returns 'idempotent' again on a repeat, where R's branch already
    # names the newest due commit and holds the same tree

    deliver($session, $record, env => $env, commits => \@pending,
        state => {state => 'approved', number => 42});
    # returns undef, having frozen the branch and held every due commit

=head2 retire_branch($session, $record [, %opts])

    my $word = Genesis::CI::PullRequest::retire_branch($session, $record,
        env      => $env,
        rejected => $state->{rejected});

Deletes the environment's pull request branch locally and marks it for
deletion on the remote, takes any closed attempt's branch with it, and deletes
the proposed record. Called when nothing is due for the environment, which is
the case after the pull request merges or after a rejection.

A rejection leaves no persistent state, and neither does a merge, so a branch
with nothing due has nothing left to say. The local refs go now, because
nothing later in the run reads one and a leftover is what made the next
cycle's branch creation die on a name that already existed. The remote refs go
through the publish instead, one push each, so what this writes onto the
record is the list C<_nothing_due_specs> reads rather than the removal itself.

B<Parameters:>

=over 4

=item C<$session>

The run's open branch session, which the local deletions go through.

=item C<$record>

The walk's per-environment record. Its C<pr> is the pull request object, whose
C<action> is set to C<delete> and whose C<retire> becomes the list of branches
the remote still carries.

=item C<%opts>

C<env> is the L<Genesis::Env> whose proposed record is deleted, C<rejected> is
the arrayref of closed-unmerged pull requests, whose head branches go with the
environment's own, and C<dry_run> marks the same branches and takes none of
them off.

=back

B<Returns:> C<idempotent>, always.

B<Examples:>

    retire_branch($session, $record, env => $env, rejected => []);
    # returns 'idempotent', with pr/qa/bosh gone from the clone, listed
    # under $record->{pr}{retire}, and the proposed record deleted

    retire_branch($session, $record, env => $env, dry_run => 1);
    # returns 'idempotent', having listed the same branches and deleted
    # nothing at all

=head2 client_for_run($top [, %opts])

    my $github = Genesis::CI::PullRequest::client_for_run($top,
        records => $record->{environments},
        refuse  => $refuse);

Returns one C<Service::Github> client for the whole run, built against the
owner half of the pair the source-control block resolves, or C<undef> where
no environment in scope has a proposed record and none would deliver into a
pull request, and also where no token is set. A run that needs no client
makes no call at all, not even to authenticate.

An environment needs the API when it has a proposed record or would deliver
into a pull request, whatever its hold state, because a hold set while a pull
request was open leaves that pull request to be read for the report. Both
facts are read off the records the caller hands in, so nothing here asks the
topology a second time.

The client authenticates once as it is built, which is what makes one client
serve the whole run rather than one per environment, and it asks the one
question no reader below can check for itself: who the token belongs to. An
endpoint that answers and names nobody is answering for somebody else, and the
readers cannot tell that from a repository with no pull request open, so the
run stops rather than propose again what it has already proposed.

An API that will not answer at all is left to the readers. C<pr_state> gives
every failure to read GitHub one refusal, at C<UNAVAILABLE> and in the
reader's own words, and a token the API rejects arrives there with the rest,
so only an answered call is refused here.

A run given no token carries on and says so. Its branches are still written
and published, and the next run with a token opens the pull requests they are
waiting for.

B<Parameters:>

=over 4

=item C<$top>

The run's L<Genesis::Top>, which the C<owner/repo> pair is resolved through.

=item C<%opts>

C<records> is an arrayref of per-environment records, each read for C<pr> and
C<proposed> and for nothing else, defaulting to an empty list and so to no
client. C<refuse> is the caller's own refusal closure, which a caller inside
an open session passes so the operator is put back on their branch before they
are told why the run stopped.

=back

B<Returns:> A C<Service::Github> client, or C<undef> where the run needs none
and where no token is set.

B<Errors:> Refuses with C<CONFIG> where an environment would deliver into a
pull request and C<pipeline.source_control.repository> is neither set nor
derivable from a git remote, naming the key to write. Refuses where the
authentication call is answered and the answer names no user. An
authentication call that is not answered raises nothing here.

B<Examples:>

    client_for_run($top, records => [{pr => {branch => 'pr/prod/bosh'}}]);
    # returns a Service::Github built against the owner of the pair

    client_for_run($top, records => [{pr => undef, proposed => undef}]);
    # returns undef, and the run makes no call to the API

=head2 pr_state($github, $owner_repo, $record, %opts)

    my $state = Genesis::CI::PullRequest::pr_state($github,
        'acme/deployments', {
            env    => 'prod',
            branch => 'prod/bosh',
            pr     => {branch => 'pr/prod/bosh'},
        }, refuse => $refuse);

Reads the environment's pull request and what a reviewer decided about it, and
returns a hashref of C<state>, C<number>, C<url>, C<title>, C<body>,
C<review>, C<rejected>, C<superseded>, and C<merged>. C<state> is one of
C<none>, C<unreviewed>, C<approved>, C<changes requested>, and C<closed
unmerged>.

C<merged> carries the merged pull requests, which the recovery reads;
C<rejected> carries the closed-unmerged ones themselves, so a commit body can
quote one; and C<superseded> carries their numbers, which is what the
aggregate's title names. Where more than one pull request is open from the
same branch, the one the API lists first is acted on and a warning names the
rest. GitHub's listing answers newest first, so that is the newest of them.

When either reader fails, this is not a fifth state but a refusal. The whole
run stops, naming the review state as the input it could not read, and exits
C<UNAVAILABLE>, because a run that cannot read what a reviewer decided cannot
know what it would do with any pull request branch.

Every failure of the two readers refuses that way, and none of them is passed
through. A token the API rejects, a repository that has been renamed, a rate
limit, and an API nobody can reach all arrive here as one refusal, because
the readers raise their own already-worded message and the code behind it
cannot be told from the message cheaply. The refusal therefore quotes what
the reader said and leaves the operator to read it, rather than claiming a
retry is what will help.

B<Parameters:>

=over 4

=item C<$github>

The run's L<Service::Github> client.

=item C<$owner_repo>

The C<owner/repo> pair the source-control block resolves.

=item C<$record>

A hashref naming the environment, under C<env>; its deployment branch, under
C<branch>; and its pull request branch, under C<< pr->{branch} >>. The walk's
own per-environment record carries all three, and so does a hashref composed
from L<Genesis::Top>'s two branch accessors, which is how the run reads every
environment's state before the walk has composed anything.

=item C<%opts>

C<refuse> is the caller's own refusal closure, which a caller inside an open
session passes so the operator is put back on their branch before they are
told why the run stopped. A caller with no session leaves it out.

=back

B<Returns:> A hashref of the nine fields above.

B<Errors:> The refusal described above, which is what every failure of the
two GitHub readers becomes. Nothing they raise is passed through.

B<Examples:>

    pr_state($github, 'acme/deployments', $record);
    # returns {state => 'approved', number => 42, ...}

    pr_state($github, 'acme/deployments', $record);
    # returns {state => 'none', number => undef, superseded => [], ...}

=head2 refuse_unreadable($env, $why, %opts)

    Genesis::CI::PullRequest::refuse_unreadable('prod', $@,
        refuse => $refuse);

Stops the run because the review state could not be read, naming the
environment and quoting what the reader said.

The refusal is whole-run rather than per environment, and it exits
C<UNAVAILABLE> (69), because the API is the service the run could not get an
answer out of. L<Genesis::Exit> declares codes and no subs, so the exit is
named through C<bail>, the way every other refusal in the tree names one.

It does not tell the operator to retry. Every failure of the two readers
arrives here, a rejected token and a renamed repository among them, and a
retry helps none of those. What the reader said is quoted instead, and that
is what says whether waiting or fixing something is the answer.

The quoted text is stripped of the wrapping the reader's own C<bail> put on
it. Inside an eval that C<bail> dies with its message already wrapped to the
terminal and already prefixed C<[FATAL]> on every line, and interpolating
that into a second refusal would give the operator a banner in the middle of
a paragraph and two different wrap widths. The prefix, the colour, and the
hard wrap within each paragraph all go, so the refusal wraps the whole thing
once.

B<Parameters:>

=over 4

=item C<$env>

The environment whose pull request could not be read.

=item C<$why>

What the reader said, usually C<$@>. Trailing whitespace is trimmed.

=item C<%opts>

C<refuse> is the caller's own refusal closure, used in place of C<bail> where
the caller has a session to close first.

=back

B<Returns:> Nothing. It does not return.

B<Errors:> The refusal itself, at C<UNAVAILABLE>.

B<Examples:>

    refuse_unreadable('prod', "HTTP 599 - curl failed\n");
    # exits 69, having said what it could not read and what fixes it

=head2 recover_marker($pr, %opts)

    my ($sha, $drifted) = Genesis::CI::PullRequest::recover_marker(
        $merged, env => 'prod', git => $git, ref => 'prod/bosh');

Returns the control commit a merged pull request's title or body names for the
environment in C<env>, and, where the text carries a marker for some other
environment instead, returns that text as a second value so the caller can say
which of the two it met. The pull request was written by Genesis, so nothing
here is inferred from somebody else's prose.

D52 makes rebase the only merge method a deployment branch allows, and
C<genesis pipeline-apply> sets it with the rest of the protection. Where the
GitHub user lacks the permission to grant that setting, C<pipeline-apply> says
so and the run carries on, and a squash then rewrites the aggregate's subject
and body and takes the marker off the branch with them. This is where the run
gets it back.

The text is read twice, once for this environment's marker and once for
whatever environment the markers in it do name, because a text carrying a
marker for another environment is a different thing from a text carrying none
and only the second read tells them apart. Both reads go through
L<Genesis::CI::Marker>, and the first goes through its recovery arm so that
the sha comes back resolved against this repository rather than at the width
the marker was written.

The pull request itself is handed in rather than fetched. The state query
fetched every closed one before the walk began, so a reader that went back to
the API for the text would spend a call on an answer the run is already
holding.

B<Parameters:>

=over 4

=item C<$pr>

The merged pull request as the state query fetched it, read for its C<title>
and its C<body>.

=item C<%opts>

C<env> is the environment the marker has to name. C<git> is the handle the sha
is resolved through, and C<ref> is the environment's deployment branch, which
is named for the reader's sake and never walked here.

=back

B<Returns:> Two values. The control commit and C<undef> where the text carries
a marker for this environment; C<undef> and the text where it carries one
naming some other environment; and C<undef> twice where it names none at all.

B<Errors:> Raises a bug where no pull request is given, there being nothing
else the marker could be read out of.

B<Examples:>

    recover_marker($merged, env => 'prod', git => $git, ref => 'prod/bosh');
    # returns ('9f1c...', undef) for a title naming prod

=head2 certified_marker($git, $github, $owner_repo, $record, $state [, %opts])

    my $marker = Genesis::CI::PullRequest::certified_marker(
        $git, $github, $owner_repo, $env_record, $state, ref => $ref);

Returns the control commit the environment's deployment branch last received,
taking it from the branch's own newest marker and falling back to the merged
pull requests' text where the branch carries none. A recovery is reported
beside the environment's outcome through L<Genesis::CI::Report/note_detail>
and nowhere else. A marker naming another environment is warned about by name
and never taken.

The merged pull requests are asked in the order C<pr_state> hands them over,
which is the order the API lists them in and so is newest first. The newest
merge is the one that says where the branch stands now, and an older one taken
ahead of it would name a commit the branch has already received and send the
run to propose everything above it a second time.

The branch always answers first, and answers alone where it can, which is why
the ref the pre-flight settled is passed in rather than composed here. A dry
run reads the ref a real run would have moved the branch to, and a reader that
spelled the remote ref itself would answer about a different commit than the
walk around it.

B<Parameters:>

=over 4

=item C<$git>

The run's git handle, standing on the repository the branch lives in.

=item C<$github>

The run's C<Service::Github> client, or C<undef> where the run has none. A run
without one gets the branch's own answer and no recovery.

=item C<$owner_repo>

The C<owner/repo> pair the pull requests were opened against.

=item C<$record>

The environment's record, which is read for C<env> and written to under
C<outcome_detail> where a recovery happens.

=item C<$state>

What C<pr_state> answered for this environment, whose C<merged> list is what
the recovery reads. C<undef> where the run read no state, which again leaves
the branch's own answer standing.

=item C<%opts>

C<ref> is the ref the branch's marker is read off, defaulting to the record's
own branch.

=back

B<Returns:> The control commit as a full sha, or C<undef> where the branch
carries no marker and no merged pull request names one for this environment.

B<Examples:>

    certified_marker($git, $gh, 'acme/ops', $record, $state, ref => $ref);
    # returns '9f1c...' and notes 'recovered the marker for prod from #7'

=head2 title_for($subject, $superseded)

    my $title = Genesis::CI::PullRequest::title_for($subject, [7, 9]);

Returns the pull request's title, which is the aggregate commit's subject,
with C<(supersedes #a, #b)> appended when there are closed-unmerged attempts
to name.

D49 puts the marker in the title as well as in the subject, so a squash merge
keeps it. The supersedes list is named by number rather than by branch, under
D12, because a number survives a closed pull request and a deleted branch
where a branch name does not.

The title is composed on every sync and not only when the pull request is
opened, which is what displaces FWT-1099's criterion that an open pull request
keeps the title it was opened with. A title left alone names whatever control
commit the first proposal carried, and a branch since rebuilt on a newer one
would then be described by a marker that is no longer true of it.

B<Parameters:>

=over 4

=item C<$subject>

The aggregate commit's subject line, which is the marker naming the newest
control commit the pull request proposes.

=item C<$superseded>

An arrayref of the numbers of the closed-unmerged pull requests this one
supersedes, which C<pr_state> answers under the same name. An empty arrayref
and C<undef> both mean there are none.

=back

B<Returns:> The title as one string.

B<Examples:>

    title_for('[pipeline] control@a1b2c3d -> prod', []);
    # returns '[pipeline] control@a1b2c3d -> prod'

    title_for('[pipeline] control@a1b2c3d -> prod', [7, 9]);
    # returns '[pipeline] control@a1b2c3d -> prod (supersedes #7, #9)'

=head2 sync_pull_request($github, $owner_repo, $record, %opts)

    my $pr = Genesis::CI::PullRequest::sync_pull_request($github,
        'acme/deployments', $record, env => $env);

Opens the environment's pull request or updates the open one with the title
and the body the aggregate produced, then writes the proposed record from
what the API answered.

It runs after the branch has published, because a pull request is opened from
a branch the remote holds and a run whose push was refused has nothing to open
one from. The proposed record is written here for the same reason: it points
at a pull request, and until the branch publishes there is none to point at.

The title goes through C<title_for> on the update as well as on the open, so a
pull request that is already open is retitled to the marker the branch now
carries rather than keeping the one it was opened with.

That composed title is a local and never goes back onto the record. The
record's own title is the aggregate's subject, and a second call that read the
composed one back would append the supersedes list to a title already carrying
it.

B<Parameters:>

=over 4

=item C<$github>

The run's L<Service::Github> client.

=item C<$owner_repo>

The C<owner/repo> pair the source-control block resolves.

=item C<$record>

The walk's per-environment record, whose C<pr> the arm has already filled in.

=item C<%opts>

C<env> is the L<Genesis::Env> whose proposed record is written.

=back

B<Returns:> The record's own C<pr>, now carrying the number and the url the
API answered with, or C<undef> where the environment has no pull request
object or the arm did not rebuild its branch.

B<Errors:> Whatever L<Service::Github> raises on the create or the update, and
whatever the proposed record's write raises.

B<Examples:>

    sync_pull_request($github, 'acme/deployments', $record, env => $env);
    # returns the pr, whose number and url are the API's own, and writes
    # them to $env->proposed_record_path

    sync_pull_request($github, 'acme/deployments', $record, env => $env);
    # returns undef, where nothing was rebuilt and there is nothing to open
