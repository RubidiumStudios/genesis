=head1 NAME

Genesis::CI::Report - the propagate run's report, on I8's three axes

=head1 SYNOPSIS

    use Genesis::CI::Report;

    # The whole of a finished run, once the session has put the operator
    # back on the branch they started from.
    Genesis::CI::Report::render_run($record, git => $git);

    # What --dry-run prints, which is the same report in two verbs of its
    # own, over a record nothing was written from.
    Genesis::CI::Report::render_preview($record, git => $git);

    # An aborted run, where nothing was published and only the
    # environment axis has anything true to say.
    Genesis::CI::Report::render_run($record, outcomes_only => 1);

    # The caveats a preview carries.  render_preview calls this for
    # itself once the banner has gone out, so a caller that renders a
    # preview never calls it.
    Genesis::CI::Report::preview_warnings($record);

=head1 DESCRIPTION

Every word an operator reads about an outcome is composed here, and
C<genesis pipeline-status> renders the same record through the same helpers,
so the two outputs cannot disagree about a phrase.

The report stands on three axes, and every one of them is exhaustive.  Each
environment in scope carries exactly one outcome, each control commit the
walk routed to an environment carries one of its own, and each file the
writer overwrote a hand edit on carries a third.  Nothing is silently
omitted: an environment with nothing due reads C<idempotent> rather than
being left out, and a held commit carries the reason somebody has to clear.
A quiet run and a blocked one have to read differently, which is the whole
reason the module exists.

The environment axis takes one of seven words, which are C<propagated>,
C<idempotent>, C<failed>, C<not attempted>, C<held>, C<publish rejected>, and
C<not published>.  The word stands alone in the record's C<outcome> field and
whatever qualifies it stands beside it in C<outcome_detail>, so a caller
deciding what status a run exits with matches one whole word rather than
cutting a phrase apart.  The commit axis takes C<delivered> or C<held>, and
the file axis takes C<overwrote-hand-edit>.

A preview changes two verbs and nothing else.  C<propagated> reads C<would
propagate> and C<delivered> reads C<would deliver>, because a preview says
what would happen rather than what did.  The environment's verb is written
into the record by L</render_preview>, which is the only thing that knows the
run did not happen, and the commit's is composed as the line is printed,
because nothing writes a per-commit outcome until the publish does.

The module also declares C<AWAITING_APPLY>, which is the qualifier an
environment the pipeline has never been applied to carries, and one with no
deployment branch on either side carries with it.  It is a constant rather
than a phrase each caller spells, because L</held_qualifier> is the one thing
that answers it: C<genesis propagate> meets the branchless environment before
the walk has anything to say about it and carries on past it without writing
a word.

=head1 FUNCTIONS

=head2 hold_reason

    my $words = Genesis::CI::Report::hold_reason($held);

One held commit's reason, in the form the design fixes.

The words are exact, so that C<genesis propagate>, its dry run, and the
routing column of C<genesis pipeline-status> can never disagree about one.
The overlap form carries the ancestor's own state and the never-certified
form carries no such clause, an environment that has never deployed being
already clear about why.  A commit held behind a gate reads C<< gate:
<reason> >> with the trailer's own text and no held prefix, because the gate
is a step somebody has to take rather than a state the pipeline works its own
way out of.  An ancestor this run could not read at all reads C<< held by
<ancestor>, which could not be read >>, since an ancestor nobody can read is
neither certified nor uncertified.  A commit standing behind one the run has
already held reads C<< held behind control@<sha> >>, naming that commit in
the marker's short form.  A commit stopped by the environment's own
propagation hold reads C<< held (<reason>) >> carrying the reason somebody
wrote on the hold record, rather than the word C<on-hold>, because what an
operator has to clear is that reason and not the state's own name.  A commit
held because the environment's pull request has been approved and frozen
reads C<< awaiting merge (#<number>) >>, naming the pull request an operator
merges to release it.  An entry carrying that reason and no number falls
through to the bare C<< held (<reason>) >> form rather than printing an empty
number, which nothing in the tree produces:
C<Genesis::CI::PullRequest::freeze> is the only writer of the reason and it
always writes the number beside it.

B<Parameters:>

=over 4

=item C<$held>

One entry of an environment record's C<held> list.

=back

B<Returns:> The reason as one line of prose.

B<Examples:>

  my $words = Genesis::CI::Report::hold_reason($held);
  # returns "held by lab (ops/shared.yml), lab awaiting deployment"

  hold_reason({reason => 'awaiting-merge', number => 42});
  # returns "awaiting merge (#42)"

  hold_reason({reason => 'awaiting-merge'});
  # returns "held (awaiting-merge)"

=head2 held_qualifier

    my $words = Genesis::CI::Report::held_qualifier($env_record);

What one held environment waits for, or undefined where nothing holds it.

It says what the environment waits for rather than why any one commit is
held.  An environment the pipeline was never applied to waits for that
command, and so does one with no deployment branch on either side, which the
walk leaves with no certified state at all because it reads nothing else
about it.  One holding commits behind an ancestor waits for that ancestor to
certify the commit it has not deployed, and one holding commits behind a gate
waits on its own deployment of the gate, which is the commit the phrase then
names.  An environment whose pull request a reviewer has approved reads C<<
awaiting merge (#<number>) >> and waits for that merge rather than for
anybody to certify anything, so that wording outranks the ancestor one.

The frozen entry is picked out of the C<held> list by its reason rather than
taken off the front of it.  The walk sends every commit from the first hold
backwards to C<held>, so an environment with a gate or an ancestor hold in
range arrives with that list already full and the freeze's own entries behind
what is there, and reading the front would name a deployment while what
releases the environment is the merge.  An entry carrying the reason and no
number falls through to the ancestor wording rather than printing an empty
number, which nothing in the tree produces:
C<Genesis::CI::PullRequest::freeze> is the only writer of the reason and it
always writes the number beside it.

Two certification states answer the apply, and they answer it in one wording.
C<never-applied> is an environment whose deployment record carries no control
commit, waiting for the apply to write one, and C<no-branch> is an environment
whose deployment branch neither side holds, waiting for the apply to cut it.
They are ranked together here so that the run and C<genesis pipeline-status>
cannot word the wait apart.

An environment with a propagation hold standing against it reads C<< needs
clearing (<reason>) >> ahead of any of those, the never-applied answer
included, because a hold is a decision somebody made for a reason the pipeline
cannot see and only a person clears it, so it outranks whatever the commits
underneath it happen to be waiting for.  An environment can be in both states
at once, since both are read for every environment the run and C<genesis
pipeline-status> read, and the ranking is settled here so that the two
commands cannot rank them apart.  The hold wins because the apply is a command
the operator may run at once while the hold is a decision standing in front of
it, and an environment that read as awaiting the apply while a hold stood
would send the operator to a command that would change nothing.  Clearing the
hold leaves the apply as what the environment waits for, and L</hold_detail>
says meanwhile what the hold is holding.

A record carrying no certified state at all is read ahead of even that, and
so outranks the standing hold.  The walk fills the certified state for every
environment it reads and applies a hold only once it has, so no record the
walk builds carries a hold and no certified state together; the reading order
is what keeps the branchless environment's own phrase answerable at all,
since that absence is the only thing the record has to say about it.

It answers the qualifier alone rather than the whole phrase.  The bare word
C<held> is the record's outcome and the qualifier is what stands beside it in
C<outcome_detail>, and L</render_run> reads the two back into one line, so
the word is written in one place and spelled in one place.

B<Parameters:>

=over 4

=item C<$record>

One environment's record, as C<Genesis::CI::Walk::plan> builds it.

=back

B<Returns:> The qualifier as one line of prose, or undefined.

B<Examples:>

  my $words = Genesis::CI::Report::held_qualifier($env_record);
  # returns "awaiting deployment (lab at control@1a2b3c4)"

  held_qualifier({env => 'prod'});
  # returns "awaiting pipeline-apply" off the head guard alone, the walk
  # having read nothing about an environment with no branch on either side

  held_qualifier({env => 'prod', certified => {state => 'never-applied'}});
  # returns the same phrase for the other reason, nothing having been
  # applied to the repository at all

  held_qualifier({env => 'prod', certified => {state => 'certified'}, held => [
      {reason => 'gate-ahead', gate => '9fc836c0...'},
      {reason => 'awaiting-merge', number => 42},
  ]});
  # returns "awaiting merge (#42)", the gate at the front notwithstanding

=head2 hold_detail

    my $words = Genesis::CI::Report::hold_detail($env_record);

What the standing hold is holding, in the three wordings D56 fixes, or
undefined where no hold stands.

A hold outranks idempotent, so an environment with one standing never reads
as though it were fine, and this is the line beside L</held_qualifier> that
says which of the three situations it is in.  Where the hold itself took
commits it names how many are blocked until the hold is released.  Where
something else is holding them it says they are blocked for reasons of their
own and stay blocked while the hold stands.  Where nothing is held at all it
reads that nothing is due now and that anything becoming due stays blocked.

The count in the first of the three is of the commits the hold itself took,
and not of everything held, because a commit a gate or an ancestor had
already stopped is reported under that reason, and counting it there would
name it twice and send an operator to the wrong command.

The nothing-due wording is answered only where nothing is held either.  The
report prints this line directly above the commit lines, so an environment
whose commits a gate is holding would otherwise read that nothing is due and
then read the commits that are.

Every wording names the one command that clears the hold,
C<genesis E<lt>envE<gt> pipeline-release>, and ends by naming who set the hold
as C<< E<lt>userE<gt>@E<lt>hostnameE<gt> >> and when they set it, from the
record's own C<user>, C<hostname>, and C<at>.  Those three facts are composed
here and not beside each caller, because the run's report, C<pipeline-status>,
and C<genesis E<lt>envE<gt> deploy> all print this sentence and a sentence
spelled three times is one the three spellings drift apart on.  A field the
record is missing is named as unrecorded rather than left to print as a gap,
since a record older than the four fields D53 fixes can lack any of them.

B<Parameters:>

=over 4

=item C<$record>

One environment's record, as C<Genesis::CI::Walk::plan> builds it, after
C<Genesis::CI::Walk::apply_hold> has run over it.  The environment's name is
read from C<env> for the release command, and the identity from the C<hold>
the walk carried onto it.  A caller with no walk record at hand, as the
deploy's own hold warning has none, builds one from the hold alone.

=back

B<Returns:> The detail as one line of prose, or undefined where the record
carries no C<hold>.

B<Examples:>

  my $words = Genesis::CI::Report::hold_detail($env_record);
  # returns "2 commits are blocked until this hold is released with
  #          `genesis prod pipeline-release`, held by ana@ops.example.com
  #          at 2026-09-18 11:02:00 +0000"

  my $words = Genesis::CI::Report::hold_detail($gated_record);
  # returns "1 commit is blocked for a reason of its own, and stays blocked
  #          while this hold stands, which `genesis prod pipeline-release`
  #          clears, held by ana@ops.example.com at 2026-09-18 11:02:00 +0000"

=head2 note_detail

    Genesis::CI::Report::note_detail($record, $line);

Appends one qualifier to the environment's C<outcome_detail>, so a run with
more than one thing to say there says all of them.

I8 puts the bare enum word in C<outcome> and everything qualifying it in
C<outcome_detail>, and L</render_run> joins the two with a comma. More than
one writer has something to say there on one run: the pull request arm writes
what the rebuild discarded, and L<Genesis::CI::Publish/publish_run> writes
what the remote made of the push, and both land on the same record. A writer
that assigned the field would drop whichever line was written first, which on
a refused push is the sentence naming the work the rebuild threw away. A line
that is undefined or empty is ignored, and the qualifiers already standing
are kept in the order they were written, separated by a semicolon.

That order is a contract rather than an accident of scheduling. A record's
qualifiers appear in the order their writers run, so the delivery's sentence
about what the rebuild discarded stands ahead of the publish's sentence about
what the remote made of the push, and a run that says both says them in that
order. A caller that moves one writer ahead of another changes what an
operator reads, and should expect the rows that pin the line to say so.

It lives here rather than beside either writer, because L</render_run> is what
reads the field and a rule about how the field is filled belongs beside the
thing that prints it.

B<Parameters:>

=over 4

=item C<$record>

The walk's per-environment record, whose C<outcome_detail> is appended to in
place.

=item C<$line>

The qualifier to add. An undefined or empty line leaves the record alone.

=back

B<Returns:> the record, so a caller may chain.

B<Examples:>

    note_detail($record, 'and something else');
    # $record->{outcome_detail} reads 'what it already said; and something
    # else'

    note_detail($record, undef);
    # the record is left exactly as it stands

=head2 render_run

    Genesis::CI::Report::render_run($record, git => $git, dry_run => 0);

Prints the run's report, one block per environment.

Every environment in the record gets exactly one outcome line, every routed
control commit beneath it gets one of its own, and every file the writer
overwrote a hand edit on gets a third.  An environment with nothing due reads
C<idempotent> rather than being left out.

Where the record leaves an environment's outcome null, the renderer settles
it.  A hold that stands writes the bare word C<held> with L</held_qualifier>
beside it, and an environment with nothing standing at all writes
C<idempotent>.  The walk computes its record from durable state alone and so
cannot know either, and settling both here is what lets the run and the
preview compose the held phrase from one line of code.

An environment with a hold already standing gets L</hold_detail>'s sentence
beneath its outcome, and that sentence carries the release command itself, so
no second line beside it says the same thing in the report's own words.

An environment whose delivery in this run carried a commit with a hold trailer
gets one added line beneath its outcome, saying that a hold was set and giving
the reason, since the environment was delivered to on this run and is held
from the next one.  The line is read off the record's C<hold_set> field, which
the run writes as it writes the hold, and it is not L</held_qualifier>'s
C<held, needs clearing>, which is what the next run reads.  This one keeps a
release line of its own beneath it, because it is about a hold the run has
just set and an operator meeting it has been told nothing yet about the
command that clears it.

The paths beneath a delivered commit are printed as the operator wrote them,
which needs the C<git> handle to strip whatever deployment root the
repository is laid out under.  Without one they are printed as the writer
recorded them.

B<Parameters:>

=over 4

=item C<$record>

The run's record, as C<Genesis::CI::Walk::plan> built it and the delivery
wrote its outcomes into.

=item C<git>

The repository handle, used to print paths as the operator wrote them.
Optional.

=item C<preview>

True where L</render_preview> is rendering, which lets the environment axis
take C<would propagate> and turns the commit axis's verb over.  A caller other
than the preview leaves it out.  Optional.

=item C<outcomes_only>

True to print the environment axis alone, which is what an aborted run wants:
nothing was published, so a pending commit printed as delivered would name a
delivery the abort has just undone.  Optional.

=back

B<Returns:> True.

B<Errors:>

=over 4

=item C<< ...was handed the outcome '...' for <env>, which is not one of the words I8 fixes >>

An environment's outcome is a word outside the seven the report fixes, which
means some stage wrote a phrase of its own into a field four stages share.

=item C<< ...was handed the commit outcome '...', which is not one of the words I8 fixes >>

A routed commit's outcome is a word outside the two the report fixes.  The
guard sits in L</_commit_word>, which this sub calls once per routed commit,
so the commit axis reaches a caller here exactly as the environment axis does.

=back

B<Examples:>

  Genesis::CI::Report::render_run($record, git => $git);
  #   lab: propagated
  #     control@1a2b3c4 Tune lab  delivered
  #       M lab.yml
  #   dev: publish rejected, dev/bosh moved on R
  #     control@1a2b3c4 Tune lab
  #       M lab.yml
  #   qa: held, awaiting deployment (lab at control@1a2b3c4)
  #     control@1a2b3c4 Tune lab  held
  #       H held by lab (lab.yml), lab awaiting deployment
  #   prod: idempotent

=head2 render_preview

    Genesis::CI::Report::render_preview($record, git => $git);

C<--dry-run>'s report, under D44.

It names, per environment and per control commit, the files that would land
and whether each commit would be delivered or held and why, and it writes
nothing.  It renders the record the run renders, through L</render_run>, so
the preview and the run cannot disagree about a word, and the held forms read
as C<genesis pipeline-status>'s do under D54.

A banner goes out before the first line of the report, because an operator
who reads the report first and the banner afterwards has already believed it.

One verb is written into the record here rather than composed by the
renderer.  An environment with commits due would have propagated had this been
a run, and the preview is the only thing that knows it was not, so the word
goes in where that is known.  Everything else the record leaves null is
settled by L</render_run>, so the run and the preview compose
the held phrase from one line of code.

The two loud warnings D44 asks for go out between the banner and the first
environment, through L</preview_warnings>, so that an operator has met both
caveats before they read a line the caveats are about.

B<Parameters:>

=over 4

=item C<$record>

The run's record, as C<Genesis::CI::Walk::plan> built it.  A preview delivers
nothing, so every environment's outcome is null but for the ones the walk
itself decided.

=item C<%opts>

Everything L</render_run> takes, handed down as it stands, so a preview prints
its paths as the operator wrote them exactly as the run does.

=back

B<Returns:> True.

B<Errors:> Raises whatever L</render_run> raises.

B<Examples:>

  Genesis::CI::Report::render_preview($record, git => $git);
  #   This is a preview.  Nothing will be written.
  #
  #   lab: would propagate
  #     control@1a2b3c4 Tune lab  would deliver
  #       M lab.yml
  #   qa: held, awaiting deployment (lab at control@1a2b3c4)
  #     control@1a2b3c4 Tune lab  held
  #       H held by lab (lab.yml), lab awaiting deployment

=head2 preview_warnings

    Genesis::CI::Report::preview_warnings($record);

Warns, under the preview's banner and above its first environment, in the two
cases D44 names where the preview's answer rests on something it did not do.
L</render_preview> calls it, so nothing else has to, and it is not exported.

A control branch that is ahead of its remote is refused by a real run until
it has been pushed, so the preview says its result assumes that push.  A
deployment branch whose local commits all carry a marker is reset to the
remote by the pre-flight before a real run walks, so the preview says its
result assumes that reset.

Each caveat names how many commits it is about, and the number governs the
noun and the verb, so one unpushed commit reads "the commit ... is pushed"
and two read "the 2 commits ... are pushed".  The count is named here because
the only other place either number is said is the pre-flight's event line,
which stands above the banner, where an operator has not yet been told they
are reading a preview.

Neither warning says anything about the files the report goes on to name.  A
preview threads each delivery's tree forward into the next, so those lists
are already true of the branch as the reset would leave it.

The caveats are read off the record rather than worked out here, counts and
all.  The run has already asked git both questions, once to decide whether to
refuse the control branch and once to decide whether to reset a deployment
branch, and a renderer that asked them again would be a second reader of a
settled fact.

B<Parameters:>

=over 4

=item C<$record>

The run's record.  Its C<warnings> key holds a list of caveats, each a hashref
with a C<kind> of C<unpushed-control> or C<unreset-branch>, the C<branch> the
caveat is about, the C<remote> it is measured against, and C<commits>, which
is how many commits are unpushed or how many the reset would discard.  A
missing C<commits> reads as one.  A record with no C<warnings> key warns about
nothing, which is every run that is not a preview.

=back

B<Returns:> True.

B<Errors:> Raises a bug where a caveat carries a C<kind> that is neither of
the two, because a caveat nobody can print is a defect in whoever wrote the
record rather than something to pass over in silence.

B<Examples:>

  Genesis::CI::Report::preview_warnings({warnings => [
      {kind    => 'unpushed-control', branch => 'control',
       remote  => 'origin', commits => 2},
      {kind    => 'unreset-branch', branch => 'qa/bosh',
       remote  => 'origin', commits => 1},
  ]});
  #   This preview assumes the 2 commits on control are pushed.
  #   It is ahead of origin/control, and a real run refuses to propagate
  #   until you push them, so what follows is what would happen once you
  #   have.
  #   This preview assumes qa/bosh is reset first.
  #   A real run resets it to origin/qa/bosh before it walks, discarding
  #   1 commit, so what follows is what would happen once that reset has
  #   run.

=head2 release_command

  my $cmd = Genesis::CI::Report::release_command('prod');

The one command that clears a hold on an environment, as its words alone.

It is composed here and nowhere else, because a command spelled in two places
is a command the two spellings drift apart on.  Its callers dress it
differently and share the words: L</hold_detail> puts it in backticks, that
sentence being printed inside a colour span already, and L</render_run> puts
it in the colour every command this report names takes, on the line beneath a
hold the run has just set, and C<genesis pipeline-hold> says it plainly in
the line it prints once a hold is set.

An environment name that is undefined answers the placeholder C<< <env> >>,
which nothing in the tree produces, the walk keying every record it builds on
the environment's name.  It is there so that such a record prints something an
operator can see is wrong rather than a command with a gap in it.

B<Parameters:>

=over 4

=item C<$env_name>

The environment the command is named for.  Undefined answers the placeholder.

=back

B<Returns:> The command, as one string, with no markup of any kind on it.

B<Errors:> None.

B<Examples:>

  release_command('prod');   # 'genesis prod pipeline-release'
  release_command(undef);    # 'genesis <env> pipeline-release'

=head1 INTERNAL FUNCTIONS

=head2 _settle

    Genesis::CI::Report::_settle($env_record);

Fills the outcome an environment's record left null.

A hold that stands writes the bare word C<held> with L</held_qualifier>
beside it in C<outcome_detail>, and an environment with nothing standing at
all writes C<idempotent>.  A record that already carries an outcome is left
exactly as whoever knew wrote it, which is the walk for a failure and the run
for a delivery.

The qualifier is assigned rather than appended through L</note_detail>, and
that is right here, because nothing an environment reaching this sub can be
carrying was written into the field already.  The one writer that appends
before the report runs is the pull request arm's discard region, and an
environment that reaches that region has an outcome by the time the arm
returns, while a freeze returns above it and writes nothing there at all.

B<Parameters:>

=over 4

=item C<$env>

One environment's record.

=back

B<Returns:> The same record.

B<Examples:>

  Genesis::CI::Report::_settle($env_record);
  # $env_record->{outcome} is now 'held' or 'idempotent'

=head2 _commit_word

    my $word = Genesis::CI::Report::_commit_word('delivered', 0);

One routed commit's outcome, checked against C<COMMIT_OUTCOMES> before it is
printed.

The commit axis reads its words out of the enum the way the environment axis
reads its own, so the enum is load-bearing on all three axes rather than on
one of them.  A word from outside it is a defect in whoever wrote the record,
and the guard names it rather than printing it.  Under a preview C<delivered>
reads C<would deliver>, and C<held> reads as it stands.

A commit carrying no word at all is answered without the guard, because the
publish writes a word only onto the commits it published.  Under a preview
that is every routed commit, and each reads C<would deliver>, since a preview
publishes nothing and the verb is the one thing it has to say.  Under a run it
is a commit that went nowhere, and the answer is the empty string, so the line
carries the commit and no word about it.

B<Parameters:>

=over 4

=item C<$outcome>

The word for this commit, or undef where nothing wrote one.  A commit under
C<pending> is handed the record's own value, which the publish fills in for
what it published and leaves undef for what it did not.  A commit under
C<held> is handed the default C<held>, because every commit on that axis is
held by definition and no stage writes the word per commit.

=item C<$preview>

True where the caller is previewing.

=back

B<Returns:> The word to print, or the empty string for a commit a run wrote
no word onto.

B<Errors:> Raises a bug where the word is not one of C<COMMIT_OUTCOMES>.  A
commit with no word at all is not one of those cases.

B<Examples:>

  my $word = Genesis::CI::Report::_commit_word('delivered', 1);
  # returns 'would deliver'

=head2 _commits

  _commits(2);

Answers a count of commits with the noun agreeing, as C<1 commit> or
C<2 commits>.

C<Genesis::CI::Preflight> carries the same three lines for its refusals and
its event lines.  The shape is mirrored rather than shared, because the one
there is private to that module and a renderer reaching across for it would be
reading another stage's internals to print a noun.

B<Parameters:>

=over 4

=item C<$n>

How many commits.

=back

B<Returns:> The count and the noun, as one string.

B<Errors:> None.

B<Examples:>

  _commits(1);   # '1 commit'
  _commits(3);   # '3 commits'

=head2 _paths

    my @paths = Genesis::CI::Report::_paths($git, $pending->{delivered});

One delivery's paths as the operator wrote them.

The writer records repository paths, which carry whatever deployment root the
repository is laid out under, and an operator reads the paths they committed.
A caller with no git handle gets them as they stand, and an empty or absent
list answers the empty list.

B<Parameters:>

=over 4

=item C<$git>

The repository handle, or undefined.

=item C<$paths>

An arrayref of repository paths, or undefined.

=back

B<Returns:> The paths as a list.

B<Examples:>

  my @paths = Genesis::CI::Report::_paths($git, ['bosh/qa.yml']);
