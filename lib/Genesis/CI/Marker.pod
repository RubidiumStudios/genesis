=head1 NAME

Genesis::CI::Marker - the propagation marker and the Genesis commit trailers

=head1 SYNOPSIS

    use Genesis::CI::Marker;

    # Render the subject a delivery commits under.
    my $subject = Genesis::CI::Marker::build($control_short, 'qa');
    # '[pipeline] control@a1b2c3d -> qa'

=head1 DESCRIPTION

C<Genesis::CI::Marker> owns the propagation marker, which is the commit
subject a delivery writes onto a deployment branch to name the control
commit that branch now mirrors.  The marker is the only durable claim a
branch makes about its own content, so the string has exactly one place
where it is written and one place where it is read, and this module is
both.

=head1 FUNCTIONS

=head2 build

    my $subject = Genesis::CI::Marker::build($control_sha, $env);

Renders the marker subject, C<[pipeline] control@E<lt>shaE<gt> -E<gt>
E<lt>envE<gt>>.

The sha is written exactly as it is handed over.  Only the caller holds a
git handle, so only the caller knows which abbreviation git resolved, and a
builder that abbreviated on its own would have to guess a width.

The environment is its own name and never the deployment slug.  A marker
speaks for one deployment root because the branch it sits on already does,
so the slug's second half would say nothing the branch has not said.

B<Parameters:>

=over 4

=item C<$control_sha>

The control commit the delivery mirrors, full or abbreviated, in hex.

=item C<$env>

The receiving environment's name.

=back

B<Returns:> The marker subject as a string.

B<Errors:> Raises a bug when the sha is missing or is not hex, and when the
environment name is missing or empty.  Both are caller defects rather than
conditions an operator can cause.

B<Examples:>

  Genesis::CI::Marker::build('a1b2c3d', 'qa');
  # returns '[pipeline] control@a1b2c3d -> qa'

=head2 in_text

    my $sha  = Genesis::CI::Marker::in_text($message);
    my @shas = Genesis::CI::Marker::in_text($message);

The control shas the markers in one commit message name.

This is the one regex.  It anchors to the start of a line, so a subject
mentioning a short sha in passing cannot match, and it runs over a whole
message rather than a subject line, so a squash merge that moved the marker
into the body still answers.  One list bullet may stand between the anchor
and the marker, because a squash that collects several commit subjects
writes each of them as a bulleted line.

The sha comes back exactly as the marker carries it, abbreviated or not,
because only a caller holding a git handle can expand one.

A squash leaves more than one marker in one message, and nothing in the text
says which of them is the newest, so this sub does not choose.  It answers
every marker in the order the text lists them, and C<newest> is where a
caller holding a git handle weighs them.

B<Parameters:>

=over 4

=item C<$message>

A commit message, a pull request body, or any other text.

=back

B<Returns:> In scalar context the first marker's sha as written, or C<undef>
where the text carries no marker.  In list context every marker's sha, in the
order the text lists them, and an empty list where there is none.

B<Examples:>

  Genesis::CI::Marker::in_text("Merge pull request #7\n\n[pipeline] control\@a1b2c3d -> qa\n");
  # returns 'a1b2c3d'

  Genesis::CI::Marker::in_text("* [pipeline] control\@a1b2c3d -> qa\n");
  # returns 'a1b2c3d', because a squash may bullet the line

  Genesis::CI::Marker::in_text('note that a1b2c3d broke the build');
  # returns undef

=head2 newest

    my $sha = Genesis::CI::Marker::newest($git, $ref);
    my ($sha, $depth, $source) = Genesis::CI::Marker::newest($git, $ref);

The control commit named by the newest marker on C<$ref>, resolved to a full
sha where this repository holds the commit.

The walk skips every commit above the marker that carries none.  A hand
commit on a deployment branch is legal and temporary, and skipping it is
what keeps the branch certified to the control commit it actually mirrors.

Where one message carries several markers, which is what a squash of more
than one delivery leaves behind, the newest is the one every other names an
ancestor of.  The order the text lists them in is no guide, because git's
own squash lists the newest commit first and GitHub's lists it last.  A
marker naming a commit this repository cannot reach is not weighed at all,
and where none of them can be weighed the first marker in the text stands.

There is no fallback to a control tip.  A ref with no marker anywhere has
been delivered nothing, and C<undef> is what says so.

B<Parameters:>

=over 4

=item C<$git>

A C<Service::Git> handle.

=item C<$ref>

Any ref the walk can log, local branch or remote-tracking alike.  Reading
the remote-tracking ref is what gives a caller the marker as R has it rather
than as a lagging local branch has it.

=item C<%opts>

=over 4

=item C<limit>

Cap the walk at this many commits.  Uncapped by default, because a marker
buried under a long stack of hand commits is still the marker.  A cap of
zero is a cap at nothing rather than no cap, so the walk reads no commit and
answers as a ref carrying no marker does.

=item C<paths>

Arrayref of git-root-relative paths the walk is scoped to.

=back

=back

B<Returns:> In scalar context, the control sha, or C<undef> where no marker
stands.  In list context, three values, which are the sha, the number of
markerless commits above it, and C<'branch'>.  A ref carrying no marker gives
C<undef>, the number of commits walked, and C<undef>.

B<Examples:>

  my $sha = Genesis::CI::Marker::newest($git, 'origin/qa/bosh');
  # returns the control commit qa/bosh currently mirrors

  my (undef, $depth) = Genesis::CI::Marker::newest($git, 'qa/bosh');
  # $depth is 2 when two hand commits stand above the marker

=head2 trailers

    my $trailers = Genesis::CI::Marker::trailers($git, $commit);

The two Genesis trailers one commit carries, as a hashref of C<stage> for
C<Genesis-Stage> and C<release_stage> for C<Genesis-Release-Stage>.

A commit carrying C<Genesis-Stage> is a gate, and the trailer's value is the
reason, whose hold form reads C<hold: E<lt>reasonE<gt>>.  A commit carrying
C<Genesis-Release-Stage> releases a gate, and the value names that gate's
control commit.  What either value means is for the walk that acts on it;
this returns the value as written.

Git parses the trailer block, so where a trailer may sit and how a folded
value unfolds are git's rules and not ours.

A trailer written with nothing after it is still a trailer, so it comes back
present with an empty string for its value rather than going missing.  That
is what lets a caller refuse a gate whose reason the operator forgot, which
it could not do if an empty gate and no gate read the same way.

A key written twice on one commit comes back once, with its values joined by
a comma, which is the separator git is asked for.  Two release trailers
therefore give one value that names no commit at all, and a caller that
resolves the value finds nothing to resolve.

B<Parameters:>

=over 4

=item C<$git>

A C<Service::Git> handle.

=item C<$commit>

Any ref naming one commit.

=back

B<Returns:> A hashref carrying only the keys the commit actually has, so a
commit with neither trailer gives an empty hashref.  A commit this
repository cannot resolve gives an empty hashref as well, because a question
git refused to answer is not a gate.

B<Examples:>

  Genesis::CI::Marker::trailers($git, $gate);
  # returns {stage => 'hold: migrate the database'}

  Genesis::CI::Marker::trailers($git, $blank_gate);
  # returns {stage => ''}

  Genesis::CI::Marker::trailers($git, $ordinary);
  # returns {}

=head1 INTERNAL FUNCTIONS

Every public entry of this module goes above this heading, under
C<FUNCTIONS>.  What follows documents the subs this module keeps to itself.

=head2 _newest_of

    my $sha = Genesis::CI::Marker::_newest_of($git, @written);

The newest of the control shas one message's markers name, resolved.

Ancestry decides it rather than position, because git's own squash lists the
newest commit first and GitHub's lists it last.  A sha this repository cannot
reach never displaces one it can, so a message whose markers cannot be
weighed answers with the first of them.

B<Parameters:>

=over 4

=item C<$git>

A C<Service::Git> handle.

=item C<@written>

The shas as their markers spell them, in the order the message lists them.

=back

B<Returns:> One sha, resolved where this repository holds the commit.

B<Examples:>

  Genesis::CI::Marker::_newest_of($git, 'a1b2c3d', 'e4f5a6b');
  # returns the full sha of e4f5a6b where a1b2c3d is its ancestor

=head2 _resolved

    my $sha = Genesis::CI::Marker::_resolved($git, $written);

Expands the sha a marker carries where this repository holds the commit, and
hands back what the marker said where it does not.

B<Parameters:>

=over 4

=item C<$git>

A C<Service::Git> handle.

=item C<$written>

The sha exactly as the marker spells it.

=back

B<Returns:> A full 40-character sha, or C<$written> unchanged.

B<Examples:>

  Genesis::CI::Marker::_resolved($git, 'a1b2c3d');
  # returns 'a1b2c3d4e5f6...' where the commit is present
