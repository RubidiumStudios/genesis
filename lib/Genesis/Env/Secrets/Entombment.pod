=head1 NAME

Genesis::Env::Secrets::Entombment - Unified credhub entombment primitives

=head1 SYNOPSIS

    use Genesis::Env::Secrets::Entombment qw(
        credhub_var_name put_secret entomb_one_secret
        prime_credhub_cache
        make_local_vault shutdown_local_vault
        populate_local_vault
    );

    # Pure: deterministic credhub variable name for (path, key, value)
    my $name = credhub_var_name('secret/db', 'password', 'hunter2', '/cpi/');
    # => "/cpi/secret/db--password--abc12345"

    # Idempotent put with verify-after-set
    my $action = put_secret($credhub, $name, 'hunter2');
    # => 'new' | 'exists' | 'altered' | 'failed'

    # One-shot: name + put
    my ($credhub_ref, $action) = entomb_one_secret(
        $credhub, 'secret/db', 'password', 'hunter2', '/cpi/'
    );
    # $credhub_ref => "((/cpi/secret/db--password--abc12345))"

    # Bulk: populate a local vault with credhub-var substitutions
    # for every (path:key) in a spruce-vaultinfo-shaped map.
    my $local_vault = make_local_vault(env => $env);
    populate_local_vault(
        paths       => $paths,        # from $manifest_provider->vault_paths
        vault       => $env->vault,
        credhub     => $env->credhub,
        prefix      => 'genesis-entombed/',
        local_vault => $local_vault,
        on_action   => sub { my (%info) = @_; ... },
    );
    # ... use $local_vault as the spruce SAFE_TARGET during merge ...
    shutdown_local_vault($local_vault);

=head1 DESCRIPTION

C<Genesis::Env::Secrets::Entombment> is the single source of truth for the
"copy a secret value out of Vault and into Credhub under a deterministic
name" operation that Genesis uses in several places:

=over 4

=item *

The full-manifest entombment performed by
L<Genesis::Env::Manifest::Entombed> (and the new
L<Genesis::Env::Manifest::EntombedSelf>) during a deploy-time spruce merge.

=item *

The post-deploy CPI config upload performed by
L<Genesis::Hook::CpiConfig> when handing values to the newly-deployed
director's Credhub.

=item *

The post-deploy runtime-config upload performed by
L<Genesis::Hook::RuntimeConfig> for the same target.

=item *

The inline C<bosh-configs.director-cpi.cpis> self-upload.

=back

Before this module, each surface re-implemented the same SHA-based naming
algorithm and the same write-once Credhub put logic.  The manifest mixin
consumes this module today; the hook surfaces are being migrated onto it.

=head1 DESIGN CONSIDERATIONS

The module is arranged in three layers, and callers should reach for the
lowest one that does what they need.

=over 4

=item Naming

L</credhub_var_name> alone.  Pure, no I/O.  Use it wherever Genesis needs
to decide what a secret I<would> be called without writing anything --
rendering a reference, or checking whether a name is already in a
manifest.

=item Write

L</put_secret> for a single idempotent write, L</entomb_one_secret> for
the common name-then-write composition, and L</prime_credhub_cache> to
make a run of either cheap.

=item Bulk

L</populate_local_vault> and the local-vault lifecycle helpers, which
compose the lower layers over a whole spruce-vaultinfo path map.

=back

The split exists because the naming algorithm is the part that must not
vary between surfaces.  Every caller that writes a secret also has to
name it, and before this module each one had its own copy of the SHA
scheme -- so a change to naming silently applied to some surfaces and not
others.  Keeping naming callable on its own means a surface that only
needs a name never has a reason to reimplement one.

=head1 FUNCTIONS

All functions are exported on request via C<use Genesis::Env::Secrets::Entombment qw(...)>;
none are exported by default.

=head2 credhub_var_name

    my $name = credhub_var_name($path, $key, $value, $prefix);
    my $name = credhub_var_name($path, $key, $value);   # default prefix

Pure function.  Returns C<"${prefix}${path}--${key}--${sha8}"> where
C<sha8> is the first 8 hexadecimal characters of
C<sha1("$path--$key--$value")>.  When C<$prefix> is omitted it defaults
to C<"genesis-entombed/">.

The sha suffix lets multiple distinct values for the same C<(path, key)>
pair coexist in Credhub (e.g. during a secret rotation) without
collision.  Because the sha is derived from the value, every change in
the value produces a different variable name.

No side effects, no I/O -- safe to call repeatedly.

B<Examples:>

    credhub_var_name('secret/foo', 'password', 's3cret', '/cpi/');
    # Returns: '/cpi/secret/foo--password--abc12345'

=head2 put_secret

    my $action = put_secret($credhub, $cred_name, $value);

Idempotent write to Credhub.  Reads the current value at C<$cred_name>,
writes C<$value> only when it differs, and verifies the write by reading
back.  Returns one of:

=over 4

=item *

C<'exists'> - Credhub already had the same value; no C<set> issued.

=item *

C<'new'> - The credential didn't exist before; written and verified.

=item *

C<'altered'> - The credential existed with a different value;
overwritten and verified.

=item *

C<'failed'> - C<set> was issued but the verify-after-set returned a
mismatch.  Callers should treat this as an error.

=back

Callers performing many puts in a row should invoke L</prime_credhub_cache>
first so the existing-check is a single in-memory lookup instead of a
Credhub-CLI subprocess.

B<Examples:>

  my $action = put_secret($credhub, '/cpi/db--password--abc12345', 's3cret');
  # returns 'new' on first write, 'exists' if unchanged, 'altered' if
  # overwritten, 'failed' if the verify-after-set did not match

=head2 entomb_one_secret

    my ($credhub_ref, $action) = entomb_one_secret(
        $credhub, $path, $key, $value, $prefix
    );

Convenience wrapper.  Composes L</credhub_var_name> + L</put_secret>
and returns a two-element list:

=over 4

=item *

C<$credhub_ref> - The string C<"((${cred_name}))"> suitable for direct
YAML substitution.

=item *

C<$action> - The L</put_secret> action.

=back

B<Examples:>

  my ($ref, $action) = entomb_one_secret(
      $credhub, 'secret/db', 'password', 's3cret', '/cpi/'
  );
  # returns ('((/cpi/secret/db--password--abc12345))', 'new')

=head2 prime_credhub_cache

    prime_credhub_cache($credhub);

Calls C<< $credhub->preload >> unless C<< $credhub->is_preloaded >>
already returns true.  Safe to call repeatedly.  Returns C<$credhub>
for chaining.

C<credhub export -p $base> is a single subprocess regardless of how
many credentials live under the base path, so priming the cache before
a batch of puts amortizes the credhub-CLI cost.

B<Examples:>

  prime_credhub_cache($credhub);
  # returns $credhub; the preload runs only on the first call

=head2 make_local_vault

    my $lv = make_local_vault(env => $env);
    my $lv = make_local_vault(name => 'foo-scratch');

Wraps C<< Service::Vault::Local->create >>.  When C<env> is supplied,
the local vault is named C<"${env->name}-entomb"> by default; pass
C<name> to override.  Returns the C<Service::Vault::Local> instance.

The returned vault is used as a transient spruce C<SAFE_TARGET> during
a manifest entombment merge.  It must be paired with
L</shutdown_local_vault> on every exit path -- typically in an C<eval>
+ C<die> guard pattern.

B<Parameters:>

=over 4

=item C<%opts>

=over 8

=item C<env>

A C<Genesis::Env>.  Supplies the default vault name.

=item C<name>

Explicit vault name, overriding the C<env>-derived default.  Required
when C<env> is not given.

=back

=back

B<Returns:> A C<Service::Vault::Local> instance.

B<Examples:>

  my $lv = make_local_vault(env => $env);
  # returns a Service::Vault::Local named "<env>-entomb"

=head2 shutdown_local_vault

    shutdown_local_vault($local_vault);

Idempotent teardown.  Calls C<< $local_vault->shutdown >> in an
C<eval>-wrapped block so cleanup paths don't bubble up exceptions.
Safe to call on C<undef>.

B<Returns:> nothing.  Swallows any exception from C<shutdown> -- a
failure to tear down a transient vault must not mask the error that
sent the caller into its cleanup path.

B<Examples:>

  shutdown_local_vault($lv);
  # no return value; safe on undef

=head2 populate_local_vault

    populate_local_vault(
        paths       => \%paths,        # map of "path:key" -> [refs from spruce]
        vault       => $source_vault,  # the source vault to read from
        credhub     => $target_credhub,
        prefix      => 'genesis-entombed/',
        local_vault => $local_vault,
        on_action   => sub { my (%info) = @_; ... },  # optional callback
    );

Bulk operation that walks a spruce-vaultinfo-shaped C<paths> map and,
for each C<"path:key"> entry:

=over 4

=item 1.

Fetches the value via C<< $vault->get($path, $key) >>.

=item 2.

Entombs it into C<$credhub> via L</entomb_one_secret>.

=item 3.

Sets a C<((credhub-var))> entry in C<$local_vault> under the original
C<(path, key)> so subsequent spruce evaluation substitutes credhub
indirection in place of the original vault reference.

=back

L</prime_credhub_cache> is invoked once at entry so every per-secret
existing-check is a cache hit.

If C<on_action> is supplied, it is called once per path:key with the
keyword arguments C<path>, C<key>, C<value>, C<credhub_var>, and
C<action> for progress reporting.

B<Parameters:>

=over 4

=item C<%opts>

=over 8

=item C<paths>

Hashref mapping C<"path:key"> to the spruce references that named it.

=item C<vault>

Source vault to read the values from.

=item C<credhub>

Target Credhub to entomb into.

=item C<prefix>

Credhub variable-name prefix.  Defaults as per L</credhub_var_name>.

=item C<local_vault>

Transient vault receiving the C<((credhub-var))> substitutions.

=item C<on_action>

Optional per-secret progress callback.

=back

=back

B<Returns:> nothing.  The result of the operation is the mutated
C<local_vault> and the credentials written to C<credhub>.

B<Examples:>

  populate_local_vault(
      paths       => {'secret/db:password' => ['meta.db.pass']},
      vault       => $vault,
      credhub     => $credhub,
      local_vault => $lv,
  );
  # no return value; writes to credhub and sets ((credhub-var)) in $lv

=head1 INVARIANTS

=over 4

=item *

The C<credhub_var_name> output is stable across processes and across
Genesis versions for a given C<(path, key, value, prefix)> tuple.

=item *

C<put_secret> is idempotent: invoking it repeatedly with the same
C<(cred_name, value)> after the first successful write returns
C<'exists'> and issues zero subprocesses (post-preload).

=item *

C<populate_local_vault> processes paths in deterministic
(sorted) order so the C<on_action> callback sees a stable sequence.

=back
