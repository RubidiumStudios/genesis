=head1 NAME

Genesis::Env::Manifest::_entombment_mixin - Mixin providing Credhub entombment of Vault secrets for manifest classes

=head1 DESCRIPTION

This is a mixin module. It has no C<package> declaration and is included into
consuming classes via C<do>. The methods it defines become available in
the consuming class's namespace after inclusion.

This mixin extends manifest classes with the ability to I<entomb> secrets: it
reads every Vault path that a rendered manifest references, copies each
key-value pair into a Credhub instance as a value-type credential, and
rewrites the consuming object's local Vault to hold Credhub variable
references (C<((path--key--sha))>) in place of the original secret values.
The result is a manifest that resolves secrets from Credhub at deploy time
rather than embedding them directly from Vault.

The entombment process is idempotent within a single object lifetime: once
C<_entomb_secrets> has run successfully it sets an C<entombed> flag on the
consuming object and returns immediately on any subsequent call.

=head1 USAGE

Include this mixin in your manifest class before calling any of its methods:

    # Typical inclusion pattern inside a consuming manifest class:
    use parent qw/Genesis::Env::Manifest/;
    require File::Basename;
    do((File::Basename::dirname(__FILE__) =~ s#^lib/##r) . "/_entombment_mixin.pm");

After the C<do>, all methods defined in this file become available as
methods on the consuming class.

=head1 METHODS

=head2 local_vault

    my $vault = $obj->local_vault;

Creates and returns a new C<Service::Vault::Local> instance scoped to the
current environment's name. The local vault is used as an in-memory store to
hold Credhub variable references during the entombment process.

B<Parameters:> None beyond the implicit invocant.

B<Returns:> A C<Service::Vault::Local> object created via
C<< Service::Vault::Local->create($env_name) >>.

B<Examples:>

    my $local_vault = $manifest->local_vault;
    # Returns: a Service::Vault::Local instance for the current environment

=head2 credhub_target

  my $credhub = $manifest->credhub_target();

The CredHub that entombed secrets are written to.

Defaults to the environment's own CredHub -- the one belonging to the
director that deploys it, or the environment's own when it I<is> a director.

B<This is the override point for self-targeting.>
C<Genesis::Env::Manifest::EntombedSelf> overrides it to reach the
newly-deployed environment's CredHub instead, so post-deploy uploads carry
references the new director can resolve rather than ones only its parent can.

B<Parameters:> None.

B<Returns:> A C<Service::Credhub> object.

B<Examples:>

  my $credhub = $manifest->credhub_target();
  # returns the deploying director's credhub

  # In EntombedSelf:
  my $credhub = $manifest->credhub_target();
  # returns the deployed environment's own credhub

=head1 INTERNAL METHODS

These methods are internal to the implementation. They may change without
notice and should not be called directly.

=head2 _entomb_secrets

    $obj->_entomb_secrets($data);

Orchestrates the full entombment workflow for the consuming manifest object.
Determines every Vault path referenced by the rendered manifest, resolves
every referenced value from the environment's Vault, and only then writes
each value into Credhub as a value-type credential under the prefix
C<genesis-entombed/>, storing the resulting Credhub variable reference back
into the local in-memory Vault. Progress is printed to STDERR as each secret
is processed.

The method is guarded by an C<entombed> flag on the consuming object: if
C<_entomb_secrets> has already completed successfully for this object it
returns C<1> immediately without repeating any work.

It works in this order.

=over 4

=item 1. Collect the references

Each reference is split at its first colon into a path and a key, so a key
such as C<tls.key:v2> keeps its dots and colons. For a vaultified manifest,
the consuming class's C<get_vault_paths> returns the references Genesis
generated from CredHub variables beside the manifest's own, so they go
through the same steps.

=item 2. Export the referenced paths

One C<safe export> names every referenced path, and its raw text is decoded
with L<Service::Vault/decode_export_text>, which keeps each value's JSON type
and marks every path holding a value that is not a string.

=item 3. Read what the export can't give as text

A referenced path is read whole with L<Service::Vault/read_flattened_secret>,
which runs C<safe get> on that one secret with no key, when the export holds
a typed value there, when the export left the path out, or when the export
itself failed. Every field of that path then comes from that one read, which
gives each value as the text a flat export gives on every C<safe> version. So
a referenced number or boolean reaches CredHub as the same text, and under
the same credential name, whichever route found it. A typed path that no
reference uses is never read, so a value nobody needs, such as the numeric
C<pid> an older Genesis writes into its network lock beside the director's
exodus, can't stop entombment.

=item 4. Resolve every reference

Each reference is looked up by the path C<safe> reads for it. C<safe> trims
one trailing and one leading slash and then collapses repeated slashes, and
the lookup copies that rule exactly, so C</secret/a>, C<secret/a>, and
C<secret//a> all read C<secret/a>, and two spellings referenced together read
it once. Each reference keeps its own spelling for the local Vault entry and
the CredHub name, so every name stays what Genesis made before for the same
spelling, and two spellings of one secret, such as C</secret/a> and
C<secret//a>, still give different names, as they always have. A spelling
with repeated slashes at either end, such as C<//secret/a>, is left with a
slash at that end by the rule, so it never matches a path in the export, and
it is read with C<safe get>, which applies the rule again and reaches the
same secret.

=item 5. Write

Only when every reference has resolved to a non-empty string does it start
the local Vault, prime the CredHub cache, and write each value.

=back

The order exists because entombment used to start the local Vault and write
values one reference at a time, so a missing value after the first one left
earlier values written. Before typed values were read again, the export's
strict policy refused any typed value under a referenced path, including a
lock that nothing references, and a failed export with nothing on stderr read
as a run of misleading "no value" errors.

The fallback to C<safe get> is kept because Genesis still accepts C<safe> as
old as 1.6.1, and older C<safe> exports dropped one of two paths when one name
begins with the other, such as C<secret/a> and C<secret/ab>. The C<safe> fix
for that is in current tags, but nothing tells Genesis which installed binary
carries it. The read is C<safe get> rather than one C<safe export> per path,
because an export needs LIST access and walks every path beneath the one
named. It is not C<kv_read> either, because C<kv_read> returns the raw JSON of
a typed value, which is not the text the export route gives.

B<Limitations:> Entombment still isn't transactional. Resolving every value
first means a missing or unreadable value stops it before anything is
written, but writes then happen one at a time, and a reference is recorded in
the local Vault even after its write fails. So a CredHub failure, an
interruption, or a local Vault failure after the first write leaves the
earlier values written, and that includes a dry run.

B<Parameters:>

=over 4

=item * C<$data> - Accepted but unused in the current implementation. Present
for forward-compatibility.

=back

B<Returns:> C<1> if secrets were entombed (or entombment had already been
performed), C<0> if the manifest references no Vault paths and there was
nothing to entomb.

B<Errors:>

=over 4

=item *

C<"Manifest references vault path #C{%s:%s} which has no value in the vault -- populate it (or fix the reference) and redeploy."> --
raised via C<bail()> when the manifest names a vault path and key that holds
nothing. Caught here rather than at deploy time because an empty value would
entomb as an empty credential, and the deployment would fail somewhere far
less informative. The substitutions are the reference's path, as the manifest
spells it, and the key. A path that C<safe get> reports as holding no secret
ends here too. It is raised before the local Vault starts or anything is
written to CredHub.

=item *

C<"Could not read #C{%s} from vault at #M{%s}: %s"> --
raised via C<bail()> by L<Service::Vault/read_flattened_secret> when a path
it reads fails for any reason other than nothing being stored there, such as
a refused read, a sealed or unreachable vault, or output that does not parse.
The substitutions are the path C<safe> reads, the vault URL, and the reason
C<safe> gave. Nothing has been written to CredHub when it is raised, because
those reads all happen before the first write.

=item *

C<"Cannot use the safe export..."> --
raised via C<bail()> by L<Service::Vault/decode_export_text> when the export
exits cleanly but its output is not JSON, or is in a shape or version Genesis
does not read. The rest of the message names the path, when there is one,
and says what is wrong. Nothing has been written
when it is raised.

=item *

C<"Failed to entomb one or more secrets into Credhub.  This may be due to a bug in Genesis, communication or authentication error with Credhub, or a value that Credhub can't support."> --
raised via C<bail()> when a secret does not round-trip correctly. The message
advises retrying without C<--entomb> (or with C<--no-entomb> when deploying)
and points at the Genesis issue tracker.

=back

B<Examples:>

    # Entomb all manifest secrets.
    my $entombed = $manifest->_entomb_secrets(undef);
    # Returns: 1 if secrets were copied to Credhub (or already entombed),
    #          0 if no vault paths found

=head2 _setup_local_vault

    my $local_vault = $obj->_setup_local_vault;

Creates the local in-memory Vault by delegating to L<"local_vault">, printing
a progress message to STDERR before and after. This is a thin wrapper that
separates the I/O notification from the construction logic.

B<Parameters:> None beyond the implicit invocant.

B<Returns:> A C<Service::Vault::Local> instance as returned by
C<< $obj->local_vault >>.

=head2 _entomb_secret_for_vault

    my ($credhub_var, $secret_sha, $action, $action_color, $existing) =
        $obj->_entomb_secret_for_vault(
            $local_vault, $vault_path, $key, $value,
            $credhub, $cred_path, $entombment_prefix
        );
    # Returns: ('((genesis-entombed/_myenv--password--a3f1c2b4))',
    #           'a3f1c2b4', 'new', 'gi', undef)

Entombs a single Vault key-value pair into Credhub and records the resulting
Credhub variable reference in the local Vault. The credential name is derived
from C<$entombment_prefix>, C<$cred_path>, C<$key>, and the first eight
hexadecimal characters of the SHA-1 digest of C<"$cred_path--$key--$value">.

If the credential already exists in Credhub with the same value the method
skips the write and reports the action as C<"exists">. If the value differs
it overwrites the credential and reports C<"altered">. If the value is new it
reports C<"new">. If Credhub does not return the expected value after a write
the action is C<"failed">.

B<Parameters:>

=over 4

=item * C<$local_vault> - A C<Service::Vault::Local> instance. If defined,
the Credhub variable reference is written back to this vault under
C<$vault_path> / C<$key>. May be C<undef> to skip the local-vault write.

=item * C<$vault_path> - The Vault path (e.g. C</secret/dev/myenv/cf/uaa>)
from which the secret originates. Used as the target path in the local Vault.

=item * C<$key> - The key within C<$vault_path> (e.g. C<password>).

=item * C<$value> - The plaintext secret value to store in Credhub.

=item * C<$credhub> - A connected C<Service::Credhub> instance used for
C<get> and C<set> operations.

=item * C<$cred_path> - The environment-relative credential path segment
used to construct the Credhub credential name.

=item * C<$entombment_prefix> - Optional string prepended to the Credhub
credential name. Defaults to C<"genesis-entombed/">.

=back

B<Returns:> A five-element list:

=over 4

=item * C<$credhub_var> - The Credhub CredHub variable reference string in
the form C<((credential-name))>.

=item * C<$secret_sha> - An eight-character hex string (first 8 chars of the
SHA-1 of C<"$cred_path--$key--$value">) used as a uniqueness suffix.

=item * C<$action> - One of C<"new">, C<"exists">, C<"altered">, or
C<"failed">, describing the outcome of the Credhub write.

=item * C<$action_color> - A Genesis terminal color code corresponding to
C<$action>: C<"gi"> (new), C<"yi"> (exists), C<"ri"> (altered), or
C<"Yr"> (failed).

=item * C<$existing> - The value previously stored in Credhub under this
credential name, or C<undef> if no prior value existed.

=back

B<Examples:>

  my ($var, $sha, $action, $color, $existing)
    = $manifest->_entomb_secret_for_vault(
        $local_vault, $secret, $key, $value, $credhub, $cred_path, $prefix);
  # returns ('/genesis-entombed/env/secret_key', 'a1b2c3d4',
  #          'new', 'gi', undef)

  # Where the credential already holds the same value:
  # returns $action of 'exists' and $existing equal to $value

=head2 _entomb_secret

    my ($credhub_var, $secret_sha, $action, $color, $existing) =
        $obj->_entomb_secret($credhub, $path, $key, $value, $prefix);
    # Returns: ('((genesis-entombed/path--key--deadbeef))',
    #           'deadbeef', 'new', 'gi', undef)

Single-secret entombment method retained for backwards compatibility. When
called with more than six arguments (counting C<$self>) it delegates
immediately to L<"_entomb_secret_for_vault"> using all passed arguments;
in that case the caller must supply the
L<_entomb_secret_for_vault|"_entomb_secret_for_vault"> parameters
(C<$local_vault, $vault_path, $key, $value, $credhub, $cred_path>),
with C<$entombment_prefix> optional (defaults to C<"genesis-entombed/">).
With six or fewer arguments the method performs the same SHA-based naming
and Credhub write logic as C<_entomb_secret_for_vault> using the
parameters listed below.

B<Parameters:>

=over 4

=item * C<$credhub> - A connected C<Service::Credhub> instance.

=item * C<$path> - The credential path segment used to construct the Credhub
credential name and SHA digest, analogous to C<$cred_path> in
L<"_entomb_secret_for_vault">.

=item * C<$key> - The key name within the credential path.

=item * C<$value> - The plaintext secret value to store.

=item * C<$prefix> - Optional prefix string for the Credhub credential name.
Defaults to C<"genesis-entombed/">.

=back

B<Returns:> A five-element list identical in structure to the return of
L<"_entomb_secret_for_vault">: C<($credhub_var, $secret_sha, $action,
$color, $existing)>.

B<Examples:>

  my ($var, $sha, $action, $color, $existing)
    = $manifest->_entomb_secret($credhub, $path, $key, $value);
  # returns ('/genesis-entombed/...', 'a1b2c3d4', 'added', 'G', undef)

  # Re-entombing an unchanged value:
  my ($var, $sha, $action) = $manifest->_entomb_secret(...);
  # returns $action of 'unchanged' -- the credential was already correct
