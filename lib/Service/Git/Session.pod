=head1 NAME

Service::Git::Session - leave a branch, do work, and come back

=head1 SYNOPSIS

  my $session = $git->session(control => $top->control_branch);

  $session->begin;
  $session->switch($top->branch_for('qa'));
  # ... work on the branch ...
  $session->finish;

=head1 DESCRIPTION

One object owns every branch change Genesis makes. It belongs to one
C<Service::Git> handle, and so to one working tree, and the handle hands out
the same session however often it is asked.

C<begin> runs the pre-flight, asserts a clean tree and index, and records the
branch, the HEAD sha, and the current directory. C<switch> changes to the
repository root, checks out a branch or a commit, and records the tip it
landed on. C<finish> re-reads the branch and the cleanliness rather than
assuming either, returns to the branch C<begin> recorded, and verifies the
return.

Clean means what C<< $git->is_clean >> means: no tracked modification and
nothing staged, with untracked files ignored. A scratch file in the working
tree blocks no session and no session deletes one.

The session also owns the one writer. C<apply_files> delivers a control commit
onto the branch the session stands on, as a mirror of the environment's
propagation set rather than as an overlay on what the branch already held, so
a path that has left the set leaves the branch with it. It reports every hand
edit it overwrote along the way, because a mirror takes such an edit away and
the run has to say so.

Beside the four verbs the session answers for what it holds, and the commands
that drive it read those answers rather than asking git themselves. C<git>
hands back the handle it was built on, C<modified_paths> names the tracked
files that are modified now, C<finish_if_clean> finishes where nothing is, and
C<finished> says afterwards whether the finish went out the clean door.

Switching is what the switch lock guards, and the lock is a C<flock> on
F<genesis-session.lock> in the git directory, so it covers one working tree
and not the repository behind it. C<switch> is the one verb that takes it and
C<finish> is the one that lets it go, so a command that opens a session and
never switches never touches it at all.

=head1 EXIT PATHS

The session restores on every exit path, not only the one where the command
succeeded. C<finish> covers the success path and C<abort> covers a die or a
failed verification, and the paths nobody calls a verb on are covered by a
last-resort C<abort> the session registers through
C<< Genesis::Commands::at_exit >> when it opens.

Those hooks run from an C<END> block, which is what makes them reach a bail,
an uncaught die, and a signal, since F<bin/genesis> routes SIGINT and SIGTERM
to C<bail>. It is deliberately not hung on C<DESTROY>: C<bail> exits when it
is not inside an eval, Perl runs C<END> before global destruction, and the
order of destruction after that is undefined, so a net there fires too late to
be of use.

What Perl cannot give us is a hook on SIGKILL, and nothing here pretends
otherwise. The switch lock covers that case instead, because the kernel
releases it with the process.

=head1 METHODS

=head2 new($git, %opts)

  my $session = Service::Git::Session->new($git, control => 'main');

Builds a session on one handle without opening it. Nothing is read from the
repository and nothing is written to it until C<begin> runs.

Callers normally reach this through C<< $git->session >>, which builds the
session on the first ask and answers with that one afterwards.

B<Parameters:>

=over 4

=item C<$git>

The C<Service::Git> handle this session belongs to, and so the working tree
every verb below acts on.

=item C<%opts>

Options. C<control> names the branch a later abort never resets, which is how
a commit made on control survives an abort whole.

=back

B<Returns:> The new session, which is closed.

B<Errors:>

=over 4

=item *

C<< "A branch session needs a Service::Git handle" >> -- raised when the
handle is missing, since a session with no working tree has nothing to leave
and nothing to come back to.

=back

B<Examples:>

  my $session = Service::Git::Session->new($git, control => 'main');
  # returns a closed session; nothing has been read or written yet

  my $session = Service::Git::Session->new(undef);
  # raises, because there is no handle to belong to

=head2 begin

  $session->begin;

Opens the session. It runs the pre-flight first, so that a working tree git
refuses under C<safe.directory>, a process with no committer identity, and a
repository with no commits each name their own cause rather than surfacing
later as a failed checkout. It then asserts a clean tree and index, and only
then records the branch, the HEAD sha, and the current directory.

The order matters: every refusal above happens before the session writes
anything at all, so a command that is going to be turned away is turned away
while the repository is still exactly as the operator left it.

What an earlier session recorded is cleared here rather than at C<finish>,
which is the target it stood on, the tips it switched to, the branches it
committed to, and whether it finished. The handle hands out one session, so a
caller that opens a second one would otherwise read the first one's answers.

Reusing a session is the ordinary way to open a second one, and it carries one
thing worth knowing. C<< $git->session >> builds the session on the first ask
and answers with that same object afterwards, ignoring the options it is
handed on every later call, so the control branch is whatever the first build
was told and a second C<< session(control => ...) >> naming another branch
does not change it. Every caller in the tree passes the same control, and one
that needs a different one asks for a handle on its own working tree.

A last-resort C<abort> is registered through C<< Genesis::Commands::at_exit >>,
whose hooks run from an C<END> block, so a session still open when the process
ends is discarded, reset, and put back rather than left standing on a branch
nobody asked for. The exit status is saved and put back around it, because the
hooks run with C<$?> already holding the code the command chose and the git
the abort shells out to would otherwise overwrite it.

B<Parameters:> None.

B<Returns:> C<$self>, so it chains.

B<Errors:>

=over 4

=item *

C<< "A branch session is already open in %s.  Sessions are sequential and are
never nested, so a command that needs another branch finishes the open session
first." >> -- raised on a second C<begin>. C<%s> is the working tree root.
Sessions are keyed on the C<Service::Git> handle, so this refusal is about one
working tree, and a caller holding a handle for a second working tree opens a
session there at the same time.

=item *

C<< "Working tree has uncommitted changes, and this command switches
branches." >> -- raised over a tracked modification or a staged change, and it
lists the paths. Untracked files are not among them.

=item *

Whatever C<< $git->preflight >> raises, which is the C<safe.directory>
refusal, the missing committer identity, or the repository with no commits.

=back

B<Examples:>

  $session->begin;
  # returns $self, and origin now holds the branch, the head, and the cwd

  $session->begin;
  # raises over a modified qa.yml, naming the file, before any switch

=head2 switch($branch_or_commit, %opts)

  $session->switch($top->branch_for('qa'));
  $session->switch($record->{git}{commit}, record => $env->exodus_base);

Takes a branch name or a commit. It changes to the repository root, takes the
switch lock, checks the target out, and returns to the original directory when
the checkout kept it. The run happens from the root because the branch being
checked out may not carry the directory we are standing in.

A branch is checked out as a branch. A commit is checked out detached, and
C<finish> restores the branch C<begin> recorded either way, so a detached HEAD
never outlives the session. Standing on one is safe because C<begin> asserted
the tree clean and C<finish> catches anything that wrote into it.

A commit the repository cannot reach is refused before anything switches,
naming the commit and, where the caller passes C<record>, the record that
named it. That happens when a branch has been rewritten or removed on the
remote since the commit was recorded, and it exits C<DATAERR>.

The switch lock is a C<flock> on F<genesis-session.lock> in the git directory,
which makes it per working tree: a linked working tree resolves it under
F<< .git/worktrees/<name>/ >>, so two working trees of one repository never
contend. The holder's pid and command are written inside, and a second process
whose C<switch> meets a held lock fails at once naming both. A command that
never switches never touches the lock, so a kit hook shelling out to genesis
inside a deploy is unaffected while one that tries to switch is refused.

There is no break-lock option and none is needed, because the kernel releases
the C<flock> when its holder dies, so a refusal always names a live process.

A refusal puts us back in the directory we were standing in before it says
anything, since the directory we exit in is the one we came in on.

The tip of the target is recorded the first time the session lands on a
branch, so C<committed_branches> can say afterwards which branches this session
moved. A commit is not recorded, because it is not a branch this session could
have moved.

B<Parameters:>

=over 4

=item C<$branch_or_commit>

The branch name to check out, or a commit to stand on. A name this repository
holds as a local branch, or as a remote-tracking branch of the remote it
tracks, is treated as a branch, and anything else is treated as a commit. A
branch that has only been fetched therefore takes the branch path, because
git's own checkout cuts the local branch for it and the caller means a branch.

=item C<%opts>

Options. C<record> names the record the commit came from, which is the exodus
path where the caller is following C<git.commit>, and it is what the refusal
quotes back so the operator knows which record is wrong.

=back

B<Returns:> C<$self>, so it chains.

B<Errors:>

=over 4

=item *

C<< "A branch change was attempted with no session open in %s." >> -- raised
where C<begin> has not run. C<%s> is the working tree root.

=item *

C<< "The commit %s is not in this repository." >> -- raised where the target is
a commit this repository cannot reach, naming the commit and the record that
named it. It exits C<DATAERR>, and nothing has switched when it is raised.

=item *

C<< "Unable to enter git root %s: %s" >> -- raised where the repository root
cannot be entered.

=item *

C<< "Another Genesis process is using this working tree." >> -- raised where
another process holds the switch lock, naming that process's pid and the
command it is running. It exits on C<TEMPFAIL>, because the holder will let go
and the same command run again will get through.

=item *

Whatever C<< $git->checkout >> or C<< $git->checkout_detached >> raises, which
is a failed checkout naming the target.

=back

B<Examples:>

  $session->switch('qa/bosh');
  # returns $self, and on now reads 'qa/bosh'

  $session->switch($sha, record => '/secret/exodus/qa/bosh');
  # stands on that commit with a detached HEAD

  $session->switch($dropped_sha, record => '/secret/exodus/qa/bosh');
  # exits DATAERR naming both, where the branch was rewritten on the remote

=head2 finish

  $session->finish;

Closes the session and puts back what C<begin> recorded. The branch and the
cleanliness are both re-read rather than assumed, the return to the recorded
branch is made from the repository root, and the result is verified before the
session reports itself closed.

The switch lock is released last, after the restore has been verified, so no
other process can switch this working tree until this one is genuinely back
where it started.

A tracked modification found here is a defect rather than a by-product. The
deploy writes no git of its own and its cleanup hands the tree back as it
found it, so what is left is a kit hook that wrote into the repository or a
deploy that died early. C<finish> names the files in the error it raises and
sends that through C<abort>, which discards them and restores the branch, and
the error reaches the caller so the command can exit on it. The files are
listed once, in that error, because C<finish> tells C<abort> it has named them
already.

Untracked files are ignored here exactly as they are at C<begin>.

The clean path is the only one that sets C<finished>, so a caller that spawns
a child behind a finished session never spawns one behind a run that was
aborted.

Calling it on a session that was never opened is a no-op, so a caller may
finish unconditionally on its way out.

B<Parameters:> None.

B<Returns:> C<$self>, so it chains.

B<Errors:>

=over 4

=item *

C<< "Something wrote into the repository during this command, which it should
not have done." >> -- raised over a tracked modification at the end of a
session, which is a defect rather than a by-product. It lists the paths, and
it comes out of C<abort>, so the changes are discarded and the branch is
restored before it reaches the caller.

=item *

Whatever C<_restore> raises, which is a root or a directory that cannot be
entered, or a return that did not land on the recorded branch.

=back

B<Examples:>

  $session->finish;
  # returns $self; the branch, the HEAD, and the directory are back

  $session->finish;
  # returns $self unchanged where begin never ran

=head2 finish_if_clean

  $session->abort('there were changes') unless $session->finish_if_clean;

Finishes the session and answers true where nothing tracked is modified, and
answers false without finishing where something is, leaving the session open
so the caller can name the files through C<modified_paths> and then abort.

A true answer means the session finished, and it is read back off the session
rather than assumed from the clean tree. A session that was never opened, and
one that has already gone out through C<abort>, both have nothing to finish,
so both answer false over a tree with nothing modified in it.

M13's deploy asks for the finish this way because it wants to say what
happened in its own words before it decides what to do, and a death would not
let it.

B<Parameters:> None.

B<Returns:> True where the session finished, false where it was left open and
false where there was no open session to finish.

B<Errors:> Raises nothing of its own. Whatever C<finish> raises on the clean
path passes through, which is a restore that did not land.

B<Examples:>

  $session->finish_if_clean;
  # returns 1 on a clean tree, and the session is finished

  $session->finish_if_clean;
  # returns 0 over a modified qa.yml, with the session still open

  $session->finish_if_clean;
  # returns 0 where begin never ran, because there was nothing to finish

=head2 abort($error, %opts)

  $session->abort($@);

Discards whatever the session wrote and did not commit, naming the modified
files first so the evidence reaches the operator, resets every deployment
branch the session committed to back to its remote-tracking ref, returns to
the branch C<begin> recorded, releases the lock, verifies the result, and then
dies with the error it was given.

Control is never reset and its local ref is never force-written, because
committed work on control is never discarded. Where control is behind its
remote-tracking ref the operator rebases it by hand.

C<git clean> is never run, so the discard reaches tracked changes only and an
untracked file survives.

The discard is read back rather than assumed. Where it failed, the changes are
still in the tree, every reset and checkout after it would fail over them, so
nothing further is attempted and the session dies at C<SOFTWARE> naming the
working tree and the branch it is left standing on.

When the return itself fails the session is stuck, and it dies naming the
original error, the restore failure, and the branch we are standing on,
because the alternative is an operator running every later command against the
wrong branch with nothing having been raised.

B<Parameters:>

=over 4

=item C<$error>

The error the session is being aborted over, which is what the process
finally dies with. Where it is missing or empty the session says it was
aborted and dies on that.

=item C<%opts>

Options. C<named> says the caller has already listed the modified files in
the error it handed us, so the discard makes no announcement of its own and
the operator is shown that list once. C<finish> passes it.

=back

B<Returns:> Nothing. C<abort> always raises.

B<Errors:>

=over 4

=item *

The error it was handed, which is re-raised once the discard, the resets, and
the restore are done. A session that is not open re-raises it and does
nothing else.

=item *

C<< "The uncommitted changes in %s could not be discarded, so the working
tree still holds them and we have left it standing on %s." >> -- raised in
place of the above where the discard itself failed, which is a defect, so it
exits C<SOFTWARE>. Nothing is reset and no return is attempted, because both
would fail over the changes that are still there.

=item *

C<< "We then failed to return to %s: %s  You are standing on %s." >> -- raised
in place of the above where the return failed. It names the original error,
the restore failure, and the branch we are stuck on, all three at once.

=back

B<Examples:>

  $session->abort($@);
  # discards, resets the branches it wrote, returns to control, and dies on $@

  $session->abort('the writer could not finish');
  # dies naming that error and the branch we are stuck on, where the return failed

=head2 apply_files($source_sha, %opts)

  my $result = $session->apply_files($source_sha,
      env     => $env,
      changed => \@files,
      deleted => \@files,
      message => $message);

The single writer. Delivers one control commit onto the branch the session
stands on, as a mirror of that environment's propagation set.

A delivery is a mirror and not an overlay, so the postcondition is that the
branch's tree equals the set, and a path the set no longer holds is removed
rather than left standing. The C<changed> and C<deleted> lists are the
caller's own diff, meant to skip blobs that cannot have moved and to name
files in the report, and they never decide what is delivered.

A path the mirror overwrites whose content differed from the source although
the delivered commit did not change it is a hand edit the branch was
carrying, and it comes back in C<overwrote> so the run can name it. An
overwrite is never silent. A path the branch does not hold at all is an
addition rather than an edit and is not reported.

The set is a list of pathspecs rather than a list of files, since a dev kit's
source is a directory and a fragment the blueprint names is in the set whether
or not anybody has written it, so the pathspecs are resolved against the
source commit's tree before the membership is worked out. What that tree does
not hold is not delivered and does not keep a path on the branch.

The pathspec list itself is still read from the tree the session is standing
on, which is the deployment branch, and only the membership is resolved at the
source commit. The step that adds the at-commit reader moves the first read
too, and until that lands a repository that restructured between the two
commits is read under the wrong prefix.

An empty set is refused before the index is read, because every path the
branch holds is outside an empty set and the mirror would take the branch
bare, and the postcondition would still hold afterwards so nothing downstream
would notice. A set that is full but whose paths the source tree holds none of
is refused for the same reason, one step later, since it ends the same way. No
real control commit holds none of an environment's set, so that state says the
set and the commit do not describe the same repository, which is what a handle
carrying the wrong deployment prefix produces.

A removal git refuses is silent, because C<< $git->rm >> discards git's
answer, so nothing in the sequence notices a path that stayed. A refused
removal is caught by the check that runs between these writes and the commit,
which is why the postcondition is asserted rather than assumed.

That check is two assertions and not one, because the source tree carries
every environment's files and no whole-tree comparison is possible. The first
is that the index matches the source over the set's own paths, and the second
is that the index holds nothing outside the set. Both run against the index
and before the commit, so a failed check never becomes a commit, and either
one raises a C<Genesis::CI::RunFailure> of the run-fatal kind, which ends the
run rather than the environment.

The session must be open and standing on the branch being written, because the
writer switches nothing itself.

B<Parameters:>

=over 4

=item C<$source_sha>

The control commit being delivered, whose tree the set is read from.

=item C<env>

The environment whose set is delivered. Required.

=item C<message>

The message is required and is used exactly as given, subject and body alike.
The writer builds no message of its own, so the marker in a direct-mode
delivery and the subject and body of a PR-mode aggregate are both the
caller's, and the check that follows reads the marker the caller wrote.
Nothing here appends, truncates, or reformats, because a body with newlines
in it is the PR-mode case.

=item C<changed>, C<deleted>

The caller's diff, both optional. C<changed> is the git-root-relative paths the
delivered commit itself moved, spelled as C<@set> spells them, and it keeps those paths out of C<overwrote>,
since an overwrite the delivery was asked for is not a hand edit. C<deleted>
is accepted and not read yet.

=back

B<Returns:> A hashref with C<commit>, the commit made, C<delivered> and
C<removed>, the paths written and taken away, and C<overwrote>, the paths the
branch held whose content differed from the source although the delivered
commit did not change them.

B<Errors:>

=over 4

=item *

C<< "apply_files needs the environment whose set it delivers" >> -- raised
where no C<env> is passed, before anything is read or written.

=item *

C<< "apply_files needs its caller's commit message, since it builds none" >>
-- raised where no C<message> is passed, before anything is read or written.

=item *

C<< "The propagation set of %s is empty" >> -- raised where the environment's
set comes back empty, naming the environment and the branch. It exits
C<SOFTWARE>, and the index has not been read when it is raised.

=item *

C<< "None of the %d paths in the propagation set of %s is in the tree of %s" >>
-- raised where the set is full but the source commit's tree holds none of its
paths, naming the count, the environment, the commit, and the branch. It exits
C<SOFTWARE>, and the index has not been read when it is raised.

=item *

C<< "Cannot read the index of %s" >> -- raised by C<< $git->ls_files >> where
git refuses to read the index. It exits C<DATAERR>.

=item *

C<< "Cannot diff %s against %s in %s" >> -- raised by C<< $git->diff_names >>
where the source commit is not in this repository. It exits C<DATAERR>.

=item *

A C<Genesis::CI::RunFailure> of the run-fatal kind, thrown as an object
rather than raised as a message, where either index assertion fails. Its
C<report_line> names the branch, the source, and the paths that differed. No
commit stands when it is thrown, and the caller ends the run on it.

=item *

C<< "Failed to checkout %s from %s" >> -- raised where a path the source tree
holds cannot be written into the working tree.

=item *

C<< "Failed to commit" >> -- raised where the commit itself fails, which
includes a delivery that changes nothing, since git finds nothing staged and
refuses. An operator meeting this after a delivery that was already current is
looking at that and not at a broken repository.

=back

B<Examples:>

  my $result = $session->apply_files($sha, env => $env,
      message => Genesis::CI::Marker::build($sha, 'qa'));
  # returns {commit => $new_sha, delivered => [...], removed => [...], overwrote => [...]}

  my $result = $session->apply_files($sha, env => $env,
      changed => ['bosh/dev/manifest.yml'], message => $message);
  # a hand-edited ops file the delivery did not change comes back in overwrote,
  # and the kit file the delivery did change does not

  $session->apply_files($sha, message => $message);
  # raises, because the writer is not told whose set it delivers

=head2 git

The C<Service::Git> handle this session was built on. A caller holding the
session reaches git through it rather than building a second handle, which
would key a second session on the same working tree.

B<Parameters:> None.

B<Returns:> The handle.

B<Examples:>

  my $git = $session->git;
  # returns the same handle $git->session was asked of

=head2 active

  my $open = $session->active;

Whether the session is open, which is true between a C<begin> that returned
and the C<finish> that closes it.

B<Parameters:> None.

B<Returns:> True where the session is open, false otherwise.

B<Examples:>

  my $open = $session->active;
  # returns 0 on a session that has been built but not begun

=head2 finished

  do_something() if $session->finished;

True only where C<finish> completed its clean path. A session that has not
opened, one that is still open, and one that went out through C<abort> all
answer false, and so does one that finished and has since been opened again.

M15's post-deploy child reads it, because D84 makes a finished session the
precondition for spawning one.

B<Parameters:> None.

B<Returns:> 1 where the session finished cleanly, 0 otherwise.

B<Examples:>

  my $done = $session->finished;
  # returns 1 after a finish that found the tree clean

  my $done = $session->finished;
  # returns 0 after an abort, however the abort was reached

=head2 origin

What C<begin> recorded, as a hashref of C<branch>, C<head>, and C<cwd>. It is

B<Parameters:> None.

B<Returns:> A hashref of the branch name, the HEAD sha, and the current

B<Examples:>

=head2 on

  my $target = $session->on;

The branch or commit C<switch> last landed on, and undefined where the session

B<Parameters:> None.

B<Returns:> The last target handed to C<switch>, or undef.

B<Examples:>

  # returns 'qa/bosh' after a switch to that branch

=head2 modified_paths

  my $paths = $session->modified_paths;

The tracked paths that are modified or staged right now, sorted, in the words
C<git status --porcelain> gives them. Untracked files are never listed,
because D84 says they block nothing.

C<begin>, C<finish>, and C<abort> all read it, so the list an operator is
shown is the same list wherever they are shown it, and a caller that wants to
say something of its own about those files says it about the same ones.

These are porcelain spellings rather than paths, and they are for showing to
an operator. A rename comes back as C<< old -> new >>, and a path holding a
space or a non-ASCII byte comes back quoted the way git quotes it, so a caller
that means to open one of these, or to hand it to git as a pathspec, unquotes
it and splits the rename form first.

B<Parameters:> None.

B<Returns:> An arrayref of paths, empty where nothing tracked is modified.

B<Examples:>

  my $paths = $session->modified_paths;
  # returns ['qa.yml'] where a hook wrote into that file

  my $paths = $session->modified_paths;
  # returns [] on a clean tree, whatever untracked files are lying about

=head2 committed_branches

  my @moved = $session->committed_branches;

The branches this session committed to, which are those whose tip differs from
the tip recorded when the session switched to them, together with any a caller
recorded outright through C<_record_commit>. The session works the first half
out for itself, so a writer that commits through the handle does not have to
report what it wrote, and the second half covers the commit that leaves a tip
where it was.

The control branch is never among them, however it got there, because I2 keeps
committed work on control whole and this is the set C<abort> resets.

B<Parameters:> None.

B<Returns:> The names, sorted. An empty list where nothing moved.

B<Examples:>

  my @moved = $session->committed_branches;
  # returns ('qa/bosh') after a commit on that branch

  my @moved = $session->committed_branches;
  # returns () after a session that only read, whatever control has done

=head1 INTERNAL METHODS

=head2 _members_at($commit, @set)

  my @members = $session->_members_at($source_sha, @set);

The propagation set's pathspecs as the paths one commit's tree actually holds.

The set is a list of pathspecs and not a list of files. A dev kit's source is
the directory entry C<dev/>, and a fragment the blueprint names is in the set
whether or not anybody has written it yet, so a membership built from the set
as it stands reads every real file under C<dev/> as a path outside the set and
asks git to check out a file the source does not carry. Resolving the
pathspecs against the source tree answers both at once, and it is the same
expansion the suite's own reader makes before it compares the two sides.

One listing is read rather than one per entry, because the set is small and a
git process per path is not.

B<Parameters:>

=over 4

=item C<$commit>

The commit whose tree the pathspecs are resolved against.

=item C<@set>

The propagation set's pathspecs. An entry ending in a slash is a directory and
covers every path the tree holds beneath it, and any other entry covers itself
where the tree holds it and nothing where it does not.

=back

B<Returns:> The covered paths, sorted, git-root-relative.

B<Errors:> None of its own. C<< $git->ls_tree >> answers an unreadable commit
with an empty listing, and the caller then refuses the delivery at
C<SOFTWARE> before it writes anything.

B<Examples:>

  my @members = $session->_members_at($sha, 'bosh/dev/', 'bosh/qa.yml');
  # returns ('bosh/dev/hooks/blueprint', 'bosh/dev/kit.yml', 'bosh/qa.yml')

  my @members = $session->_members_at($sha, 'bosh/ops/gone.yml');
  # returns (), because the delivered commit does not hold that path

=head2 _record_commit($branch)

  $session->_record_commit($branch);

Remembers that this session committed to a branch, so that C<abort> resets it
even where the tip cannot say so.

C<committed_branches> works the set out for itself by comparing each branch's
tip against the tip recorded when the session switched to it, and this covers
the one case that comparison cannot see, which is a commit that leaves the tip
where it was. M8's writer is the caller, and it says so outright rather than
relying on the comparison.

B<Parameters:>

=over 4

=item C<$branch>

The branch that was committed to. A name that is missing or empty records
nothing.

=back

B<Returns:> C<$self>, so it chains.

B<Examples:>

  $session->_record_commit('qa/bosh');
  # returns $self, and committed_branches now names that branch

  $session->_record_commit($session->on);
  # returns $self unchanged where the session has not switched

=head2 _standing_on

  my $where = $session->_standing_on;

What to call the place we are standing, for a message that has to tell an
operator where a failed restore left them.

C<< $git->current_branch >> runs C<git rev-parse --abbrev-ref HEAD>, which
answers the literal string C<HEAD> on a detached HEAD rather than answering
undefined, so a fallback behind it can never fire and the operator is told
they are standing on "HEAD", which names nothing they can act on. Standing on
a commit is a designed state rather than an accident now, so the question is
asked here instead.

On a branch it answers the branch name. Detached it answers the commit, and it
names the target C<switch> was handed beside it where the two are not the same,
because that is the target the caller asked for.

B<Parameters:> None.

B<Returns:> The branch name, or a phrase naming the commit we are detached at.

B<Examples:>

  my $where = $session->_standing_on;
  # returns 'qa/bosh' on a branch

  my $where = $session->_standing_on;
  # returns 'a detached HEAD at 9f0d1c2a...' after a switch to a commit

=head2 _register_net

  $session->_register_net;

Hangs the last-resort C<abort> on C<< Genesis::Commands::at_exit >>, so that a
session still open when the process ends is discarded, reset, and put back.
C<begin> is the only caller and it registers once, so a session that is opened
and closed again hangs one hook and no more.

The hook does nothing on a session that is no longer open, which is what makes
an ordinary run pay nothing for it. Nobody is left to catch a die inside an
C<END> block, so the abort is wrapped and whatever it could not do is printed
to standard error instead. The exit status is saved and put back around the
whole of it, because the git the abort shells out to would otherwise overwrite
the code the command chose.

B<Parameters:> None.

B<Returns:> C<$self>, so it chains.

B<Examples:>

  $session->_register_net;
  # returns $self, with the net hung and the session covered on every exit path

  $session->_register_net;
  # returns $self unchanged on a session that already registered one

=head2 _through_the_door($code)

  $session->_through_the_door(sub { $git->checkout($branch) });

Runs C<$code> with the handle's guard lifted, and lowers it again however that
code ends.

C<Service::Git> refuses a checkout, a detached checkout, or a working-tree
reset from outside a session, and this is what a session is from the handle's
side. The door is open for exactly as long as one of the verbs is running,
because the flag is localised rather than set and cleared, so a call that dies
inside leaves it shut behind it. C<switch> and C<_restore> are the only
callers.

B<Parameters:>

=over 4

=item C<$code>

The code to run with the guard lifted. Called with no arguments.

=back

B<Returns:> Whatever C<$code> returns.

B<Errors:> Raises nothing of its own. Whatever C<$code> raises passes through
untouched, with the guard already lowered.

B<Examples:>

  $session->_through_the_door(sub { $git->checkout($branch) });
  # returns the handle, with the guard lowered again

  $git->checkout($branch);
  # raises, naming the repository, because the door is shut

=head2 _is_branch($name)

  my $branch = $session->_is_branch($target);

Whether the name is a branch of this repository, which is how C<switch> tells
a branch from a commit.

It asks the strict question here rather than narrowing
C<< $git->branch_exists >>, because that reader cannot be narrowed under its
callers. C<branch_exists> runs C<git rev-parse --verify> on the name, which
resolves a sha and a tag as readily as a branch, and C<resolve_branch> and the
propagation both lean on that looseness to answer whether a thing is here at
all. This one reads named refs through C<git show-ref --verify>, so it answers
about a branch and nothing else.

It asks about the local branch and about the remote-tracking one, because
git's own checkout knows a branch it has only fetched and this has to know it
too. C<git checkout qa/bosh> against a repository holding
C<refs/remotes/origin/qa/bosh> alone cuts the local branch and tracks it,
which is what the caller means. Reading such a name as a commit would stand us
on a detached HEAD, and a commit made there afterwards would belong to no
branch at all.

B<Parameters:>

=over 4

=item C<$name>

The target C<switch> was handed.

=back

B<Returns:> True where the name is a branch here or on the remote we track,
false otherwise, including where it is missing or empty.

B<Examples:>

  my $branch = $session->_is_branch('qa/bosh');
  # returns 1 where refs/heads/qa/bosh or refs/remotes/origin/qa/bosh is there

  my $branch = $session->_is_branch($sha);
  # returns 0, so switch stands on it as a commit

=head2 _verify_reachable($commit, $record)

  $session->_verify_reachable($sha, $env->exodus_base);

Refuses a commit this repository cannot reach, before C<switch> moves
anything. The append-only protection over the deployment branches makes that
rare rather than impossible: a branch rewritten or removed on the remote
leaves behind a commit that a record still names.

The refusal names the commit and the record it came from, because the record
is the input and the operator needs to know which one is wrong, and it exits
C<DATAERR>. Where the caller passed no record it says so in those words rather
than naming a path it does not have.

B<Parameters:>

=over 4

=item C<$commit>

The commit to look for.

=item C<$record>

The record that named it, which is quoted back in the refusal. It may be
omitted.

=back

B<Returns:> C<$self>, so it chains, where the commit is there.

B<Errors:>

=over 4

=item *

C<< "The commit %s is not in this repository.  It is named by %s, and the
branch it sat on has been rewritten or removed on the remote since it was
recorded." >> -- raised where the repository cannot reach the commit. It exits
C<DATAERR>.

=back

B<Examples:>

  $session->_verify_reachable($sha, '/secret/exodus/qa/bosh');
  # returns $self where the commit is there

  $session->_verify_reachable($dropped, '/secret/exodus/qa/bosh');
  # exits DATAERR naming the commit and the record

=head2 _take_lock($restore)

  $session->_take_lock($cwd);

Takes the switch lock, which is a non-blocking C<flock> on
F<genesis-session.lock> in the git directory. It writes the holder's pid on
the first line of that file and the command the holder is running on the
second, which is the form every reader of the file agrees on, so a command
carrying spaces cannot be mistaken for part of the pid.

Taking it twice in one session is a no-op, so a session that has already
switched switches again without asking for what it holds.

There is no break-lock option. The kernel drops the C<flock> when its holder
dies, so an abandoned lock cannot arise and a refusal always names a process
that is still running.

B<Parameters:>

=over 4

=item C<$restore>

The directory to stand back in before refusing, which is where C<switch> was
called from. A refusal is an exit, and the directory we exit in has to be the
one we came in on. It may be omitted, and a directory that is gone is left
alone.

=back

B<Returns:> C<$self>, so it chains.

B<Errors:>

=over 4

=item *

C<< "Unable to open the session lock at %s: %s" >> -- raised where the lock
file in the git directory cannot be opened.

=item *

C<< "Another Genesis process is using this working tree." >> -- raised where
another process holds the lock. It names that process's pid and its command,
reading both out of the lock file, and falls back to saying they are unknown
where the file holds neither. It exits on C<TEMPFAIL>.

=back

B<Examples:>

  $session->_take_lock($cwd);
  # returns $self, holding the lock, with our pid and command written inside

  $session->_take_lock($cwd);
  # stands back in $cwd and exits TEMPFAIL, naming the process that holds it

=head2 _release_lock

  $session->_release_lock;

Lets the switch lock go and closes the handle on it. C<finish> is the only
caller, so the lock is held for the whole of a session and released once the
restore has been verified.

Releasing a lock that is not held is a no-op, so a session that never switched
may be finished like any other.

B<Parameters:> None.

B<Returns:> C<$self>, so it chains.

B<Examples:>

  $session->_release_lock;
  # returns $self, and another process may now switch this working tree

=head2 _command_line

  my $what = Service::Git::Session::_command_line();

What the lock file names the holder as, so that a process refused by the lock
can say which command is standing in its way. It is the genesis command being
run where there is one, and the program name with its arguments otherwise,
which is what a child process spawned outside a command has to offer.

B<Parameters:> None.

B<Returns:> A one-line description of the running command.

B<Examples:>

  my $what = Service::Git::Session::_command_line();
  # returns 'genesis propagate' inside that command

=head2 _reset_to_remote($branch)

  $session->_reset_to_remote('qa/bosh');

Puts one branch back at its remote-tracking ref. It is a ref write rather
than a switch, so it takes no lock and needs no checkout, except on the
branch we are standing on, where a hard reset is what puts the tree and HEAD
back together.

A repository with no remote, or a branch with no remote-tracking ref, is left
exactly as it is, since there is no C<T> to go back to.

The control branch never reaches here, because C<committed_branches> is the
set this session moved and that accessor filters control out of it.

B<Parameters:>

=over 4

=item C<$branch>

The deployment branch to put back.

=back

B<Returns:> C<$self>, so it chains.

B<Errors:>

=over 4

=item *

C<< "Failed to reset %s" >> -- raised where the reset or the ref write
itself failed. C<%s> is the branch name.

=back

B<Examples:>

  $session->_reset_to_remote('qa/bosh');
  # returns $self, with qa/bosh sitting back at origin/qa/bosh

  $session->_reset_to_remote('qa/bosh');
  # returns $self unchanged where there is no remote-tracking ref to go back to

=head2 _restore

  $session->_restore;

Returns to the branch C<begin> recorded, from the repository root, and then to
the directory C<begin> recorded. Where that directory is gone, because the
branch we came back to does not carry it, it says so and leaves us at the
root rather than somewhere the caller did not choose. The branch is read back
afterwards and a return that did not land raises.

B<Parameters:> None.

B<Returns:> C<$self>, and C<$self> unchanged where C<begin> never ran.

B<Errors:>

=over 4

=item *

C<< "Unable to enter git root %s: %s" >> -- raised where the repository root
cannot be entered.

=item *

C<< "Unable to return to %s: %s" >> -- raised where the recorded directory is
there but cannot be entered.

=item *

C<< "Failed to return to %s: we are on %s." >> -- raised where the checkout
reported no failure but we are not on the recorded branch, which is a working
tree we could not put back.

=back

B<Examples:>

  $session->_restore;
  # returns $self, standing on the recorded branch in the recorded directory

  $session->_restore;
  # raises naming the branch we are stuck on, where the return did not land

=cut
