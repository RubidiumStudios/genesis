=head1 NAME

Service::Vault::Remote - A remote Vault target managed through safe

=head1 SYNOPSIS

  use Service::Vault::Remote;

  # Create a new safe target and get a vault object
  my $vault = Service::Vault::Remote->create(
    'https://vault.example.com:8200',
    'my-vault',
    skip_verify => 0,
  );

  # Attach to an existing safe target by URL
  my $vault = Service::Vault::Remote->attach(
    url    => 'https://vault.example.com:8200',
    verify => 1,
  );

  # Select or validate a target interactively
  my $vault = Service::Vault::Remote->target('my-vault');

  # Rebind to the previously selected vault inside a Genesis hook callback
  my $vault = Service::Vault::Remote->rebind();

  # Find all known remote vault targets
  my @vaults = Service::Vault::Remote->find();

  # Connect and authenticate
  $vault->connect_and_validate();

=head1 DESCRIPTION

C<Service::Vault::Remote> represents a remote HashiCorp Vault instance
managed through the C<safe> CLI tool. It inherits from C<Service::Vault>
and provides class methods for acquiring a vault object (C<create>,
C<target>, C<attach>) and instance methods for connecting to,
authenticating against, and holding a live session with the vault.

C<rebind> is inherited unchanged from L<Service::Vault> -- it looks up
whatever vault kind sits at C<GENESIS_TARGET_VAULT> and is deliberately
class-agnostic, so it is documented there rather than here.

Remote vaults are backed by entries in the user's C<~/.saferc> file. Each
safe target has a name (alias), a URL, and TLS verification settings.
C<Service::Vault::Remote> enforces that the URL is unique across all aliases,
which is required for Genesis's distributed deployment model.

Once a vault is acquired and validated, it is set as the C<current> vault
for the process, available via C<< Service::Vault->current >>.

=head1 METHODS

=head2 create

  my $vault = Service::Vault::Remote->create($url, $name, %opts);

Creates a new safe target pointing at C<$url> with alias C<$name> and
returns a C<Service::Vault::Remote> object representing that target. The
previous system safe target (if any) is restored after the new target is
registered.

If a vault with the same C<$name> already exists in the internal cache, it
is replaced by the newly created object.

B<Parameters:>

=over 4

=item $url

The URL of the Vault, e.g. C<https://vault.example.com:8200>.

=item $name

The alias name for the safe target.

=item %opts

Optional key-value pairs:

=over 4

=item skip_verify

If true, TLS certificate verification is skipped (passes C<-k> to C<safe target>).

=item namespace

The Vault namespace to use (passes C<-n NAMESPACE> to C<safe target>).

=item no_strongbox

If true, disables strongbox support (passes C<--no-strongbox> to C<safe target>).

=item mount

The secrets mount point to use (default: C</secret/>).

=back

=back

B<Returns:> A C<Service::Vault::Remote> object for the newly created target.

B<Errors:>

=over 4

=item C<"Could not create new Safe target %s pointing at %s:\n %s">

Raised if C<safe target> exits with a non-zero status. The first C<%s> is
the target name, the second is the URL, and the third is the error output
from safe.

=back

B<Examples:>

  my $vault = Service::Vault::Remote->create(
    'https://vault.example.com:8200',
    'prod-vault',
    skip_verify => 0,
    namespace   => 'myorg',
  );
  print $vault->name;  # Returns: 'prod-vault'

=head2 target

  my $vault = Service::Vault::Remote->target($target, %opts);
  my $vault = Service::Vault::Remote->target(undef, %opts);

Returns a C<Service::Vault::Remote> object for the given target, or presents
an interactive prompt for the user to select one. Use this when setting up
a deployment repository for the first time or switching vaults.

When C<$target> is provided, it is resolved to a URL via the known safe
targets. If the target is unknown or if its URL is shared by more than one
alias, an error is raised.

When C<$target> is not provided, the user must be in a controlling terminal.
All targets whose URLs are unique across aliases are presented for selection.
Targets whose URLs are shared by multiple aliases are omitted with an
explanatory note. The previously active system vault is shown as the
default selection.

In both cases the resolved vault is validated as reachable and authenticated
before being returned.

B<Parameters:>

=over 4

=item $target

An alias or URL of an existing safe target. Pass C<undef> (or omit) to
enter interactive selection mode.

=item %opts

Optional key-value pairs:

=over 4

=item default_vault

A C<Service::Vault> object to use as the pre-selected default in the
interactive prompt. If not provided, the current system target vault is
used. Has no effect when C<$target> is specified.

=back

=back

B<Returns:> A C<Service::Vault::Remote> object that has been connected and
validated via C<connect_and_validate>.

B<Errors:>

=over 4

=item C<"Safe target \"#M{%s}\" not found.  Please create itand authorize against it before re-attempting this command.">

Raised when the specified C<$target> does not match any known safe target.
C<%s> is the provided target value.

=item C<"Multiple safe targets use url %s:\n%s\n\nYour ~/.saferc file cannot have more than one target for the given url.  Please remove any duplicate targets before re-attempting this command.">

Raised when the resolved URL is used by more than one safe alias. C<%s> is
the URL, and the second C<%s> is a formatted list of the conflicting alias
names.

=item C<"There are no valid vault targets found on this system.">

Raised in interactive mode when no targets with unique URLs exist.

=item C<"Cannot interactively select vault unless in a controlling terminal - terminating!">

Raised when C<$target> is not provided and the process is not attached to
a controlling terminal.

=back

B<Examples:>

  # Select by known alias
  my $vault = Service::Vault::Remote->target('prod-vault');
  print $vault->url;  # Returns: 'https://vault.example.com:8200'

  # Interactive selection (requires a terminal)
  my $vault = Service::Vault::Remote->target(undef,
    default_vault => Service::Vault->default,
  );

=head2 attach

  my $vault = Service::Vault::Remote->attach(%opts);

Returns a C<Service::Vault::Remote> object for a safe target whose URL
matches C<url> in C<%opts>, according to the user's C<~/.saferc> file.

Each option value may be a literal string or an environment variable
reference beginning with C<$> (e.g., C<'$VAULT_ADDR'>), resolved at call
time.

TLS mode is inferred from the URL scheme (C<https> implies TLS) unless
C<tls> is provided explicitly.

When multiple targets share the same URL, namespace, and strongbox setting,
and an C<alias> is provided that matches one of them, that specific target
is selected. If no alias match is found among multiple candidates, an error
is raised.

When no matching target is found in C<~/.saferc> and no similar-URL targets
exist either, C<attach> will auto-provision a target from the caller-supplied
C<url> and options I<if> at least one complete set of authentication
environment variables is present (see L</"Auto-provisioning">). The
deployment's secrets provider is treated as the authoritative source; the
C<.saferc> file is a local cache and may be re-populated on demand. When no
close targets exist and no env credentials are present, the historical
"safe target not found" error is still raised.

B<Parameters:>

=over 4

=item url (required)

The URL of the Vault. May be a literal URL or a C<$ENV_VAR> reference.

=item alias

The preferred safe target alias to use when multiple targets match the
other filter criteria.

=item tls

Explicit TLS flag (1 for TLS, 0 for plain HTTP). If omitted, derived from
the URL scheme.

=item verify

If true and TLS is active, TLS certificate verification is required.

=item namespace

The Vault namespace. Used as an additional filter when searching for
matching safe targets.

=item strongbox

Whether strongbox support is expected. Used as an additional filter.

=item no_vault

If true and no matching safe target is found, return C<undef> instead of
raising an error.

=item silent

If true, suppresses progress output during C<connect_and_validate>.

=back

B<Returns:> A C<Service::Vault::Remote> object that has been connected and
validated, or C<undef> if C<no_vault> is true and no target is found.

B<Errors:>

=over 4

=item C<"No vault target specified">

Raised when C<url> is not provided or resolves to an empty value.

=item C<"Expecting vault target '$url' to be a url">

Raised when the resolved C<url> value is not a valid URL.

=item C<"Could not find matching safe target, but the following are similar:\n...">

Raised when no target exactly matches the filter but similar targets exist.
Includes a listing of the similar targets with their differing properties.

=item C<"Safe target for %s not found.  Please run\n\n  safe target <name> \"%s\"%s\n\nthen authenticate against it using the correct auth method before re-attempting this command.">

Raised when no target matches, no similar targets exist, and no environment
credentials are set to permit auto-provisioning. The first two C<%s> are
the URL, and the third C<%s> is C<""> when C<verify> is true or C<" -k">
otherwise.

=item C<"Multiple safe targets found for %s:\n%s\n\nYour ~/.saferc file cannot have more than one target for the given url, namespace, insecure or strongbox combination.  ...">

Raised when more than one target matches the filter and no C<alias> matches
any of them. C<%s> is the URL, and the second C<%s> is a list of matching
alias names.

=back

B<Examples:>

  my $vault = Service::Vault::Remote->attach(
    url    => 'https://vault.example.com:8200',
    verify => 1,
  );
  print $vault->name;  # Returns: the matching safe alias

  # Allow missing vault (returns undef instead of dying)
  my $vault = Service::Vault::Remote->attach(
    url      => '$VAULT_ADDR',
    no_vault => 1,
  );

=head3 Auto-provisioning

C<attach> fills a missing C<.saferc> target from its own arguments when:

=over 4

=item * No target matches the full filter (URL, namespace, strongbox, verify), AND

=item * No target matches the URL alone (no "similar" targets to reconcile), AND

=item * At least one complete environment-variable credential set is present:

=over 4

=item - AppRole:  C<VAULT_ROLE_ID> + C<VAULT_SECRET_ID>

=item - Token:    C<VAULT_AUTH_TOKEN>

=item - Userpass: C<VAULT_USERNAME> + C<VAULT_PASSWORD>

=item - GitHub:   C<VAULT_GITHUB_TOKEN>

=back

=back

The created target's alias is C<$alias> when supplied by the caller;
otherwise it is derived from the URL host with dots replaced by dashes
(e.g., C<https://vault.example.com:8200> becomes C<vault-example-com>).

After C<create> writes the target, C<attach> re-runs its filtered search
and proceeds with C<connect_and_validate>, which invokes C<authenticate>
against the same environment variables that gated the auto-provision.

The env-credentials gate exists because C<authenticate> would otherwise
fail immediately on the auto-provisioned target with no credentials to
try. Callers that want a target created without an authentication attempt
(e.g., operator-driven provisioning workflows) should call
C<Service::Vault::Remote-E<gt>create> directly instead.

Bulk-provisioning CLI callers, Concourse pipeline tasks, and other
non-interactive contexts that ship both the vault URL (via
C<.genesis/config> or C<genesis.vault>) and one auth-method credential
set benefit from this path: they no longer need a pre-configured
C<.saferc> in the working directory.

=head2 find

  my @vaults = Service::Vault::Remote->find(%filter);

Returns all known C<Service::Vault::Remote> objects, optionally filtered by
property. This is a subclass-scoped version of C<< Service::Vault->find >>:
it delegates to the parent and then retains only objects whose ref is
exactly C<Service::Vault::Remote>, excluding C<Service::Vault::Local>
instances and other subclasses.

B<Parameters:>

=over 4

=item %filter

Optional hash of property-value pairs. Valid properties include C<url>,
C<name>, C<tls>, and C<verify>. Each property is compared as a string.

=back

B<Returns:> A list of C<Service::Vault::Remote> objects matching the filter.

B<Examples:>

  # All remote vaults
  my @all = Service::Vault::Remote->find();

  # Only TLS-enabled vaults
  my @tls_vaults = Service::Vault::Remote->find(tls => 1);
  # Returns: list of Service::Vault::Remote objects using https

=head2 connect_and_validate

  my $vault = $vault->connect_and_validate($silent);

Verifies that the vault is reachable and authenticated, then sets it as the
current vault. If the vault is already current, no network calls are made.

If the vault's status is C<unauthenticated>, C<authenticate> is called to
attempt automatic login using environment variables. If the vault is still
not in C<ok> status afterward, an error is raised.

Unless C<$silent> is true, progress output is printed to the terminal
during the check. Output is also suppressed when running inside a Genesis
callback (C<in_callback>) or under the test harness (C<under_test>).

B<Parameters:>

=over 4

=item $silent

Optional. If true, suppresses all progress and status output.

=back

B<Returns:> The vault object itself after being set as the current vault via
C<set_as_current>.

B<Errors:>

=over 4

=item C<"Could not connect to vault%s">

Raised when the vault status is not C<ok> after connection and optional
authentication. When running silently, in a callback, or under test, the
C<%s> placeholder expands to C<" 'name' (url): status is STATUS)">. When
running interactively, it expands to an empty string (the status was already
printed to the terminal).

=back

B<Examples:>

  my $vault = Service::Vault::Remote->find(url => 'https://vault.example.com:8200');
  $vault->connect_and_validate();
  # Returns: the $vault object, now set as current

  # Silent validation (no terminal output)
  $vault->connect_and_validate(1);
  # Returns: the $vault object

=head2 authenticate

  my $vault = $vault->authenticate();

Attempts to authenticate against the vault using credentials found in
environment variables. Returns immediately if already authenticated.

After any successful authentication path (including the
already-authenticated short-circuit and the post-credential
last-chance check), a background token renewer is armed via
L</start_token_renewer>. Token renewal is only attempted if the token
itself is renewable and has a positive TTL; otherwise the renewer is a
no-op. See L</LIMITATIONS> for the conditions under which the renewer
declines to arm.

The following authentication methods are tried in order. The first method
whose required environment variables are all present and non-empty is
attempted:

=over 4

=item AppRole

Requires C<VAULT_ROLE_ID> and C<VAULT_SECRET_ID>.

=item Vault Token

Requires C<VAULT_AUTH_TOKEN>.

=item Username/Password

Requires C<VAULT_USERNAME> and C<VAULT_PASSWORD>.

=item Github Personal Access Token

Requires C<VAULT_GITHUB_TOKEN>.

=back

After all env-var methods are tried, a final check confirms authentication.
When that check still reports unauthenticated, the method falls through to an
B<interactive re-auth ladder>:

=over 4

=item 1.

L</_interactive_auth_available> evaluates the gating predicate. The
interactive prompt only fires when the process is attached to a controlling
terminal and is not running inside a Genesis kit-hook callback, with
C<GENESIS_QUIET> unset, C<GENESIS_NONINTERACTIVE> unset, and
C<GENESIS_TESTING> unset (test harnesses must never prompt).

=item 2.

If interactive auth is available, L</_authenticate_interactively> prompts
the operator with a menu of the same four auth methods, collects the
required credentials (hidden input for tokens, passwords, secret-ids,
PATs), and runs the identical C<safe auth $method> call the env-var path
uses.

=item 3.

If interactive auth is unavailable or the operator's response did not
produce a valid session, the method bails. The bail message distinguishes
two cases:

=over 4

=item *

When L</start_token_renewer> previously succeeded in this session
(C<$self-E<gt>{__renewer_armed_at}> is set), the message leads with
S<C<"Your vault session at %s has expired and could not be renewed.">> so
operators understand that a working session lapsed rather than seeing a
first-time-setup hint.

=item *

When no renewer was ever armed, the original C<"Could not successfully
authenticate against %s vault with safe."> heading is retained.

=back

In both cases, the bail body lists each supported auth method and its
required environment variables, with C<#R{[present, but failed]}>
annotations for any env-var attempt that ran but did not authenticate.

=back

B<Parameters:> None beyond C<$self>.

B<Returns:> The vault object itself if authentication is confirmed.

B<Errors:>

=over 4

=item C<"Your vault session at %s has expired and could not be renewed.\n\nGenesis can automatically re-authenticate with safe in the following ways:\n...">

Raised when a previously-armed token renewer's session has lapsed and no
re-auth path succeeded. C<%s> is the vault reference.

=item C<"Could not successfully authenticate against %s vault with safe.\n\nGenesis can automatically authenticate with safe in the following ways:\n...">

Raised on initial auth failure when no renewer has ever been armed for
this vault. C<%s> is the vault reference (name or alias).

=back

B<Examples:>

  # With VAULT_AUTH_TOKEN set in the environment:
  $ENV{VAULT_AUTH_TOKEN} = 'hvs.EXAMPLE';
  my $result = $vault->authenticate();
  # Returns: the $vault object

=head2 start_token_renewer

  my $pid = $vault->start_token_renewer();

Forks a background child that periodically renews the vault token for
the lifetime of the parent vault object. The child runs in its own
process (signal table, alarm timer, scheduler view) so it is immune to
the parent's C<alarm> usage in kit hooks, blocking C<system> calls
during long deploys, and reuse of C<$SIG{ALRM}> elsewhere.

Renewal loop body:

=over 4

=item *

Sleep for C<max(60, int($ttl / 2))> seconds.

=item *

Check the parent is alive (C<kill 0> against parent PID, plus
a C<getppid> of 1 as a reparented-to-init backstop immune to PID
reuse). Exit cleanly if the parent is gone.

=item *

Issue C<vault token renew>. On non-zero return code, exit with code 1
so the parent re-authenticates on its next vault call.

=item *

Re-read C<token_info()>. If the token has become non-renewable or its
TTL has dropped to zero, exit cleanly.

=back

Dead-man switches:

=over 4

=item *

B<Idempotent re-arm.> Any prior renewer is stopped before a new one
starts, so repeated C<authenticate()> calls never leak children.

=item *

B<eval-wrapped child body.> Every exit path goes through
C<POSIX::_exit>. A C<die> from anywhere inside the renewer loop is
caught and converted to C<POSIX::_exit(2)>, bypassing Perl's normal
exit machinery (which would otherwise run END blocks).

=item *

B<Fail-closed.> If C<token_info()> dies (vault unreachable, malformed
response, etc.), no renewer is started and C<authenticate()> proceeds
normally. The renewer is best-effort; its absence never crashes
callers.

=back

The child runs L<Genesis/init_forked_child> immediately after C<fork>
to neutralise inherited END/DESTROY hooks and install signal handlers
that bypass them.

B<Parameters:> None beyond C<$self>.

B<Returns:> The child PID on success; C<undef> when the token is not
renewable, when C<token_info()> failed, or when C<fork> failed.

B<Side effects:>

=over 4

=item *

Stores the child PID on C<$self-E<gt>{__renewer_pid}>.

=item *

Stores the start time on C<$self-E<gt>{__renewer_armed_at}>. Consumed
by L</authenticate>'s bail message to distinguish "session expired"
from "first-time authentication failure" -- see the heading variants
documented under L</authenticate>'s B<Errors>.

=item *

Reaps any prior renewer recorded on C<$self> before forking.

=back

=head2 stop_token_renewer

  $vault->stop_token_renewer();

Signals and reaps the background renewer child if one is running.

The stop sequence is:

=over 4

=item *

C<SIGTERM> the child.

=item *

Poll C<waitpid(..., WNOHANG)> for up to ~2 seconds.

=item *

If the child has not exited (it ignored TERM, or is stuck in an
uninterruptible syscall), escalate to C<SIGKILL> and block on
C<waitpid> to reap.

=back

This dead-man escalation is the load-bearing guarantee that
C<DESTROY> never hangs Genesis at command exit.

B<Parameters:> None.

B<Returns:> Nothing meaningful; called for side effects only. Safe to
call when no renewer is running (no-op).

=head2 renewer_pid

  my $pid = $vault->renewer_pid;

Returns the PID of the running token renewer child, or C<undef> when
none is running. Primarily a test seam.

=head2 DESTROY

Automatically invoked when the vault object goes out of scope. Calls
L</stop_token_renewer> to ensure no renewer child outlives its parent
vault instance.

=head1 INTERNAL METHODS

These are not part of the public interface. They are documented because
each one carries a behavioural contract that the public methods depend
on, and because three of them (L</_run_renewer_loop>,
L</_token_renewal_available>, L</renewer_pid>) exist specifically as
test seams.

=head2 _has_env_creds

  return 1 if _has_env_creds();

Returns true when at least one complete environment-variable credential
set for L</authenticate> is present (all vars in one method's list are
set to a true value).  Called by L</attach>'s auto-provision branch to
gate creation of a C<.saferc> target from the caller-supplied URL: an
auto-provisioned target with no credentials to try would immediately
fail C<connect_and_validate>, so the fallback is short-circuited when
no method could succeed.

Package-scoped C<@AUTH_TYPES> (the same array L</authenticate> iterates)
is the single source of truth for the supported methods:

=over 4

=item * AppRole -- C<VAULT_ROLE_ID> + C<VAULT_SECRET_ID>

=item * Token -- C<VAULT_AUTH_TOKEN>

=item * Userpass -- C<VAULT_USERNAME> + C<VAULT_PASSWORD>

=item * GitHub -- C<VAULT_GITHUB_TOKEN>

=back

B<Parameters:> None.

B<Returns:> C<1> if any method's env-var set is fully present, C<0>
otherwise.

=head2 _derive_target_name

  my $name = _derive_target_name($url);

Derives a stable, human-readable target alias from a Vault URL when the
caller of L</attach> did not supply one for auto-provisioning.  The
scheme and port are stripped, and dots in the host are replaced by
dashes so the result is a valid C<safe target> alias.

B<Parameters:>

=over 4

=item $url

A Vault URL, e.g. C<https://vault.example.com:8200>.

=back

B<Returns:> A dashed-host string (e.g. C<vault-example-com>), or the
literal C<'vault'> if the URL cannot be parsed to a host.

=head2 _on_auth_success

  return $self->_on_auth_success;

The common return path for every successful branch of L</authenticate>.
Arms the token renewer and returns the vault object.

L</authenticate> succeeds from four different places -- an
already-authenticated session detected on entry, a successful env-var
method, a re-check after all env-var methods have been tried, and a
successful interactive re-auth. Routing all four through this method is
what guarantees the renewer is armed regardless of which one won; adding
a fifth success branch without calling it would silently produce an
authenticated vault with no renewal.

B<Parameters:> None beyond C<$self>.

B<Returns:> C<$self>, so it can be used as a tail call.

B<Examples:>

  return $self->_on_auth_success if $self->authenticated;
  # returns the vault object, with the renewer started

=head2 _interactive_auth_available

  my $bool = $vault->_interactive_auth_available;

Pure predicate. Returns true only when L</authenticate> can safely
prompt the operator for credentials. Gates checked, all of which must
report "open" for the predicate to be true:

=over 4

=item *

Process is attached to a controlling terminal
(L<Genesis::Term/in_controlling_terminal>).

=item *

Not running inside a Genesis kit-hook callback
(L<Genesis::State/in_callback>). The parent Genesis owns user
interaction in that case.

=item *

C<GENESIS_QUIET> is not set.

=item *

C<GENESIS_NONINTERACTIVE> is not set. This is the explicit operator
opt-out for environments where a TTY happens to be attached (some CI
runners with PTY allocation) but interactive behaviour is undesired.

=item *

C<GENESIS_TESTING> is not set (L<Genesis::State/under_test>). Test
harnesses must never prompt.

=back

B<Returns:> 1 when interactive prompting is allowed, 0 otherwise.

=head2 _authenticate_interactively

  my $ok = $vault->_authenticate_interactively;

Prompt-driven re-auth flow used by L</authenticate> when env-var
auth methods have not produced a valid session and
L</_interactive_auth_available> reports true.

Presents the operator with a menu (via L<Genesis::UI/new_prompt_for_choice>)
of the same four auth methods the env-var path supports plus
C<Abort>:

=over 4

=item AppRole

Prompts for role-id (visible) and secret-id (hidden via
L<Genesis::UI/prompt_for_password>).

=item Vault Token

Prompts for the token (hidden).

=item Username/Password

Prompts for username (visible) and password (hidden).

=item GitHub Personal Access Token

Prompts for the PAT (hidden).

=back

Once credentials are collected the same C<safe auth $method> query
the env-var path uses is issued, and C<authenticated()> is checked
to confirm.

B<Returns:> 1 on successful re-auth, 0 when the operator aborts, enters
a blank credential, the safe call returns non-zero, or the
post-auth C<authenticated> check still reports false.

=head2 _run_renewer_loop

  my $rc = $self->_run_renewer_loop(%opts);

The body of the renewer child, factored out of L</start_token_renewer> so
it can be exercised without forking. Returns an exit code rather than
calling C<POSIX::_exit> itself; the caller in the child is what turns
that code into a process exit.

Every side-effecting operation is injected, which is the whole point of
the split -- a test drives the loop in-process by passing closures that
record their arguments instead of sleeping, signalling, or talking to a
vault.

B<Parameters:> a hash with these keys, all required:

=over 4

=item C<parent_pid>

The PID to monitor. Passed to C<kill_fn> on each iteration.

=item C<ttl>

The token's initial TTL in seconds. Re-read from C<info_fn> after each
successful renewal.

=item C<sleep_fn>

Invoked with the computed sleep duration. In production this is
C<sub { sleep $_[0] }>.

=item C<kill_fn>

Invoked with C<parent_pid>. Truthy means the parent is alive. Production
returns 0 immediately when C<getppid> is 1 -- reparenting to init is a
definitive orphan signal, unlike C<kill 0>, which can be fooled by PID
reuse on long-running systems.

=item C<query_fn>

Invoked as C<< $query_fn->('vault', 'token', 'renew') >>; must return
C<($out, $rc, $err)>.

=item C<info_fn>

Invoked after each renewal; must return a C<token_info> hashref.

=back

B<Returns:> the child's intended exit code.

=over 4

=item C<0>

The parent is gone, or the token became non-renewable / its TTL decayed
to zero. Either way there is nothing left to renew.

=item C<1>

C<vault token renew> returned non-zero. The parent re-authenticates on
its next vault call.

=back

The sleep interval is C<int($ttl / 2)>, floored at 60 seconds so a
pathologically short token cannot cause a busy-renew loop.

B<Examples:>

  # Parent already gone: the loop sleeps once and exits cleanly.
  my $rc = $vault->_run_renewer_loop(
    parent_pid => 4242,
    ttl        => 3600,
    sleep_fn   => sub { push @slept, $_[0] },
    kill_fn    => sub { 0 },
    query_fn   => sub { ('', 0, '') },
    info_fn    => sub { {} },
  );
  # returns 0; @slept is (1800)

  # Renewal rejected by the vault.
  my $rc = $vault->_run_renewer_loop(
    parent_pid => $$,
    ttl        => 60,
    sleep_fn   => sub {},
    kill_fn    => sub { 1 },
    query_fn   => sub { ('', 1, 'permission denied') },
    info_fn    => sub { {} },
  );
  # returns 1

=head2 _token_renewal_available

  my $bool = $self->_token_renewal_available($info);

Pure predicate over a C<token_info> response. Decides whether a token
supports background renewal at all -- consulted once by
L</start_token_renewer> before forking, and again by
L</_run_renewer_loop> after every renewal.

True requires all of: C<$info> is a hashref, it has a C<data> key, that
data is marked C<renewable>, and its C<ttl> is a positive integer. Root
tokens, batch tokens, and non-expiring periodic tokens fail this and are
correctly skipped rather than treated as an error.

B<Parameters:>

=over 4

=item C<$info>

The hashref returned by C<token_info>, or any value at all -- the
predicate is total, so a malformed or undefined response is simply
false rather than a die.

=back

B<Returns:> 1 when the token is renewable with a positive TTL, 0
otherwise.

B<Examples:>

  $vault->_token_renewal_available({data => {renewable => 1, ttl => 3600}});
  # returns 1

  $vault->_token_renewal_available({data => {renewable => 1, ttl => 0}});
  # returns 0 (expired or non-expiring)

  $vault->_token_renewal_available(undef);
  # returns 0 (token_info failed; fail-closed)

=head1 LIMITATIONS

=over 4

=item *

The token renewer only arms when C<token_info()> returns a token that
is both C<renewable> and has a positive C<ttl>. Tokens issued without
the C<renewable> capability (root tokens, batch tokens, periodic
tokens that don't expire) are correctly skipped.

=item *

The renewer is fail-closed: any failure during C<token_info()> (auth
denied to C<vault token lookup>, malformed response, network error)
results in B<no renewer> being started. Callers are not informed; a
later token expiry surfaces as a normal vault failure.

=item *

The child's parent-liveness check polls C<kill 0> and C<getppid> at
the half-life of the current token TTL. In the worst case the child
runs up to one half-life past the parent's exit before noticing it
was orphaned (mitigated by Genesis's own C<DESTROY>-driven
C<SIGTERM>).

=item *

Self-deploy guard (skipping renewal when deploying the vault that
issued the token) is handled at the env layer, not by
C<Service::Vault::Remote>. See
L<Genesis::Env/_stop_renewer_for_self_deploy>.

=item *

The interactive re-auth ladder only fires when L</authenticate> is
called and discovers no env-var method succeeded. Code paths that
talk to the vault without going through C<authenticate> first (e.g.
direct C<safe> CLI invocations bypassing this module) will surface a
token expiry as a normal vault failure rather than triggering the
prompt.

=item *

B<Auto-provisioning does not reconcile mismatched targets.>
When a C<.saferc> target exists for the same URL but with a different
namespace, strongbox, or verify setting, C<attach> raises the historical
"similar targets" error rather than adding a second target or overwriting
the existing one. The operator must edit C<.saferc> (or the caller's
options) so that URL + namespace + strongbox + verify agree.

=item *

B<Auto-provisioned targets survive auth failure.>
The env-credentials gate on C<attach>'s auto-provision path only checks
that a credential set is I<present>, not that it I<works>. If
C<connect_and_validate> subsequently fails to authenticate, the newly
created target still lives in C<~/.saferc> for future runs. Interactive
callers may want to remove such stale targets with C<safe target -d>.

=item *

B<Multi-worker C<HOME> collisions are the caller's responsibility.>
Parallel workers that share a C<HOME> race on C<.saferc>. C<attach>'s
auto-provision does not guard against this. Test harnesses and CI runners
that fork per-env workers should isolate C<HOME> per worker.

=back
